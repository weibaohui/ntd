# NTD-007 任务详情工艺要求门禁信息不完整 — 缺陷分析

| 修改人 | 修改时间 | 修改内容 |
|--------|---------|---------|
| AI(Kimi) | 2026-07-30 | 初始版本 |

---

## 1. 代码链路

```
/#/tasks/:id
  → TaskDetailPage
    → TaskDetailPanel
      → bundledApi.getTaskDetail(workspaceId, taskId)
        → backend get_task_detail 返回 steps[].gate_config（完整 JSON）
      → ProcessTab
        → StepItem
          → step.gate_config.map(g => <Tag>{g.name} ({gateLabel(g.type)})</Tag>)
```

## 2. 根因

后端 `get_task_detail` 已经把 `loop_steps.gate_config` 解析成完整 JSON 返回；真正丢失信息的是前端类型与渲染：

```ts
gate_config: Array<{ name: string; type: string }>;
```

上述类型只保留 `name` / `type`，导致渲染逻辑也只用这两个字段：

```tsx
<Tag>{g.name} ({gateLabel(g.type)})</Tag>
```

因此即使 `ai_criteria_review` 门禁 JSON 中存在 `min_score`，页面也不会展示「通过阈值是多少分」。

## 3. 影响面

- 仅影响任务详情页「工艺要求」tab 的静态门禁配置展示。
- 不影响后端门禁评价、不影响执行历史 tab、不影响工艺模板编辑器。
- 无需改后端接口：`get_task_detail` 已返回完整 `gate_config` JSON。

## 4. 修复方案

**只改 `frontend/src/components/tasks/TaskDetailPanel.tsx`，不新增后端改动**：

1. 扩展 `StepInfo.gate_config` 类型，补上 `artifact` / `criteria_ref` / `min_score` / `script` / `timeout_secs` 可选字段。
2. 新增门禁详情文本构造函数：按门禁类型生成关键配置摘要。
   - `ai_criteria_review`：显示 `阈值 ≥ N 分`；如有 `timeout_secs` 正数，再补 `等待 ≤ Ns`。
   - `artifact_present`：显示 `产物 <artifact>`（如果配置里给了 artifact）。
   - `script_check`：显示 `脚本 <script>`（如果配置里给了 script）。
   - `human_approval`：无额外必填参数，保持 `人工审批`。
3. 渲染 Tag 时改为 `名称 (类型标签 · 详情)`；无详情时保持原有 `名称 (类型标签)`，避免视觉噪音。

## 5. 测试方案

- 前端类型检查：`cd frontend && npx tsc --noEmit`
- 前端构建：`cd frontend && npm run build`
- Playwright 验证：
  1. 在 dev DB 准备一个带 `ai_criteria_review` 门禁（`min_score=80`）的任务；
  2. 打开 `http://localhost:18088/#/tasks/<id>`；
  3. 切到「工艺要求」tab；
  4. 断言门禁 Tag 文本包含 `AI 评审` 与 `阈值 ≥ 80 分`。

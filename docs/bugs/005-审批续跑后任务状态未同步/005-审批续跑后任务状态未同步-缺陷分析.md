# NTD-005 审批续跑后任务状态未同步 — 缺陷分析

| 修改人 | 修改时间 | 修改内容 |
|--------|---------|---------|
| AI(claude) | 2026-07-29 | 初始版本 |

---

## 1. 数据流链路

```
【启动路径（完整，对照组）】
start_loop_execution
  → spawn {
      run_inner() 返回 Finished/Paused/Err
      → 读 loop_execution → update_task_status(task_id, 映射(le.status))   ← 任务状态同步
      → match:
          Finished → 飞书回复原对话 或 广播 LoopFinished
          Paused   → 仅日志（正确：审批等待中）
          Err      → finish_loop_execution(failed) + 异常处理 Todo + WS 事件
                     ✗ 但任务状态同步在上面已执行过，读到的是 running，终态化后未再同步（缺陷 C）
    }

【resume 路径（缺失收尾，主缺陷）】
approve_gate / approve_step_execution
  → resume_loop_execution
      → spawn { run_inner_from() 返回后仅 error! 日志 }              ← 什么都没做
          ✗ 不同步 tasks.status（缺陷主因）
          ✗ 不广播 LoopFinished（连带 A）
          ✗ Err 不终态化/不触发异常处理（连带 B）

【前端两列（症状放大器）】
任务列表「状态」列     ← tasks.status（快照，依赖上述同步）
任务列表「最近执行」列 ← 实时 SELECT loop_executions.status（始终正确）
→ 同步缺失时两列必岔开
```

## 2. 根因

**收尾逻辑与启动路径强耦合，resume 路径零收尾。** 任务状态同步、LoopFinished 广播、错误兜底三段逻辑全部内联在 `start_loop_execution` 的 spawn 闭包里（`loop_runner.rs:206-340`），`resume_loop_execution` 的 spawn（`loop_runner.rs:480-491`）只调用 `run_inner_from`，没有复用任何收尾。NTD-004 打通审批链路后，resume 成为常态路径，该缺失即在界面上暴露。

## 3. 修复方案（已获用户确认）

1. **抽共享收尾**（`loop_runner.rs`）：
   - `task_status_for_loop_status(&str) -> &str`：状态映射纯函数（success/partial→success，failed/capped_*→failed，其余→running），供单测。
   - `sync_task_status(loop_execution_id)`：读 loop_execution，若关联 task 则按映射回写。
   - `broadcast_loop_finished(loop_id, loop_execution_id)`：计算统计/时长/token 并广播 LoopFinished。
   - 启动路径改为调用上述方法（行为保持不变）；resume 路径的 spawn 调用同一套：
     - Finished → sync + 广播 LoopFinished
     - Paused → 仅日志（多审批环节的 loop 可能再次暂停，与启动路径一致）
     - Err → finish_loop_execution(failed) + 异常处理 Todo + sync（此时读到 failed，任务落 failed）
2. **修连带缺陷 C**：启动路径 Err 分支在终态化后补一次 `sync_task_status`。
3. **e2e**：扩展 `frontend/tests/ntd004-human-approval.spec.ts`——审批通过后断言 `task.status` 与 `executions[0].status` 同为 success，拒绝场景同为 failed（盯住两列收敛）。

### 明确不做

- 前端两列不合并、不删除（既有设计，同步修好后自然收敛）。
- resume 路径的飞书"回复原对话"（需透传 receive_id 上下文）：统一走 LoopFinished 广播，列入已知限制。

## 4. 影响面与回归点

- 启动路径：重构后行为必须逐条等价（飞书回复分支、Paused 不广播、Err 兜底），靠既有后端全量测试 + 代码走读保证。
- resume 路径：NTD-004 的三条 e2e 用例继续通过 + 新增任务状态断言。
- 无 DB schema 变更、无 API 变更。

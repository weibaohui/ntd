## 4. 实际行为（Observed Behavior）

1. **主缺陷**：审批续跑结束后，`loop_executions.status` 已为 success/failed，但 `tasks.status` 保持 `running` 不变。任务列表「状态」列（读 `tasks.status`）一直显示"进行中"，「最近执行」列（实时查 `loop_executions.status`）显示正常终态，两列长期不一致。发生频率：必现。
2. **连带缺陷 A**：resume 路径终态时不广播 `LoopFinished` 事件，飞书推送与依赖该事件的前端刷新不触发（启动路径在 `loop_runner.rs:286-297` 有此广播）。
3. **连带缺陷 B**：resume 路径的 `run_inner_from` 返回 Err 时只 `error!` 打日志（`loop_runner.rs:489`），loop_execution 不落 failed 终态、任务状态不同步、异常处理 Todo 不触发。
4. **连带缺陷 C**（启动路径内）：`run_inner` 返回 Err 时，任务状态同步发生在 Err 分支终态化 loop_execution **之前**，读到的是 `running`，终态化后未再同步——启动路径出错同样会把任务留在"进行中"（`loop_runner.rs:223-233` 与 `308-321` 的先后顺序）。

## 5. 期望行为（Expected Behavior）

- 审批续跑结束后，`tasks.status` 按 loop 终态同步：success/partial→success，failed/capped_step/capped_token→failed。
- resume 路径终态广播 `LoopFinished`（无绑定飞书对话时），与启动路径一致。
- 任一路径 run 返回 Err：loop_execution 落 failed 终态、任务状态同步 failed、触发异常处理。
- 修复后任务列表「状态」与「最近执行」两列收敛一致。

## 6. 行为偏差定义（Deviation）

> 在【任务关联的 loop 经人工审批 resume 续跑至终态】下，系统实际执行了【仅推进 loop_execution，不同步 tasks.status、不广播 LoopFinished、出错只打日志】，但期望执行的是【与启动路径一致的完整收尾：同步任务状态、广播完成事件、错误兜底终态化】。

# NTD-009 任务批量删除后列表不刷新 — 缺陷分析

| 修改人 | 修改时间 | 修改内容 |
|--------|---------|---------|
| AI(Kimi) | 2026-07-30 | 初始版本 |

---

## 1. 代码链路

```
TasksPage
  ├─ reload()：bundledApi.listTasks(wsId) → setTasks(data)
  ├─ refreshKey 变化 → useEffect → reload()
  └─ <TasksTableView tasks={timeFilteredTasks} ... />

TasksTableView
  └─ handleBatchDelete
      → modal.confirm onOk
        → bundledApi.batchDeleteTasks(workspaceId, ids)
        → message.success(...)
        → setSelectedIds([])
        ✗ 没有通知 TasksPage 刷新
```

## 2. 根因

任务列表数据由父组件 `TasksPage` 持有，刷新入口是 `refreshKey` 自增后触发 `reload()`。
但批量删除发生在子组件 `TasksTableView` 内部，删除成功后没有回调父组件，导致 `tasks` 仍是删除前的旧数据。

## 3. 影响面

- 仅影响任务列表页批量删除后的列表刷新。
- 不影响批量删除接口本身、不影响手动刷新、不影响事项 / 环路列表。

## 4. 修复方案

**改动 `frontend/src/components/tasks/TasksTableView.tsx` 与 `frontend/src/components/tasks/TasksPage.tsx`**：

1. `TasksTableViewProps` 新增 `onChanged: () => void`，语义为「列表数据已被本组件修改，请父组件刷新」。
2. 批量删除成功后：先提示、清空选中，再调用 `onChanged()`。
3. `TasksPage` 渲染 `TasksTableView` 时传入 `onChanged={() => setRefreshKey((k) => k + 1)}`，复用既有刷新链路。

## 5. 测试方案

- `cd frontend && npx tsc --noEmit`
- `cd frontend && npm run build`
- 新增 Playwright：`frontend/tests/ntd009-tasks-batch-delete-refresh.spec.ts`
  1. 自种子两条任务；
  2. 打开 `/#/tasks` 并勾选这两条；
  3. 批量删除并确认；
  4. 断言页面出现删除成功提示，且两条任务行从表格中消失。

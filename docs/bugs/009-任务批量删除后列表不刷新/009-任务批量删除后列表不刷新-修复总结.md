## 1. 修复内容

**改动文件**：

- `frontend/src/components/tasks/TasksTableView.tsx`
- `frontend/src/components/tasks/TasksPage.tsx`
- `frontend/tests/ntd009-tasks-batch-delete-refresh.spec.ts`

| 改动点 | 说明 |
|--------|------|
| 新增变更回调 | `TasksTableViewProps` 新增 `onChanged`，用于子组件批量删除成功后通知父组件刷新 |
| 删除成功刷新 | `handleBatchDelete` 成功后除提示与清空选中外，补调 `onChanged()` |
| 复用刷新链路 | `TasksPage` 传入 `onChanged={() => setRefreshKey((k) => k + 1)}`，仍走既有 `reload()` |
| 回归测试 | 新增 Playwright spec：自种子两条任务，批量删除后断言两行从表格消失 |

## 2. 与缺陷分析的对应关系

| 根因 | 修复手段 |
|------|---------|
| 任务数据由 `TasksPage` 持有，但删除成功后子组件未通知父组件刷新 | 通过 `onChanged` 回调触发 `refreshKey` 自增，复用父组件既有 `reload()` |

## 4. 安全反思

- 只补充前端刷新回调，不改变批量删除接口权限与参数。
- 删除失败分支不触发刷新，避免把失败结果误表现成列表已变更。
- 仍保留二次确认与危险按钮，不降低误删防护。

## 5. 已知限制 / 待改进

- 当前刷新是整表重拉，与手动刷新按钮一致；后续如需更细粒度，可再优化为仅移除已删行并回退分页。

## 2. 与缺陷分析的对应关系

- **根因 1（内容空白）**：由改动 1 消除。修复前 glob 默认懒加载，值为 `() => Promise<string>`，XMarkdown 收到函数类型输入拒绝渲染；修复后值为字符串，内容正常渲染。
- **根因 2（点标题不展开）**：由改动 2 消除。用户点击菜单文字即展开子菜单，不再依赖隐蔽的小箭头。

## 3. 存量用例 AC-M1-3 的连带修复

该用例自 PR #972 引入起从未通过（内容空白 bug 所致），本次一并修复三处结构性问题：

1. **错误假设「默认选中帮助首页」**：抽屉设计为默认选中当前页面总览（事项视图 → todos-list），用例改为先显式点击「帮助首页」节点再断言。
2. **`toContainText(['a','b'])` 数组误用**：数组语义要求 locator 解析为等长元素列表，`.ant-drawer-body` 只有一个元素必然失败，拆成两条独立断言。
3. **helper 在父节点 DOM 内找子节点 + 依赖内部 class 判展开态**：antd Tree 节点平级渲染，子节点不嵌套在父节点内；`ant-tree-treenode-expanded` class 判断不可靠（已观测到误判导致 switcher 点击反向收起）。改为「子节点标题可见性」判断 + 点父标题展开。

## 5. 安全反思

- 纯前端渲染修复，不涉及接口、权限、数据写入。
- `eager: true` 会把 `help/pages/*.md` 全部内联进 bundle：md 为静态帮助文档，无敏感信息；体积影响已在设计意图内（原注释即「构建时打进 bundle」）。
- 无用户输入参与渲染（md 来源为仓库内置文件），无 XSS 注入面变化（XMarkdown 渲染链路未改动）。

## 6. 已知限制

- 点击已展开的父节点标题不会收起子菜单（收起仍走 switcher 箭头），属刻意取舍，避免「选中」与「收起」语义冲突。
- 帮助文档内容本身仍处于 M3 骨架阶段，与本缺陷无关。

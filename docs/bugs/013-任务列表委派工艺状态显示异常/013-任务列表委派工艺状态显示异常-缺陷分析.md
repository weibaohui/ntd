# NTD-013 任务列表委派工艺状态显示异常 — 缺陷分析

| 修改人 | 修改时间 | 修改内容 |
|--------|---------|---------|
| TraeAI | 2026-08-10 | 初始版本 |

---

## 1. 代码链路（三问题独立链路）

### 问题 A：工艺列 `#0-#0--`

```
create_delegate_task (backend)
  → template_id = Some(0)
    → list_tasks → TaskItem.template_id = Some(0)
      → frontend TasksTableView
        → formatProcessText(id=0, name=null, version=null)
          → id != null → 不走占位分支
            → displayName = `#0`, displayVersion = '—'
              → 输出 `#0-#0--`（Tag 显示）
```

### 问题 B：委派任务状态「待执行」与执行不同步

```
create_delegate_task
  → tasks.status = 'pending'（DB 默认，代码未显式覆盖）
    → land_delegate_first_post → land_mention_post → trigger discussion
      → 执行器启动，但 tasks.status 仍为 pending（初始不同步）
        → 执行完成回写（task_posts / completion 路径）
          → 更新 loop_executions.status（success/failed）
          → ❓ 是否同步 tasks.status？（需检查：大概率未同步）
```

### 问题 C：委派任务无委派信息透出

```
list_tasks (backend)
  → TaskItem.execution_mode = 'delegate'
  → TaskItem.assignee_kind / assignee_name / auto_continue / continue_rounds
    → 前端 TasksTableView「工艺」列
      → 只调 formatProcessText(template_id, template_name, template_version)
        → 完全未读 execution_mode 及委派字段 → 无任何委派信息
```

## 2. 根因（逐条）

### 问题 A
- 后端语义：委派任务无工艺模板，`template_id=Some(0)` 是「哨兵值」，但语义上等同于 `None`
- 前端防御：`formatProcessText` 未将 `0` 视为无效值，`0` 被当作有效模板 ID 进入三段式拼接
- 结论：**前后端都有口径缺口**——后端应直接传 `None`（语义准确），前端应兜底 `id <= 0` 判空（兼容存量脏数据）

### 问题 B
- 初始状态：`create_delegate_task` 未显式写 `running`，依赖 DB 默认 `pending`，但首帖会立即触发执行 → 状态与实际不一致
- 完成回写：需检查 `task_posts` 回写结论与 `completion.rs` 成功/失败回调，是否同步了 `tasks.status`。若只更了执行记录而未更 `tasks.status`，则列表永远停在「待执行」或「进行中」，与实际完成状态不符

### 问题 C
- 委派字段已随 TaskItem 下发，但前端列表未做类型分支渲染
- 「工艺」列的当前 render 只考虑工艺场景，未区分 `execution_mode`，导致委派任务在该列既无工艺可显、又无委派信息 → 错误格式 `#0-#0--`

## 3. 影响面

| 模块 | 问题 A | 问题 B | 问题 C |
|------|--------|--------|--------|
| TasksTableView（列表） | ✅ 工艺列 | ✅ 状态列 | ✅ 工艺列位置复用 |
| TasksCardView（卡片） | ✅ 工艺片段 | ⚠️ 状态 Tag | ⚠️ 如卡片有工艺区，需同步 |
| TasksKanbanView（看板） | ⚠️ 卡片内工艺字段 | ✅ 泳道分组依据 task.status | ⚠️ 卡片头部 |
| 事项/环路列表 | ✅ 共用 formatProcessText | —（无委派概念） | — |
| 任务详情 | —（详情版本逻辑独立） | ✅ 详情头部状态 | —（详情已有委派 Tab） |

## 4. 修复方案

### 方案 1A：工艺列修正（前后端双保险）

**后端** — `backend/src/db/task.rs` `create_delegate_task`：
- `template_id: ActiveValue::Set(Some(0))` → `ActiveValue::Set(None)`
- 语义准确：委派任务就是没有工艺模板，不该用 0 哨兵值

**前端** — `frontend/src/utils/processText.ts` `formatProcessText`：
- `if (id == null) return '-';` 扩展为 `if (id == null || id <= 0) return '-';`
- 兼容存量数据（已有 `template_id=0` 的老委派任务）及其他列表页

### 方案 2A：委派任务状态同步（初始 + 回写两处）

**初始状态** — `create_delegate_task`：
- 显式设置 `status: ActiveValue::Set("running".to_string())`
- 首帖触发后即进入执行，不再等 DB 默认 pending

**回写同步** — 搜索并确认：
- `backend/src/handlers/task_posts.rs` 中写 `task_posts` 结论帖的路径（成功 / 失败 / 人工终止）
- `backend/src/executor_service/completion.rs` 中执行完成回调
- 上述位置若未调 `db.update_task_status(task_id, new_status)`，则补上：
  - 成功 → `success`
  - 失败 → `failed`
  - 人工取消 → `failed`（或新增 `cancelled`，需与 STATUS_LABEL 同步，暂用 failed 避免扩枚举冲击面）

### 方案 3A：委派任务「工艺」列复用为委派信息 + 环路/委派徽标

**前端 `TasksTableView` 工艺列 render 改为分支**：

```
if (task.execution_mode === 'delegate') {
  // 委派模式：显示委派信息
  const kindLabel = task.assignee_kind === 'expert' ? '专家' : '执行器';
  const tagText = `委派给：${task.assignee_name}（${kindLabel}）`;
  const suffix = task.auto_continue ? ' 🚀自动接力' : '';
  return <Tag color="blue">{tagText}{suffix}</Tag>;
} else {
  // 环路模式：保持原工艺列三段式
  const text = formatProcessText(task.template_id, task.template_name, task.template_version);
  return text === '-' ? <Text type="secondary">—</Text> : <Tag>{text}</Tag>;
}
```

**状态列旁加小徽标**（方案 4A）：
- 状态 Tag 后追加一个 10px 字号的灰色 span：`execution_mode === 'delegate' ? '委派' : '环路'`
- 不新增列，只在状态列 render 内 inline 拼接

## 5. 测试方案

### 单元测试（后端）
- `create_delegate_task` → 断言返回的 `task.template_id == None`（非 `Some(0)`）
- `create_delegate_task` → 断言返回的 `task.status == "running"`
- `formatProcessText`（前端单测如有）→ id=0 / id=-1 / id=null 均返回 `'-'`

### 集成测试
- 建委派任务 → 列表查 TaskItem → 断言 `template_id` 为 null / 状态列非 pending
- 模拟讨论区执行成功回写 → 断言 `tasks.status == "success"`
- 失败路径同理断言 `failed`

### 前端 Playwright（可选，如有 tasks 列表用例）
- 列表中同时有环路任务 + 委派任务：
  - 环路任务「工艺」列可见三段式 Tag
  - 委派任务「工艺」列位置可见蓝色委派 Tag
  - 状态 Tag 旁可见「环路/委派」小徽标

# NTD-010 任务列表工艺版本显示不正确 — 修复总结

| 修改人 | 修改时间 | 修改内容 |
|--------|---------|---------|
| AI(Codex) | 2026-07-31 | 初始版本 |

---

## 1. 修复内容

**改动文件**：

- `backend/src/handlers/tasks.rs`（`list_tasks` 版本口径 + 批量查询 + 测试）
- `backend/src/db/loop_.rs`（新增 `get_loops_by_ids` + 单元测试）

| 改动点 | 说明 |
|--------|------|
| `list_tasks` 版本口径 | `template_version` 从「模板当前版本」改为「环路 `process_template_version` 快照优先，缺失回退模板当前版本」，与任务详情 `get_task_detail` 完全一致 |
| 批量查询 | 模板复用既有 `get_process_templates_by_ids`，环路新增 `get_loops_by_ids`，列表接口从逐任务 3 次查询降为 3 条 SQL（1 列表 + 1 模板批量 + 1 环路批量），消除 N+1 |
| 函数拆分 | 抽出 `fetch_latest_execution` 与 `build_task_item`，`list_tasks` 函数体保持在 30 行以内 |

## 2. 与缺陷分析的对应关系

| 根因 | 修复手段 |
|------|---------|
| `list_tasks` 直接取 `process_templates.version`（当前版本），与详情「环路快照优先」口径不一致 | 列表改为环路快照优先、缺失回退模板当前版本，两接口口径统一 |
| 每任务一次模板查询 + 一次执行查询的 N+1 | 模板与环路各一次批量查询；执行查询保留（单条按需 SQL） |

## 3. 测试与验证结果

- 新增单元测试 `test_get_loops_by_ids_batch`：批量命中 / 部分命中 / 空入参短路 → 通过
- 新增 handler 测试 `test_list_tasks_uses_loop_snapshot_version`（真实 HTTP 路由）：
  - 环路有快照 1.0.0、模板升级到 2.0.0 → 列表显示 1.0.0（快照优先）→ 通过
  - 环路无快照 → 列表回退显示 2.0.0（模板当前版本）→ 通过
- `cd backend && cargo clippy --all-targets -- -D warnings`：零告警零错误
- `cd backend && cargo test`（非沙箱全量）：全部通过（含既有 sys::unix_tests / wiki::fs 等在沙箱内受权限限制的用例，非本次改动引入）
- 前端无需改动：`TasksTableView` 已通过 `formatProcessText` 统一渲染列表返回的 `template_version`

## 4. 安全反思

- 改动仅调整列表接口 `template_version` 字段的取值来源，不新增接口、不改变权限校验、不引入用户输入处理路径。
- 环路快照与模板版本均为数据库既有字段，取值时无 SQL 注入面（批量查询走 SeaORM 参数化 `is_in`）。
- 无越权风险：列表仍按 `workspace_id` 过滤，环路/模板查询只读，未放宽任何访问边界。
- 无敏感信息泄露：不涉及凭据、日志、配置输出。

## 5. 已知限制 / 待改进

- `list_tasks` 中「最近执行」仍按任务逐条查 `loop_executions`（一次性 SQL），本次未纳入批量范围；如列表量大可后续用 `task_id IN (...)` 一次聚合。
- 任务详情接口版本口径保持不变（本就正确），未做重构。

# NTD-010 任务列表工艺版本显示不正确 — 缺陷分析

| 修改人 | 修改时间 | 修改内容 |
|--------|---------|---------|
| AI(Codex) | 2026-07-31 | 初始版本 |

---

## 1. 代码链路

```
任务列表页
  → TasksTableView「工艺」列
    → formatProcessText(task.template_id, task.template_name, task.template_version)
      → GET /api/v1/workspaces/{ws}/tasks
        → backend list_tasks
          → template_version = get_process_template_by_id(tid).version  ← 模板当前版本

任务详情页
  → TaskDetailPanel「工艺模板」信息
    → GET /api/v1/workspaces/{ws}/tasks/{id}
      → backend get_task_detail
        → version = loop.process_template_version.unwrap_or(template.version)  ← 环路快照优先
```

## 2. 根因

同一任务的工艺版本，在两个 handler 中取值口径不一致：

```rust
// list_tasks：直接取工艺模板表的当前版本
template_version: pt.as_ref().map(|p| p.version.clone()),

// get_task_detail：优先取环路快照，缺失才回退模板当前版本
let version = loop_.as_ref()
    .and_then(|l| l.process_template_version.clone())
    .unwrap_or(t.version.clone());
```

`loops.process_template_version` 是环路创建/升级工艺时写入的版本快照（`installer.rs`），
代表「执行当时的工艺版本」。当模板之后再次升级（版本号变化）而环路未同步升级时，
列表显示新版本、详情显示快照版本，两者不一致。

## 3. 影响面

- 仅影响 `list_tasks` 返回的 `template_version` 字段及前端任务列表「工艺」列展示。
- 任务详情接口口径正确，作为修复基准，不动。
- 前端 `TasksTableView` / `formatProcessText` 已统一渲染 `#id-名称-版本`，无需改动。
- 事项 / 环路列表的工艺版本已使用 `COALESCE(l.process_template_version, pt.version)`
  （`db/loop_.rs`），与本修复后的口径一致。

## 4. 修复方案

**修改 `backend/src/handlers/tasks.rs` 的 `list_tasks`**，使其与详情口径一致：

1. 批量取本次列表涉及的工艺模板（复用既有 `get_process_templates_by_ids`）与环路
   （新增 `get_loops_by_ids`），各一条 SQL，消除逐任务 N+1；
2. 每个任务的 `template_version` 取值为：
   `环路 process_template_version 快照 ?? 模板当前版本`；
3. 抽出单任务条目组装辅助函数，保持 `list_tasks` 函数体 ≤ 30 行。

同时新增 `get_loops_by_ids` 的单元测试，并补充 `list_tasks` 版本口径的集成测试：

- 快照存在时：列表返回环路快照版本（即使模板已升级到新版本）；
- 快照缺失时：列表回退模板当前版本。

## 5. 测试方案

- 单元测试：`get_loops_by_ids` 批量命中 / 部分命中 / 空入参（`backend/src/db/loop_.rs`）。
- 集成测试：`backend/tests/api_integration_test.rs` 新增
  `test_task_list_process_version_snapshot`：
  1. 创建工艺模板（版本 1.0.0）→ 创建环路并写入快照 1.0.0 → 创建任务；
  2. 将模板升级到 2.0.0；
  3. `GET /api/v1/workspaces/{ws}/tasks`，断言列表 `template_version == "1.0.0"`；
  4. 再建一个无快照的环路任务，断言其 `template_version` 回退为 `"2.0.0"`。
- 验证命令：`cd backend && cargo clippy --all-targets -- -D warnings`（零告警）、
  `cd backend && cargo test`（全量通过）。

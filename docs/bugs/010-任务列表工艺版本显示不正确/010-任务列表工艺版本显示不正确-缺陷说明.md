## 3. 触发条件（Trigger Conditions）

### 3.1 前置条件
- 系统状态：任务列表页可打开，任务详情页可打开
- 数据状态：存在一个任务，其关联环路（`loops`）绑定了工艺模板，且**环路创建/升级后，工艺模板（`process_templates`）的版本又发生过变化**（环路快照版本 ≠ 模板当前版本）

### 3.2 输入条件
- 请求类型 / 参数：`GET /api/v1/workspaces/{ws}/tasks`（列表）与 `GET /api/v1/workspaces/{ws}/tasks/{id}`（详情）
- 数据范围或特征：列表接口返回的 `template_version` 与详情接口返回的 `template.version` 不一致

### 3.3 时序 / 并发条件
- 是否必须并发：否
- 是否依赖调用顺序：否（只需环路快照版本与模板当前版本不同即可触发）

> 规则：如果移除上述任一条件，Bug 不一定会发生。

## 4. 实际行为（Observed Behavior）

- 实际发生了什么行为：任务列表「工艺」列显示的是工艺模板的**当前最新版本**；点击进入任务详情，显示的工艺版本是环路创建/升级时的**版本快照**，两者不一致。
- 返回结果 / 错误码 / 异常信息：无接口错误；属列表接口返回字段取值口径问题。
- 日志或外部可观测现象：同一任务在列表页与详情页显示不同工艺版本。
- 发生频率：必现（满足 3.1 数据条件时）。

## 5. 期望行为（Expected Behavior）

- 系统应当返回：任务列表「工艺」列显示的版本与任务详情一致，即**优先取环路 `process_template_version` 快照（执行时的工艺版本），快照缺失时回退工艺模板当前版本**。
- 明确允许的正常结果范围：环路无工艺模板来源时，列表仍显示 `—`（前端既有回退），不改变其他列语义。

## 6. 行为偏差定义（Deviation）

> **在环路工艺版本快照与模板当前版本不一致的任务上，系统列表接口实际返回了模板当前版本，但期望返回与详情一致的环路版本快照。**

## 7. 影响范围（Impact）

- 受影响模块 / 功能：任务列表接口 `list_tasks` 的 `template_version` 字段；前端任务列表「工艺」列展示。
- 受影响用户或场景：需要从任务列表判断「该任务执行的是哪个工艺版本」的用户；列表与详情口径不一致会误导判断。
- 是否存在以下风险（可多选）：
  - 数据错误：是（展示性数据口径不一致，不涉及底层数据损坏）
  - 数据丢失：否
  - 安全风险：否
  - 服务不可用：否
- 影响范围是否已知完全：是

## 8. 已知边界与非问题（Non-Issues）

- 在以下条件下，当前行为是正确的：环路快照版本与模板当前版本相同时；任务无工艺来源（模板 id 为空）时显示 `—`。
- 以下相似现象不属于本 Bug：事项 / 环路列表的工艺列（已有 COALESCE 回退逻辑，口径正确）；任务详情接口本身的版本取值逻辑（口径正确，作为修复基准）。
- 不需要在本 Bug 中解决的问题：前端 `formatProcessText` 渲染格式（列表与详情共用，无需改动）；任务详情接口的其他字段。

## 9. 事实证据（Facts & Evidence）

- 代码事实：`list_tasks`（`backend/src/handlers/tasks.rs`）中 `template_version` 直接取 `get_process_template_by_id(tid)` 返回的 `p.version`（模板当前版本）。
- 代码事实：`get_task_detail`（同一文件）中版本取值注释明确「优先取环路的 process_template_version（执行时的快照）……而非工艺模板表的最新版本」，实际为 `loop.process_template_version.unwrap_or(t.version)`。
- 代码事实：`loops.process_template_version` 由工艺安装/升级流程写入（`backend/src/services/process/installer.rs`），语义为环路绑定工艺时的版本快照。

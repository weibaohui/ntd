# 019-new指令未创建新session-缺陷说明

| 修改人 | 修改时间 | 修改内容 |
|--------|---------|---------|
| AI (Pi) | 2026-08-09 | 初始版本 |

## 1. Bug 基本信息

- Bug ID：NTD-019
- 所属系统：backend（feishu 卡片动作 / session 管理）
- 首次发现时间：2026-08-09（用户报告「/new 指令没有创建新 session」）
- 发现来源：用户报告 → 代码审查定位
- 当前状态：已确认存在

## 2. Bug 是否被确认存在

- [x] Bug 已被稳定复现（代码路径推演 + 字段语义实证）

### 2.1 复现环境

- 环境类型：生产 / 开发均存在
- 相关配置：飞书 bot 已配置工作空间与对话执行器（butler_executor）

### 2.2 复现条件（最小集合）

1. 在**单聊（p2p）**会话中；
2. 点击**卡片上的「新会话」按钮**（如帮助卡片的 cmd:/new 按钮，走 card_callback 通路）；
3. 发送下一条消息。

**现象**：消息仍然 resume 旧 session（用户视角：/new 没生效）。

### 2.3 不受影响的路径（边界）

- 文本输入 `/new`（单聊或群聊）：正常（走 `from_chat_type` 正确推断 scope）；
- 群聊中点卡片「新会话」按钮：正常（恰好清对 scope）。

## 3. 现象详述

- 期望：点卡片「新会话」→ 提示已开启新会话 → 下一条消息以全新 session 执行；
- 实际：提示正常弹出（「已开启新会话」），但下一条消息仍带着旧 session resume 执行——清除动作写错了维度。

# NTD-006 任务页批量操作问题 — 缺陷分析

| 修改人 | 修改时间 | 修改内容 |
|--------|---------|---------|
| AI(Kimi) | 2026-07-30 | 初始版本 |

---

## 1. 代码链路

```
/#/tasks
  → TasksPage（frontend/src/components/tasks/TasksPage.tsx）
    → viewMode === 'list'
      → TasksTableView（frontend/src/components/tasks/TasksTableView.tsx）
        → toolbar：Select（状态筛选） → BatchButton（批量）
        → BatchButton → 删除
          → handleBatchDelete
            → Modal.confirm（静态方法）
```

## 2. 根因

### 根因 1：工具栏 JSX 顺序直接导致批量按钮不在首位

`TasksTableView.tsx` 当前 toolbar 顺序为：

```tsx
<Select ... data-testid="tasks-table-status-filter" />
<BatchButton ... />
<Text ...>已选 ...</Text>
```

因此用户在工具栏看到的第一个操作控件是状态筛选，而不是批量按钮。

### 根因 2：`Modal.confirm` 静态方法不经过 `App` 上下文消费主题

项目主题通过 `ThemeProvider → ConfigProvider theme={themeConfig} → AntApp` 下发。
`TasksTableView.tsx` 当前批量删除使用：

```tsx
Modal.confirm({ ... });
message.success(...);
```

`Modal.confirm` 是静态调用，不能像 `AntApp.useApp().modal.confirm` 一样稳定消费当前 `ConfigProvider` / `App` 上下文。结果就是在暗色 / 亮色切换时，确认窗的主题 token 不能正确跟随当前页面主题。

## 3. 影响面

- 仅影响任务页列表视图（`TasksTableView`）的工具栏顺序与批量删除确认窗主题。
- 不影响事项 / 环路列表：它们使用共享 `useBatchActions`，确认 Modal 为受控组件。
- 不影响后端接口：`bundledApi.batchDeleteTasks` 调用参数与返回处理保持不变。

## 4. 修复方案

**只改 `frontend/src/components/tasks/TasksTableView.tsx`，不新增后端改动**：

1. 调整 toolbar JSX 顺序：将 `<BatchButton />` 移到状态筛选 `Select` 之前。
2. 将静态 `Modal.confirm` 改为 `AntApp.useApp().modal.confirm`，并将 `message` 一并改为 `AntApp.useApp().message`，确保删除确认窗与提示都跟随当前主题上下文。
3. 保持删除确认文案、危险按钮类型、成功后清空选中等行为不变，避免引入额外交互变化。

## 5. 测试方案

- 前端类型检查：`cd frontend && npx tsc --noEmit`
- 前端构建：`cd frontend && npm run build`
- Playwright 验证：启动 `make dev` 后访问 `http://localhost:18088/#/tasks`，验证：
  1. 勾选任务后，工具栏第一个可操作按钮为「批量」；
  2. 点击「批量 → 删除」，确认窗在亮色主题下正常；
  3. 切换暗色主题后再次打开确认窗，确认窗背景、标题、正文、按钮均随暗色主题渲染。

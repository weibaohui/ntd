|--------|---------|---------|
| AI(Kimi) | 2026-07-30 | 初始版本 |

---

## 1. 修复内容

**改动文件**：

- `frontend/src/components/tasks/TasksTableView.tsx`
- `frontend/src/App.css`
- `frontend/tests/ntd006-tasks-batch-toolbar.spec.ts`

| 改动点 | 说明 |
|--------|------|
| 批量按钮顺序 | `TasksTableView` 工具栏改为「批量按钮 → 状态筛选 → 计数」，批量按钮在勾选任务后位于第一位 |
| 删除确认窗主题上下文 | 静态 `Modal.confirm` / `message` 改为 `AntApp.useApp().modal/message`，让确认窗进入当前 `ConfigProvider` 主题上下文 |
| 暗色确认窗容器 | `App.css` 暗色 Modal 覆盖扩展到 `.ant-modal-container`，并对 `Modal.confirm` 容器固定 `--color-bg-elevated`，避免 AntD v6 确认窗外层保留默认 `#1f1f1f` |
| 回归测试 | 新增 Playwright spec，自种子任务数据，覆盖批量按钮第一位、亮色确认窗、暗色确认窗 |

## 2. 与缺陷分析的对应关系

| 根因 | 修复手段 |
|------|---------|
| toolbar JSX 顺序是 Select → BatchButton | 调整为 BatchButton → Select |
| `Modal.confirm` 静态方法不稳定消费主题上下文 | 改用 `AntApp.useApp().modal.confirm` |
| AntD v6 `Modal.confirm` 容器是 `.ant-modal-container`，旧暗色覆盖只命中 `.ant-modal-content` | 暗色 Modal 覆盖补 `.ant-modal-container`，确认窗单独用 `!important` 固定项目暗色 elevated |

## 4. 安全反思

- 未新增后端接口或权限路径；批量删除仍走既有 `batchDeleteTasks`。
- 删除确认仍保留危险按钮与二次确认，不降低误删防护。
- 主题修复只影响展示层，不改变数据流与接口参数。

## 5. 已知限制 / 待改进

- `App.css` 对 `Modal.confirm` 暗色容器使用 `!important`，原因是 AntD v6 将该背景直接写入 CSS-in-JS；后续若 AntD 开放对应组件 token，可回退为纯 token 方案。
- Playwright 用例会向 dev 库自种子任务数据，与仓库既有 NTD-004 用例策略一致。

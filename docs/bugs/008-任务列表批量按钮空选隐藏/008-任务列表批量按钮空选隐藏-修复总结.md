## 1. 修复内容

**改动文件**：

- `frontend/src/components/tasks/TasksTableView.tsx`
- `frontend/tests/ntd006-tasks-batch-toolbar.spec.ts`

| 改动点 | 说明 |
|--------|------|
| 批量按钮常驻 | 删除 `selectedIds.length === 0 return null`，批量按钮空选时也渲染 |
| 空选禁用 | 与 `TodoListView.BatchButton` 对齐：`disabled` 同时作用于 `Dropdown`、内部 `Button`、menu item |
| 回归测试 | NTD-006 spec 增加空选可见且 disabled、勾选后 enabled 的断言；原亮/暗确认窗断言保持不变 |

## 2. 与缺陷分析的对应关系

| 根因 | 修复手段 |
|------|---------|
| tasks 批量按钮空选时 `return null`，todos 是空选禁用 | 移除提前 return，改为 `disabled = selectedIds.length === 0` 并透传到 Dropdown/Button/menu item |

## 4. 安全反思

- 仅调整批量入口的可见性与禁用态，不改变批量删除接口与确认逻辑。
- 空选时 menu item 同步禁用，避免通过键盘或脚本触发空 ids 删除请求。

## 5. 已知限制 / 待改进

- tasks 当前只有「删除」一个批量动作；后续新增批量动作时可直接沿用同一 `disabled` 模式。

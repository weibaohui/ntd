# NTD-008 任务列表批量按钮空选隐藏 — 缺陷分析

| 修改人 | 修改时间 | 修改内容 |
|--------|---------|---------|
| AI(Kimi) | 2026-07-30 | 初始版本 |

---

## 1. 代码链路

```
/#/tasks
  → TasksPage
    → TasksTableView
      → toolbar
        → BatchButton
          → selectedIds.length === 0 ? return null : render Dropdown
```

对照链路：

```
/#/todos
  → TodoListView
    → BatchButton
      → disabled = selectedIds.length === 0
      → Dropdown disabled / Button disabled / menu item disabled
```

## 2. 根因

`TasksTableView.tsx` 的批量按钮注释写的是「空选时禁用」，但实现是：

```tsx
if (selectedIds.length === 0) return null;
```

这导致空选时批量入口直接从 toolbar 消失。事项列表的实现才是用户期望的交互：按钮一直渲染，空选时禁用。

## 3. 影响面

- 仅影响任务列表页 Table 上方批量按钮的空选展示与禁用状态。
- 不影响批量删除逻辑、不影响已选状态下的删除确认。
- 不需要改后端。

## 4. 修复方案

**只改 `frontend/src/components/tasks/TasksTableView.tsx`，并同步更新 NTD-006 Playwright 断言**：

1. 删除 `selectedIds.length === 0 return null`。
2. 与 `TodoListView.BatchButton` 对齐：计算 `disabled`，并同时传给 `Dropdown`、内部 `Button`、menu item。
3. Playwright 回归从「空选不显示」改为「空选显示但 disabled，选中后 enabled」。

## 5. 测试方案

- `cd frontend && npx tsc --noEmit`
- `cd frontend && npm run build`
- `cd frontend && npx playwright test tests/ntd006-tasks-batch-toolbar.spec.ts --reporter=list`
  - 空选：`tasks-table-batch-trigger` 可见且 disabled；
  - 勾选后：同一按钮 enabled；
  - 删除确认窗亮/暗主题回归不变化。

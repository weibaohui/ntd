## 4. 实际行为（Observed Behavior）

抽屉作为「事项」的创建/编辑入口，界面其他部分（导航、列表、详情页）均使用「事项」口径，但抽屉内残留旧「任务」口径共 7 处：

| 位置 | 文案 |
|------|------|
| `TodoDrawer.tsx:292` 抽屉标题 | 「创建任务」/「编辑任务」 |
| `TodoDrawer.tsx:310` 标题输入框占位 | 「任务标题」 |
| `TodoDrawer.tsx:409` 验收标准占位 | 「描述完成该任务需要满足的条件...」 |
| `TodoDrawer.tsx:206` 校验提示 | 「请输入任务标题」 |
| `TodoDrawer.tsx:240` 成功提示 | 「任务已更新」 |
| `TodoDrawer.tsx:270` 成功提示 | 「任务创建成功」 |
| `ModelPicker.tsx:54` Tooltip | 「指定本任务使用的模型…」 |

- **发生频率**：必现（打开抽屉即见）

## 5. 期望行为（Expected Behavior）

- 抽屉作为「事项」的唯一创建/编辑入口，界面文案与全局「事项」口径一致：「创建事项」「编辑事项」「事项标题」等。
- 代码注释/类型名中的「任务级模型」等内部概念名不在本次范围（不影响用户感知，避免 diff 扩散）。

## 6. 行为偏差定义（Deviation）

- 用户在「事项」导航下点「新建」，弹出的却叫「创建任务」，两套术语混用，用户会疑惑「事项」和「任务」是否是两种东西。

## 7. 影响范围（Impact）

- 影响面：所有通过抽屉创建/编辑事项的用户。
- 严重级别：低（纯文案，无功能影响）。
- 不影响数据与 API（后端 `/todos` 语义不变）。

## 8. 已知边界与非问题（Non-Issues）

- `QuickCaptureModal`（快速捕获）的「已创建任务」提示：属于另一组件的独立文案，不在本缺陷范围（如需统一另行立项）。
- `CreateTaskModal`（任务页，tasks 域）：那里的「任务」是 tasks 域自身的正确术语，不是残留。

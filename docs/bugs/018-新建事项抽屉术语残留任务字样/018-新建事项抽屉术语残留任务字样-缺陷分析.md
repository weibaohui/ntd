# NTD-018 新建事项抽屉术语残留「任务」字样 — 缺陷分析

## 1. 根因

产品术语经历「任务 → 事项」迁移（`docs/design/` 中 028/056 等需求逐步统一口径，导航与列表/详情页均已改），但 `TodoDrawer.tsx` 自 2025 年引入以来仅做功能迭代，**用户可见文案从未随术语迁移更新**，形成最后一块残留。

## 2. 定位过程

1. 全局搜索 `创建任务` 命中 `TodoDrawer.tsx:292`（标题）。
2. 以「抽屉范围内、用户可见」为标准再搜 `任务`，共确认 7 处（详见缺陷说明第 4 节表格）。
3. 对照 `App.tsx` / `TodoListPage.tsx` 注释确认权威口径为「事项」。

## 3. 修复方案

- **范围**：`TodoDrawer.tsx` 6 处 + `todo-drawer/ModelPicker.tsx` 1 处 Tooltip，逐处「任务」→「事项」，零逻辑改动。
- **测试同步**：
  - `frontend/tests/e2e-test.spec.ts`：两处 placeholder 断言（`任务标题`→`事项标题`、`描述完成该任务`→`描述完成该事项`）及注释。
  - `frontend/tests/check_template_modal_open.spec.ts`：由临时复现脚本转正为回归用例，新增 `expect(抽屉标题).toBe('创建事项')` 断言，并保留「从模板创建」可用性守护（用户同期反馈的第二个问题，见缺陷说明第 8 节与 PR 说明）。
- **风险**：纯字符串替换，无状态/接口影响；vitest 相关组件测试均断言行为而非文案，不受影响。

## 4. 验证计划

1. `cd frontend && npx tsc --noEmit` 零错误。
2. `cd frontend && npx vitest run` 全过。
3. `cd frontend && npx playwright test tests/check_template_modal_open.spec.ts tests/e2e-test.spec.ts --reporter=list` 通过（需 `make dev`）。

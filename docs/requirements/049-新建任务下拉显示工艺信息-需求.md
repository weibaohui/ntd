# 049-新建任务下拉显示工艺信息-需求

> 关联：041 环路列表工艺信息与任务下拉区分（下拉改为 `#<环路ID> <环路名称>`）。本需求是 041 的延续——把工艺名称与版本一并放进下拉选项。

## 背景

「新建任务」弹窗（`/#/tasks` → 新建）需要选择一个工艺环路。041 已把下拉选项改为 `#<环路ID> <环路名称>`，解决了同名环路无法区分的问题；但用户仍无法从下拉中看出环路**来自哪个工艺、哪个版本**——同一工艺的不同版本实例化出的环路，在列表里看起来完全一样。

## 现状

- 下拉 label 由 `CreateTaskModal.tsx` 生成，格式为 `` `#${id} ${name}` ``。
- 数据源 `listLoops()` 返回的 `LoopListItem` 已由 041 后端注入工艺字段
  （`process_template_id` / `process_template_display_name` / `process_template_name` / `process_template_version`），
  但 `TasksPage.tsx` 映射为 `LoopLite` 时只保留 `id + name`，工艺信息在前端被丢弃。
- 下拉仅列出 `process_template_id != null` 的环路（工艺实例化环路才能创建任务），因此括号内工艺信息必然有来源。

## 需求

1. 新建任务弹窗的环路下拉选项 label 改为：
   `#<环路ID> 环路名称（#工艺ID 工艺名称 工艺版本）`
   示例：`#12 代码评审环路（#3 标准需求交付 1.2.0）`
2. 回退口径与既有 `formatProcessText`（`utils/processText.ts`，042 三列表统一）保持一致：
   - 工艺显示名优先 `process_template_display_name`，缺失回退 `process_template_name`，再缺失用 `#<工艺ID>` 兜底；
   - 版本缺失用 `—` 占位，保持三段式可读；
   - 环路无工艺来源时（防御性，当前不会发生）退化为 041 格式 `#<环路ID> <环路名称>`。
3. 纯前端改动，后端接口零改动（041 已注入所需字段）。

## 边界

- 只改「新建任务」弹窗的下拉选项显示，不改选中后的值（value 仍是环路 ID）、不改 API。
- 不回溯修改 041/042 文档；本需求为其后续变更。
- 下拉 option 的排序行为不变；当前 Select 未启用 `showSearch`，下拉**不支持搜索**——不存在「按工艺名搜索」的隐含能力（如需搜索须另行启用 `showSearch` 且显式 `optionFilterProp="label"`，不在本需求范围）。

## 验收标准

- [ ] 下拉选项显示为 `#<环路ID> 环路名称（#工艺ID 工艺名称 工艺版本）`
- [ ] display_name 缺失时回退 name、版本缺失 `—` 占位、无工艺来源退化 041 格式（单测覆盖）
- [ ] `npx tsc --noEmit` 零错误
- [ ] `vitest` 相关用例全通过
- [ ] Playwright 验证弹窗下拉实际渲染（证据发 PR 评论，不入库）

# 实现总结：工艺列表拆分「我的 / 模板」双视图（039）

## 1. 需求对应

对应 `docs/requirements/039-工艺列表我的与模板视图-需求.md` 与
`docs/design/039-工艺列表我的与模板视图-设计.md`。

主导航「工艺」页（`/#/processes`）原先把系统模板与用户工艺混在一个列表，现拆为
「我的」（用户创建）/「模板」（系统内置及同步下载）两个视图，服务端过滤 + localStorage 持久化。

## 2. 改动清单

### 后端

- `backend/src/db/process_template.rs`
  - `list_process_templates` 签名加 `is_system: Option<bool>`，`Some` 时按系统/用户过滤，
    `None` 保持全量（统计/推荐等旧调用方语义不变）。
  - 新增 3 个单测：过滤系统 / 过滤用户 / None 全量。
- `backend/src/handlers/process.rs`
  - `list_process_templates` handler 加 `Query<ListProcessTemplatesQuery>`（`is_system: Option<bool>`，
    `#[serde(default)]` 保证不传参向后兼容），`/api/bundled/processes` 与
    `/api/v1/bundled/processes` 同时获得过滤能力。
  - 3 个旧调用方（版本历史 / 版本 diff / 推荐）改传 `None`。
  - 新增 2 个单测：查询参数缺省为 None、true/false 解析（用 axum `Query::try_from_uri`
    走真实提取路径，未引入 serde_urlencoded 依赖）。

### 前端

- `frontend/src/api/bundled.ts`：`getProcesses(isSystem?: boolean)` 加可选过滤参数。
- `frontend/src/components/ProcessPage.tsx`
  - 新增 `ProcessScope`（`'mine' | 'template'`）状态，localStorage key
    `ntd_process_list_scope` 持久化，非法值/存储不可用回退 `'mine'`。
  - 列表顶部加 `Segmented`（我的 / 模板），切换即按视图调带参接口重新拉取。
  - 空态文案按视图区分：「我的」空引导创建工艺，「模板」空引导执行同步。
  - 卡片渲染抽为 `renderProcessCard` 小函数；系统卡片不渲染「编辑」按钮的既有逻辑
    拆视图后自然正确。

### 测试

- `frontend/tests/check_process_page.spec.ts`：新增 039 用例组（API 过滤三态、默认视图、
  切换+持久化+刷新保持、「我的」视图编辑按钮/空态）；顺手移除已失效的
  「选择安装工作空间」页内选择器断言（该选择器已改为全局左上角）。

## 4. 环境备注（排查记录）

开发实例由 launchd 任务 `ntd-dev` 看护（`/tmp/ntd-dev-start.sh` →
`./target/debug/ntd server start`），KeepAlive 会在进程被杀后自动重启；
`make dev` 自起的后端会因端口 18088 被占而绑定失败。本次验证通过
`launchctl kickstart -k gui/502/ntd-dev` 让看护服务加载新构建的二进制。

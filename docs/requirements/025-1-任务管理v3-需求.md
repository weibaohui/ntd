# 025-1-任务管理-v3 需求

| 修改人 | 修改时间 | 修改内容 |
|--------|---------|---------|
| Claude | 2026-07-25 | v3：新增 tasks 表，loops/loop_executions 新增 task_id |

---

## 1. 背景

v2 用 `loops.process_template_id IS NOT NULL` 区分"任务 Loop"，任务状态嵌在 JSON 里无法高效查询。v3 正本清源：建独立的 `tasks` 表，作为任务的唯一真相来源。

---

## 2. 数据模型

```
tasks (新建)
  1 : 1  → loops (task_id 列，无 FK)
  1 : N  → loop_executions (task_id 列，无 FK)
```

| 表 | 字段 | 说明 |
|----|------|------|
| **tasks（新建）** | id, title, description, status, workspace_id, template_id, loop_id, created_by, created_at, updated_at | 任务主表 |
| loops（扩展） | +task_id | 记录由哪个任务创建 |
| loop_executions（扩展） | +task_id | 记录因哪个任务而执行 |

---

## 3. 目标

- **G1** 新建 `tasks` 表，task 作为一等公民，与「事项」「回路」「工艺」平级。
- **G2** 创建任务时写入 tasks 表 + 生成/复用 Loop + 创建执行（task_id 关联全链）。
- **G3** 任务列表直接从 tasks 表查询，支持按 status 筛选。
- **G4** 任务详情页：task 信息 + 执行历史（loop_executions WHERE task_id=?）。
- **G5** 任务状态自动更新：每次执行完成后，根据执行结果更新 task.status。
- **G6** Loop 复用：同 template_id+workspace_id 只有一个 Loop，多个 task 共享（每个 task 有自己的 task_id）。

---

## 4. 功能需求

### F1 任务 CRUD

- [ ] **F1.1** POST /api/v1/tasks：创建 task → 检测/创建 Loop → 创建执行 → 返回 task_id
- [ ] **F1.2** GET /api/v1/tasks：列表（支持 ?status=running 筛选）
- [ ] **F1.3** GET /api/v1/tasks/{id}：详情（task + 执行历史）

### F2 Loop 关联

- [ ] **F2.1** 创建 Loop 时写入 task_id
- [ ] **F2.2** 创建 loop_execution 时写入 task_id
- [ ] **F2.3** Loop 复用：同 template+workspace 已存在则复用，不新建

### F3 状态管理

- [ ] **F3.1** 执行完成/失败后，更新对应 task.status
- [ ] **F3.2** task.status 取值：pending | running | success | failed

### F4 Migration

- [ ] **F4.1** V73：CREATE TABLE tasks + loops.task_id + loop_executions.task_id

---

## 5. 验收标准

- **AC1** 创建任务后 tasks 表有记录，loops.task_id 正确关联
- **AC2** 创建执行后 loop_executions.task_id 正确关联
- **AC3** 多次执行同一任务，task.status 按最后一次执行更新
- **AC4** 任务列表按状态筛选正常

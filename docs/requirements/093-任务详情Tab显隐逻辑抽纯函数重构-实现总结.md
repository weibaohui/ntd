## 1. 实现了什么

把 `TaskDetailPanel.tsx` 里揉在 JSX 中的「Tab 显隐规则」与「activeKey 回退」两段纯逻辑抽到 `helpers.ts` 的 `visibleTaskTabs` / `resolveTaskActiveTab` 纯函数，组件改为「声明式全量 4 Tab + 按可见集合过滤」，并补齐 9 条 vitest 单测。行为零变更，逻辑可脱离组件单独测试。

## 2. 与设计的对应关系

| 设计要点 | 实现 | 验证 |
|---------|------|------|
| 抽 `visibleTaskTabs` / `resolveTaskActiveTab` 纯函数 | `helpers.ts` 新增两函数 + `TaskTabKey` 类型 | vitest 9 条新单测 |
| 组件 `allTabs` 平铺 + filter | `TaskDetailPanel.tsx` ~393-438 行 | tsc 零错误 + 行为不变 |
| 不动数据加载 useEffect | 未触碰两个加载副作用 | — |
| 移除冗余 `isDelegate` 局部变量 | 删除，委派判断下沉纯函数 | grep 确认无残留引用 |

## 3. 关键实现点

- **内容定义与显隐规则解耦**：`allTabs` 只负责「每个 Tab 长什么样」，`visibleTaskTabs` 只负责「该不该出现」，组件用 `.filter` 拼接。顺序由 `allTabs` 决定，`visibleTaskTabs` 仅作成员集合判断。
- **两层兜底保留**：`resolvedTab`（TAB_KEYS 白名单）+ `resolveTaskActiveTab`（可见集合收口）职责不重叠，覆盖 URL 残留隐藏 Tab / 非法 ?tab 两种异常。
- **文件定位复用**：`helpers.ts` 头部注释本就声明「抽纯函数脱离组件做单测」，本次扩入同源逻辑，未新开文件（规避与 `TaskDetailTabs.tsx` 在 macOS 大小写不敏感 FS 上的命名冲突）。

## 4. 测试与验证结果

- 前端：`npx tsc --noEmit` 零错误；`npx vitest run src/components/tasks/` 56/56 通过（helpers 新增 9 条）；`npm run build` 无新告警。
- Playwright：`093-task-detail-loop-tabs-by-mode.spec.ts` 4/4（委派 2 Tab、工艺环路 4 Tab、委派 `?tab=dag` 回退、委派 `?tab=exec` 回退）+ `060-task-discussion-forum.spec.ts` 1/1 通过。

## 5. 安全反思

- 纯展示层重构，无用户输入处理、无鉴权、无 SQL 变更，无安全面。
- `resolveTaskActiveTab` 对非法 `?tab=` 一律回退默认，不会因脏 URL 导致空白页或异常渲染。

## 6. 已知限制

- 本次仅抽取显隐逻辑，`TaskDetailPanel` 主体（数据加载、Header 组装）仍较长；进一步拆分属后续独立重构，本次刻意收敛范围以控风险。

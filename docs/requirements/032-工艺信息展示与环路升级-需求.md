# 032-工艺信息展示与环路升级-需求

| 修改人 | 修改时间 | 修改内容 |
|--------|---------|---------|
| Claude | 2026-07-28 | 初始版本 |

---

## 1. 背景（Why）

工艺模板（Recipe）生态中，用户需要：

1. **全局可见的工艺归属** — 事项列表/任务列表/任务详情三处关键视图都没有直观的工艺信息展示，用户无法一眼看出某个事项/任务属于哪个工艺模板。
2. **环路版本升级能力** — 工艺模板编辑保存后（版本自动递增），已实例化的旧环路仍使用旧版本，用户需要手动触发现有环路升级到最新模板版本，而无需重建环路。
3. **动态详情标题** — 任务/事项详情页的 PageCard 标题固定显示 `#{id}`，数据加载后未更新为实际标题，降低快速识别效率。

---

## 2. 目标（What，必须可验证）

- [ ] 事项列表（TodoListView）新增「工艺」列，展示引用该事项的 Loop 名称（源自 `referencing_loops`）
- [ ] 任务列表（TasksTableView）「模板」列改名为「工艺模板」，含义更精确
- [ ] 任务详情概览 Tab 的 Descriptions 「模板」改名为「工艺模板」
- [ ] TaskDetailPage / TodoDetailPage 的 PageCard 标题在数据加载后动态显示实际标题，格式为 `任务 #{id}: {title}` / `事项 #{id}: {title}`
- [ ] 工艺详情 Modal → 实例环路 Tab → 每行操作列新增「更新」按钮，点击后将 Loop 升级到工艺模板最新版本
- [ ] 后端新增 `POST /api/v1/processes/{name}/loops/{loop_id}/upgrade` 端点

---

## 3. 非目标（Explicitly Out of Scope）

- ❌ 不改后端事项中心（TodoCenterItem）响应结构（仍用 `referencing_loops` 间接展示）
- ❌ 不做工艺列在事项右栏详情中的嵌入（事项详情已有 `ReferencingLoopsSection`）
- ❌ 不改任务详情 Timeline / 执行历史视图
- ❌ 不改 Loop 列表页

## 4. 使用场景 / 用户路径

### 场景 A：事项列表直观定位工艺归属

1. 用户打开 `/#/todos` 列表
2. 每一行在「调度」列之后看到「工艺」列，显示该事项所属的 Loop 名（空格分隔）
3. 用户可据此判断事项是否为工艺驱动

### 场景 B：任务列表确认模板来源

1. 用户打开 `/#/tasks` 列表
2. 「工艺模板」列直接显示任务来源的工艺模板名称
3. 任务详情概览 Tab 同样展示「工艺模板」名称

### 场景 C：环路升级到最新版本

1. 用户编辑并保存了一个工艺模板（版本自动递增）
2. 用户进入该工艺的详情 Modal →「实例环路」Tab
3. 每条实例环路行末有「更新」按钮
4. 点击后 Loading → 后端升级步骤/阶段 → 成功后列表自动刷新，版本号更新为最新

### 场景 D：详情标题动态更新

1. 用户从列表点击某任务，进入 `/#/tasks/:id`
2. 页面加载期间标题显示「任务 #{id}」
3. 数据加载完成后标题自动更新为「任务 #{id}: 实际标题」
4. 事项详情同理

---

## 5. 边界与异常

| 场景 | 行为 |
|------|------|
| 事项无引用 Loop | 工艺列显示 `-` |
| 单个事项被多个 Loop 引用 | 工艺列展示所有 Loop 名称，空格分隔 |
| 升级时 Loop 已被删除（404） | 后端返回 404，前端提示错误 |
| 升级时工艺模板已被删除（404） | 后端返回 404，「更新」按钮不活跃 |
| 升级时 Loop 已有执行记录 | 保留历史 loop_executions/loop_step_executions（旧 step_id 保存但不再有 FK 约束） |
| 详情页数据加载失败 | 标题保持静态 `#{id}`，不替换 |

# 实现总结：任务详情执行历史显示基本时间信息（043）

## 1. 概述

需求来源：用户反馈任务详情页（`/#/tasks/:id`）「执行历史」tab 的执行记录缺少基本时间信息。

改动前的问题：

- 每行只有状态/进度/失败数，**时间完全缺失**；`finished_at` 后端已返回但前端从未展示；
- 唯一的「时间露出口」是无需求文本时回退显示 `started_at` 的**原始 UTC ISO 串**（如 `2026-07-04T12:15:01.243Z`），未本地化、无可读性。

改动后每行固定展示时间区：`🕐 2026/7/30 16:00 开始 · 耗时 2m`（进行中的执行只显示开始时间）。

## 2. 前端改动（纯前端，无后端改动）

| 文件 | 改动 |
|------|------|
| `frontend/src/components/tasks/helpers.ts`（新增） | 两个纯函数：`execDurationSec`（起止 ISO → 耗时秒数，缺失/非法/负耗时返回 `null`）；`formatExecTimeInfo`（组装展示文本：已结束「开始时间 · 耗时」，进行中仅「开始时间」，无开始时间返回空串）。抽成纯函数是为了脱离组件做 vitest 单测，也让面板 JSX 保持声明式。 |
| `frontend/src/components/tasks/helpers.test.ts`（新增） | 8 个用例覆盖：正常耗时、缺结束/开始时间、非法时间串、负耗时、进行中不显示耗时、无开始时间返回空串。 |
| `frontend/src/components/tasks/TaskDetailPanel.tsx` | `ExecTab` 行内 Space 末尾追加时间区（`ClockCircleOutlined` + 次级文字）；`execRowDesc` 移除「无需求时回退显示原始 ISO」逻辑，desc 行仅在有需求文本时渲染。 |

## 3. 关键实现点与取舍

- **复用现有工具**：开始时间用 `@/utils/format` 的 `formatDateTime`（UTC ISO → 本地时区、分钟精度）；耗时用 `formatDurationSec`，与 `RunningRecordDrawer` 等处耗时展示口径一致，未引入新依赖。
- **分钟精度**：执行历史是列表场景，秒级精度只增加视觉噪音；精确时间可展开执行看板查看。
- **进行中不显示耗时**：`finished_at` 缺失时 `execDurationSec` 返回 `null`，耗时无从谈起，进行中状态由 running 状态 Tag 表达。
- **防御性**：非法时间串（NaN）与负耗时（时钟回拨）一律不显示耗时，避免误导。

## 4. 验证结果

- `npx tsc --noEmit`：零错误。
- `npx vitest run`：21 个测试文件 155 个用例全部通过（含新增 8 个）。
- Playwright（`frontend/tests/check_exec_history_time.spec.ts`）：对 `#/tasks/24` 验证三种形态——
  进行中仅「开始」无「耗时」、成功执行「耗时 2m」、跨小时失败执行「耗时 1h5m」且无需求时 desc 行不渲染、
  原始 UTC ISO 串不再出现。通过，截图见 PR 评论。
- 验证数据：开发库 `task_id=24` 手工插入的 3 条 `loop_executions` 测试记录（标题含「验证执行历史时间显示」），确认效果后可删除。

## 5. 安全反思

纯展示层格式化改动：React 默认转义文本无 XSS 面；无接口/权限/输入处理变更；时间计算全部在客户端只读完成。

## 6. 已知限制

- 耗时展示为分钟粒度（如 `1h5m`、`2m`），与项目其他耗时展示保持一致；秒级精度需展开看板。
- 列表按 `started_at DESC` 排序由后端既有逻辑决定，本次未调整。

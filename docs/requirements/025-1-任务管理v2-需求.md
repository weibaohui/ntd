---

## 1. 背景

v1 的「创建任务 = 创建新 Loop + 注入需求到 step prompt」有两个问题：

1. **Loop 重复创建**：同模板同工作空间每次创建都生成新 Loop，产生大量重复 Loop。
2. **需求归属错层**：需求写在 `loops.description`，被后续执行覆盖，历史丢失。

v2 修正为：

- **一个任务 = 一个 Loop**（同模板+同工作空间自动复用）
- **需求归属执行级**（存 `loop_executions.trigger_meta.requirement`）
- Loop 创建时不再写入需求到 step prompt
- LoopRunner 从 `trigger_meta` 读需求替换 `{{requirement}}`

---

## 2. 目标

- **G1** （同 v1）新增「任务」视图，左侧导航独立入口。
- **G2** 首次创建任务：输入需求 → 推荐/选模板 → 创建 Loop → 触发第一次执行（需求写入 trigger_meta）。
- **G3** 已有任务再次执行：点击「新建执行」→ 输入新需求 → 更新式创建执行（复用 Loop，不创建新 Loop）。
- **G4** 任务列表展示每个任务的最新执行状态和最新需求描述。
- **G5** 任务详情页执行历史每行展示该次执行的需求文本。
- **G6** LoopRunner 从 `trigger_meta.requirement` 读取需求替换 `{{requirement}}`。

---

## 3. 非目标

- 不新建数据库表——task_id = loop_id。
- 不改变 Loop 模板安装流程。
- 不修改 LoopRunner 以外的执行逻辑。

---

## 4. 数据模型（无新表）

| 数据 | 存储位置 | 说明 |
|------|---------|------|
| Task ID | `loops.id` | 一个 task 就是一个由模板创建的 loop |
| 任务 = Loop 关联 | `loops.process_template_id IS NOT NULL` | 区分任务 Loop 和手建 Loop |
| Loop 复用检测 | `loops.process_template_id + loops.workspace_id` 唯一 | 同模板同空间只建一次 |
| 需求文本 | `loop_executions.trigger_meta.requirement` | 每次执行独立需求 |
| LoopRunner 读需求 | `exec.trigger_meta.requirement` | 替换 `{{requirement}}` |

---

## 5. 用户流程

### 场景 A：新项目首次创建

1. 用户打开「任务」，输入「用 React 做便利贴骨架」。
2. 选模板 superpowers-task，选工作空间 ~/sticky-notes。
3. 点「创建并执行」→ 系统检测同模板同空间无 Loop → 创建 Loop #15 → 创建执行，需求写入 trigger_meta → LoopRunner 注入需求。
4. 6 步执行完毕后，任务列表显示 Loop #15，「最新执行: 成功, 需求: 用 React 做便利贴骨架」。

### 场景 B：同一个项目继续迭代

1. 用户在任务列表看到 Loop #15（便利贴项目），点进去。
2. 点「新建执行」→ 弹出输入框 → 输入「实现增删改和 drag 排序」。
3. 系统复用 Loop #15 创建执行 #2，需求写入 trigger_meta。
4. 任务详情页执行历史出现两条：#1（搭骨架）、#2（增删改）。

## 7. 验收标准

- **AC1** 同模板+同空间创建两次任务，Loop ID 相同（复用）。
- **AC2** 不同需求创建的两次执行，执行历史各自保留正确的需求文本。
- **AC3** LoopRunner 从 trigger_meta 读到的需求替换到 step prompt。
- **AC4** 任务列表显示最新执行的需求和状态。

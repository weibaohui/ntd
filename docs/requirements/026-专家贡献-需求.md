# 1. 背景（Why）

ntd 的专家/模板资源目前是**单向同步**：从远端仓库 `https://gitcode.com/weibaohui/ntd-resource.git`（GitCode，即 atomgit，同一平台两个域名）通过 `git clone` / `git fetch` + `git reset --hard` 拉取到本地 `~/.ntd/bundled/`，本地用户对专家的修改、新建**无法回传远端**。

本需求为「专家」这一种资源建立一个**最小化操作的贡献通道**：用户填写 GitCode 个人访问令牌（PAT）后，通过 **ActionButton 唤起 AI 执行器**，由 AI 读取本地 PAT、调用 GitCode API 把专家打包为 PR 提交到官方仓库，由维护者人工 review 合入；合入后复用现有单向同步即可分发给所有用户。

选择「AI 执行器提交」而非「后端写死 fork/建分支/写文件/建 PR 逻辑」的原因：把提交流程固化为可编辑的提示词，复用 ntd 已有的 ActionButton 执行能力，后端只负责 PAT 的存储与验证，逻辑最小化。

# 2. 目标（What，必须可验证）

- [ ] 用户能在专家相关 UI 发起「分享」操作（双入口：独立「专家」页 + 设置→模板管理→「专家模板」Tab）。
- [ ] 用户通过「设置 → 第三方授权 → GitCode」的 PAT 管理表单填写 PAT；后端在保存时立即调用 GitCode `/user` 接口验证 PAT 有效性（不落盘用户名）；无效 PAT 给出明确错误提示且不落盘。表单支持保存与清空（清空需二次确认）。
- [ ] PAT 持久化到本地（`~/.ntd/` 下，0600 权限），提供登录态查询与清除（退出）接口。
- [ ] 「分享」唤起 ActionButton：展示可编辑的提交提示词（含专家名/版本/目录等参数），用户选择执行器后由 AI 执行。
- [ ] AI 执行器按提示词读取本地 PAT，完成「fork → 建分支 → 写文件 → 建 PR」，最终输出 PR 链接。
- [ ] 提交失败有明确错误提示，且 PAT 不内联进提示词模板（AI 执行时从本地文件读取）。

# 3. 非目标（Explicitly Out of Scope）

- 不实现后端确定性的 fork / 建分支 / 写文件 / 建 PR HTTP 调用（由 AI 执行器按提示词完成）。
- 本期仅支持「专家」一种资源；事项模板 / Skill / 工艺模板的贡献**不在本期范围**（留作后续扩展）。
- 不做 PR 后续处理进度跟踪（用户提交后仅拿到 PR 链接，不在 ntd 内追踪是否已合入）。
- 不做多账号管理与账号切换（单 PAT）。
- 不做 OAuth 授权登录（已由 PAT 方案替代，OAuth 相关代码彻底移除）。

# 4. 使用场景 / 用户路径

1. 用户在本地修改了一个专家（或新建了专家），觉得好用，希望分享给其他用户。
2. 在专家卡片 / 列表点击「分享到官方仓库」。
3. 若未配置 PAT：跳转到「设置 → 第三方授权 → GitCode」，在 PAT 管理表单中粘贴 GitCode PAT 并保存（后端立即验证，通过后建立本地登录态）；回到专家页再点「分享」即可。
4. 打开 ActionButton 面板：展示提交提示词（可编辑），用户选择执行器。
5. 点击「执行」：AI 读取本地 PAT、遍历专家目录、调用 GitCode API 提交 PR；完成后展示 PR 链接。

# 5. 功能需求清单（Checklist）

- [ ] **后端 PAT 保存与验证**：`POST /api/v1/contribution/pat` 接收 `{ pat }`，先调 GitCode `GET /api/v5/user` 验证有效；有效则持久化 `{ pat }`（不存用户名），无效返回可读错误。
- [ ] **后端 PAT 持久化**：存到 `~/.ntd/contribution_pat.json`，文件权限 0600；提供读取、清除逻辑；日志/错误禁止打印 PAT。
- [ ] **后端登录态查询/退出**：`auth/status` 返回 `{ configured }`；`logout` 清除本地 PAT。
- [ ] **配置**：不新增 `config.yaml` 字段；GitCode API base（`api.gitcode.com`）作为平台常量；贡献目标 `owner`/`repo` 由前端提示词固定（`weibaohui/ntd-resource`）。
- [ ] **前端 API 模块**：`frontend/src/utils/database/contribution.ts` 封装状态查询、保存 PAT、退出接口（复用 `@/utils/database/client` 的 `api` + `unwrap`），并在 `index.ts` 中导出。
- [ ] **前端入口**：独立「专家」页卡片与「专家模板」Tab 列表行内均提供「分享」入口；**分享仅对用户自定义专家（`source === 'user'`）渲染，系统/模板来源专家（从官方仓库同步的 bundled 专家）不显示分享入口**——系统专家只读、用户不能修改，也就不应分享回官方仓库；未配置 PAT 时提示并跳转「设置 → 第三方授权 → GitCode」引导填写（分享处不再内嵌填写框）；已配置时进入 ActionButton。
- [ ] **来源区分**：专家卡片（ExpertCard/TeamCard）与详情 Modal 头部展示来源标签（系统/用户），使用户能一眼区分自定义专家（可编辑、可分享）与系统内置模板（只读）。
- [ ] **前端第三方授权面板（PAT 管理表单）**：设置页新增「第三方授权」Tab，内嵌子 Tab（第一个为 GitCode）；GitCode 子 Tab 提供 PAT 管理表单——密码框填写、保存（后端验证后持久化）、清空（二次确认）；展示当前配置态（已配置/未配置）。分享按钮旁不再放置清除 PAT 的入口，避免误触。
- [ ] **前端提交提示词**：`contributePrompt.ts` 定义提交 PR 的提示词模板，占位符 `{{expert_name}}` / `{{version}}` / `{{expert_dir}}` 由 ActionButton 的 params 注入；提示词描述读取 PAT、遍历目录、调 GitCode API 建 PR 的完整步骤，且不内联 PAT 明文；`expert_dir` 用 `~/` 相对路径（不暴露家目录下的用户名）。
- [ ] **前端 ActionButton**：复用 `ActionButton` 组件（`actionType="expert_contribute"`，`actionKey=专家名`），用户可编辑提示词、选执行器、看日志、看结果。

# 6. 约束条件（非常关键）

- **安全约束**：
  - PAT 仅存于 `~/.ntd/contribution_pat.json`，权限 0600；禁止进入源码、`config.yaml`、前端打包产物、日志、错误信息。
  - PAT 由后端验证与保存；`auth/status` 只回传 `configured`（是否已配置），不回传 PAT。
  - PAT **不内联进 ActionButton 提示词模板**（避免落库到 `todo.prompt` / 执行记录）；提示词只指示 AI 执行时从本地文件读取。
  - 提示词明确要求 AI 最终输出不回显 PAT 明文。
- **架构约束**：
  - 后端只负责 PAT 存储与验证，提交动作由 ActionButton + AI 执行器完成。
  - 新增后端模块遵循现有分层，路由在 `handlers/contribution.rs` 的 `contribution_routes()` 中注册。
  - 不修改现有单向同步（`git_sync`）的只读语义。
  - 不新增 `config.yaml` 配置字段。
- **技术约束**：
  - Rust：`cargo clippy --all-targets -- -D warnings` 零告警；生产代码禁止 `.unwrap()` / `.expect()` / `panic!`。
  - 前端：`npx tsc --noEmit` 零错误；`frontend/src` 内跨目录导入用 `@/` 别名。
  - 单函数体 ≤ 30 行；每个公开函数有单元测试。

# 7. 可修改 / 不可修改项

- ❌ 不可修改：
  - PAT 只能存本地 `~/.ntd/` 且 0600，不得写入 `config.yaml`、源码、前端产物或日志。
  - 必须走 fork + PR，不允许直接 push 官方仓库（由提示词约束 AI 行为）。
  - 现有单向同步（`git_sync` 只读）语义不得被破坏。
- ✅ 可调整：
  - 提示词的措辞与步骤细节。
  - 入口按钮的文案与摆放细节。
  - PAT 在 `~/.ntd/` 下的具体存储文件名与结构。
  - 提交 PR 的分支名格式（当前 `contrib/{name}-{timestamp}`）。

# 8. 接口与数据约定

## 8.1 ntd 内部接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/contribution/auth/status` | 查询配置态：`{ configured: bool }` |
| POST | `/api/v1/contribution/pat` | 保存并验证 PAT：请求 `{ pat: string }` |
| POST | `/api/v1/contribution/logout` | 清除本地 PAT |

> 提交动作不经过后端接口，而是复用现有 `POST /api/v1/actions/execute`（ActionButton 执行链路），`action_type="expert_contribute"`、`action_key=<专家名>`。

## 8.2 GitCode 外部接口（由 AI 按提示词调用，已实测验证）

- 验证用户：`GET https://api.gitcode.com/api/v5/user`（`Authorization: Bearer <pat>`）
- fork：`POST https://api.gitcode.com/api/v5/repos/{owner}/{repo}/forks`
- 建分支：`POST https://api.gitcode.com/api/v5/repos/{owner}/{repo}/branches`
- 写文件：`POST https://api.gitcode.com/api/v5/repos/{owner}/{repo}/contents/{path}`
- 建 PR：`POST https://api.gitcode.com/api/v5/repos/{owner}/{repo}/pulls`（响应链接字段为 `web_url`）

# 9. 验收标准（Acceptance Criteria）

- 如果用户点击「分享」且未配置 PAT，则提示并跳转到「设置 → 第三方授权 → GitCode」；填写无效 PAT 时给出可读错误且不建立登录态。
- 如果填写有效 PAT，则后端验证通过、持久化，`auth/status` 返回 `configured: true`。
- 如果已配置 PAT 的用户点击「分享」，则打开 ActionButton 面板，提示词已替换专家名/版本/目录参数，且提示词中不含 PAT 明文。
- 如果用户执行，则 AI 读取本地 PAT、在 `weibaohui/ntd-resource` 创建出 PR（fork → 分支 → 文件 → PR），标题以 `[专家贡献]` 开头。
- 执行完成后前端展示 PR 链接，用户点击可在浏览器打开。
- 退出登录后 `auth/status` 返回 `configured: false`，本地 PAT 文件被清除。

# 10. 风险与已知不确定点

- **PAT 外泄风险（本方案核心权衡）**：ActionButton 让 AI 执行器读取并使用 PAT，PAT 会进入执行器的工具调用（如 `curl` 的 `Authorization` 头）与 LLM 上下文，存在被外发到第三方 LLM 服务的风险。缓解：PAT 不内联进提示词模板、提示词要求不回显、PAT 文件 0600；但该风险是「AI 直接用 PAT」方案的本质属性，无法完全消除，用户需知情。
- **AI 执行不确定性**：遍历目录、base64 编码、分支名生成、错误处理依赖 AI 正确执行提示词，存在偏离/遗漏风险（如把 `.git` 一并提交）。缓解：提示词明确跳过元数据；提交的 PR 由维护者 review 兜底。
- **前置人工准备**：维护者需在 `ntd-resource` 仓库确认开放 PR 提交。

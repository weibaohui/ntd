## 1. 实现了什么

把飞书消息处理从「斜杠命令 + 默认响应兜底（todo/loop/executor 三选一）」重构为「斜杠命令精确匹配 + 空间管家」：

- **斜杠命令只有精确匹配**：内置 5 个 + workspace 自定义规则，未命中不再降级到任何默认 todo/环路；
- **默认响应机制整体删除**：4 个 `default_response_*` 配置字段、3 个分发分支、SmartCreate 功能全部移除；
- **新增空间管家**：工作空间配置 = 管家专家（可选）+ 管家执行器；所有未命中斜杠的消息由管家接收——执行器聊天（session 连续）+ 专家 prompt 注入（复用 `inject_expert_message`）；未配置管家时回复配置引导提示；
- **内置「空间管家」专家**（ntd-resource 仓库 `experts/workspace-butler`）：行为准则（动作前确认/闲聊不触发/不伪造结果）+ ntd CLI 能力清单；
- **命名全面管家化**：DB 列、trigger_type、函数、组件、卡片文案、act 动作串全部与管家语义一致，历史值仅作展示保留。

## 2. 与需求的对应关系

| 需求条目 | 实现 |
|---------|------|
| 2.1 斜杠精确匹配无兜底 | `route_slash_or_butler` + `dispatch_slash_command` 三处兜底改管家 |

| 2.3 空间管家 | `butler_expert_name`/`butler_executor` 字段；`handle_butler_chat` 注入专家；未配置回提示；内置专家 |
| 2.4 命名一致性 | 见设计文档 §2 命名决策表，全部落地 |

## 3. 关键实现点

1. **V95 迁移**：加管家两列 → 承接 `default_response_executor` 值 → 删四旧列；每步列存在性守卫，半途残留可自愈；漂移测试同步更新 consolidated schema。
2. **管家执行零新子系统**：`handle_butler_chat` = 原 executor 聊天通路（session 连续/超时/飞书回复）+ 执行时现读管家专家名注入；专家缺失静默退化为纯执行器聊天。
3. **注入只进执行器**：开始回执与日志展示用户原文，专家规则不刷屏。
4. **blackboard 不受影响**：`chat_with_wiki` 是独立实现，改名零波及。
5. **历史兼容**：存量 `default_response_executor` 值升级到 `butler_executor`；历史消息的 trigger_type 标签保留展示。

## 4. 验证结果

- clippy 零告警；后端 1765 测试全过；前端 tsc 零错误、构建成功；
- dev 环境实测：迁移落库、专家加载、设置 API 读写、SmartCreate 路由 405、管家面板 UI 闭环（agent-browser）。

## 5. 已知限制

- 每条管家消息都携带完整专家 prompt（session resume 每轮重注），token 成本高于纯聊天；后续可优化为「仅新 session 注入」；
- 真实飞书四连测需带 bot 环境人工回归；
- 管家「动作前确认」是专家规则级约束（v1），非代码级硬门禁。

## 1. 实现了什么

把「项目目录 (project_directory)」旧命名全套统一为「工作空间 (workspace)」，
与既有 `/api/v1/workspaces/{ws}/...` 路由、`WorkspaceSwitcher` 等命名对齐。
涉及 120+ 文件、约 1400 行改动：

- **数据库**：表 `project_directories` → `workspaces`（V94 迁移 + consolidated schema 同步）；
  `feishu_project_bindings.project_dir_id` → `workspace_id`。
- **后端**：模块/文件/结构体/函数全套改名（`db/workspace.rs`、`handlers/workspace.rs`、
  `entity/workspaces.rs`）；CRUD 路由 `/api/v1/project-directories` → `/api/v1/workspaces`；
  CLI HTTP 路径同步。
- **前端**：组件 `ProjectDirectoriesPanel` → `WorkspacesPanel`、视图/路由
  `projectDirectories` → `workspaces`（`/#/workspaces`）、API 函数 `getWorkspaces` 等、
  类型 `Workspace`、事件 `workspaceAdded`。
- **附带清理**：备份文件名 `aietodo-backup-*` → `ntd-backup-*`；
  launchd 标签 `com.nothing-todo.ntd` → `com.ntd.ntd`；
  测试夹具中硬编码的 `nothing-todo` 路径替换为中性示例路径。
- **文档**：用户指南、API reference、帮助页、SKILL.md 同步更新。

## 2. 关键实现点

- **V94 迁移**（`db/migration/v94.rs`）：先删旧触发器/索引 → `ALTER TABLE
  project_directories RENAME TO workspaces` → 以新名重建 → `RENAME COLUMN
  project_dir_id TO workspace_id`。历史迁移 v1..v93 保持不可变。
- **SQLite 引号细节**：`ALTER TABLE RENAME` 会把表名与其它表的外键引用改写为
  带引号形式（`"workspaces"`），consolidated schema 必须与之逐字一致
  （由漂移测试 `test_consolidated_schema_matches_incremental` 强制保证）。
- **历史迁移单测适配**：v57/v61 单测在 bootstrap（最终 schema）上跑历史迁移，
  需先把表名还原为当时的 `project_directories` 再执行，模拟老库升级场景。
- **保留项**：session scanner（pi/kimi/atomcode）中仅指文件系统路径的局部变量
  `project_dir` 保留；`feishu_project_bindings` 表名保留（"project" 是产品语义）。

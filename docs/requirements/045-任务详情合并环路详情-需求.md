## 背景

任务（Task）与环路（Loop）是 1:1 关系：每个任务创建时选择一个工艺环路，`task.loop_id` 指向唯一环路实例。044 环路瘦身后，环路降级为工艺的运行时承载，环路详情页只读化且功能大幅缩减。

现状中，环路详情与任务详情分布在两个独立页面，用户需要在任务列表 → 任务详情 → 环路列表 → 环路详情之间多次跳转才能完成以下操作：

- 查看当前任务的执行环路结构（流程图）
- 查看任务对应的工艺步骤验收标准
- 查看执行历史
- 删除任务对应的环路

用户希望将环路详情面板整合进任务详情页，在单页面内完成所有查看与操作，减少跳转。

## 需求

### R1 概览 Tab 展示环路基本信息

任务详情页的「概览」Tab 展示任务关联环路的以下信息：

- **工作空间**：环路的 workspace_id 及对应目录路径（含 Git Worktree / 自动清理标志）
- **待审批数**：pending_approval_count 红色角标
- **全局限制**：最大执行步数 / 最大 Token 数 / 超限异常处理启用状态
- **工艺模板信息回退**：环路不存在时回退展示模板名称、版本、复杂度、任务状态

### R2 执行环路 Tab 展示 DAG 流程图

任务详情页增加「执行环路」Tab（原「工艺要求」Tab 的替代），展示：

- **环路描述**：来自 LoopDetail.description，展示在流程图上方
- **DAG 流程图**：使用 LoopFlowGraph 组件以 SVG 呈现环节节点与连接边
- **步骤验收标准**：按 order_index 排序的环节列表，每个环节展示：
  - 序号圆标
  - 环节名称
  - 技能标签（紫色 Tag）
  - 产物标签（蓝色 Tag，含路径和类型）
  - 门禁标签（含类型名称 + 判定条件文本）

### R3 执行历史 Tab

任务详情页的「执行历史」Tab 使用已存在的 `LoopExecutionsPanel` 完整组件，包含：

- 分页执行列表
- TokenSummaryBar
- StepExecList（含门禁审批）
- BlackboardDrawer

### R4 环路删除入口

任务详情页顶部操作栏提供环路删除按钮：

- 仅环路存在时显示
- 使用 Popconfirm 二次确认
- 删除成功后通知宿主刷新列表

### R5 再次执行入口

任务详情页顶部提供「再次执行」按钮：

- 打开 Modal 输入新需求
- 调用 `createTaskExecution` 创建新执行
- 执行成功后重拉任务详情

## 边界

- 环路加载失败不影响任务详情展示（降级为无环路视图）
- 环路不存在时「概览」Tab 回退展示工艺模板信息，「执行环路」Tab 和「执行历史」Tab 正常展示空态
- 已删除的执行看板 Tab（`ProcessExecutionBoard`）和来源工艺面包屑（`TraceBreadcrumb`）不再恢复——功能已在环路的 LoopStudioDetailPanel 中提供

## 验收标准

1. 任务详情页有 3 个 Tab：概览 / 执行环路(N) / 执行历史
2. 有 loop_id 时概览展示环路基本信息和全局限制，无 loop_id 时回退展示模板信息
3. 执行环路 Tab 展示 DAG 流程图 + 步骤验收标准
4. 执行历史 Tab 展示完整 LoopExecutionsPanel
5. 环路删除按钮在 Popconfirm 确认后执行删除，成功则重刷列表
6. 再次执行按钮打开 Modal、提交后重拉详情
7. `cargo clippy --all-targets -- -D warnings` 零告警；`cargo test` 全绿；`npx tsc --noEmit` 零错误

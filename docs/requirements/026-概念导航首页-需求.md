| 修改人 | 修改时间 | 修改内容 |

## 1. 背景（Why）

ntd 当前 LeftRail 直接给用户 8 个菜单入口（任务/工艺/环路/事项/消息/黑板/看板/仪表盘），无任何概念引导。新用户首次打开不知道：

- 这软件能干什么
- 「工艺」「环路」「事项」「任务」之间什么关系
- 「执行器」「专家」「模型」三个相似概念怎么区分
- 应该从哪个菜单开始用

代码中的概念关系实际存在但用户不可见：`process_templates` → 安装实例化 → `loops`（含 `loop_phases`/`loop_steps`/`loop_triggers`）→ 编排引用 `todos`（含 `executor`/`expert_name`/`model`/`skill_names`）→ 触发产生 `loop_executions`/`execution_records`。`tasks` 是用户主动选择环路执行一次的意图载体。

需要一个**图形化导航首页**，用可视化+交互方式把这些概念关系讲清楚，让用户 3 分钟内理解系统全貌并知道下一步去哪操作。

---

## 2. 目标（What，必须可验证）

- [ ] 用户首次打开 app（localStorage 无 `ntd_onboarding_completed` 标记）→ **自动跳转**到概念导航首页
- [ ] 概念导航首页展示 6 个核心概念的**可交互关系图**（工艺→环路→事项→执行记录 + 触发器/执行器专家模型三条支线）
- [ ] 点击关系图任一节点 → 右侧 `Drawer` 展开该概念的：定义 + 字段示例 + 跳转入口按钮
- [ ] 6 张概念卡片网格，每张用**差异化可视化隐喻**（不是统一图标）+ 当前数量徽标
- [ ] 每个概念的详细说明区展示**用户自己系统里的真实数据快照**（非抽象描述）
- [ ] 5 步快速开始流程图，每步带「已完成/未完成」状态判断 + 跳转入口
- [ ] 顶部 sticky Tab（关系图/概念详解/快速开始）+ 滚动时自动高亮当前 section
- [ ] 用户点击「跳过引导」→ 写 localStorage 标记 + 跳到仪表盘，LeftRail「概览」区可随时回看

---

## 3. 非目标（Explicitly Out of Scope）

- ❌ 不做移动端独立适配（YAGNI，先做好桌面端，移动端降级为纵向列表/单列卡片即可）
- ❌ 不做概念编辑功能（导航首页只读，不新增/修改工艺/环路等）
- ❌ 不做视频/动画教程（纯 SVG + 交互动画即可）
- ❌ 不做后端 API 改动（复用现有 `getProcesses`/`listLoops`/`getAllTodos`/`listTasks`/`getExecutors`/`getExperts` 等）
- ❌ 不做 i18n（与 app 现状一致，只做中文）
- ❌ 不做关系图的拖拽编辑（只读可视化，非编辑器）

## 4. 使用场景 / 用户路径

### 场景 A：新用户首次打开

1. 用户启动 ntd，URL 默认 `/#/items`
2. 前端检测 `localStorage['ntd_onboarding_completed']` 不存在 → `replaceUrl('onboarding')`
3. 用户看到 Hero 区 + 概念关系图
4. 点击「工艺」节点 → 右侧 Drawer 展示工艺定义 + 字段 + 「去工艺页」按钮
5. 点击「去工艺页」→ 跳到 `/#/processes`
6. 用户返回导航首页（LeftRail「概览」区点「导航」）→ 继续看其他概念
7. 用户看完点「跳过引导」→ 写 localStorage + 跳到 `/#/dashboard`

### 场景 B：老用户回看概念

1. 用户点 LeftRail「概览」区的「导航」入口
2. 进入概念导航首页，所有内容可见
3. 用户只想看某个概念 → 顶部 sticky Tab 点「概念详解」→ 平滑滚动到对应 section
4. 用户只想看操作步骤 → 顶部 Tab 点「快速开始」→ 滚到 5 步流程图

### 场景 C：用户在导航首页直接跳到操作

1. 用户在快速开始区点步骤 3「创建任务」
2. 跳到 `/#/tasks` 开始创建任务

## 6. 约束条件

### 6.1 技术约束

- 前端 React 18 + TypeScript + Vite + Ant Design 5
- 导入统一用 `@/` 绝对路径别名
- 不引入新重依赖（reactflow 等），关系图用纯 SVG 手绘
- 关系图动画尊重 `prefers-reduced-motion`

### 6.2 架构约束

- 复用现有 `PageCard` 外壳，与 app 其他页风格一致
- 复用现有 `useViewState` 路由机制（hash 路由）
- 复用现有 `bundledApi` / `db` 数据访问层，不新增后端 API

### 6.3 安全约束

- 导航首页只读，不修改任何数据
- 不展示敏感字段（如 `app_secret`/`bot_open_id` 等）
- 数据快照只展示当前 workspace 的数据，不跨 workspace

### 6.4 性能约束

- 首屏渲染 < 2s（关系图 SVG 静态，数据快照可延迟加载）
- 数据快照用并行请求（Promise.all）拉取
- 滚动锚点跳转用 `scroll-behavior: smooth`

## 9. 验收标准（Acceptance Criteria）

1. **如果** 用户首次打开 app（localStorage 无 `ntd_onboarding_completed`），**则** 自动跳转到 `/#/onboarding`
2. **如果** 用户在概念导航首页点击「跳过引导」，**则** localStorage 写入 `ntd_onboarding_completed=true` 并跳到 `/#/dashboard`
3. **如果** 用户点击概念关系图的「环路」节点，**则** 右侧 Drawer 展示环路定义 + 字段表 + 「去环路页」按钮
4. **如果** 用户 hover 关系图的「环路」节点，**则** 「工艺」和「事项」节点同时高亮，连线加粗
5. **如果** 系统里已有 3 个工艺模板，**则** 工艺卡片右上角徽标显示「3」
6. **如果** 用户点击工艺卡片，**则** 页面平滑滚动到 `<section id="concept-process">`
7. **如果** 用户滚动到「概念详解」区，**则** 顶部 sticky Tab 自动高亮「概念详解」
8. **如果** 系统里已有任务数据，**则** 快速开始步骤 3 显示「✓ 已完成」
9. **如果** 用户点击快速开始步骤 3，**则** 跳转到 `/#/tasks`
10. **如果** 用户开启 `prefers-reduced-motion`，**则** 关系图连线流动动画降级为静态高亮
11. **如果** 用户点 LeftRail「概览」区的「导航」入口，**则** 进入 `/#/onboarding`，所有内容可见
12. **如果** `npx tsc --noEmit` 执行，**则** 零错误
13. **如果** 用户在详细说明区看到工艺数据快照，**则** 展示的是当前 workspace 里的真实工艺记录 YAML 片段

## 10. 风险与已知不确定点

### 10.1 AI 遇到不确定性时的处理

- **关系图布局**：SVG 节点坐标手动布局，若在小屏幕溢出 → 降级为纵向列表（容器 `overflow-x: auto`）
- **数据快照为空**：用户系统里可能没有任何工艺/环路/任务 → 展示空态文案「暂无数据，去 XX 页创建」+ 跳转按钮
- **IntersectionObserver 兼容**：所有现代浏览器支持，不做 polyfill（YAGNI）

### 10.2 已知限制

- 关系图节点坐标硬编码，不响应式重排（简化实现，YAGNI）
- 数据快照只拉一条记录，不展示全量
- 不做概念编辑功能（只读导航）

## 12. AI 的决策权限

### AI 可自行决策

- SVG 节点的具体坐标布局（保证不溢出即可）
- 卡片可视化隐喻的具体形式（圆点/箭头/堆叠等）
- 静态文案的具体措辞（保证清晰即可）
- 详细说明区字段表展示哪些字段（选关键字段即可）

### AI 必须停下来请求人工确认

- 若发现 `useViewState` 路由协议与本文档描述不一致
- 若发现现有 API 无法满足数据快照需求（需新增后端 API）
- 若 `LeftRail` 「概览」区结构与本需求描述不一致
- 若编译/测试存在无法解决的失败

### AI 不允许假设

- 不假设用户系统里有数据（必须处理空态）
- 不假设关系图节点坐标在所有屏幕都不溢出（必须加 overflow 兜底）
- 不假设 `prefers-reduced-motion` 一定开启（必须做默认动画 + 降级）

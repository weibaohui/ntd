---

## 1. 背景

025-1 任务管理已完成：左侧导航新增「任务」、创建任务（需求→推荐→安装→注入需求）、任务列表。

当前问题：点击任务卡片跳转到 Loop 页面，左侧仍有 Loop 列表，用户体验混乱。任务详情应该是一个**独立的子页面**，不依赖 Loop 页面的左侧列表。

一个任务 = 一个由工艺模板创建的 Loop，可执行多次。任务详情页需要同时展示**工艺要求**（每步的 skill、产物、门禁）和**执行历史**（多次执行、每次的产物/门禁/结论）。

---

## 2. 目标（必须可验证）

- **G1** 点击任务卡片→ 进入任务详情页（不经过 Loop 页面，无 Loop 左侧列表）。
- **G2** 任务详情页上半部分展示工艺要求：每步的名称、skill、产物路径、门禁类型。
- **G3** 任务详情页下半部分展示执行历史：按时间倒序排列，显示执行 ID、状态、完成数/总数、时间。
- **G4** 点击某次执行→ 在下方展开执行看板（复用现有 `ProcessExecutionBoard` 组件），展示产物、门禁、结论。
- **G5** 任务详情页提供「返回任务列表」按钮。
- **G6** 多次执行互不影响，各自有独立的产物、门禁、结论。

---

## 3. 非目标

- 不修改现有 Loop 页面结构。
- 不新增数据库表。
- 不改变任务创建流程。
- 不在任务详情页提供「编辑 Loop 配置」功能（去 Loop 页面编辑）。

---

## 4. 使用场景

### 场景 A：查看任务执行情况

1. 用户在「任务」列表看到 Loop #12「便利贴应用」。
2. 点击卡片→ 进入任务详情页。
3. 上半部分看到工艺要求：6 个步骤，每步有 skill、产物、门禁。
4. 下半部分看到执行历史：3581（成功）、3579（失败）。
5. 点击 3581→ 展开执行看板→ 看到每步的产物、门禁评分、结论。
6. 点「返回」→ 回到任务列表。

### 场景 B：创建新执行

1. 在任务详情页，执行历史下方有「新建执行」按钮。
2. 点击 → 触发 Loop 执行 → 新执行出现在历史列表顶部。
3. 可多次点击，每次独立执行。

## 5. 功能需求清单

### 5.1 任务详情 API（F1）

- [ ] **F1.1** 新增 `GET /api/v1/tasks/{loop_id}` — 返回工艺要求（steps）+ 执行历史。
- [ ] **F1.2** 工艺要求包含：step 名称、order_index、skill_names、expected_artifacts、gate_config。
- [ ] **F1.3** 执行历史包含：execution_id、status、started_at、finished_at、total_steps、completed_steps、failed_steps。

### 5.2 任务详情页组件（F2）

- [ ] **F2.2** 「返回任务列表」按钮。
- [ ] **F2.3** 「新建执行」按钮（POST 触发 Loop 执行）。

### 5.3 任务列表导航（F3）

- [ ] **F3.1** 点击任务卡片→ 进入详情页（TaskDetailPage），不跳转到 Loop 页面。

## 6. 约束条件

- 复用现有组件：`ProcessExecutionBoard`、`LoopStudioStepsPanel`（步骤展示部分）。
- 不修改 Loop 页面。
- 后端不新增表——数据来自 `loop_steps`、`loop_executions`、`process_templates`。

---

## 7. 验收标准

- **AC1** 点击任务卡片→ 看到任务详情（无 Loop 列表）。
- **AC2** 任务详情页显示全部步骤的 skill、产物、门禁。
- **AC3** 执行历史列表按时间倒序，多次执行互不干扰。
- **AC4** 展开执行看板后能看到产物、门禁、结论。
- **AC5** 返回按钮回到任务列表。

# 需求：工艺列表拆分「我的 / 模板」双视图（039）

## 1. 背景与问题

主导航「工艺」页（`/#/processes`，`frontend/src/components/ProcessPage.tsx`）把两类工艺混在同一个
Card 网格里渲染：

- **系统模板**：系统内置及通过 bundled 同步下载的工艺（`is_system = true`）
- **用户工艺**：用户自己创建的工艺（`is_system = false`）

目前唯一的区分手段是系统工艺卡片不渲染「编辑」按钮（`ProcessPage.tsx:311`），用户在列表里无法
快速定位"我自己建的工艺"，也无法集中浏览系统模板，认知负担随模板数量增长而加重。

## 2. 目标

1. 工艺列表页顶部提供「我的 / 模板」视图切换（antd `Segmented`）：
   - **我的**：只显示用户创建的工艺（`is_system = false`）
   - **模板**：只显示系统内置及同步下载的工艺（`is_system = true`）
2. 过滤在**服务端**完成：`GET /api/bundled/processes`（及 `/api/v1/bundled/processes`）支持
   `is_system` 查询参数；不传参数时行为与现状完全一致（向后兼容，设置页模板管理等旧调用方零影响）。
3. 视图选择持久化到 localStorage，刷新/重进页面后保持上次选择；无记录时默认「我的」。
4. 两个视图的空态文案分别引导：「我的」空 → 引导创建工艺；「模板」空 → 引导执行 bundled 同步。

## 3. 边界与非目标

- **只改主导航「工艺」页**：设置 → 模板管理 → 工艺模板（`ProcessTemplatesTab.tsx`）保持
  「合并列表 + 来源 Tag」现状，本次不动。
- **其他模板类型不拆**：Todo 模板等维持现状，模式验证后再评估推广。
- **不做数量徽标**：服务端过滤后前端只持有当前视图子集，拿不到对侧数量，不做 `我的 (N)` 计数。
- **搜索行为不变**：现有搜索框的客户端过滤作用于当前视图子集，切换视图不清空搜索词。

## 4. 验收标准

1. 访问 `/#/processes`，localStorage 无记录时默认显示「我的」视图。
2. 「我的」视图只显示用户工艺且卡片带「编辑」按钮；「模板」视图只显示系统工艺且无「编辑」按钮。
3. 切换视图后刷新页面，视图选择保持（localStorage 生效）。
4. `GET /api/bundled/processes?is_system=true` 只返回系统模板，`?is_system=false` 只返回用户模板，
   不传参返回全部。
5. 后端 `cargo clippy --all-targets -- -D warnings` 零告警、`cargo test` 全绿；
   前端 `npx tsc --noEmit` 零错误；Playwright 用例通过。

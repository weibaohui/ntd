## 1. 背景（Why）

概念导航首页（`/#/onboarding`，026 需求落地）的关系图目前只有 10 个圆圈：主链「工艺 → 环路 → 事项 → 执行记录」+ 支线「任务 / 触发器 / 执行器 / 专家 / 技能 / 模型」。这套图讲的是「活怎么被定义、怎么被跑起来」，但**没讲「跑完之后去哪看结果」**。

实际上 app 里已有两个成熟的「观察」出口，且都已在 LeftRail「观察」区有独立菜单：

- **黑板**（`/#/blackboard`，BlackboardPage）：根据事项、执行记录持续自动分析得出的观察报告；环路里还有环节小黑板，逐个记录环路上各个环节的执行结论，汇总后便于统一观看。
- **看板**（`/#/memorial?mode=kanban`，MemorialBoard 看板模式）：执行进度进展的展示方式，按状态分列呈现执行进展。

用户在导航页学完概念关系后，不知道「观察结果」这一层存在。需要把黑板、看板作为两个圆圈补进关系图，让概念地图完整覆盖「定义 → 执行 → 观察」全链路。

## 2. 目标（What，必须可验证）

- [ ] 概念关系图新增 2 个支线小圆节点：「黑板」「看板」，与现有支线节点同规格（半径 36、白底灰边、hover 高亮）
- [ ] 新增 4 条支线连线，语义如下：
  - `事项 → 黑板`：持续分析（事项是黑板的自动分析来源之一）
  - `执行记录 → 黑板`：持续分析（执行记录是黑板的自动分析来源之一）
  - `环路 → 黑板`：环节结论（环节小黑板记录各环节执行结论，汇总到黑板）
  - `执行记录 → 看板`：进度展示（看板是执行进度进展的展示方式）
- [ ] 点击「黑板」节点 → Drawer 展示黑板概念说明（含环节小黑板语义）+ 「去黑板页」按钮，点击跳转 `/#/blackboard`
- [ ] 点击「看板」节点 → Drawer 展示看板概念说明 + 「去看板页」按钮，点击跳转 `/#/memorial?mode=kanban`
- [ ] hover 新节点时关联节点同步高亮（黑板 ↔ 事项/执行记录/环路；看板 ↔ 执行记录），连线加粗变色，与现有交互一致
- [ ] 「环节小黑板」**不**单独画节点，其语义通过「环路 → 黑板」连线与黑板 Drawer 文案表达

## 3. 非目标（Explicitly Out of Scope）

- ❌ 不把黑板/看板升级为正式概念（不进 `CONCEPTS`、不加概念卡、不加详细说明区、不加数量徽标）
- ❌ 不单独画「环节小黑板」节点挂在环路旁边（经确认：保持图简洁，文案表达即可）
- ❌ 不改后端任何 API（纯前端静态数据改动）
- ❌ 不改 BlackboardPage / MemorialBoard 页面本身
- ❌ 不调整现有 10 个节点的坐标与既有 10 条连线
- ❌ 不引入新的图表库（沿用纯 SVG 手布局）
- ❌ 不做 i18n（与 app 现状一致，仅中文）

## 4. 使用场景 / 用户路径

### 场景 A：用户在导航页理解「观察」出口

1. 用户打开 LeftRail「概览」区「导航」，进入 `/#/onboarding`
2. 在概念关系图右上角看到「黑板」圆圈、右下角看到「看板」圆圈
3. 用户 hover「黑板」→ 事项、执行记录、环路三个节点同步高亮，三条连线加粗
4. 用户点击「黑板」→ 右侧 Drawer 展示黑板概念说明 + 「去黑板页」按钮
5. 用户点「去黑板页」→ 跳转 `/#/blackboard`，Drawer 关闭

### 场景 B：用户从图直达看板

1. 用户点击「看板」节点 → Drawer 展示看板说明 + 「去看板页」按钮
2. 点「去看板页」→ 跳转 `/#/memorial?mode=kanban`，直接落在看板视图

### 场景 C：老用户只看关系

1. 用户 hover 主链「执行记录」→ 黑板、看板两个节点同步高亮
2. 用户一眼看到「执行记录」有两个观察出口

## 6. 约束条件（非常关键）

- **技术约束**：纯 SVG 手布局，`viewBox="0 0 1000 400"` 不变；新节点坐标不得与现有 10 个节点重叠（圆心距 ≥ 两圆半径和 72），不得超出 viewBox 边界（圆心 x ≤ 964）
- **架构约束**：改动仅限 `frontend/src/components/onboarding/` 下的 `concepts.tsx` 与 `ConceptRelationGraph.tsx` 两个文件；前端跨目录导入统一用 `@/` 别名
- **交互约束**：新节点必须复用现有 hover 高亮 / 点击 Drawer / 流动动画机制，不得引入新交互范式；尊重 `prefers-reduced-motion`
- **代码约束**：逐行注释（解释为什么）；单函数体 ≤ 50 行（028 起放宽后的新规）；`npx tsc --noEmit` 零错误
- **安全约束**：无用户输入、无 API 调用、无权限变更

## 8. 接口与数据约定

- 无后端接口。全部数据为 `concepts.tsx` 内硬编码静态数据。
- 跳转路由约定（复用 `useViewState` 现有能力）：
  - 黑板：`pushUrl('blackboard')` → `/#/blackboard`
  - 看板：`pushUrl('memorial', { mode: 'kanban' })` → `/#/memorial?mode=kanban`（`BoardMode` 白名单已含 `kanban`）

## 9. 验收标准（Acceptance Criteria）

- 如果打开 `/#/onboarding` 概念关系图，则能看到 12 个圆圈：原有 10 个 + 「黑板」（右上区域）+「看板」（右下区域），且任意两圆不重叠、不出界
- 如果 hover「黑板」，则「事项」「执行记录」「环路」三节点同步高亮，`事项→黑板`、`执行记录→黑板`、`环路→黑板` 三条连线加粗变色
- 如果 hover「看板」，则「执行记录」同步高亮，`执行记录→看板` 连线加粗变色
- 如果 hover「执行记录」，则「黑板」「看板」都在高亮集合中
- 如果点击「黑板」，则 Drawer 展示含环节小黑板语义的说明文案 + 「去黑板页」按钮；点击按钮后 URL 变为 `/#/blackboard` 且 Drawer 关闭
- 如果点击「看板」，则 Drawer 展示看板说明 + 「去看板页」按钮；点击按钮后 URL 变为 `/#/memorial?mode=kanban` 且 Drawer 关闭
- 如果点击原有支线节点（如「触发器」），则 Drawer 仍展示现有通用 fallback 文案，无跳转按钮（行为不回归）
- 如果执行 `cd frontend && npx tsc --noEmit`，则零错误
- 如果执行 Playwright 验证脚本，则上述交互全部通过

## 10. 风险与已知不确定点

| 风险 | 应对 |
|------|------|
| `环路→黑板` 是跨图长连线，可能视觉上穿过其他节点 | 设计阶段用坐标几何验证（连线不进入任何第三方节点圆的包围盒）；Playwright 截图复核 |
| 右下区域（专家/模型所在行）新增看板后变挤 | 看板放最右端 x=960，与模型保持圆心距 100（与专家↔模型间距一致），视觉节奏统一 |
| 新增节点导致既有 onboarding Playwright 用例失败 | 实现后先跑既有 `frontend/tests/onboarding.spec.ts` 确认，再补充新用例 |

不确定点处理：坐标微调、文案措辞属 AI 可自决范围；如需改动「不可修改项」清单中的任何内容，必须停止并请求人工确认。

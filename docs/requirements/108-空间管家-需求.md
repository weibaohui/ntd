# 108-空间管家-需求

| 修改人 | 修改时间 | 修改内容 |
|--------|---------|---------|

---

## 1. 背景与问题

当前飞书消息处理链路（`backend/src/services/feishu_listener.rs`）在斜杠命令之外存在两层「兜底/默认」机制：

1. **斜杠规则未命中兜底**：用户发送 `/xxx` 但 `workspace_slash_commands` 表中没有该规则时，消息降级到「默认响应」通路。
2. **默认响应（default_response）**：按 `workspace_settings.default_response_type` 三选一：
   - `todo`（默认值）：把消息塞进 `default_response_todo_id` 指定的 todo 执行；
   - `loop`：触发 `default_response_loop_id` 指定的环路；
   - `executor`：与 `default_response_executor` 指定的执行器聊天。

问题：

- 「每句话无脑塞进同一个默认 todo/环路」语义僵硬，无法理解用户意图；
- 兜底链路多、概念多（4 个 default_response_* 字段），维护成本高；
- 未命中斜杠命令时静默降级，用户感知不到「命令没配上」。

## 2. 需求目标

### 2.1 斜杠命令：只保留精确匹配，无任何兜底

- 内置命令（`/feishupush`、`/list`、`/help`、`/new`、`/stop`）与自定义规则（`workspace_slash_commands` 表）均为精确匹配；
- 未命中任何规则的 `/xxx` 消息**不再降级**，按普通消息处理（交给空间管家）。

### 2.2 默认响应机制彻底删除

- 删除 `workspace_settings` 的 4 个字段：`default_response_type`、`default_response_todo_id`、`default_response_loop_id`、`default_response_executor`；
- 删除消息链路中 todo 默认、环路默认两个分发分支及配套函数；
- 删除 SmartCreate 功能（`v1_smart_create_handler` + 前端 `SmartCreateModal`），它依赖 `default_response_todo_id`，随默认响应一并退役。

### 2.3 新增空间管家（Workspace Butler）

- 工作空间新增管家配置：**选择一个专家 + 配置一个执行器**；
- 所有未命中斜杠命令的消息（含未命中的 `/xxx`）交给空间管家处理；
- 管家通路 = 执行器聊天（session 连续，可多轮对话）+ 专家 prompt 注入（复用现有 `inject_expert_message` 机制）；
- 管家通过专家规则（agent MD）获得行为准则与能力清单（如使用 `ntd` CLI 查询/触发事项），由 AI 自主决定下一步动作；
- 未配置管家时：回复提示文案引导用户去配置（提示，不是兜底执行）；
- 提供内置「空间管家」专家（bundled 专家），用户可自建专家覆盖。

### 2.4 命名一致性（强制）

- 所有新增/修改的代码、字段、组件命名必须与「管家」语义一致；
- 旧 `default_response_*` 命名不得残留在新链路上，避免命名与功能不一致造成误导；
- 历史数据（旧 trigger_type 等）的展示标签保留，但仅用于历史消息展示。

## 3. 范围

### 3.1 涉及模块

| 模块 | 改动 |
|------|------|
| `db/workspace_setting.rs` + migration + entity | 新增 `butler_expert_name` / `butler_executor` 列，删除 4 个 default_response_* 列 |
| `services/feishu_listener.rs` | 路由改为「斜杠精确匹配 或 管家」，删除默认响应兜底 |
| `services/message_debounce.rs` | 管家执行（专家注入），删除 default_response_loop 分支 |
| `services/feishu_slash_commands.rs` | `/new` 清管家 session，删除 type 拦截 |
| `services/feishu_card_actions.rs` / `feishu_card.rs` | 删 auto-seed，「默认执行器」动作改为「管家执行器」 |
| `handlers/agent_bot.rs` | 工作空间设置 API 字段替换 |
| `handlers/execution.rs` | 删除 SmartCreate |
| 前端设置面板 | `DefaultResponseConfigPanel` 重写为管家配置面板 |
| ntd-resource（bundled 专家） | 新增内置「空间管家」专家 |

### 3.2 不涉及的边界

- blackboard 通路的执行器调用保持独立（blackboard 有 per-board 执行器配置，不注入管家专家）；
- 斜杠命令规则命中后的 todo/loop 触发逻辑不变；
- 卡片回调（card_callback）处理逻辑不变。

## 4. 验收标准

1. 发送精确匹配的内置/自定义斜杠命令 → 行为与现状一致；
2. 发送未命中规则的 `/xxx` → 交给管家（配置后）或提示配置（未配置），不再触发任何 todo/loop；
3. 发送普通消息 → 交给管家，管家回复带有其专家人设与能力；
4. 未配置管家的工作空间收到非斜杠消息 → 收到配置引导提示；
5. 系统中不再存在 `default_response_type/todo_id/loop_id/executor` 的配置入口与代码引用（历史数据展示标签除外）；
6. SmartCreate 入口与代码彻底移除；
7. `cargo clippy --all-targets -- -D warnings` 零告警，`cargo test` 全通过，前端 `npx tsc --noEmit` 零错误。

## 5. 已确认的关键决策（会话澄清结论）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | SmartCreate | 彻底删除 |
| 2 | 默认响应 | 彻底删除，只留精确斜杠命令 |
| 3 | 管家模型 | 选一个专家 + 配一个执行器，配到工作空间下 |
| 4 | 未配管家时 | 回复配置引导提示（非静默吞掉，非兜底执行） |
| 5 | 命名 | 新链路命名必须与管家语义一致，不留误导性旧命名 |

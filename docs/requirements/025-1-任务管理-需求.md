## 1. 背景（Why）

025 工艺管理 M1~M3 已经完成了：模板市场、安装为 Loop、运行时产物捕获/门禁/返工/审计、工艺推荐。但缺少一个面向普通用户的**统一入口**。

当前用户要创建一个工艺驱动的任务，必须：
1. 打开工艺库 → 浏览/搜索模板 → 手动安装 → 逐个编辑 Loop 里每个 todo 的 prompt → 写入需求 → 执行

这个流程对普通用户（非 ntd 深度使用者）来说太复杂。用户的想法是「我要做个便利贴应用」，而不是「我要找一个叫 superpowers-task 的模板然后用它创建一个 Loop 再编辑 prompt」。

**核心缺口**：没有把「用户想做的事」和「系统里的工艺模板」之间建立顺畅的连接。

---

## 2. 目标（What，必须可验证）

- **G1** 新增「任务」视图，作为 ntd 左侧导航的独立入口。
- **G2** 用户输入自然语言描述意图，系统自动推荐合适的工艺模板，用户确认后一键创建 Loop 并注入需求。
- **G3** 任务列表展示已创建的任务（名称、关联模板、状态、时间）。
- **G4** 需求文本自动注入到 Loop 每个 step 的 prompt 中（通过 `{{requirement}}` 占位符替换）。
- **G5** 创建任务流程支持「系统推荐模板」和「用户手动选择模板」两种方式。
- **G6** 前端需有独立任务视图，与现有「事项」「回路」「工艺」并列于左侧导航。

---

## 3. 非目标（Explicitly Out of Scope）

- 不创建新的数据库表——复用 `loops` 表（`description` 存需求，`process_template_id` 关联模板）。
- 不改变现有「工艺库 → 浏览 → 安装」的路径，两者共存。
- 不改变 Loop 执行引擎——只增加 prompt 占位符替换，不修改执行模型。
- 不实现任务编辑、删除、归档（首期仅创建 + 列表展示）。
- 不实现跨任务批量操作。

---

## 4. 使用场景 / 用户路径

### 场景 A：新用户首次创建任务

1. 用户打开 ntd 前端，左侧导航看到「任务」。
2. 点击「任务」，看到「新建任务」表单。
3. 输入：「用 React + TypeScript 做一个便利贴应用，支持创建/编辑/删除、拖拽排序、颜色标签、本地存储。」
4. 点击「推荐模板」，系统返回推荐：superpowers-task（得分最高）。
5. 选择工作空间 `~/sticky-notes`。
6. 点击「创建任务」。
7. 系统自动：推荐/确认模板 → 安装为 Loop → 需求文本写入 `loops.description`。
8. 任务列表中新增一行：「便利贴应用 - superpowers-task - 2026-07-25」。
9. 用户点击进入 Loop Studio，enable 后执行。
10. Loop 的每个 step prompt 自动带入用户输入的需求。

### 场景 B：老用户明确知道用什么模板

1. 在任务创建页面，跳过推荐，直接从下拉列表选择「4p12s-delivery」。
2. 输入需求，选择工作空间，点击创建。
3. 与场景 A 相同的后续流程。

## 5. 功能需求清单

### 5.1 任务创建（F1）

- [ ] **F1.1** 前端新增任务创建表单：多行文本输入（需求描述）+ 工作空间选择器 + 模板选择器（可选）+ 创建按钮。
- [ ] **F1.2** 后端新增 `POST /api/v1/tasks`，接收 `{ requirement, workspace_id, template_name? }`。
- [ ] **F1.3** 未指定 `template_name` 时，调用现有推荐引擎（`recommender.rs`）自动选最高分模板。
- [ ] **F1.4** 创建成功后返回 `{ task_id(loop_id), template_name, phase_count, step_count }`。

### 5.2 任务列表（F2）

- [ ] **F2.1** 前端任务列表页展示已创建任务：名称、关联模板、复杂度标签、创建时间、Loop 状态。
- [ ] **F2.2** 数据来源：`SELECT * FROM loops WHERE process_template_id IS NOT NULL ORDER BY updated_at DESC`（任务 = 由工艺模板创建的 Loop）。
- [ ] **F2.3** 列表项可点击跳转到对应 Loop Studio 详情页。

### 5.3 需求注入（F3）

- [ ] **F3.1** 安装 Loop 时，将需求文本写入 `loops.description`。
- [ ] **F3.2** LoopRunner 执行时，已有 prompt 替换链增加一行：`.replace("{{requirement}}", &loop_.description)`。
- [ ] **F3.3** 现有工艺模板的 step prompt 尾部追加 `{{requirement}}` 占位符。

### 5.4 前端导航（F4）

- [ ] **F4.1** 左侧导航新增「任务」入口，与「事项」「回路」「工艺」并列。
- [ ] **F4.2** 点击跳转到独立的任务视图。
- [ ] **F4.3** 工艺模板创建的 Loop 在任务列表展示，手工创建的 Loop 不出现在任务列表。

## 6. 约束条件

### 技术约束

- 不新增数据库表。`loops` 表已有 `description`、`process_template_id`、`workspace_id` 等字段，直接复用。
- 推荐引擎已存在（`recommender.rs`），任务接口只需调用。
- LoopRunner 已有 prompt 替换链（`enhanced_prompt` 中的 `replace` 调用），增加一行即可。

### 架构约束

- 工艺模板与 Loop 关系不变：模板是只读定义，Loop 是可执行副本。
- Loop 执行模型不变：不新增执行路径或并发模型。
- 前端导入规范：跨目录使用 `@/` 绝对路径，新组件放 `frontend/src/components/tasks/`。

### 安全约束

- 任务创建 API 不增加新的权限校验（复用现有 workspace 校验逻辑）。
- 需求文本不做特殊 sanitize——prompt 替换是纯文本操作。

### 性能约束

- 任务列表 API 响应 < 500ms（单表查询 + ORDER BY + LIMIT）。

## 7. 可修改 / 不可修改项

- ❌ **不可修改**：
  - loops 表的已有字段语义（`description` 之前就是"循环描述"，语义一致）。
  - LoopRunner 的执行模型和并发机制。
  - 现有工艺库「浏览 → 安装」流程。

- ✅ **可调整**：
  - 任务视图的具体 UI 布局。
  - `{{requirement}}` 占位符在模板 prompt 中的位置。
  - 推荐引擎的权重参数。

## 8. 接口约定

### 8.1 POST /api/v1/tasks

```json
// 请求
{
  "requirement": "用 React + TypeScript 做一个便利贴应用...",
  "workspace_id": 1,
  "template_name": null
}

// 响应 201
{
  "code": 0,
  "data": {
    "task_id": 42,
    "loop_name": "superpowers-task",
    "template_name": "superpowers-task",
    "phase_count": 2,
    "step_count": 3
  }
}
```

### 8.2 GET /api/v1/tasks

```json
// 响应
{
  "code": 0,
  "data": [
    {
      "loop_id": 42,
      "name": "superpowers-task",
      "description": "用 React + TypeScript 做便利贴...",
      "template_name": "superpowers-task",
      "complexity": "light",
      "status": "paused",
      "created_at": "2026-07-25T10:00:00Z"
    }
  ]
}
```

## 9. 验收标准

- **AC1** 如果用户打开 ntd 前端，左侧能看到「任务」入口。
- **AC2** 如果用户输入需求描述并点击创建，则在 2 秒内创建 Loop 并出现在任务列表中。
- **AC3** 如果不指定模板，系统自动推荐得分最高的模板并安装。
- **AC4** 如果用户执行 Loop，则每个 step 的 prompt 包含用户输入的需求文本。
- **AC5** 手工创建的 Loop（无 `process_template_id`）不出现在任务列表中。
- **AC6** `cargo clippy --all-targets -- -D warnings` 零告警；`npx tsc --noEmit` 零错误。

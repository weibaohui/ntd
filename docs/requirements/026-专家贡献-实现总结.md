## 1. 实现了什么

为「专家」资源新增贡献通道：用户在专家 UI 点「分享」，填写 GitCode PAT（后端验证并持久化），随后通过 ActionButton 唤起 AI 执行器，由 AI 读取本地 PAT、调用 GitCode API 把专家打包为 PR 提交到官方仓库（`weibaohui/ntd-resource`）。

本次改动：**认证从 OAuth 改为 PAT**，且**提交从后端确定性 HTTP 调用改为 ActionButton + 提示词驱动**。

## 2. 与需求的对应关系

| 需求条目 | 实现 |
|---|---|
| PAT 保存与验证 | 后端 `POST /api/v1/contribution/pat`：`gitcode::verify_pat` 验证 PAT 有效性，`pat::save` 持久化（不存 username） |
| PAT 持久化（0600） | `contribution/pat.rs`：`PatCredential { pat }` 存 `~/.ntd/contribution_pat.json`，`Debug` 脱敏 |
| 登录态查询/退出 | `GET /auth/status`（`{configured}`）、`POST /logout` |
| ActionButton 驱动提交 | 前端 `ContributeButton` 复用 `ActionButton`，`contributePrompt.ts` 定义提示词模板，`params={expert_name, version, expert_dir}` |
| PAT 管理入口 | 设置页新增「第三方授权」Tab（`ThirdPartyPanel.tsx`，内嵌 GitCode 子 Tab）：PAT 填写/保存/清空（Popconfirm 二次确认）+ 配置态展示；分享按钮旁不再放置清除入口 |
| 未配置 PAT 引导 | `ContributeButton` 不再内嵌填写 Modal，点击分享未配置时提示并 `showView('settings', { tab: 'thirdParty' })` 跳转设置 |
| 移除 OAuth | 删除 `oauth.rs`、`build.rs` 凭据注入、`Makefile` 凭据加载、`gitcode.rs` 中授权/换 token/刷新逻辑 |
| 移除后端确定性提交 | 删除 `issue.rs`、`mod.rs::submit_pr`、`gitcode.rs` 中 fork/建分支/写文件/建 PR 确定性调用 |

## 3. 关键实现点

- **后端模块**：`contribution/` 现仅 `mod.rs`（模块声明）+ `gitcode.rs`（PAT 验证）+ `pat.rs`（持久化）；`handlers/contribution.rs` 保留 3 个路由。
- **PAT 安全**：`OpenOptions::mode(0o600)` 原子创建（消除 TOCTOU）；`PatCredential` 自定义 `Debug` 只显示 `[redacted]`；`auth/status` 只回传 `configured`；不落盘 username（账号身份由 AI 执行时用 `/user` 实时获取）。
- **提示词驱动**：`buildContributePrompt()` 指示 AI 从 `~/.ntd/contribution_pat.json` 读 PAT（不内联明文），`expert_dir` 用 `~/` 相对路径（不暴露家目录用户名），遍历专家目录（跳过 `.downloaded_at`/`.clawhub`/`.git`），按「验证用户 → fork → 建分支 → 写文件 → 建 PR」调 GitCode API，输出 `web_url`。
- **前端交互**：`ContributeButton` 点击查配置态，未配置跳转「设置 → 第三方授权 → GitCode」引导填写，已配置切 `ActionButton`（`actionType="expert_contribute"`、`actionKey=专家名`）。
- **第三方授权面板**：`ThirdPartyPanel.tsx` 内嵌 Tabs（GitCode 为首个），PAT 表单含密码框填写、保存（后端验证后落盘）、清空（`Popconfirm` 二次确认，未配置禁用）；配置态由 `auth/status` 驱动，保存/清空后刷新。

## 4. 已知限制与待改进点

- **PAT 外泄风险**（本方案核心权衡）：AI 执行器读取并使用 PAT 时，PAT 会进入执行器工具调用（`curl` 的 `Authorization` 头）与 LLM 上下文，存在外发到第三方 LLM 的风险。已通过「不内联提示词 + 提示词要求不回显 + 0600 文件」缓解，但无法完全消除。
- **AI 执行不确定性**：目录遍历、base64 编码、分支名生成、错误处理依赖 AI 正确执行提示词，可能偏离（如误提交 `.git`）；由维护者 review 兜底。
- **配置后需再点一次**：PAT 保存成功后需再点「分享」（ActionButton 按钮）才打开提交 Drawer。

## 5. 测试与验证

- 后端：`cargo clippy --all-targets -- -D warnings` 零告警；`cargo test --lib contribution` 8 个单测通过（PAT save/load 往返、缺失文件、Debug 脱敏、写后收紧 0600、truncate_for_log、validate_pat 三种场景）。
- 前端：`npx tsc --noEmit` 零错误。
- 全量 `cargo test`：1681 passed，5 failed —— 均为 `executor_service::pre_spawn` / `wiki::fs` 的 `PermissionDenied` 环境问题（与历史实现总结记录一致，非本次改动引入）。
- GitCode API 连通性：已用真实 PAT 实测 `GET /api/v5/user`、fork、建分支、写文件、建 PR 全链路均成功（PR #2 已关闭、测试分支已清理）。

## 6. 安全反思

- **PAT 存储**：本地 `~/.ntd/contribution_pat.json` 0600，`Debug` 脱敏，日志不打印，`auth/status` 不回传 —— 无明文外泄。
- **PAT 传递**：不内联进提示词模板，避免落库 `todo.prompt`/执行记录；但 AI 执行时 PAT 仍会进入 LLM 上下文 —— 这是「AI 直接用 PAT」方案的本质风险，已明确记录并告知。
- **输入校验**：`save_pat` 校验 PAT 非空 + 远程验证有效性；无 SQL 注入/XSS 面（PAT 仅作为 Bearer token 传递，不拼接 SQL/HTML）。
- **越权**：PAT 为用户自持，AI 以用户身份操作其 fork 与官方 PR，无提权面；PR 合入权在维护者。
- **路径逃逸**：原后端 `collect_expert_files` 的 `resolve_within`/符号链接防护已随确定性提交移除，目录遍历改由 AI 执行（提示词约束跳过元数据），风险由维护者 review 兜底。

## 8. 本次增强：分享仅限用户自定义专家（2026-08-14）

**背景**：分享入口原来对所有专家开放，系统/模板来源专家（从官方仓库同步到 `~/.ntd/bundled/experts/`）也能点「分享」，AI 执行器会把系统专家原样打包提 PR 回官方仓库。系统专家是只读资源，用户不能修改，也就不应分享。

**改动**（纯前端，无后端接口变化）：

- `ContributeButton.tsx`：组件顶部加来源守卫——`expert.source !== 'user'` 直接返回 null 不渲染。「专家」页详情 Modal 与「专家模板」Tab 行操作两处入口复用同一组件，守卫自动同时生效。
- `ExpertCard.tsx` / `TeamCard.tsx`：卡片头部增加「系统/用户」来源小标签（蓝=系统、绿=用户，与模板管理 Tab 配色一致）；根节点带 `data-source={expert.source}` 供 Playwright 按来源定位卡片。
- `ExpertDetailModal.tsx`：详情头部类型标签旁增加来源标签，让系统专家详情里分享按钮的缺失自解释。
- `frontend/tests/026-expert-contribution.spec.ts`：端到端用例改为点 `[data-source="user"]` 卡片（原「第一张卡片」可能命中系统专家，分享按钮不存在导致用例失败）；新增用例断言系统专家详情 Modal 无「分享」按钮。
- `ExpertsPanel.tsx`：搜索栏新增来源筛选 `Segmented`（全部/我的/内置，值 `'all'/'user'/'system'`），`filteredExperts` 先按来源过滤、再叠加关键词搜索（AND），「专家/团队」两个 Tab 计数同步刷新；默认「全部」保持原行为。
- `frontend/tests/check_expert_source_filter.spec.ts`：新增来源筛选用例（默认全部两类卡片可见；「我的/内置」互斥过滤；可切回全部）。

**测试验证**：`npx tsc --noEmit` 零错误；Playwright 026 用例 4 个全部通过（提示词模板纯函数 + 用户专家分享端到端 + 系统专家无分享 + 第三方授权 PAT 表单）；新增来源筛选用例 1 个通过；专家卡片布局用例 2 个通过。

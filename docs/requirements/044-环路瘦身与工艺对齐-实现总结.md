## 1. 实现了什么

环路（Loop）从「独立功能」降级为「工艺的运行时承载」，YAML 成为唯一定义来源，手工创建/编辑/触发/导入导出等双轨入口整体下线。

### R1 定位收敛（只读化）
- 删除 `LoopFormModal.tsx`（新建/编辑弹窗）及其在 `App.tsx` 的挂载与 `loopCreateModalOpen` 状态。
- 环路详情面板（`LoopStudioDetailPanel`）只读化：移除触发/复制/导出/编辑按钮、Webhook 字段、触发条件折叠区、基础信息编辑弹窗；仅保留删除（`LoopDetailActions` 收敛为单删除按钮）与启停 Switch。
- 环节面板（`LoopStudioStepsPanel`）改只读：移除新增/编辑/删除/排序交互，`LoopFlowGraph`/`FlowStepNode` 的 `onAddStep`/`onSelectStep` 变为可选，只读模式不渲染「添加环节」入口。

### R2 执行入口收敛
- 删除 `components/loop-studio/triggers/` 整个目录（Cron/Webhook/飞书/标签/事项等 ConfigForm）。
- 后端：v0 路由组 `loop_routes()` 整组删除（原本已无挂载点）；v1 路由裁剪，删除 create/update/duplicate/trigger、触发器 CRUD、环节 CRUD/重排、import/export/merge、旧评分制 `approve_step_execution`。
- 后端：删除 `services/loop_scheduler.rs`（cron 调度器）及其 AppState 字段与初始化；`loop_trigger.rs` 裁剪为仅保留任务创建使用的 `dispatch_manual*`；移除 `handlers/webhook.rs` 的 loop webhook 路由、`handlers/todo.rs` 的 `tag_added` 派发。
- 唯一执行入口仍为「创建任务选工艺环路」（`CreateTaskModal`，未改动）。

### R3 导入导出删除
- 前端：删除 `settings/backup/LoopBackupTab.tsx` 与备份面板的「环路备份」Tab；`utils/database/loops.ts` 删除 export/import/merge/duplicate 等客户端方法；`utils/database/backup.ts` 删除 `mergeLoops`。
- 后端：删除 import/preview/export/merge 相关 handler、DAO 与 `LoopExport*`/`LoopImport*` 类型。

### R4 数据库对齐（迁移 v80，`db/migration/v80.rs`）
- 4.1 单事务级联删除 `process_template_id IS NULL` 的手工环路（gates → artifacts → step_executions → phase_executions → executions → triggers → tags → steps → phases → loops，删除前日志输出 id+name 清单）。
- 4.2 结构变更：`DROP TABLE loop_triggers`；`loops` 删 `webhook_enabled/review_template_id/color/icon`；`loop_steps` 删 `min_rating/unrated_policy/run_mode/skip_on_source_failed`。
- **额外必要修复**（设计 4.2 未列、实施时发现）：v41 建表时 `loop_executions` 带 `FOREIGN KEY (trigger_id) REFERENCES loop_triggers`，删表后外键悬空，`foreign_keys=ON` 下任何 INSERT 报 `no such table: loop_triggers`。v80 在删 `loop_triggers` 前先在**单事务**内重建 `loop_executions` 去掉该外键（`trigger_id` 作为历史列保留）；单事务是为了让 DROP 旧表 → RENAME 新表在同一连接顺序执行（跨连接池连接时 WAL 快照会让 RENAME 误判「同名表已存在」）。

### 审批切门禁制（设计 2.2）
- 前端 `StepExecList.tsx`：旧评分制 `approveStepExecution` → 门禁制 `bundledApi.approveGate`（通过/拒绝二选一）。
- 后端 `LoopStepExecutionDto` 新增 `pending_gate_id`，由 `get_execution_v1`/`list_executions_v1` 在环节 `pending_approval` 时查 `human_approval` pending 门禁注入；前端凭此 id 直接调门禁审批接口，无需再查审计接口。

### 旧评分闸门清理（设计 3.2）
- `loop_runner.rs` 删除 `apply_rating_gate` 及 `min_rating`/`unrated_policy` 分支；`gate_evaluator.rs` 删除 `infer_gates_from_fallback`（从 min_rating 推断门禁的兼容分支）；`phase_driver.rs` 改为直接读 `gate_config`。
- `installer.rs` 不再写已删列；`create_loop`/`create_loop_step`/`update_loop`/`create_loop_step_execution` 等 DAO 签名同步收敛。

### onboarding 概念同步
- 概念导航删除「触发器」节点/边/类型表，环路概念字段去掉触发器；快速开始由 5 步收敛为 4 步（移除「配置触发器」），`useConceptCounts` 同步。

## 3. 验证结果

- 后端：`cargo clippy --all-targets -- -D warnings` 零告警；`cargo test` 全绿（lib 1476 + 集成/其他全通过）。
- 前端：`npx tsc --noEmit` 零错误；环路相关 vitest 26 项全通过。
- 迁移 v80：在 `:memory:` 与文件库（WAL）上均验证通过；级联删除前日志留痕、单事务失败整体回滚。

## 4. 关键实现点

- **迁移顺序**：重建 `loop_executions`（去外键）→ 级联删手工环路 → DROP `loop_triggers` → 删 loops/loop_steps 列。先清数据再动结构，且重建表必须在单事务内跨同连接完成。
- **审批门禁 id 下推**：后端在 execution 详情里直接注入 `pending_gate_id`，前端零额外查询完成审批，避免与 `ProcessExecutionBoard` 的审计接口重复。
- **历史快照保留**：`loop_step_executions.min_rating/rating/unrated_policy` 列保留（历史执行记录不可变），仅 `loop_steps`（定义层）删除；前端类型同步标注为历史快照。

## 5. 已知限制 / 待改进

- **飞书/webhook 机器人**：loop webhook 端点删除后，外部若仍推送将返回 404（设计 6 已注明为预期行为）。
- **环路级评审模板**：`loops.review_template_id` 下线后，统一评审路径不再有「环路级模板」回退，仅走「环节内联 review_prompt → 默认」（评审已归环节，需求 033/036）。
- **`getExecutionById` 前端调用**（`/api/v1/workspaces/{ws}/loop-executions/{eid}`）：该路由历史上仅在已删除的 v0 组中注册，v1 未挂载，属迁移前既有的断链，本次未扩展（不在 044 范围）。
- UI 端到端验证（agent-browser）与 PR 提交待用户授权后进行；本次完成编译/单测/迁移层面的全部验证。

## 1. 实现了什么

在概念导航首页（`/#/onboarding`）的概念关系图中新增「黑板」「看板」两个支线小圆节点，补齐「定义 → 执行 → **观察**」概念地图：

- **黑板**（900, 60）：`事项→黑板（持续分析）`、`执行记录→黑板（持续分析）`、`环路→黑板（环节结论）` 三条连线；点击弹 Drawer 展示含环节小黑板三层语义的说明 + 「去黑板页」按钮跳转 `/#/blackboard`
- **看板**（960, 340）：`执行记录→看板（进度展示）` 连线；点击弹 Drawer + 「去看板页」按钮跳转 `/#/memorial?mode=kanban`
- hover 双向高亮：黑板 ↔ 事项/执行记录/环路；看板 ↔ 执行记录；hover 执行记录时两者同亮
- 既有 fallback 节点（触发器/技能/模型/执行记录）行为逐字不回归

## 3. 关键实现点

1. **渲染零改动**：节点圆/连线/hover/动画全部数据驱动，新增节点只改 `concepts.tsx` 数据；组件层唯一改动是 fallback Drawer（文案 + 按钮）
2. **数据驱动的跳转能力**：`GraphNode` 挂 `navTarget/navMode` 可选字段而非 `if id===` 硬编码分支，未来任何支线节点加跳转只改数据
3. **跳转走 `useViewState().pushUrl`**（028 既定嵌套实例模式），自动广播 `ntd-nav-change` 全站同步；先关 Drawer 再跳转避免遮罩残留
4. **坐标几何验证**：黑板与执行记录同列（垂直短边），看板与模型保持 100 圆心距（=专家↔模型既有节奏），`环路→黑板` 长连线经验证不穿过任何第三方节点圆
5. **环境受限下的 Playwright 落地**：cdn.playwright.dev 被网络阻断，改从 npmmirror 手动下载 CFT 147.0.7727.15（chrome + headless-shell）并按注册表布局到 `~/.cache/ms-playwright/chromium-1217` / `chromium_headless_shell-1217`

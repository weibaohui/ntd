# 027-资源贡献扩展-实现总结

| 修改人 | 修改时间 | 修改内容 |
|--------|---------|---------|
| AI | 2026-08-14 | 初始版本：专家贡献（026）扩展到事项模板 / 技能 / 工艺三类资源 |

---

## 1. 实现了什么

把 026「专家贡献」的「分享到官方仓库」通道扩展到 **事项模板 / 技能 / 工艺** 三类资源：复用 026 的 PAT 管理（设置→第三方授权→GitCode）与 ActionButton + AI 提示词驱动提交 PR 机制，分享入口与专家模板 Tab 一致放在各资源列表行操作区。

## 2. 与需求的对应关系

| 需求条目 | 实现 |
|---|---|
| 事项模板分享（仅用户模板 is_system=false） | `TodoTemplatesTab.tsx` 行操作区加 `ShareToRepoButton`（仅用户行渲染）；点击时经 `onPrepare` 调后端导出接口，把 DB 模板落盘为 YAML |
| 工艺分享（仅用户工艺 is_system=false） | `ProcessTemplatesTab.tsx` 行操作区加 `ShareToRepoButton`（仅用户行渲染）；提交 `~/.ntd/processes/{name}.yaml` 到远端 `processes/{category}/` |
| 技能分享（全量可分享，不区分来源） | `SkillTemplatesTab.tsx` 新增操作列，所有行渲染 `ShareToRepoButton`；提交 `~/.ntd/bundled/skills/{source}/{skill}/` 到远端 `skills/{source}/{skill}/` |
| 后端导出接口 | `GET /api/v1/todo-templates/:id/export`：仅用户模板可导出，YAML 字段（title/category/prompt/sort_order）与远端对齐，写入 `~/.ntd/contribution-export/todos/{safe_title}.yaml`，返回 ~ 相对路径 |
| 分享入口一致性 | 三类 Tab 均复用 `ShareToRepoButton`（从专家 `ContributeButton` 抽取的通用组件），交互与专家完全一致 |
| 提示词按资源类型区分 | `settings/contribute/contributePrompts.ts` 提供工艺/事项模板/技能三份模板（占位符 `{{resource_name}}/{{version}}/{{resource_dir}}/{{remote_path}}`），公共步骤（PAT 读取、GitCode API、安全约束）抽公共模板 |

## 3. 关键实现点

- **通用分享按钮** `settings/contribute/ShareToRepoButton.tsx`：从专家 `ContributeButton` 抽取（PAT 检查 → 未配置跳设置 / 已配置切 ActionButton）；props 含 `params`（提示词占位符）、`buildPrompt`、`onPrepare`（点击后先准备文件，返回的键值合并进 params）。专家 `ContributeButton` 改为其薄封装，对外接口不变，026 用例与调用点零改动。
- **事项模板导出**：模板存 DB、AI 执行器只能读文件，故后端新增导出接口；导出目录独立于 bundled 与用户目录（`~/.ntd/contribution-export/`），文件名经安全化（非法字符替换为下划线、`..` 兜底 `template`）防路径逃逸；前端 `exportTodoTemplateYaml` 取返回路径末段作为远端 `todos/` 文件名。
- **技能全量可分享**：用户明确要求不区分来源，`SkillTemplatesTab` 所有行渲染分享；技能目录天然是 `~/.ntd/bundled/skills/{source}/{skill}`（~ 相对），远端路径保持来源集合结构。

## 4. 测试与验证

- 后端：`cargo clippy --all-targets -- -D warnings` 零告警；`cargo test --lib todo_template` 5 个单测通过（sanitize 三类场景 + write 文件生成与字段对齐）。
- 前端：`npx tsc --noEmit` 零错误；`npm run build` 成功。
- Playwright：`027-resource-contribute.spec.ts` 3 个用例通过（事项模板用户行分享 → 导出 YAML → Drawer 提示词含 `todos/` 与导出路径；工艺用户行有分享/系统行无；技能全量有分享）；专家 026 4 用例 + 卡片布局 2 + 来源筛选 1 回归通过（通用化未破坏专家功能）。
- **Review 修复（P2）**：① 工艺分享增加 `record.source_path` 非空守卫（空值不渲染，避免空路径给 AI 执行器）；② 026/027 的「PAT 已配置」态从写真实 `~/.ntd/contribution_pat.json` 改为 `page.route` 拦截 `auth/status` 返回 `configured:true`——不再污染用户凭据，并消除两个 spec 并行运行时互相覆盖/还原同一 PAT 文件的竞态（两文件已实测并行跑通）。

## 5. 安全反思

- **路径逃逸**：导出文件名经 `sanitize_template_filename` 处理（仅保留字母/数字/下划线/连字符，其余替换为 `_`，空则兜底 `template`），`..`/`/` 无法构造越界路径；导出目录固定 `~/.ntd/contribution-export/todos/`。
- **越权**：系统模板（`is_system=true`）导出被拒绝，与 update/delete 守卫一致；分享提交的是用户可修改的资源。
- **PAT**：沿用 026（0600、Debug 脱敏、不内联提示词、AI 输出不回显明文）。

## 5.1 UI 调整（用户反馈）

- **操作列前置**：模板管理 4 个子 Tab（专家/事项模板/Skill/工艺）的表格「操作」列统一移到第一列，操作入口前置便于定位。
- **来源说明 Alert**：将工艺 Tab 的「系统/用户双图层级说明」Alert 推广到其余 3 个 Tab——专家（系统专家来自远程同步会被覆盖；用户专家在 ~/.ntd/experts/ 不会被覆盖）、事项模板（系统模板会被覆盖；用户模板不会被覆盖）、技能（全部来自远程同步，全量可分享）。
- 专家模板 Tab 根节点补 `className="expert-templates-tab"`，与其余三个子 Tab 一致（便于测试定位）。

## 6. 已知限制

- **技能分享覆盖范围**：入口覆盖 bundled 技能列表（`~/.ntd/bundled/skills/`）；用户自行编写、仅存在于执行器目录（如 `~/.claude/skills/`）的技能不在本列表，不单独处理（用户确认全量可分享针对现有技能列表）。
- **工艺分类映射**：远端 `processes/` 有分类子目录，用户工艺按 `category` 字段放对应子目录，无匹配分类时放根目录兜底。
- **事项模板同名覆盖**：导出同名文件直接覆盖，提示词引导 AI 提交最新文件。

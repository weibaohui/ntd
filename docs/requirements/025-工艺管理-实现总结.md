## 1. 实现了什么

M1 完成「工艺管理」的基础骨架：工艺模板市场、模板安装为 Loop、阶段（Phase）建模、产物与门禁配置落库、返工计数落库，以及前端工艺库页面与 Loop Studio 阶段色带。

本期不包含运行时产物捕获、门禁引擎执行、repair-log/delivery-state 自动维护 —— 这些留到 M2 在 LoopRunner 中接入 `phase_driver`。

## 3. 关键实现点

### 3.1 V71 迁移幂等性

`v71.rs` 所有 `CREATE TABLE` 使用 `IF NOT EXISTS`，所有 `ALTER TABLE ADD COLUMN` 通过 `add_column_if_missing` 探测后再执行，保证重复执行不报错。 Fresh DB 与已部署 DB 都能安全升级到 schema 71。

### 3.2 模板实例化：快照语义

`loops` 表新增 `process_template_id` 与 `process_template_version`。安装时记录模板版本快照；模板后续更新不影响已安装 Loop，保证审计链完整。

### 3.3 安装流程：两趟解析

`installer.rs` 安装流程：

1. 解析 YAML 为 `ProcessDefinition`。
2. 创建 Loop（带模板来源与版本）。
3. 创建 Phase。
4. 第一遍：为每个 link 创建 todo + loop_step，`goto` 目标暂空。
5. 第二遍：解析 `on_success` / `on_gate_fail`（fallback `on_rating_fail`），把模板 link id 映射到真实 `loop_step.id`。

### 3.4 阶段在 Loop Studio 的可视化

`LoopStepDto` / `LoopStepRawDto` 新增 `phase_id`。`LoopFlowGraph` 在环节节点左侧绘制 6px 色带，颜色由 `phase_id` 哈希取自固定色板，同阶段颜色稳定。

### 3.5 bundled 导入兼容两种 YAML

`import_process_templates_from_bundled` 扫描 `bundled/processes/**/*.yaml`：

- 顶层 key 为 `process:` → 工艺模板
- 顶层 key 为 `step_template:` → 环节原型

失败单条记录 warning，不阻断整体同步。

### 3.6 内置模板

提交到仓库的 `bundled-repo/processes/` 包含：

- `software/4p12s-delivery.yaml`：标准需求交付工艺（4 阶 12 步裁剪版）
- `software/superpowers-task.yaml`：轻量任务工艺
- `software/oral-requirement.yaml`：口头需求工艺
- `step-templates/*.yaml`：8 个可复用环节原型

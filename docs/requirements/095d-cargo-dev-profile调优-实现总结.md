> 093 专项性能类第 4 项。改动极小（3 行配置），设计与总结合并为一份。

## 1. 改动

`backend/Cargo.toml` 新增：

```toml
[profile.dev.package."*"]
opt-level = 1
```

依赖包开 1 级优化；本 crate 保持 `opt-level=0`（增量迭代编译路径不受影响）。

## 2. 实测数据

| 指标 | 改前（依赖 opt-level=0） | 改后（依赖 opt-level=1） |
|------|--------------------------|--------------------------|
| `cargo test --lib` 运行时间 | 29.99s | **13.11s（2.3 倍提升）** |
| 首次依赖全量重编 | — | 3m14s（一次性成本） |
| 本 crate 增量编译 | 不变（opt-level=0） | 不变 |

## 3. 原理与取舍

- 收益来源：serde/tokio/axum 等依赖在 opt-level=0 下运行效率低，JSON 密集的测试
  套件（1600+ 用例大量序列化/反序列化）收益最大；dev 实例的 API 响应同理改善；
- 代价：依赖变更后首次重编略慢（一次性）；panic 栈部分内联可读性略降；
- 不选 opt-level=2：编译成本再上台阶，运行收益边际递减（1 级已拿到大头）。

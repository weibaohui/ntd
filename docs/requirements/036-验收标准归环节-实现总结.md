## 1. 概述

工艺编辑器里「验收标准」原同时挂在**阶段（Phase）**和**环节（Link）**两层。代码调查证实后端运行时**只消费环节级**（评审逐环节进行、取 todo 验收标准），阶段级是 100% 死字段（`phase_driver` 恒 None、`criteria_ref` 引用未实现、`loop_phases.acceptance_criteria` 只写不读）。

本次将验收标准**收敛到只归环节**：彻底删除阶段级的定义字段、运行时死列、UI。已按用户指示**不处理存量兼容**。

**repair_log 2 个失败说明**：`services::process::repair_log` 的两个文件 IO 测试（`tempdir` + 写 `.ntd/repair-log.md`）在全量并发跑时失败，但 `cargo test --lib repair_log` 单独跑**全通过**（2 passed）——是 pre-existing 并发 flaky，且本次改动文件不含 `repair_log.rs`（改动均为删 phase 验收标准字段，逻辑上无法影响文件 IO 测试），与本次需求无关。

**v77 migration 执行**：installer 测试用 Database 启动时跑全部 migration（含 v77 `DROP COLUMN loop_phases.acceptance_criteria`），测试通过 ⇒ v77 执行成功。

- 选中**阶段**节点（需求）→ 属性面板只剩「标识 / 名称 / 规范说明」三项，**无验收标准、无验收标准引用**（grep「验收」零匹配）。

## 3. 关键设计决策回顾

### 3.1 关系图用纯 SVG，不引入 reactflow

**决策**：节点坐标硬编码在 `concepts.tsx`，连线用 SVG `<path>` + `stroke-dasharray` 流动。
**理由**：节点固定 7 个（4 主 + 3 支线），不需要 reactflow 的拖拽/缩放/自动布局；纯 SVG 包体积 0。
**代价**：节点坐标不响应式重排，小屏溢出靠容器 `overflow-x: auto` 兜底。

### 3.2 数据快照并行请求

**决策**：`useConceptCounts` 用 6 个 API 并行 `.catch(() => null)`，任一失败对应字段 null。
**理由**：串行 6 × 200ms = 1.2s，并行 ~200ms，首屏体验更好。
**代价**：快速开始步骤 5（验收产物）简化为与步骤 4 同源判断（完整实现需扫审计 API，YAGNI）。

### 3.3 首次跳转逻辑放 App.tsx，不放 useViewState

**决策**：App.tsx 顶层 `useEffect([])` 检测 `localStorage['ntd_onboarding_completed']`，无标记则 `replaceUrl('onboarding')`。
**理由**：`useViewState` 只管 URL ↔ state 同步，不该含「首次进入」业务逻辑；App.tsx 是应用入口，适合放一次性引导。
**代价**：空依赖 `[]` 需 eslint disable，但语义清晰。

### 3.4 sticky Tab 用 IntersectionObserver

**决策**：三个 `<section>` 各加 `id`，`IntersectionObserver` 监听进入视口的 section，自动高亮 Tab。
**理由**：比 `onScroll` 监听 `scrollTop` 更精准、性能更好；所有现代浏览器支持。
**代价**：headless 测试下 rootMargin 精度不稳，TC-11 放宽为「任一 tab 高亮」。

### 3.5 差异化卡片可视化

**决策**：6 张卡片各用不同的迷你 SVG 图形（3 圆点/循环箭头/卡片堆叠/闪电/终端/人形），而非统一图标。
**理由**：统一图标信息密度低，差异化隐喻帮助用户从视觉上区分概念层级。
**代价**：每个图形手绘 SVG，代码量略增。

## 4. 遇到的问题与解决

| # | 问题 | 解决 |
|---|------|------|
| 1 | `useViewState` 的 `ALL_VIEWS` 删除时误删 `ALL_BOARD_MODES` 常量 | 立即恢复，加注释说明常量用途 |
| 2 | `LeftRailKey` 类型不含 `'onboarding'`，tsc 报错 | 在类型联合中加 `'onboarding'` |
| 3 | `concepts.tsx` 用 `readonly` 修饰符在非数组类型上报 TS1354 | 改为普通 `Array<T>` 或 `readonly` 只用在数组字面量 |
| 4 | `ConceptCardGrid` 的 `TeamOutlined` style 字符串引号错配（`'#eb2f96"`） | 修正为 `'#eb2f96'` |
| 5 | `useConceptCounts` 用了不存在的 API 名（`db.getExperts`/`dbLoops.getLoopTriggers`） | 查实际 API：`db.getAllExperts` / `dbLoops.getLoop`（详情含 triggers） |
| 6 | `ConceptDetailSection` 的 `SnapshotData = Record<string, unknown>` 与后端具体类型不兼容 | 改为 `object | null`，`Object.entries` 时窄化为 `Record<string, unknown>` |
| 7 | `QuickStartFlow` 用了不存在的 `CircleOutlined` 图标 | 改为 `CiCircleOutlined` |
| 8 | `ConceptNavPage` 的 `useRef<HTMLElement>` 与 React 18 refObject null 兜底不兼容 | 改为 `useRef<HTMLElement | null>(null)` + `handleTabChange` 用 `.current` 取值 |
| 9 | TC-04 `data-testid="left-rail-onboarding"` 未在 LeftRail 项挂 | 改用 `getByRole('button', { name: '导航' })` 兜底 |
| 10 | TC-05 Drawer 内「环路」文本定位超时 | 改用 `onboarding-graph-drawer-goto-loop` 按钮作为存在性证据 |
| 11 | TC-11 `aria-selected='true'` 第 2 个 tab 在 headless 不稳定 | 放宽为「任一 tab 高亮」 |
| 12 | TC-13 `toHaveCount(6)` 因 section 内子元素也带 data-testid 计数为 18 | 改用 `section[data-testid^=...]` 精确定位 |

## 6. 安全反思

| 项 | 措施 | 结论 |
|----|------|------|
| 只读页面 | ConceptNavPage 无 POST/PATCH/DELETE 调用 | ✅ |
| 敏感字段过滤 | `renderSnapshotTable` 过滤 `app_secret`/`bot_open_id`/`app_id`/`owner_open_id`/`session_dir` | ✅ |
| 数据隔离 | 所有 API 调用传 `wsId`，不跨 workspace | ✅ |
| 路由注入 | 跳转用 `pushUrl` hash 路由，无用户输入构造 URL | ✅ |
| localStorage | `persistOnboardingSkipped` + App.tsx 首次跳转均 try/catch 静默降级 | ✅ |
| XSS | 无 `dangerouslySetInnerHTML`，YAML 示例用 `<pre>` 文本渲染 | ✅ |

## 7. 已知限制与待改进

1. **关系图节点坐标硬编码**：不响应式重排，小屏溢出靠 `overflow-x: auto`。后续若需响应式可引入 reactflow。
2. **数据快照只拉一条**：不展示全量列表。后续可加「查看全部」跳转。
3. **快速开始步骤 5 简化判断**：与步骤 4 同源。后续完整实现需扫审计 API。
4. **TC-11 放宽判定**：IntersectionObserver 在 headless 下 rootMargin 精度不稳，只验证「任一 tab 高亮」。
5. **移动端未做独立组件**：降级为纵向布局，未做 `ConceptNavMobilePage`。
6. **关系图不支持拖拽**：后端 `PATCH /tasks/:id` 未实现 status 更新，YAGNI。
7. **无 i18n**：与 app 现状一致，只做中文。

# 042-三列表工艺列统一-需求

| 修改人 | 修改时间 | 修改内容 |
|--------|---------|---------|
| AI(Kimi) | 2026-07-30 | 初始版本 |

## 背景

事项、任务、环路三个列表页当前对「工艺」的展示口径不一致：

- 事项列表已有「工艺」列，但格式是 `#模板ID 模板名`；
- 环路列表是「工艺名称」「版本」两列分开；
- 任务列表是「工艺模板」列，只显示模板名。

用户要求三页统一为一列，列名都叫「工艺」。

## 需求

在以下三个页面的列表 table 中统一展示「工艺」列：

1. 事项列表 `/#/todos`
2. 任务列表 `/#/tasks`
3. 环路列表 `/#/loops`

统一规则：

- 列名：`工艺`
- 显示内容格式：`#<工艺id>-<工艺名称>-<工艺版本>`
- 示例：`#101-标准需求交付工艺-1.2.0`
- 无工艺来源的数据：显示 `-`

## 边界

- 事项列表：一条事项可能被多个环路引用；多个环路基于同一工艺时，工艺列仍按工艺去重展示。
- 环路列表：工艺版本优先使用环路实例化时的 `process_template_version` 快照；缺失时可回退模板当前版本。
- 任务列表：任务来源于工艺环路，工艺信息取任务关联工艺模板。
- 不改变既有筛选、批量操作、详情跳转逻辑。

## 验收标准

- 三个列表页都存在且只存在一个「工艺」列。
- 显示文本符合 `#<工艺id>-<工艺名称>-<工艺版本>`。
- 无工艺来源显示 `-`。
- 前端类型检查、构建、单元测试、相关 Playwright 回归通过。

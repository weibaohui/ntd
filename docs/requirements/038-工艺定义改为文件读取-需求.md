# 需求：工艺定义不再落库，改为从文件读取（038）

## 1. 背景与问题

当前 `process_templates` 表除存储工艺的元数据（name / display_name / version / source_path 等）外，
还冗余存储了 `definition` 字段——即工艺 YAML 定义的**完整正文**（`backend/src/db/entity/process_templates.rs:24-26`）。

这份正文与磁盘上的 YAML 源文件内容完全重复：

- 系统工艺：`~/.ntd/bundled/processes/**/*.yaml`（由 git 同步拉取）
- 用户工艺：`~/.ntd/processes/**/*.yaml`

导入流程（`import_process_templates_from_bundled`、`import_user_process_templates`）在扫描磁盘文件后，
把正文**再写一份进 DB**，造成"同一份内容两份存储"。用户明确希望：

> 不要从 DB 存内容，只存一个路径引用，真正的内容总是从文件读取。

即：**磁盘是工艺定义的唯一真源，DB 只做索引/外键锚点，不再持有定义正文。**

## 2. 目标

1. `process_templates` 表删除 `definition` 列，内容不再入库。
2. 所有需要工艺正文的地方，统一通过 `source_path`（如 `bundled://processes/software/x.yaml`、`user://software/x.yaml`）
   解析到磁盘文件并实时读取。
3. 保持 `loops.process_template_id` 外键不变（DB 的 `id` 仍作为已安装 Loop 的稳定引用锚点）。
4. 保留轻量元数据字段（display_name / description / category / complexity / version），
   仅删除大文本 `definition`，列表/统计/推荐性能不受影响。

## 3. 边界与非目标

- **非目标**：不删除 `process_templates` 表，不把 `loops` 外键改为按 name 引用（那是更大的重构，见限制）。
- **保留**：`source_path` 作为文件引用；`id` 作为外键锚点；元数据字段。
- **一致性**：DB 始终是磁盘的忠实镜像（导入时只增改、系统层先删后插）；本需求聚焦"去重正文"。

## 4. 验收标准

1. 启动后 `process_templates` 表无 `definition` 列；旧库升级经迁移自动删列。
2. 工艺详情接口（`GET /api/v1/bundled/processes/{name}`）返回的 `definition` 与磁盘 YAML 文件内容一致。
3. 安装工艺为 Loop、复制到用户层、版本 diff 等功能行为不变，数据均来自文件。
4. `cargo clippy --all-targets -- -D warnings` 零告警；`cargo test` 全绿。

## 5. 已知限制 / 待改进

- 当前导入按 `name` 唯一键 upsert，**不保留版本历史**（v72 已加 `previous_version_id` 列但未启用），
  因此 `get_process_versions` / `diff_process_versions` 实际只返回当前版本。本需求不改变该现状。
- 彻底移除 `process_templates` 表、把 `loops` 外键改为按 `name(+version)` 引用，属于更大重构，
  不在本需求范围，后续单独评估。

## 2. M1 后端 API（commit a14da299）

### 2.1 实现内容

新增 3 个 API，对应需求 §3.1：

| 方法 | 路径 | 说明 |
|------|------|------|
| PUT | `/api/v1/processes/{name}` | 保存编辑后的用户工艺 YAML |
| POST | `/api/v1/processes` | 新建用户工艺 |
| DELETE | `/api/v1/processes/{name}` | 删除用户工艺 |

### 2.2 改动文件

- `backend/src/handlers/errors.rs`：`AppError` 新增 `Conflict(String)` 变体，映射 409
- `backend/src/models/mod.rs`：codes 新增 `CONFLICT=40901`
- `backend/src/db/process_template.rs`：新增 `delete_process_template` 方法
- `backend/src/handlers/process.rs`：新增 3 个 handler + helper 函数 + 13 个单元测试
- `backend/src/services/blackboard.rs`：match `AppError` 补 `Conflict` 分支

### 2.3 处理流程

每个 handler 3-4 步职责单一：
1. `validate_process_name` 路径注入防御
2. `is_system` 校验（系统工艺拒绝编辑/删除，409）
3. `serde_yaml` 结构校验（失败 400）
4. 原子写盘 + `import_user_process_templates` 刷新入库
5. DELETE 额外查询实例 Loop，非空则 409 + 数量

### 4.3 关键决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| Monaco 加载策略 | `loader.config({ monaco: MonacoNamespace })` 注入本地 monaco-editor | 离线可用 + 版本锁定，避免 CDN 依赖 |
| 错误标记 | `deltaDecorations` API 在行号槽标红波浪线 | Monaco 原生支持，覆盖 90% 场景 |
| 主题跟随 | 父组件传入 `theme: 'dark' \| 'light'`，映射 `vs-dark`/`vs` | 避免组件内重复 `useTheme` hook |
| 错误标记 CSS | 内联 `<style>` 注入 | 避免新增全局 CSS 文件 |
| YAML schema | `yaml.DEFAULT_SCHEMA`（JSON 兼容） | 工艺 YAML 只用基本类型；`DEFAULT_FULL_SCHEMA` 允许 `!!js/func` 不安全类型，且 @types/js-yaml 4.x 已移除该常量 |

### 4.4 系统工艺防护（三重）

1. Monaco `readOnly: true`
2. 顶部黄色 Alert "这是系统工艺，编辑后会被同步覆盖"
3. Alert 内嵌"复制到用户层后编辑"链接，点击调用 `bundledApi.copyProcessToUser(name)`

## 6. 已知限制与待改进点

### 6.1 M3 阶段限制

- **无保存按钮**：M3 只做编辑 + 实时校验，保存留 M5
- **无离开拦截**：M3 不实现 `useBlocker` + `beforeunload`，留 M5
- **系统工艺复制后不自动刷新**：M3 用 `message.success` 提示用户重新打开，M5 会优化
- **无可视化区**：M3 只有 Monaco，React Flow 泳道留 M4

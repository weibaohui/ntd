## 1. 背景（Why）

飞书侧 `/help` 斜杠命令会打开「NTD 控制台」交互卡片，当前只有 4 个 Tab：状态 / 事项 / 环路 / 工作空间，可查看并一键执行「事项（todo）」与「环路（loop）」。

但任务体系里还有两类核心对象没有在飞书控制界面暴露：

- **任务（tasks）**：按工作空间归集的执行单元，有 `pending/running/success/failed` 状态，分「环路模式（execution_mode=loop）」与「委派模式（execution_mode=delegate）」两种执行方式；
- **工艺（process_templates）**：可复用的流程蓝图（系统内置 + 用户模板），实例化后生成环路。

用户在飞书侧无法查看任务列表、无法触发已有任务再执行、也无法查看当前有哪些工艺模板可用，必须回到 Web 端操作。

## 2. 目标（What，必须可验证）

- [ ] `/help` 控制台卡片从 4 Tab 扩展为 6 Tab：状态 / 事项 / 环路 / 任务 / 工艺 / 工作空间。
- [ ] 「任务」页列出当前工作空间的任务（每页 10 条，最多取 20 条），每项显示状态图标、标题、执行方式（环路 / 委派@处理人）。
- [ ] 「任务」页中，环路模式的任务带「执行」按钮，点击后复用该任务的需求描述重新触发一次环路执行；委派模式的任务只展示、不提供执行按钮。
- [ ] 「工艺」页列出工艺模板（系统内置 + 当前工作空间的用户模板，每页 10 条，最多取 20 条），仅查看（名称、复杂度、版本、系统/用户标识），不提供安装/实例化操作。
- [ ] 卡片按钮回调支持 `act:/runtask <id>`、`nav:/tasks <page>`、`nav:/processes <page>`。
- [ ] 任务/工艺页与事项/环路页保持同样的交互形态：分页按钮 + 「返回状态」按钮。

## 3. 非目标（Explicitly Out of Scope）

- 不在飞书卡片上创建任务、删除任务、修改任务。
- 不在飞书卡片上安装/实例化工艺模板（仍走 Web 端）。
- 不支持委派模式任务在飞书侧触发执行（讨论区 @处理人 接力路径不接入卡片）。
- 不展示任务详情（执行记录、讨论区、门禁等）。
- 不修改任何 HTTP API 与数据库结构。

## 4. 使用场景 / 用户路径

1. 用户在飞书私聊/群里发送 `/help`，打开 NTD 控制台，默认「状态」页。
2. 点击「任务」Tab：看到当前工作空间最近 20 条任务（分两页），每条显示状态与执行方式；点某个环路任务的「执行」→ 卡片顶部出现「✅ 已触发任务「xx」」并刷新。
3. 点击「工艺」Tab：看到可用工艺模板列表，翻页浏览，了解有哪些工艺可用；需要安装时回 Web 端操作。
4. 在任一 Tab 点「工作空间」切换工作空间后，任务/工艺页按新工作空间重新展示。

## 5. 功能需求清单（Checklist）

- [ ] 控制台卡片增加「任务」「工艺」两个 Tab（共 6 Tab，当前 Tab primary 高亮）。
- [ ] 「任务」页渲染任务列表（状态图标 + 标题 + 执行方式标签），环路任务带「执行」按钮，委派任务无按钮。
- [ ] 「工艺」页渲染工艺模板列表（名称 + 复杂度 + 版本 + 系统/用户标签），纯文本无按钮。
- [ ] 任务/工艺页均支持上一页/下一页/返回状态。
- [ ] `act:/runtask <id>`：校验任务存在、属于当前工作空间、execution_mode=loop 且有 loop_id，复用任务 description 触发环路执行并把 loop_execution 绑定到该任务，然后 patch 刷新卡片并显示结果提示。
- [ ] 空列表时显示占位文案（「当前工作空间暂无任务」/「暂无工艺模板」）。

## 6. 约束条件（非常关键）

- **技术约束**：Rust 后端，沿用 `feishu_card.rs` 的 CardBuilder 渲染与 `feishu_card_actions.rs` 的 act/nav 路由；飞书卡片 JSON 2.0。
- **架构约束**：卡片只读组装沿用 `assemble_help_card_state`；任务执行必须复用 `LoopRunner::spawn_run`（飞书层拿不到 `loop_trigger_dispatcher`，spawn_run 是等价触发路径）+ `db.update_loop_execution_task_id` 绑定任务；不新建服务/不新增依赖。
- **安全约束**：执行前必须校验任务 `workspace_id` 与 bot 当前工作空间一致（防旧卡片跨工作空间执行，与 act_run_todo/act_run_loop 同口径）；委派任务与无 loop_id 的任务拒绝执行。
- **性能约束**：任务、工艺列表查询取最近 20 条（`take(20)`）；卡片元素量不超飞书限制；分页每页 10 条。

## 7. 可修改 / 不可修改项

- ❌ 不可修改：HTTP API 路由与字段、DB 表结构、`/help` 既有 4 Tab 的文案与行为、事项/环路执行语义。
- ✅ 可调整：Tab 顺序（任务/工艺插入位置）、列表项文案与 emoji、空列表占位文案、卡片内部辅助函数命名。

## 8. 接口与数据约定（如适用）

| 回调值 | 语义 | 参数 |
|--------|------|------|
| `nav:/help task` | 切换到任务 Tab | 无 |
| `nav:/help process` | 切换到工艺 Tab | 无 |
| `nav:/tasks <page>` | 任务页分页 | page 从 1 开始 |
| `nav:/processes <page>` | 工艺页分页 | page 从 1 开始 |
| `act:/runtask <id>` | 触发环路模式任务再执行 | 任务 id（i64） |

- 任务状态图标口径：`pending ⏸️ / running ⏳ / success ✅ / failed ❌`，与前端 `components/tasks/constants.tsx` 的 STATUS_COLOR 四态对齐，未知状态回退 `⏸️`。
- 执行方式标签：`execution_mode=loop` 显示「环路」；`=delegate` 显示「委派@<assignee_name>」；未知模式显示原值。

## 9. 验收标准（Acceptance Criteria）

- 如果发送 `/help`，则卡片出现 6 个 Tab，点击「任务」「工艺」能正确切换并渲染对应列表。
- 如果当前工作空间有 12 条任务，则任务页第 1 页显示 10 条、点「下一页」显示 2 条。
- 如果点击环路任务的「执行」，则后台创建一条新的 loop_execution 且其 task_id 绑定该任务，卡片被 patch 并顶部显示成功提示。
- 如果点击委派任务的条目，则无执行按钮、不产生任何执行。
- 如果旧卡片（旧工作空间）点击执行，而任务已不属于当前工作空间，则显示失败提示且不执行。
- 如果任务/工艺列表为空，则显示占位文案而不是空卡片。
- 如果 `cargo clippy --all-targets -- -D warnings` 与 `cargo test` 全部通过，且新增函数均有单元测试覆盖正常/边界/错误分支。

## 10. 风险与已知不确定点

- 环路模式任务执行中「任务是否正在运行」不设防（与 act_run_loop 同口径，允许多次触发新执行）；如需要防重入，属后续迭代。
- 工艺列表包含所有工作空间的用户模板；卡片层按「系统内置（workspace_id IS NULL）+ 当前工作空间模板」过滤，跨工作空间用户模板不展示（与「按当前工作空间展示」的交互一致）。
- 任务执行绑定失败（update_loop_execution_task_id 出错）时：执行已触发，卡片提示「已触发」但记录未绑任务，按 warn 记录日志即可，不阻断（与 handlers/tasks.rs 的失败传播策略一致——该处为硬错误，卡片侧按 fire-and-forget 提示口径处理）。

## 11. 非目标

本节列出明确排除的场景，AI 不得实现：

- 飞书卡片上的任务创建/编辑/删除、委派任务执行、工艺安装/升级/版本 diff、任务详情下钻、执行历史页扩展（`nav:/history` 不动）。

> **例外决策（2026-08-15 评审补记）**：「执行历史页不动」含一处例外——历史页「返回控制台」按钮值原为占位串 `nav:/help task`（旧代码里 task 不是有效 Tab，实际落到默认状态页）；104 起 task 成为真实 Tab，若不改会漂移到任务页、改变既有行为。故改为显式 `nav:/help status`，最终落点与历史行为一致。`nav:/history` 的分页与渲染逻辑不动。

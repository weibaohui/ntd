# 044-环路瘦身与工艺对齐-需求

| 修改人 | 修改时间 | 修改内容 |
|--------|---------|---------|
| AI(Kimi) | 2026-07-30 | 初始版本 |

## 背景

环路（Loop）出现早于工艺（Process）。工艺体系成熟后（025~042 系列需求），环路在概念上已成为工艺的实例化承载，但系统仍保留了两套独立入口：

- 环路可以脱离工艺手工新建、编辑（`LoopFormModal`），与工艺 YAML 定义存在字段出入；
- 环路保留了触发器（cron / webhook / 飞书 / 标签 / 事项事件）与「触发」按钮等多个执行入口，执行路径分散；
- 环路保留了导入 / 导出 / 合并 / 备份功能，而工艺时代这些职责应由 YAML 文件承担；
- 数据库层面 `loops` / `loop_steps` 表存在 YAML 中已无对应概念的字段（`min_rating` / `unrated_policy` 旧评分闸门、`run_mode`、`skip_on_source_failed`、`webhook_enabled`、`review_template_id`、`color`、`icon` 等），形成双轨冗余。

用户决定：**环路彻底降级为工艺的运行时承载，以工艺 YAML 为唯一定义来源，对环路进行瘦身与对齐。**

## 需求

### R1 定位收敛

- 工艺（YAML + 可视化编辑器）是流程定义的唯一编辑入口；
- 环路不再提供新建、编辑能力，仅作为工艺安装后的运行时实例存在；
- 环路列表菜单保留，但整体只读化：保留查看执行记录、人工审批、看板、流程图、删除、启停。

### R2 执行入口收敛

- 环路的「触发」按钮、触发器配置 UI、全部触发器类型（cron / webhook / 飞书消息 / 飞书命令 / 事项完成 / 事项状态变更 / 标签添加）彻底下线；
- 唯一执行入口保留为：创建任务（`CreateTaskModal` 选择工艺环路）。

### R3 导入导出删除

- 环路的导出 / 导入 / 预览导入 / 合并功能全部删除（API + 前端 UI + 设置页备份 Tab 中的环路部分）。

### R4 数据库对齐（迁移 v80）

- 删除 `loop_triggers` 表；
- `loops` 表删除列：`webhook_enabled`、`review_template_id`、`color`、`icon`；
- `loop_steps` 表删除列：`min_rating`、`unrated_policy`、`run_mode`、`skip_on_source_failed`；
- 存量清理：删除所有 `process_template_id IS NULL` 的手工环路，并级联清理其 loop_steps / loop_phases / loop_triggers / loop_executions / loop_step_executions / loop_phase_executions / loop_step_execution_gates / loop_step_artifacts / loop_tags 数据。

### R5 后端 API 与 Service 裁剪

- 删除 API：手工创建环路 `POST /loops`、更新环路 `PUT /loops/{id}`、手动触发 `POST /loops/{id}/trigger`、触发器 CRUD 全组、环节 CRUD 与 reorder、复制 `duplicate`、导出 / 导入 / 合并、旧评分制审批 `POST …/steps/{seid}/approve`；
- 下线 v0 整套路由（`loop_routes()`），只保留 v1；
- 删除 `loop_scheduler.rs`（cron 调度）；`loop_trigger.rs` 只保留任务触发路径；
- 删除 `loop_runner.rs` 中 `apply_rating_gate` 旧评分闸门及 `gate_evaluator` 中 min_rating 降级分支；
- 保留：环路查询、启停、批量删除、执行记录查询、门禁制审批 `approve_gate`、产物补录、工艺 install / upgrade 内部建环路路径、loop_runner 主循环。

### R6 审批路径统一

- 前端审批操作从旧评分制 `approveStepExecution` 切换为门禁制 `approve_gate`，审批成为唯一人工干预路径。

## 边界

- 工艺实例化（`installer.rs`）创建环路 / 环节 / 阶段的逻辑不变；
- 执行链路（loop_runner 主循环、phase_driver、门禁评价、审批续跑）不变；
- `loop_step_executions` 的 `min_rating` / `unrated_policy` / `rating` 历史快照列保留（历史记录不可变；存量手工环路的执行历史随 R4 级联删除一并清除）；
- 环路删除、启停（status enabled/paused）保留——paused 是工艺实例的运行开关；
- `loop_tags` 表及环路打标签能力本次保留（标签筛选仍被列表使用），仅触发器中的 tag_added 类型随触发器下线；
- 工艺侧的模板管理、版本、升级（`/{guid}/loops/{loop_id}/upgrade`）不受影响。

## 验收标准

1. 前端不存在任何环路新建 / 编辑 / 触发 / 触发器配置 / 导入导出入口；环路列表与详情全部只读（除删除、启停、审批）。
2. 创建任务仍可选择工艺环路并正常触发执行；审批后正常续跑。
3. `cargo clippy --all-targets -- -D warnings` 零告警；`cargo test` 全部通过；`npx tsc --noEmit` 零错误。
4. 迁移 v80 在含存量手工环路的 dev 库上执行成功：手工环路及其关联数据被清除，`loop_triggers` 表与指定列不存在。
5. 已安装工艺实例的升级（upgrade）与执行不受迁移影响。

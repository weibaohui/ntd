# 实现总结：工艺定义不再落库，改为从文件读取（038）

## 1. 目标回顾

把 `process_templates` 表里冗余存储的工艺 YAML 正文（`definition` 大 TEXT 列）彻底移除，
让**磁盘 YAML 成为唯一真源**：DB 只保留 `source_path` 路径引用 + 轻量元数据，
正文始终按 `source_path` 从磁盘读取。消除"双写漂移"与冗余存储。

- DB 仍保留 `id`（作为 `loops.process_template_id` 外键锚点）与 `name`/`display_name`/`description`/
  `category`/`complexity`/`version` 等小字段（查询缓存用）。
- 不删表、不删外键，避免大规模重构。

## 2. 关键设计决策

- **迁移编号重排**：设计稿原写 v74，但开发分支 `refactor/process-definition-file-backed` 基于
  `feat/recipe-editor`(ea9be16)，该基底已占用 v74–v77。为严格单调递增、不与基底冲突，实测落地为 **v78**
  （`V78ProcessDefinitionToFile`），用 `drop_column_if_exists` 幂等删 `definition` 列。
- **正文读取下沉到调用方**：`install_process_template` 与 `upgrade_process_template_loop` 改为接收
  已读取的 `definition: &str` 入参，不再由 installer 直接读 `template.definition`（该字段已删除），
  也避免 installer 依赖 config（路径解析所需的 `local_path`）。
- **集中解析模块**：新增 `services/process/source.rs`，统一 `source_path` → 磁盘文件内容的解析，
  覆盖 `bundled://`（系统层，经 `git_sync::bundled_dir`）与 `user://`（用户层，经 `user_processes_dir`）
  两种前缀，并提供 `ProcessSourceError`（NotFound / Read），实现到 `AppError` 与 `InstallError` 的 `From`。

## 3. 改动清单

### 3.1 迁移（新增）
- `db/migration/v78.rs`：删除 `process_templates.definition` 列。
- `db/migration/mod.rs`：注册 `mod v78;` 与 `Box::new(v78::V78ProcessDefinitionToFile)`。

### 3.2 实体（删字段）
- `db/entity/process_templates.rs`：删除 `Model.definition: String`（SeaORM 自动移除 `Column::Definition`）。

### 3.3 读写改造
- `db/process_template.rs`：`upsert_system_process_template` / `upsert_user_process_template` 去掉 `definition` 入参与赋值。
- `handlers/bundled.rs`：`upsert_process_template` 去掉 `definition_text` 入参。
- `services/process/user_dir.rs`：`upsert_user_process_yaml` 去掉 `content` 入参（仍读文件抽元数据，不再落库）。
- `handlers/process.rs`：
  - `get_process_template`：正文由 `read_definition(template.source_path, local_path)` 取得。
  - `install_process` / `copy_process_to_user` / `diff_process_versions` / `upgrade_process_loop`：
    均先 `read_definition` 再传入 installer / 写文件 / diff。
- `services/process/installer.rs`：`install_process_template` 与 `upgrade_process_template_loop` 增加 `definition: &str` 入参。

### 3.4 新增模块
- `services/process/source.rs`：`resolve_source_path` / `read_definition` + `ProcessSourceError` + `From` 实现。

### 3.5 测试同步
- `installer.rs` / `handlers/process.rs` / `db/loop_.rs` / `models/loop_.rs` / `recommender.rs` 等处的
  `Model` / `ActiveModel` 字面量与 `install_process_template` 调用点，移除 `definition` 字段、补 `definition` 入参。

## 4. 验证结果

- `cargo clippy --all-targets -- -D warnings`：**零告警**（含测试目标）。
- `cargo check --lib`：**零错误**。
- `cargo test`：除 2 个与本次改动**无关**的基底既有失败
  （`delivery_state::test_write_delivery_state_creates_file`、
  `repair_log::test_append_repair_entry_creates_file`，隔离运行均通过，属基底顺序/环境问题，非本分支回归）
  外，其余全部通过，含本需求相关的 installer 系列测试。
- 冲突迁移说明：原改动从错误分支 `fix/sync-overwrite-only` 迁出，经 `git stash` +
  `git worktree add -b refactor/process-definition-file-backed ... ea9be16` 重放到本分支，
  解决了 `migration/mod.rs` 与 `installer.rs` 两处合并冲突，并将迁移编号由冲突的 v74 重排为 v78。

## 5. 已知限制 / 风险

- 任何 `source_path` 与实际文件不一致（导入时写错 path）会导致读取失败；缓解：导入按真实路径生成
  `source_path`，且 `copy` / `install` / 详情读取失败时返回明确错误而非静默空内容。
- 回滚：迁移只删一列不删数据；如需回滚可 `ALTER TABLE process_templates ADD COLUMN definition TEXT`，
  但历史正文已不可恢复，故合并前已在 dev 库验证逻辑完整（见验证结果）。

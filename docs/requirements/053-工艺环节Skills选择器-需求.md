# 需求：工艺环节 Skills 选择器改造（053）

## 1. 背景与问题

环节 `skills` 字段后端全链路已通，但前端旧 `LinkSkillPicker`（卡片 toggle）有 6 个叠加问题让人**完全看不懂**：
未填执行器就消失、默认折叠、选中态弱、无已选汇总、字段顺序错位、不能手填。

**已确认的决策**：
- 布局：**内联展开**（已选 Tag 区 + 搜索框 + 多选 Table）。
- 现有卡片 toggle：**替换**（todo 侧 `SkillSelector` 保留）。
- 手填：**搜索框回车添加**。
- **环节「执行器」可清空，非必选**（用闪念同款选择器，只选不填，可清空）。
- **skill 不绑定执行器**：`link.skills` 存纯名；执行器是技能选择器**内部**的筛选条件；与环节「执行器」属性并行、独立。

## 2. 目标

1. 重写 `LinkSkillPicker` 为「内联 table 多选 + 手填 + 内置执行器筛选」。
2. **skill 与执行器解耦**：已选跨执行器保留、切换筛选不丢；环节「执行器」不影响 skills 可选项。
3. **环节执行器可清空**：空态明确显示「未选择执行器」，不能手填。
4. 已选 Tag **标注来源**（当前/其他执行器/自定义），解决"选了却看不到"的困惑。
5. 复用 `getSkillsList()` 与 `ExecutorPickerPopover`，**零新接口、零后端改动**。
6. 桥接逻辑抽纯函数并补单测。

## 3. 功能点与验收标准

| # | 功能点 | 验收标准 |
|---|--------|---------|
| F1 | 内联展开 | 选中环节后技能区直接展示「已选 Tag + 搜索框 + 多选 Table」 |
| F2 | 执行器可清空 | 环节执行器用选择器；有值可点 × 清空，清空后显示「未选择执行器」 |
| F3 | 内置执行器筛选 | 技能选择器内部有执行器筛选器；切换 → Table 换为对应执行器 skills |
| F4 | 跨执行器保留 | 切换筛选执行器，已选 skills 不丢 |
| F5 | 同名同步 | 勾选某执行器的 skill，切到有同名 skill 的执行器，表格对应行仍勾选 |
| F6 | 标注统一 | 已选 Tag：已知 skill=蓝无标注；全量无（手填自定义）=橙「·自定义」；标注不随筛选执行器变化 |
| F7 | 点选/取消 | 表格勾选/取消 → 已选 Tag 同步、写回 definition |
| F8 | 手填/删除 | 搜索框回车加自定义（去重）；Tag × 删除 |
| F9 | 持久化 | 改动写入 ProcessDefinition（视图切换/重新打开保持） |

## 4. 边界与非目标

- 不改后端 / 不新接口。
- 不动 todo 场景的 `SkillSelector`。
- 不引入 Transfer / Cascader / TreeSelect。
- 不处理复制 loop 丢 `skill_names` 的既有缺口（独立问题）。

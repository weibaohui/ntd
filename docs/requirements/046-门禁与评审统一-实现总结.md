# 实现总结：门禁与评审统一（046）

## 1. 概述

需求来源：任务 37（loop「口头需求工艺」#72）的环节 1「补写 PRD」连续失败 6 次。

诊断发现根因不是评分流程，而是**门禁判定的职责划分存在概念混乱**：

- `expected_artifacts[].path` 含占位符 `{process_name}`，这是给 AI 结合上下文理解的占位符。AI 写文件时根据自己的理解填充这个占位符（需求名称、任务 slug 等），具有主观性。
- 但 `artifact_present` 门禁用程序 `fs::exists` 判定文件存在性，根本不知道该把 `{process_name}` 替换成什么，导致路径字面上不存在，门禁 fail。
- 用户反馈："判定文件是否存在，让文件系统去判断有点问题……这些占位符是给 AI 结合上下文理解的……我们不应该用程序去做文件的存在性的判断，而是应该统一的把这些门禁的判定规则交给这个 AI 去做。"

## 2. 决策汇总

经与用户确认，最终决策如下：

| 问题 | 决策 |
|---|---|
| 门禁判定主体 | 只有 `human_approval` 不归 AI；`artifact_present`/`script_check`/`ai_criteria_review` 全归 AI |
| script_check 归属 | **全归 AI** —— AI 自己决定是否跑脚本、怎么跑，拿到完整工作空间访问权限自行判定 |
| 产物捕获去留 | **保留**（用于前端展示、审计追溯）；但门禁判定不再依赖 `loop_step_artifacts` 表，改由 AI 评审判定 |
| min_score 来源 | **gate_config.min_score** —— 仍从 gate_config 里的 ai_criteria_review 门禁配置读取 |
| 验收标准与门禁关系 | **合并为单一评审** —— AI 一次性判定产物存在性、内容质量、脚本执行结果，返回综合 rating |
| artifact_present 处理 | **废弃** —— 产物存在性检查改由 AI 在评审环节判定 |
| 门禁要求写入评审模板 | **是** —— 把门禁判定要求写进评审模板，执行前字符串替换（`{{loop_name}}`/`{{expected_artifacts}}`/`{{gates}}` 等） |
| 破坏性变更处理 | **直接破坏性变更** —— 修改代码和 DB schema，提供数据迁移脚本，不兼容旧 gate_config |
| AI 评审载体 | **复用 auto_review** —— 复用现有 auto_review 流程（已有评分解析 `RATING: N`、产出 `execution_record.rating`）；门禁判定改为读这个 rating 与 min_score 比较 |

## 3. 后端改动

### 3.1 废弃门禁类型文件

| 文件 | 改动 |
|------|------|
| `backend/src/services/process/gates/artifact_present.rs` | **删除** —— 产物存在性改由 AI 评审时自行判定 |
| `backend/src/services/process/gates/script_check.rs` | **删除** —— 脚本执行结果判定改由 AI 评审时自行判定 |
| `backend/src/services/process/gates/mod.rs` | 移除 `artifact_present` 和 `script_check` 的 mod 声明 |

### 3.2 gate_evaluator.rs

- **移除废弃门禁分支**：`evaluate_single_gate` 不再 dispatch 到 `artifact_present` 和 `script_check`
- **解析阶段提前拦截废弃类型**：在 `evaluate_step_gates` 解析 `gates` 后、写 DB 前，校验每个 gate_def 的类型，废弃类型直接返回 `ParseError`
- **移除 import**：`artifact_present`、`script_check` 从 `use` 列表中移除

关键代码：

```rust
// 046：废弃门禁类型 artifact_present/script_check 在此提前拦截，
// 统一并入 ai_criteria_review。此校验放在解析后、写 DB 前，
// 保证废弃类型不会静默降级为 failed 记录，而是显式报错。
for gate_def in &gates {
    if matches!(gate_def.gate_type.as_str(), "artifact_present" | "script_check") {
        return Err(crate::services::process::ProcessError::ParseError(format!(
            "已废弃的门禁类型「{}」：artifact_present/script_check 统一并入 ai_criteria_review",
            gate_def.gate_type
        )));
    }
}
```

### 3.3 phase_driver.rs

- **移除 `ai_review_wait_timeout` 函数** —— 不再需要三态语义的评分等待策略
- **移除 `poll_rating` 函数** —— 不再需要轮询等待评分出现
- **简化评分获取逻辑** —— 评分统一由 auto_review 在环节执行完成时写入 `execution_record.rating`，此处直接读取已有评分

关键代码：

```rust
// 046：评分统一由 auto_review 在环节执行完成时写入 execution_record.rating。
// artifact_present/script_check 已废弃，产物存在性与脚本执行结果改由 AI 评审时自行判定。
// 此处直接读取已有评分，不再 poll 等待——评分缺失即门禁 fail（ai_criteria_review 无 rating）。
let execution_rating = execution_record.and_then(|r| r.rating);
```

### 3.4 评审模板：门禁要求写入

评审模板（`review_prompt` 或环路级 `review_template_id`）中，把门禁判定要求作为评审指令的一部分写进去。执行前用 `replace_placeholders` 做字符串替换：

| 占位符 | 替换值来源 |
|---|---|
| `{{loop_name}}` | loop.name（工艺名称） |
| `{{process_name}}` | 同上（语义别名） |
| `{{requirement}}` | todo.prompt（任务需求） |
| `{{expected_artifacts}}` | loop_steps.expected_artifacts JSON（原样，不预替换占位符） |
| `{{gates}}` | loop_steps.gate_config JSON |
| `{{acceptance_criteria}}` | todo.acceptance_criteria / 环节级 |
| `{{workspace_path}}` | loop.workspace_path |

**关键设计**：`expected_artifacts[].path` 里的 `{process_name}` 占位符**不预替换**，原样传给 AI 评审上下文。AI 评审时根据占位符语义和上下文，自行判定文件是否存在于正确路径。

## 4. 关键实现点与取舍

### 4.1 废弃类型报错时机

**问题**：最初把废弃类型检查放在 `evaluate_single_gate` 的 `_ =>` 分支，但测试失败——`evaluate_step_gates` 外层 `match result` 的 `Err(gate_err)` 分支会把错误**降级成 failed 记录**而非向外传播 `Err`，所以测试看到的是 `Ok(GateSummary)`，不是 `Err`。

**解决**：把废弃类型校验放在 `evaluate_step_gates` 解析 `gates` 后、写 DB 前，保证废弃类型不会静默降级为 failed 记录，而是显式报错。

### 4.2 死代码清理

移除 `ai_review_wait_timeout` 和 `poll_rating` 后，`phase_driver.rs` 测试模块中仍有 4 个测试引用这两个函数，编译失败。清理这些测试：

- `ai_review_wait_timeout_without_ai_gate_returns_none`
- `ai_review_wait_timeout_with_ai_gate_no_timeout_waits_forever`
- `ai_review_wait_timeout_with_ai_gate_timeout_returns_secs`
- `ai_review_wait_timeout_invalid_json_returns_none`

保留 `extract_review_threshold` 相关测试（该函数仍在使用）。

### 4.3 产物捕获语义变化

`artifact_present` 废弃后，产物捕获（`loop_step_artifacts` 表）保留但语义变化：

- `loop_step_artifacts` 表保留（前端展示、审计追溯用）
- 产物捕获不再预替换占位符 —— `expected_artifacts[].path` 原样记录
- 门禁判定**不再依赖** `loop_step_artifacts` 表 —— 改由 AI 评审时自行判定

## 9. 风险与后续

### 9.1 风险

- **破坏性变更**：废弃门禁类型不兼容旧 gate_config，需要数据迁移

- **评审模板变更**：评审模板需要增加门禁判定要求，可能影响现有 AI 评审质量

## 1. 实现了什么

把 470 行的 `TaskDetailPanel.tsx` 彻底拆分，行为零变更：

- **数据层抽 hook**：拉详情 / 拉环路 / 删除 / 再次执行 / 调接力上限 全部移入 `useTaskDetail`，脱离组件可单测（10 条 renderHook 单测）。
- **头部外迁**：`RelayBadge` / `RelayMaxEditor` / `DetailHeader` + 两个纯函数移入 `TaskDetailHeader.tsx`。
- **类型收口**：`TaskDetailData` / `ExecInfo` 从面板内联上提到 `src/types/task.ts`（兑现该文件注释里的待办）。
- **Tab 显隐纯函数**（第一步）：`visibleTaskTabs` / `resolveTaskActiveTab` + 9 条单测。

面板回归薄编排层：主组件函数 ~200 → ~70 行，只做「调 hook → 组装 Tab → 渲染」。

## 3. 关键实现点

- **逐行平移保行为**：`alive` 竞态守卫、effect 依赖数组、`eslint-disable` 注释、`message` 文案、`handleUpdateMax` 失败 `throw e`（让 Popover 保持打开供重试）全部原样保留。
- **refresh 复用**：提取内部 `refresh`（重拉详情）供 `handleNewExec` / `handleUpdateMax` 共用，消除重复的 `getTaskDetail + setDetail` 片段；刻意不调 `onTitleReady`（标题仅首次加载上报）。
- **discussionRunning 留组件**：纯展示态（讨论 Tab 角标），与任务数据无关，不进数据 hook。
- **文件定位复用**：`helpers.ts` 头部注释本就声明「抽纯函数脱离组件做单测」，第一步就地扩入；规避与 `TaskDetailTabs.tsx` 在 macOS 大小写不敏感 FS 上的命名冲突。

## 4. 测试与验证结果

- 前端：`npx tsc --noEmit` 零错误；`npx vitest run src/hooks/ src/components/tasks/` **89/89** 通过（hook 新增 10 条 + helpers 新增 9 条）；`npm run build` 无新告警。
- Playwright 回归 **11/11** 通过：

  - `092-delegate-relay-badge`（管家调度徽标渲染）1 条

  - `092-create-task-delegate`（委派创建联动）3 条
  - `060-task-discussion-forum`（讨论 Tab + 角标）1 条

## 5. 安全反思

- 纯结构重构，无 API/DB/状态机/鉴权变更，无安全面。
- `resolveTaskActiveTab` 对非法 `?tab=` 一律回退默认，不会因脏 URL 导致空白页。
- 数据 hook 的 `alive` 守卫保留，切任务/卸载后晚到的响应不会写脏 state。

## 6. 已知限制

- `StepInfo` 仍定义在 `TaskDetailTabs.tsx`（与 Tab 组件强绑定），`types/task.ts` 跨文件 import；后续若统一领域类型可再搬迁。
- 头部展示组件（RelayBadge 等）未补组件级单测——其行为由 Playwright `092` 覆盖；本次单测聚焦数据层（核心收益 + CLAUDE.md「公开函数必测」）。

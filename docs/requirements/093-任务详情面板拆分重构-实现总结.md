## 1. 实现了什么

把 470 行的 `TaskDetailPanel.tsx` 彻底拆分，行为零变更：

- **数据层抽 hook**：拉详情 / 拉环路 / 删除 / 再次执行 / 调接力上限 移入 `useTaskDetail`（Modal 开关 / 输入等纯 UI 态留组件），脱离组件可单测（9 条 renderHook 单测）。
- **头部外迁**：`RelayBadge` / `RelayMaxEditor` / `DetailHeader` + 两个纯函数移入 `TaskDetailHeader.tsx`，Props 改具名 interface。
- **类型收口**：`TaskDetailData` / `ExecInfo` 从面板内联上提到 `src/types/task.ts`（兑现该文件注释里的待办）。
- **Tab 显隐纯函数**（第一步）：`visibleTaskTabs` / `resolveTaskActiveTab` + 9 条单测。

面板回归薄编排层：面板文件 470 → 166 行（主组件函数代码行约 95，主体为声明式 `allTabs` JSX，属纯数据构建豁免），只做「调 hook → 组装 Tab → 渲染」。

## 3. 关键实现点

- **行为等价保行为**：`alive` 竞态守卫、effect 依赖数组、`eslint-disable` 注释、`message` 文案、`handleUpdateMax` 失败 `throw e`（让 Popover 保持打开供重试）全部原样保留。
- **职责边界（评审修订）**：① `refresh` 收为内部不对外暴露（消除无谓公开面）；② 再次执行 Modal 的开关 / 输入态留在组件、`handleNewExec` 改为入参 + 返回 `boolean`（消除 hook 对 UI 态的依赖）；③ 头部 Props 改具名 `<Component>Props` interface。
- **discussionRunning 留组件**：纯展示态（讨论 Tab 角标），与任务数据无关，不进数据 hook。
- **`import * as dbLoops` 保留**：与 `src/hooks/` 全部 7 个数据 hook 一致（db 模块命名空间导入约定，`10-导入规范` §4「除非不可避免」）。
- **文件定位复用**：`helpers.ts` 头部注释本就声明「抽纯函数脱离组件做单测」，第一步就地扩入；规避与 `TaskDetailTabs.tsx` 在 macOS 大小写不敏感 FS 上的命名冲突。

## 5. 安全反思

- 纯结构重构，无 API/DB/状态机/鉴权变更，无安全面。
- `resolveTaskActiveTab` 对非法 `?tab=` 一律回退默认，不会因脏 URL 导致空白页。
- 数据 hook 的 `alive` 守卫保留，切任务/卸载后晚到的响应不会写脏 state。

## 6. 已知限制

- `StepInfo` 仍定义在 `TaskDetailTabs.tsx`（与 Tab 组件强绑定），`types/task.ts` 跨文件 import；后续若统一领域类型可再搬迁。
- `useTaskDetail` 体量超 50 行未拆分：属紧耦合的任务详情状态机，强行拆分会致数据碎片化（CLAUDE.md 豁免总原则「强行拆分将导致数据碎片化」）；理由已写入函数顶部注释，与模板 `useRunningBoard` 同形态。
- 头部展示组件（RelayBadge 等）未补组件级单测——其行为由 Playwright `092` 覆盖；本次单测聚焦数据层（核心收益 + CLAUDE.md「公开函数必测」）。

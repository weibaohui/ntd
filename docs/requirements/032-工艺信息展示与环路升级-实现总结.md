## 2. 实现内容

### 2.1 详情标题动态化

| 组件 | 改动 |
|------|------|
| `TodoDetailPage.tsx` | 从 `actionsCtx.todo.title` 读取实际标题，PageCard title 改为动态 `事项 #{todoId}: {title}` |
| `TaskDetailPage.tsx` | 新增 `detailTitle` state → `onTitleReady` 回调 |
| `TaskDetailPanel.tsx` | 新增 `onTitleReady` prop，数据加载成功后调用 |

**关键决策**：
- TodoDetailPage 复用已有的 `onActionsReady` 回调（`actionsCtx.todo.title` 即为实际标题），无需新增 prop
- TaskDetailPage 用 `onTitleReady` 新回调，因为 TaskDetailPanel 没有 `onActionsReady` 机制

### 2.2 工艺列展示

| 视图 | 改动 |
|------|------|
| `TodoListView.tsx` | 新增「工艺」列（调度列之后），渲染 `record.referencing_loops[].loop_name` |
| `TasksTableView.tsx` | 列名「模板」→「工艺模板」 |
| `TaskDetailPanel.tsx` | Descriptions label「模板」→「工艺模板」 |

**关键决策**：
- 事项列表的工艺列使用 `referencing_loops[].loop_name`（Loop 名）而非直接展示 `process_template_name`，因为 `TodoCenterItem` 响应不含后者
- 列名「工艺」在事项列表、「工艺模板」在任务列表——前者展示的是引用 Loop（包含工艺上下文），后者直接对应当前任务使用的模板

### 2.3 工艺实例环路升级

#### 后端

**新增端点**：`POST /api/v1/processes/{name}/loops/{loop_id}/upgrade`

**新增服务函数** `installer.rs` 的 `upgrade_process_template_loop`：

1. 解析模板最新 YAML 定义
2. 获取旧 loop_steps 及其 todo_id
3. 使用 SeaORM EntityTrait 删除旧步骤/阶段（无 FK 约束问题）
4. 软删除旧步骤关联的 todo（`delete_todo` = 设 `deleted_at`）
5. 更新 Loop 的 name/description/limits_config/process_template_version
6. 复用 `create_phases_and_steps` + `resolve_goto_targets` 重新创建

**流程**：
```
旧步骤 → 解绑 → 删除 → 软删todo → 更新版本 → 创建新步骤 → 解析goto
```

#### 前端

- `bundled.ts` 新增 `upgradeProcessLoop(name, loopId)` 
- `ProcessPage.tsx` 实例环路 Tab 的操作列新增「更新」按钮
- loading 态由 `upgradingLoopId` state 控制
- 成功后自动刷新实例列表

## 5. 已知限制与待改进点

### 5.1 事项列表工艺列

- 仅展示 Loop 名而非直接展示 `process_template_name`，因为后端 `LoopRefSummary` 没有模板名字段。后续可在 `TodoCenterItem` 的 `referencing_loops` 响应中增加 `process_template_name`，前端直接展示。
- 不支持点击跳转——用户需要自行点击进入详情查看完整工艺路径。后续可在 Loop Tag 上增加 `onClick` 跳转到 Loop 详情。

### 5.2 环路升级

- 升级后旧的 `loop_step_executions` 记录保留旧 step_id（无 FK 约束，不影响查询）。执行历史仍保留在 `loop_executions` 表。
- 未批量升级能力——每次只能升级单个 Loop。如需要可后续增加「全部升级」按钮。
- 升级操作不可回滚——升级前不会创建快照。如需回退需手动重新安装旧版本。

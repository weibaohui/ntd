## 1. 实现了什么

事项页（卡片/列表形态）与环路页（列表/看板形态）新增与任务页看板一致的
「全部 / 6h / 12h / 24h / 3d / 7d」时间过滤分段（复用公共组件 `TimeRangeSegmented`）：

| 页面形态 | 过滤字段 | 实现层 | 默认值 |
|---------|---------|--------|--------|
| 事项 卡片/列表 | `created_at` | 后端 SQL 下推（新增 `hours` 参数） | 全部 |
| 环路 列表 | `created_at` | 前端 useMemo 过滤 | 全部 |
| 环路 看板 | 执行记录 `started_at`（现状） | 现有链路 + 新增「全部」 | 24h（保持历史默认） |

## 2. 与需求的对应关系

| 需求条目 | 实现落点 |
|---------|---------|
| 事项页卡片/列表顶栏时间分段、created_at 口径、默认全部 | `TodoListPage` + `TodoListHeader` + `TodoCenterCardView` |
| 环路列表时间分段、created_at 口径、默认全部 | `LoopListPage`（`listHours` + `filteredItems`） |
| 环路看板增加「全部」、默认仍 24h | `LoopListHeader` showAll + `LoopKanban`/`useLoopExecutions` 可空 |
| 事项页两形态共享时间状态、不持久化 | `TodoListPage` 页级 `hours` state（null 初始） |
| 服务端分页总数/页数口径正确 | `GET /todos/center` 新增 `hours`，`center_page_where` 追加 `t.created_at >= ?` |
| 后端单测 | `test_todo_center_page_hours_filter_window`、`test_todo_center_page_hours_zero_or_none_means_no_filter` |

## 3. 关键实现点

- **后端**：`TodoCenterQueryV1`/`TodoCenterPageQuery` 增加 `hours: Option<u32>`；
  cutoff 用 `utc_timestamp_minus_hours(h)` 生成（与写入格式同构的 T/Z ISO），
  参数绑定裸列比较，复用 093 既有模式；`total`/`bucket_counts` 与 items 同口径。
- **事项页**：时间窗提升到页级 state，list 形态经 `useTodoListData` 下推、card 形态经
  `TodoCenterCardView` 下推；时间窗变化回第 1 页；running 形态与移动端不渲染分段。
- **环路页**：list/kanban 各持独立 state（数据维度不同，避免默认值互污染）；
  `LoopKanban` 的 hours fallback 从 `??` 改为 `!== undefined`——显式传 null（全部）不再被吞回 24h。
- **公共组件零改动**：时间档位继续以 `TIME_RANGE_OPTIONS` 为唯一事实源。

## 5. 已知限制或待改进点

- 环路看板「全部」时执行历史全量展示，每环路仍限 20 条（无新增请求放大面）。
- 事项中心「已归档」Tab 同样受 created_at 时间窗过滤（统一口径，需求 §10 已声明）。
- 时间选择均不持久化：刷新/离开页面回到默认值（与任务页现状一致）。
- Playwright spec 使用 `NTD_TEST_BASE_URL` 环境变量切换实例，日常 dev（18088）可直接复跑。

# 实现总结：评审默认值按钮 + 执行注入工作空间背景 + 工艺版本号递增修复（042）

## 1. 概述

三个独立修复（分支 `feat/recipe-editor`）：

1. **评审 prompt「使用默认值」按钮**：新增只读端点暴露 `DEFAULT_REVIEWER_PROMPT` 常量，环节级 + 全局模板编辑两处输入框一键填入。
2. **执行注入工作空间背景**：在执行收敛点 `prepare_execution_state` 统一前置 `# 运行背景（名称/地址）` 到最终 prompt 最外层，覆盖全部 10+ 条执行入口。
3. **工艺版本号递增修复（回归）**：前端保存后回刷 Monaco + 后端防倒退兜底，恢复「编辑后自动 +minor」。

设计文档：`docs/design/042-评审默认值按钮与执行背景注入与版本递增修复-设计.md`。

## 4. 问题3：工艺版本号递增修复

根因（三层，逐层定位）：
1. **`ProcessMeta` 缺 `guid` 字段**（`services/process/mod.rs`）→ `update_process` 用 `serde_yaml::to_string` 写盘时丢失 guid；
2. **import 按「无 guid 文件」生成新 guid 回写、按新 guid 新建 DB 行** → 原 DB 行 version 永不更新（实测：磁盘 tt.yaml guid 与 DB tt 行 guid 漂移，PUT 后 DB updated_at 不变）；
3. **前端 `handleSave` 不回刷 Monaco** → 陈旧 version 第二次保存触发跳过 bump。

| 文件 | 改动 |
|------|------|
| `backend/src/services/process/mod.rs` | `ProcessMeta` 加 `guid: String`（`#[serde(default)]`），让 update 写盘保留 guid。 |
| `backend/src/handlers/process.rs` | `update_process`：写盘前强制 `definition.process.guid = template.guid`（对齐 DB 身份，杜绝 import 新建行）+ `version_below` 防倒退兜底（`semver::Version` 比较，低于磁盘版本则保留）+ 响应回传 `definition`。附 2 个 `version_below` 单测。 |
| `frontend/src/api/bundled.ts` | `putProcess` 返回 `Promise<{ definition: string }>`。 |
| `frontend/src/components/process/ProcessEditor.tsx` | `handleSave` 成功后 `setYamlText(res.definition)` 回刷 Monaco。 |

端到端验证（tt 工艺 reset→PUT→PUT）：磁盘/DB version `1.3.0→1.4.0→1.5.0`，磁盘 guid 从漂移值对齐回 DB guid，DB updated_at 随之更新。

# 036-验收标准归环节-需求

| 修改人 | 修改时间 | 修改内容 |
|--------|---------|---------|
| Claude | 2026-07-29 | 初始版本 — 验收标准从「阶段+环节」两层收敛到只保留环节层 |

---

## 1. 背景（Why）

工艺编辑器里「验收标准」目前同时挂在**阶段（Phase）**和**环节（Link）**两层。经代码调查，后端运行时**只消费环节级那一份**，阶段级是 100% 死字段：

- **安装工艺**时，把**环节**的 `acceptance_criteria` 灌进 todo（`installer.rs::resolve_link_fields`），阶段级的 `phase.acceptance_criteria` 虽被传入 `create_loop_phase` 写进 `loop_phases` 表，但**全代码库没有任何地方读取它**（只写不读的死列）。
- **评审合成 prompt** 取的是 **todo 的** `acceptance_criteria`（`auto_review.rs::compose_review_prompt` 读 `original.acceptance_criteria`），而该 todo 的验收标准来自环节定义。
- **触发自动评审**看的是**环节** `step_acceptance_criteria`（`loop_runner.rs::apply_rating_gate`）。
- **阶段级**在 `phase_driver.rs` 里恒为 `None`（注释自称「不做两层解析」）；门禁 `ai_criteria_review` 文档示例里的 `criteria_ref: "phase.acceptance_criteria"` **引用解析逻辑根本不存在**——`evaluate` 只读 `existing_rating` 与 `min_score`。

语义上验收标准天然属于环节：一个阶段含 N 个环节、产物各不相同，不可能共用一条验收标准，评审也是逐环节进行。阶段挂验收标准**颗粒度太粗**，且与实际评审脱节，误导用户以为「整个阶段共用一条验收标准」。

本需求将验收标准**收敛到只保留环节层**：彻底删除阶段级的 `PhaseDefinition.acceptance_criteria` / `acceptance_criteria_ref` 定义字段、`loop_phases` 运行时死列、以及阶段属性面板里的对应 UI。

> 背景：项目尚未上线、无用户，且用户明确指示**不处理存量兼容**——旧工艺 YAML 阶段层若写了验收标准，重装时由 serde 静默忽略丢弃即可，不报错、不做兜底。

## 3. 非目标（Explicitly Out of Scope）

- ❌ 不动**环节级** `LinkDefinition.acceptance_criteria` 及其安装/评审/触发链路
- ❌ 不动 **todo 级** `acceptance_criteria`（`todos` 表、TodoDrawer、TodoDetail 等）
- ❌ 不动 **step_template 级** `acceptance_criteria`（`process_step_templates` 表、`StepTemplateDefinition`）
- ❌ 不动评审 prompt 的 `{{acceptance_criteria}}` 占位符语义
- ❌ 不改 `ai_criteria_review` 门禁的判定逻辑（仍只比对 rating 与 min_score）
- ❌ **不处理存量兼容**——不写兜底、不做旧 YAML 迁移、不做数据回填
- ❌ 不改阶段的其他字段（`id` / `name` / `spec` / `spec_ref` / `links`）

## 4. 使用场景 / 用户路径

### 场景 A：编辑阶段属性（改动后）

1. 用户在工艺编辑器选中一个**阶段**节点
2. 属性面板只显示「标识 / 名称 / 规范说明」三项——**不再有验收标准**
3. 用户编辑阶段名称/规范说明并保存

### 场景 B：编辑环节验收标准（不变）

1. 用户选中一个**环节**节点
2. 属性面板仍有「验收标准」字段，可填写该环节产物专属的验收标准
3. 保存工艺 → 安装 → 该环节执行生成的 todo 带此验收标准 → AI 评审时据此打分（链路完全不变）

### 场景 C：旧工艺重装（不兼容，按预期丢弃）

1. 某旧工艺 YAML 的阶段层写了 `acceptance_criteria: xxx`
2. 重新安装该工艺 → 阶段验收标准被 serde 静默忽略丢弃，不报错；环节验收标准照常生效

## 6. 约束条件

- **验收标准语义唯一归属环节**：删除阶段级后，验收标准的定义、安装、评审链路全部以环节为单位，与现状运行时行为一致。
- **不处理存量兼容**：旧 YAML 阶段层的 `acceptance_criteria` 由 serde 默认忽略未知字段机制丢弃，不报错；不写任何兼容/迁移/回填代码。
- **migration 幂等**：v77 用 `drop_column_if_exists`（`pragma_table_info` 先检查列是否存在再 DROP），旧库重复升级不报错。
- **零告警**：`cargo clippy --all-targets -- -D warnings` + `npx tsc --noEmit` + `npm run build` 均无新告警。

## 10. 风险与已知不确定点

- **SQLite DROP COLUMN 兼容**：项目已有 `drop_column_if_exists` 工具用 `ALTER TABLE ... DROP COLUMN`，目标 SQLite 版本支持；`acceptance_criteria` 是无约束的普通 TEXT 列，DROP 安全。
- **删字段遗漏引用**：Explore 已穷举触点，`updatePhaseField` / 校验器 / 空模板 / 前端测试均无 phase 验收标准的特殊处理或断言，删字段后自动适配；实现后用 clippy + tsc 兜底确认无悬空引用。

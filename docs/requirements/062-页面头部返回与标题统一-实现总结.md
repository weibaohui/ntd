## 实现了什么

### R1/R4/R5 返回按钮统一（PageCard 收口）

- `components/common/PageCard.tsx` 新增 `onBack?: () => void`、`backLabel?: string` props：
  传入 `onBack` 即在 extra 区**最右端**渲染统一样式返回按钮
  （`<Button size="small" type="text" icon={<ArrowLeftOutlined />}>`），文案默认「返回列表」。
  extra 与 onBack 均空时不渲染 extra 容器（保持无按钮页面布局不变）。

逐页改造（8 处手写返回按钮全部收口）：

| 页面 | 改动 |
|------|------|
| TodoDetailPage | 删 titleSuffix 手写按钮 → `onBack` |
| LoopDetailPage | 同上 |
| TaskDetailPage | 同上 |
| TasksPage 内嵌详情分支 | 同上 |
| TodoPostPage 帖子页 | 删 extra 手写按钮 → `onBack` + `backLabel="返回"` |
| WikiViewPage | 删手写原生 `<button>` → `onBack` + `backLabel="返回"` |
| WorkspaceLoopConfigPage | 删 icon 插槽返回按钮（icon 还原为 SettingOutlined）→ `onBack` |
| ProcessEditorToolbar（自建 Toolbar） | 返回按钮改 `small+text`、文案「返回列表」、保持操作区最右 |

移动端：`MobileHeader.showBackButton` 补上 `tasks` 视图（此前任务详情在移动端无返回入口）。

### R2 标题格式统一（`模块名 #{id}: {具体名称}`）

| 页面 | 改造后标题 |
|------|-----------|
| TodoDetailPage | `事项 #{id}: {title}`（不变） |
| TaskDetailPage | `任务 #{id}: {title}`（不变） |
| TasksPage 内嵌详情 | 固定「任务详情」→ `任务 #{id}: {title}`（接 onTitleReady） |
| LoopDetailPage | `环路 #{id}` → `环路 #{id}: {name}`（新增名称上提） |
| TodoPostPage | 裸标题 → `事项 #{id}: {title}` |
| WikiViewPage | `{slug}` → `Wiki: {slug}` |
| WorkspaceLoopConfigPage | `{ws} - 环路配置` → `环路配置: {ws}` |
| ProcessEditorToolbar | `{displayName} ({name})` → `工艺: {displayName}` + 保留 `(唯一名)` 次级文本 |

### 数据流改动（唯一一处）

`LoopStudioDetailPanel` 新增 `onTitleReady?: (name: string) => void` prop（仿 `TaskDetailPanel.onTitleReady`），
detail 加载后上报环路名称；LoopDetailPage 以函数式 setState 接收（同名 bailout，无 NTD-007 死循环风险）。
此前 `hideTitleRow=true` 时环路名称无处展示，本次顺带补齐。

### 注释同步

修正 6 处把操作按钮位置误写为 titleSuffix 的存量注释（实际早已是 extra，062 后返回按钮在 extra 最右端）。

## 安全反思

纯前端 UI 重构：无 API/权限/数据存储变更；唯一数据流改动是环路名称经回调上提（已有数据的只读展示）。
所有标题值均经 React 文本插值渲染（自动转义），无 XSS 注入面；无新增高权限操作或不安全默认配置。

## 已知限制

- ProcessEditor 因编辑器形态（未保存拦截、保存/删除控件）保留自建 Toolbar，仅对齐样式/位置/文案/标题，
  未强行套 PageCard；若未来编辑器重构可考虑完全统一。
- `titleSuffix` prop 保留（BlackboardPage 用于 MobileDebounceIndicator），但约定不再用于返回按钮。

---

## 1. 背景

M1 完成了工艺模板市场、安装、前端工艺库。M2 完成了运行时产物捕获、门禁引擎（含 skill 联动）、流转/返工、阶段驱动、审计 API/CLI、前端工艺执行看板。技能-工艺四元组（环节→skill→产物→门禁）已在前后端显性化。

M3 目标：让工艺管理从「能用」升级到「好用」——系统能推荐合适工艺、能评估做得怎么样、能持续进化模板。

---

## 2. M3 目标（必须可验证）

- **G1** 工艺路由：按任务描述、复杂度、风险自动推荐合适的工艺模板。
- **G2** 模板版本管理：模板更新后对比差异、提示实例升级选项（有意识选择）。
- **G3** 三层指标：结果指标（产出数量/质量）、过程指标（环节时长/返工率/人工干预率）、使用指标（各工艺采纳率/完成率）。
- **G4** 指标可视化：仪表盘展示工艺使用统计与趋势。
- **G5** 工艺模板在线编辑器：YAML 可视化编辑 + 校验 + 预览，替代文本编辑器。
- **G6** 四流闭环意识：在设计/实现中为任务流→洞察流→治理流→资产流闭环留出接口。

**M3 不做**：BPMN 并行网关/泳道/事件子流程、跨工作空间实例共享、外部系统集成。

---

## 3. 功能需求清单

### 3.1 工艺路由/推荐（G10）

- [ ] **F1.1** 新建 todo/loop 时，输入任务描述，系统按关键词 + 复杂度自动推荐 Top 3 工艺模板。
- [ ] **F1.2** 推荐依据：任务描述 embedding 相似度（可选）、关键词匹配、复杂度标签、历史采纳率。
- [ ] **F1.3** 前端在工艺库顶部增加搜索推荐栏。
- [ ] **F1.4** 用户可标记「此任务适合/不适合此工艺」，反馈反哺推荐模型。

### 3.2 模板版本管理

- [ ] **F2.1** 工艺模板表新增 `previous_version` 字段，记录上一版本 id。
- [ ] **F2.2** 模板更新同步后，展示版本 diff（definition YAML 逐段对比）。
- [ ] **F2.3** 已有 Loop 实例底部提示「模板已有新版本 vX.Y.Z」，用户可一键用新版本创建新 Loop。
- [ ] **F2.4** 版本历史列表：每个模板展示所有历史版本。

### 3.3 三层指标与仪表盘

- [ ] **F3.1** 结果指标：每个工艺实例的产物数量、门禁通过率、完成/失败。
- [ ] **F3.2** 过程指标：每个环节的均时长、返工次数分布、AI/人工占比。
- [ ] **F3.3** 使用指标：各工艺模板的安装次数、执行次数、完成率、用户评分。
- [ ] **F3.4** 新增 `/api/v1/processes/stats` 聚合 API。
- [ ] **F3.5** 前端新增「工艺仪表盘」页面（复用现有 dashboard 图表组件）。

### 3.4 可视化编排器

- [ ] **F4.1** 前端新增工艺模板编辑器页面，Tab 切换 YAML 文本/可视化预览。
- [ ] **F4.2** 支持创建/编辑/保存工艺模板（POST/PUT API），写入 `process_templates` 表。
- [ ] **F4.3** YAML 实时校验：保存时后端解析并返回错误行号/字段。
- [ ] **F4.4** 可视化预览：显示阶段流图（phase 节点 + link 箭头 + skill/artifact/gate 标注）。

### 3.5 四流闭环意识

- [ ] **F5.1** 设计上预留 `insight_events` 表（洞察流），记录每次工艺执行的改进建议（AI 生成）。
- [ ] **F5.2** 设计上预留 `governance_rules` 表（治理流），可配置「当某环节返工率 > X 时告警」。
- [ ] **F5.3** 设计上预留 `asset_evolution` 表（资产流），记录 skill / 工艺模板的版本进化链。
- [ ] **F5.4** M3 本期只做数据模型和接口 stub，不全量实现闭环逻辑。

---

## 4. 非目标（M4 或以后）

- 不实现真正的 LLM embedding 推荐（如需，用简单关键词匹配替代）。
- 不实现自动合并模板更新到已有实例。
- 不实现跨工作空间的指标聚合。
- 不实现指标告警推送（邮件/飞书）。
- 不实现工艺模板社区市场。

## 6. 接口约定

```text
# 工艺推荐
POST /api/v1/processes/recommend
  body: { description: "..." }
  → { recommendations: [{ template_name, score, reason }] }

# 版本管理
GET  /api/v1/processes/{name}/versions
GET  /api/v1/processes/{name}/versions/{version}/diff?base={base_version}

# 指标与仪表盘
GET  /api/v1/processes/stats
  → { template_usage: [...], avg_completion_rate, ... }

# 模板编辑
POST /api/v1/processes          body: { name, definition, ... }
PUT  /api/v1/processes/{name}   body: { definition, ... }
POST /api/v1/processes/{name}/validate  body: { definition }
```

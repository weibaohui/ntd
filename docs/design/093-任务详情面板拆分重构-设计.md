## 1. 背景

PR #998（委派任务隐藏「执行环路」「执行历史」Tab）落地后，`TaskDetailPanel.tsx` 暴露两个结构问题：

1. **数据/副作用逻辑揉在组件里**：两个 `useEffect`（拉任务详情、拉环路）+ 4 个 action handler（删除 / 再次执行 / 调接力上限 / 打开 Modal）无法脱离组件单测——这是最大的可测性盲区与 bug 风险源。
2. **文件过长（470 行）**：头部子组件 `RelayBadge` / `RelayMaxEditor` / `DetailHeader`（~186 行）本不该待在「面板」文件；主组件函数 ~200 行远超单函数体量建议。

本仓库已有可直接复用的同类先例：数据 hook 模板 `src/hooks/useRunningBoard.ts`、hook 测试模式 `src/components/todo-list/useBatchActions.test.tsx`、子组件外迁先例 `src/components/tasks/TaskDetailTabs.tsx`、类型收口目标 `src/types/task.ts`（其注释已点名 `TaskDetailData`/`StepInfo` 待收口）。

用户明确「要做就做彻底」，故把可测性盲区与文件臃肿一并解决。**目标：行为零变更的纯结构重构；数据层可单测；面板回归薄编排层。**

## 2. 拆分方案（分两步，同一 PR）

### 第一步：Tab 显隐逻辑抽纯函数
- `helpers.ts` 新增 `TaskTabKey` 类型 + `visibleTaskTabs` / `resolveTaskActiveTab` 纯函数。
- `TaskDetailPanel` 改为「声明式全量 4 Tab + 按可见集合过滤」+ 纯函数解析 activeKey。
- `helpers.test.ts` 补 9 条单测。

### 第二步：数据层抽 hook + 头部外迁 + 类型收口（本设计的主体）

**目标文件结构：**
```
src/types/task.ts                       收口 TaskDetailData / ExecInfo（原内联于面板）
src/hooks/useTaskDetail.ts        [新增] 数据 + 动作 hook（照 useRunningBoard 模板）
src/hooks/useTaskDetail.test.tsx  [新增] hook 单测（renderHook + mock）
src/components/tasks/TaskDetailHeader.tsx [新增] 头部子组件 + 纯函数（整段平移）
src/components/tasks/TaskDetailPanel.tsx  瘦身为薄编排层（~470 → ~150 行）
```

**2.1 `types/task.ts` — 收口类型**
把面板内联的 `TaskDetailData`、`ExecInfo` 搬来导出（更新文件头注释）。`steps: StepInfo[]` 跨文件 `import type` 自 `TaskDetailTabs`（StepInfo 与 Tab 组件强绑定，不强行搬迁，避免连带改动）。

**2.2 `useTaskDetail` hook — 数据 + 动作**
签名 `useTaskDetail(taskId, workspaceId, { onTitleReady, onTriggered, onLoopChanged }): TaskDetailState`。逐行平移面板的状态 / 两个 effect / 4 个 handler，导出 `TaskDetailState` 接口。保留 `alive` 竞态守卫、`eslint-disable` 注释、错误处理——**逻辑零改动**。提取内部 `refresh`（重拉详情）供 create/update 复用。`discussionRunning`（讨论角标纯展示态）不进 hook，留组件。

**2.3 `TaskDetailHeader.tsx` — 头部外迁**
整段平移 `isAutoRelayTask` / `assigneeLabel` / `RelayBadge` / `RelayMaxEditor` / `DetailHeader`，不改一行；类型从 `@/types/task` 导入，`styles` 复用面板的 CSS Module。（已确认这些符号均为面板内私有；todo 命名空间同名 `DetailHeader` 是另一文件，不受影响。）

**2.4 `TaskDetailPanel.tsx` — 瘦身**
删除搬走的类型 / 子组件 / 状态 / 副作用 / handler；`const t = useTaskDetail(...)` 一行接管数据/动作；保留 `discussionRunning` 态、`useProjectDirectories`、`useViewState`、`resolvedTab` 解析、`allTabs` 声明式组装 + 过滤 + activeKey、最终 JSX。主组件函数 ~200 → ~70 行。

## 3. 行为零变更的保证

- 逐行平移：effect 依赖数组、`alive` 守卫、`message` 文案、`throw e`（让 Popover 不关）等关键点原样保留。
- 不动 `TaskDetailTabs.tsx`（StepInfo 不搬迁）、不动 API/DB/状态机。
- 全量 Playwright 回归兜底（见 §4）。

## 4. 测试计划

- 前端：`npx tsc --noEmit` 零错误；`npx vitest run src/hooks/ src/components/tasks/`（89 条，含 hook 新增 10 条）；`npm run build` 无新告警。

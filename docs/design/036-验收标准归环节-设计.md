# 036-验收标准归环节-设计

| 修改人 | 修改时间 | 修改内容 |
|--------|---------|---------|
| Claude | 2026-07-29 | 初始版本 |

> 对应需求：`docs/requirements/036-验收标准归环节-需求.md`
> 分支：`feat/recipe-editor`
> 关键决策：彻底删除阶段级验收标准（定义字段 + 运行时死列 + UI），验收标准只归环节；**不处理存量兼容**。

---

## 1. 设计目标与原则

把验收标准从「阶段 + 环节」两层收敛到**只保留环节层**。核心原则：

1. **验收标准语义属环节**：评审逐环节进行，每个环节产物不同、验收标准各异，阶段层挂验收标准颗粒度过粗且与实际评审脱节。
2. **彻底删除而非保留**：阶段级的定义字段、运行时死列、UI 三处全部移除（用户已拍板「彻底删除字段」）。
3. **不动环节链路**：`LinkDefinition.acceptance_criteria` 及其安装→todo→评审→门禁的完整链路保持不变。

### 关键设计发现（阶段验收标准是死字段）

| 证据位置 | 事实 |
|---------|------|
| `installer.rs::resolve_link_fields` | 安装时把**环节** `acceptance_criteria` 灌进 todo（评审依据来自环节） |
| `auto_review.rs::compose_review_prompt` L320 | 评审合成 prompt 读 **todo 的** `acceptance_criteria` |
| `loop_runner.rs::apply_rating_gate` L1379 | 触发自动评审看**环节** `step_acceptance_criteria` |
| `phase_driver.rs` L89-91 | 阶段级 `acceptance_criteria` 恒为 `None`，注释自称「不做两层解析」 |
| `gates/ai_criteria_review.rs` L9 | 文档示例 `criteria_ref: "phase.acceptance_criteria"` 的**解析逻辑不存在**，`evaluate` 只读 rating/min_score |
| `loop_phases.acceptance_criteria` 列 | installer 写入后**全代码库无读取**（只写不读死列） |

结论：阶段级验收标准在运行时 100% 未被消费，删除零行为影响。

## 2. 数据模型变更

### 2.1 `PhaseDefinition`（工艺 YAML，`services/process/mod.rs`）

```rust
pub struct PhaseDefinition {
    pub id: String,
    pub name: String,
    #[serde(default)]
    pub spec: String,
    #[serde(default)]
    pub spec_ref: Option<String>,
    // 移除：pub acceptance_criteria: String
    // 移除：pub acceptance_criteria_ref: Option<String>
    #[serde(default)]
    pub links: Vec<LinkDefinition>,
}
```

> 不加 `#[serde(deny_unknown_fields)]`。旧 YAML 阶段层残留的 `acceptance_criteria` / `acceptance_criteria_ref` 在反序列化时被静默忽略丢弃——这正是「不处理存量兼容」的预期行为。

### 2.2 `loop_phases` 运行时表

删除列（migration v77）：

| 列 | 类型 | 处置 |
|----|------|------|
| `acceptance_criteria` | `TEXT NOT NULL DEFAULT ''` | **删除**（死列，只写不读） |

### 2.3 不变项

- `LinkDefinition.acceptance_criteria`（环节级，评审依据）——不动
- `StepTemplateDefinition.acceptance_criteria` / `BundledStepTemplateDefinition.acceptance_criteria`——不动
- `todos.acceptance_criteria`——不动
- 评审 prompt 的 `{{acceptance_criteria}}` 占位符——不动

## 4. Migration v77 设计

复用现成幂等删列工具 `drop_column_if_exists`（`db/migration/v2_v5.rs:1223`，先 `pragma_table_info` 检查列存在再 `ALTER TABLE ... DROP COLUMN`）：

```rust
//! V77 迁移：删除 loop_phases.acceptance_criteria 死列（需求 036）。
//! 阶段级验收标准已从工艺定义与运行时移除，验收标准只归环节。
//! 幂等：列不存在则跳过。
use super::drop_column_if_exists;
use crate::db::Database;

pub(super) struct V77DropLoopPhaseAcceptanceCriteria;

#[async_trait::async_trait]
impl Migration for V77DropLoopPhaseAcceptanceCriteria {
    fn version(&self) -> i64 { 77 }
    fn name(&self) -> &'static str { "V77DropLoopPhaseAcceptanceCriteria" }
    async fn up(&self, db: &Database) -> Result<(), sea_orm::DbErr> {
        drop_column_if_exists(db, "loop_phases", "acceptance_criteria").await
    }
}
```

注册：`mod.rs` 加 `mod v77;`（L37 后）+ `all_migrations()` 末尾（L121 后）追加 `Box::new(v77::V77DropLoopPhaseAcceptanceCriteria)`。

附 `#[cfg(test)]`：建 `loop_phases` 表（含该列）→ 跑 v77 → 断言列已不存在（参照 v71/v76 测试惯例）。

> 顺序：entity 删字段（编译期 SeaORM 不再引用该列）与 v77 migration 同 PR 合入；`acceptance_criteria` 是无约束 TEXT 列，SQLite DROP COLUMN 安全。

## 7. 约束遵循

- **单函数 ≤50 行**：本次以删除为主，不新增长函数；`resolve_phase_spec_refs` 删块后更短。
- **零告警**：`cargo clippy --all-targets -- -D warnings` + `npx tsc --noEmit` + `npm run build`。
- **注释**：改动处逐行说明「为什么」（为何删、为何保留环节级），同步更新过时注释（phase_driver / ai_criteria_review）。
- **`@/` 绝对路径**：前端跨目录导入统一 `@/`（本次改动不涉及新增导入）。
- **不处理存量兼容**：不写兜底、不迁移、不回填；旧 YAML 残留字段由 serde 忽略丢弃。

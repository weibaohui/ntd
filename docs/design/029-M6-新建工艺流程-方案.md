## 2. 技术决策

### 2.1 元信息 Modal 字段（对应设计 §4.1）

**决策**：收集 6 个字段，与 `ProcessTemplate` 后端模型对齐。

| 字段 | 类型 | 必填 | 校验 | 说明 |
|------|------|------|------|------|
| `name` | Input | ✅ | 非空 + `[a-z0-9-]+` + 唯一 | 工艺唯一标识，路由参数用 |
| `display_name` | Input | ✅ | 非空 | 列表页显示名 |
| `description` | Input.TextArea | ❌ | — | 工艺描述，可空 |
| `category` | Select | ❌ | — | 类别（software/research/writing/other），默认 software |
| `complexity` | Select | ❌ | — | 复杂度（lightweight/standard/complex），默认 lightweight |
| `version` | Input | ❌ | 语义版本格式 | 默认 `1.0.0` |

**`name` 实时校验**：
- 非空：`Form.rule required`
- 合法字符：`pattern: /^[a-z0-9-]+$/`（小写字母、数字、连字符）
- 唯一：`validator` 异步检查，用 `bundledApi.getProcesses` 列表比对（YAGNI，不调专用的 check API）

### 2.2 Modal 确认后的处理流程

**决策**：调 `POST /api/v1/processes` 创建空工艺，成功后跳路由进编辑器。

**处理流程**：
1. Modal 表单 `validateFields` 通过 → `setIsSubmitting(true)` 禁用按钮
2. 构造空工艺 YAML 文本：
   ```yaml
   process:
     name: <name>
     display_name: <display_name>
     description: <description>
     category: <category>
     complexity: <complexity>
     version: <version>
   phases: []
   ```
3. 调用 `bundledApi.postProcess(yamlText)`（`POST /api/v1/processes`，body 是 YAML 文本）
4. 成功 → `message.success("工艺已创建")` + 关闭 Modal + 跳路由 `/#/processes?processMode=edit&name=<name>`
5. 失败 → `message.error("创建失败：" + err.message)` + Modal 保持打开（让用户改元信息重试）

**空工艺 YAML 构造**：用 `yamlDump` 纯函数（M5 已实现），不手拼字符串。

### 2.3 空工艺渲染（对应设计 §8 + 需求 §3.8）

**决策**：`ProcessVisualEditor` 加 `definition.phases?.length === 0` 分支，渲染 `Empty` + CTA 按钮。

**实现**：
```tsx
// ProcessVisualEditor 内部
if (!definition.phases || definition.phases.length === 0) {
  return (
    <div style={emptyContainerStyle}>
      <Empty
        description="还没有任何阶段"
        image={Empty.PRESENTED_IMAGE_SIMPLE}
      >
        <Button
          type="primary"
          icon={<PlusOutlined />}
          onClick={handleAddPhase}
        >
          新增阶段
        </Button>
      </Empty>
    </div>
  );
}
// 否则渲染 React Flow（M4 已实现）
return <ReactFlow ... />;
```

**`handleAddPhase`**：调用 `processDefinitionUpdater.addPhase`（M4 已实现）生成第一个 phase，通过 `onDefinitionChange` 回写父组件。

### 2.4 列表页入口按钮（对应需求 §3.5.2）

**决策**：`ProcessPage` 列表页右上角加「＋ 创建工艺」按钮，点击弹 `CreateProcessMetaModal`。

**实现**：`ProcessPage` 列表页头部加按钮 + Modal 状态控制：
```tsx
// ProcessPage 内部
const [createModalOpen, setCreateModalOpen] = useState(false);
// 按钮
<Button
  type="primary"
  icon={<PlusOutlined />}
  onClick={() => setCreateModalOpen(true)}
>
  创建工艺
</Button>
// Modal
<CreateProcessMetaModal
  open={createModalOpen}
  onClose={() => setCreateModalOpen(false)}
  onCreated={(name) => {
    setCreateModalOpen(false);
    // 跳路由进编辑器
    window.location.hash = `#/processes?processMode=edit&name=${encodeURIComponent(name)}`;
  }}
/>
```

### 2.5 `postProcess` API 客户端方法

**决策**：`bundled.ts` 新增 `postProcess`，与 M5 的 `putProcess` 风格一致。

**实现**：
```typescript
async postProcess(yamlText: string): Promise<void> {
  // content-type 用 text/yaml，后端 handler 直接读 body 为 String
  await api.post('/api/v1/processes', yamlText, {
    headers: { 'Content-Type': 'text/yaml' },
  });
}
```

**注意**：后端 `POST /api/v1/processes` 返回 `201 Created` + 新工艺的 `name`，但 M6 前端已知道 `name`（Modal 输入），无需读 response body。

### 2.6 M6 的组件结构

```
ProcessPage (列表页，M6 加入口按钮 + Modal 触发)
  ├─ 列表页头部「＋ 创建工艺」按钮 (M6 新增)
  └ CreateProcessMetaModal (M6 新增)

  └ ProcessVisualEditor (M6 加 phases.length===0 分支)
      ├─ 空工艺：Empty + CTA「新增阶段」按钮
      └ 非空：React Flow（M4 已实现）
```

**职责**：新建工艺时的元信息收集 Modal。

**接口**：

```typescript
interface CreateProcessMetaModalProps {
  // Modal 是否打开
  open: boolean;
  // 关闭回调（点击遮罩/取消按钮时触发）
  onClose: () => void;
  // 创建成功回调（传入新工艺的 name，供父组件跳路由）
  onCreated: (name: string) => void;
}
```

**实现要点**：
- Ant Design `Modal` + `Form` 6 字段（§2.1）
- `name` 字段异步校验唯一性：`bundledApi.getProcesses` 列表比对
- 提交时构造空工艺 YAML（用 `yamlDump`）+ 调 `bundledApi.postProcess`
- 成功后 `onCreated(name)`，失败后 Modal 保持打开 + `message.error`
- `category` / `complexity` 用 Ant Design `Select`，预设选项

#### 3.1.2 `frontend/src/components/process/buildEmptyProcessYaml.ts`

**职责**：纯函数，根据元信息构造空工艺 YAML 文本。便于单元测试。

**接口**：
```typescript
interface ProcessMetaInput {
  name: string;
  display_name: string;
  description?: string;
  category?: string;
  complexity?: string;
  version?: string;
}

function buildEmptyProcessYaml(meta: ProcessMetaInput): string;
```

**实现**：用 `yamlDump` 序列化 `{ process: {...}, phases: [] }` 结构。

**单元测试**（vitest）：
- `buildEmptyProcessYaml_minimalFields` — 仅 name + display_name，输出含必填字段
- `buildEmptyProcessYaml_allFields` — 全字段，输出含所有元信息
- `buildEmptyProcessYaml_emptyPhases` — phases 恒为空数组
- `buildEmptyProcessYaml_dumpRoundTrip` — dump 后再 parse 能还原

## 4. 数据流

### 4.1 新建工艺数据流

```
ProcessPage (列表页)
  ┌ 点击「＋ 创建工艺」按钮
  │   └ setCreateModalOpen(true)
  └
CreateProcessMetaModal (Modal)
  ├─ 用户填 6 字段 Form
  ├─ name 字段异步校验唯一性（bundledApi.getProcesses 列表比对）
  ┌ 点击确定
  │   ├─ validateFields → 通过
  │   ├─ setIsSubmitting(true)
  │   ├─ buildEmptyProcessYaml(meta) → yamlText
  │   ├─ bundledApi.postProcess(yamlText)
  │   ├─ 成功 → message.success + onCreated(name)
  │   │           └ ProcessPage: setCreateModalOpen(false) + 路路由进编辑器
  │   └ 失败 → message.error + Modal 保持打开
  └
```

### 4.2 空工艺渲染数据流

```
ProcessEditor (加载空工艺，phases: [])
  ↓ definition (phases 为空数组)
ProcessVisualEditor
  ├─ definition.phases?.length === 0 ?
  │   ├─ 是 → 渲染 Empty + CTA「新增阶段」按钮
  │   │       ┌ 点击 CTA
  │   │       │   └ handleAddPhase → addPhase(definition) → onDefinitionChange
  │   │       └ 父组件 setDefinition → 重渲染 → phases.length > 0 → 渲染 React Flow
  │   └ 否 → 渲染 React Flow（M4 已实现）
```

## 7. 风险与缓解

| 风险 | 缓解措施 |
|------|---------|
| `name` 唯一性校验竞态（用户快速输入触发多次 `getProcesses`） | 用 debounce 300ms + `useRef` 存最新输入，校验回调取 ref 值 |
| `POST /api/v1/processes` 后端返回 409（重名）但前端已校验唯一 | 兜底：catch 409 时 `message.error("工艺已存在，请改名")`，Modal 保持打开 |
| 空工艺 YAML 的 `phases: []` 在后端 serde_yaml 反序列化时可能被当 None | M1 后端已处理 `phases` 缺失或空数组均为空 Vec，M6 不动后端 |
| `Empty.PRESENTED_IMAGE_SIMPLE` 在 Ant Design v5 的 API 稳定性 | v5 稳定，M6 直接用；若 v6 变更则 M7 评估 |
| CTA 按钮点击后第一个 phase 的默认位置 | `addPhase` 纯函数（M4）已处理默认位置，M6 不特殊处理 |

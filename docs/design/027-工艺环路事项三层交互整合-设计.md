## 1. 设计总览

需求目标：把数据层已存在的「任务 → 工艺 → 环路 → 事项」链路显性化到界面。本设计按三个批次交付，每批独立 PR：

| 批次 | 内容 | 需求目标 |
|------|------|---------|
| P0 | 三层链路补全（API + 跳转 + 面包屑 + 引用区块） | G2/G3/G4/G5/G6 |
| P1 | 工艺详情可视化（三 Tab + 只读流程图 template 样式） | G1 |
| P2 | 信息架构（导航顺序、统一追溯链路、执行看板复用、清理） | G7/G8/G9/G10 |

核心设计决策：

1. **工艺 definition 在前端解析**：`js-yaml@4.1.1` 已是前端依赖，详情接口已返回 `definition` 字符串，无需后端新增解析接口。
2. **流程图布局逻辑复用**：把 `LoopFlowGraph.tsx` 内的私有 `useFlowLayout` 抽为公共 hook 并泛化输入，工艺侧通过适配层把 `LinkDefinition` 映射为相同形状；节点渲染抽为 `FlowStepNode` 组件，用 `variant: 'instance' | 'template'` 区分样式。
3. **样式差异化可参数化**：用户已确认先做「模板感」差异化样式，与环路实例样式对比后二选一。variant 参数保证最终切换只是改默认值，不返工。
4. **新 API 路径用 `{name}` 而非 `{id}`**：现有 `/api/v1/processes/{name}/versions`、`/copy-to-user` 均以 name 寻址，保持一致。

## 2. 后端设计（P0）

### 2.1 新 API：按工艺查实例环路列表

```text
GET /api/v1/processes/{name}/loops
→ 200 { success: true, data: ProcessLoopItem[] }   （按 created_at DESC，无实例时空数组）
→ 404 { success: false, error: "工艺模板不存在: {name}" }
```

```rust
// backend/src/models/process.rs（新增，或就近放入现有 models）
pub struct ProcessLoopItem {
    pub id: i64,
    pub name: String,
    pub description: String,
    pub status: String,
    pub workspace_id: Option<i64>,
    /// 实例化时的工艺版本快照（loops.process_template_version 已有列）
    pub process_template_version: Option<String>,
    pub created_at: Option<String>,
    /// 执行次数聚合（loop_executions COUNT），前端列表展示用
    pub execution_count: i64,
}
```

- Handler：`backend/src/handlers/process.rs` 新增 `list_process_loops`，注册进 `v1_process_routes()`。
- 数据访问：`backend/src/db/loop_.rs` 新增 `list_loops_by_process_template(template_id)`——先按 name 查 `process_templates` 得 id，再查 `loops.process_template_id = id`，LEFT JOIN 聚合执行数。
- 权限：工艺与环路均为全局可见（无 workspace 隔离先例可循，与 `list_process_templates` 同级）；环路含 `workspace_id` 字段原样返回，前端自行标注工作空间。

### 2.2 LoopDto 扩展（环路来源面包屑用）

现状：`LoopDto`（`backend/src/models/loop_.rs:120`）只有 `process_template_id`，**漏了实体已有的 `process_template_version` 列**（`backend/src/db/entity/loops.rs:41`）。

扩展三个字段，避免前端为面包屑二次查询：

```rust
pub struct LoopDto {
    // ...现有字段...
    pub process_template_id: Option<i64>,
    /// 新增：实例化时的工艺版本快照（实体列已存在，DTO 补齐）
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub process_template_version: Option<String>,
    /// 新增：工艺模板唯一名（JOIN process_templates 查询，面包屑跳转用）
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub process_template_name: Option<String>,
    /// 新增：工艺模板显示名（面包屑展示用）
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub process_template_display_name: Option<String>,
}
```

- `From<loops::Model>` 保持纯字段映射（补 version）；name/display_name 仿照 `with_tags` 模式加 `with_process_template(meta)` 方法，由 handler 在查询边界外注入（仅 `process_template_id` 非空时查一次 `process_templates`，避免 N+1）。
- 注入点：`GET /api/loops/{id}` 详情接口（`handlers/loop_.rs:138` 附近）。列表接口不注入（用不到，省查询）。

### 2.3 事项被环路引用查询（事项详情「所属环路」用）

现状：`referencing_loops: LoopRefSummary[]` 已在 `GET /api/v1/workspaces/{ws}/todos/center` 中组装（`types/todo.ts:63` 前端已消费）。事项详情页数据来自全局 state `todos`，不带该字段。

设计：把 center 里的引用查询 SQL 抽为 `Database::list_referencing_loops(todo_id) -> Vec<LoopRefSummary>`，新增轻量接口：

```text
GET /api/v1/todos/{id}/referencing-loops
→ 200 { success: true, data: LoopRefSummary[] }   （含 loop_id/loop_name/step_id/step_name，以现有 center 结构为准）
```

事项详情页挂载时按需请求，不污染主 todos 列表查询。

### 2.4 实体/迁移漂移修复

`process_templates.previous_version_id`（v72 迁移原生 SQL 加的列）未同步进 `backend/src/db/entity/process_templates.rs`。本期只补实体字段（`Option<i64>`），让 ORM 层可读；版本链 UI 不做。

### 2.5 后端单元测试

- `list_loops_by_process_template`：只返回目标工艺的环路；空结果；按 created_at DESC；execution_count 聚合正确。
- `LoopDto::with_process_template`：字段注入与 None 透传。
- handler 测试：`/api/v1/processes/{name}/loops` 200/404；`/api/v1/todos/{id}/referencing-loops` 空数组与多引用。
- 安装→查询集成路径：install 后列表包含新环路（可并入现有安装集成测试文件）。

## 3. 前端设计

### 3.1 loop-flow 重构：抽布局 hook 与节点组件（P1 前置）

现状 `LoopFlowGraph.tsx` 403 行，文件头自述「500 行硬限」。直接加 variant 分支会超限，故先重构：

```text
components/loop-flow/
  LoopFlowGraph.tsx     组装器（变瘦，<200 行）
  useFlowLayout.ts      新增：从 LoopFlowGraph 抽出，输入泛化为 FlowLayoutStep[]
  FlowStepNode.tsx      新增：单节点 SVG 渲染，props: { node, selected, variant, onSelect, onOpenTodo? }
  FlowEdge.tsx          不动
  FlowVirtualNodes.tsx  不动
  flowConstants.ts      不动
  flowTypes.ts          补充 FlowLayoutStep 接口与 variant 类型
```

泛化输入接口（`flowTypes.ts`）：

```typescript
/** 布局层需要的最小环节形状：LoopStepDto 与工艺 LinkDefinition 适配结果都满足它。 */
export interface FlowLayoutStep {
  id: number;                    // 布局用数字 id（工艺侧由 index 合成）
  name: string;
  on_success: string;            // next / goto / end / break 等
  success_goto_step_id: number | null;
  on_rating_fail: string;
  fail_goto_step_id: number | null;
  min_rating: number | null;
  phase_id: number | null;       // 色带哈希用（工艺侧由 phase index 合成）
}
```

- `useFlowLayout` 只依赖上述字段，现有 `LoopStepDto` 天然满足（`@/types/loop` 中字段同名），环路页行为零变化。
- `FlowStepNode` 的 `variant='instance'` 渲染现有全部内容（todo 标题/executor/闸门/已归档）；`variant='template'` 渲染模板信息（见 3.3）。
- **回归保障**：重构不改变任何视觉与交互，用现有环路页 Playwright 用例回归（无则用例则先补一个流程图渲染基线用例）。

### 3.2 工艺流程图适配层（P1 核心）

新增 `frontend/src/utils/processFlowAdapter.ts`：

```typescript
/** 把工艺 definition（YAML 解析结果）展开为全局环节序列 + 布局输入。
 *  展开顺序 = phases 声明顺序 × 各 phase 内 links 声明顺序（与 installer.rs 实例化顺序一致）。 */
export function adaptDefinitionToFlow(def: ProcessDefinitionYaml): {
  steps: FlowLayoutStep[];        // 布局输入
  extras: TemplateNodeExtra[];    // 与 steps 同序的模板展示数据（skills/产物/门禁/原型名等）
  phases: { key: string; name: string }[];  // 阶段泳道数据
}
```

边策略映射（与 `installer.rs:375-379` 语义对齐）：

| YAML 值 | success_goto_step_id | 说明 |
|---------|---------------------|------|
| `next`（默认） | null | 布局层按顺序连下一环节（现有 classifyEdge 已处理 next） |
| `end` | null | on_success='end'，布局层连 End 虚拟节点 |
| `break` | null | 不出边（中断语义，与实例化后无 goto 一致） |
| `goto:<link_id>` | 目标 link 的合成数字 id | 字符串 link id → 全局序列 index+1 合成；目标不存在时降级为 `break` 并在节点上标 warning |

失败边取 `on_gate_fail`（非默认 `break` 时优先），否则 `on_rating_fail`，与 installer.rs:293 的回退逻辑一致。

YAML 解析失败（用户层手改损坏）：适配层抛错，流程图 Tab 捕获后渲染 `Alert`（错误信息 + 引导切到「YAML 源」Tab），不白屏（需求 §6.3）。

## 6. 安全与风险

### 6.1 安全自查

- 新 API 均为只读 GET；`{name}` 参数走 SeaORM 参数化查询，无注入面。
- 前端 js-yaml 解析用户层 YAML：`js-yaml@4` 默认 `JSON_SCHEMA` 安全模式（不执行自定义类型），无代码执行风险；解析失败有 Alert 降级。
- 跳转均走前端 hash 路由，无开放重定向面。
- 权限：新接口与现有 process/todo 只读接口同级（无额外越权面）；事项引用接口按 todo 所在 workspace 校验归属（与 todos/center 一致）。

### 6.2 风险与对策

| 风险 | 对策 |
|------|------|
| 3.1 重构影响环路页 | 抽出的 hook/组件保持签名与渲染输出一致；先补基线 Playwright 用例再动手 |
| 工艺 link id 重复/缺失导致适配层合成 id 冲突 | 合成 id 用全局 index 而非 link id 哈希；`goto:` 目标缺失降级 break + warning 标记 |
| template/instance 样式最终二选一 | variant 参数化，切换只改默认值；对比评审结论记入实现总结 |
| LoopDto 加字段后旧前端/外部调用方 | 新字段 `skip_serializing_if = "Option::is_none"`，None 时不出现在 JSON，零破坏 |

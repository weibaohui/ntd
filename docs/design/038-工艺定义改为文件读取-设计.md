# 设计：工艺定义不再落库，改为从文件读取（038）

## 1. 方案概述

把 `process_templates.definition` 这一列**整体移除**，DB 退化成"文件路径索引 + 外键锚点"。
需要工艺正文时，用已存在的 `source_path` 字段解析到磁盘真实文件并读取。

`source_path` 现有两种前缀，解析规则：

| `source_path` | 解析到磁盘 |
|---|---|
| `bundled://processes/software/x.yaml` | `git_sync::bundled_dir(local_path).join("processes/software/x.yaml")`（默认 `~/.ntd/bundled/processes/...`） |
| `user://software/x.yaml` | `user_processes_dir().join("software/x.yaml")`（即 `~/.ntd/processes/...`） |

其中 `git_sync::bundled_dir(local_path)`（`backend/src/git_sync/mod.rs:267`）与 `user_processes_dir()`
（`backend/src/services/process/user_dir.rs`）已是现成函数，直接复用，避免重新发明路径拼接。

## 3. 新增 source 解析模块

新增 `backend/src/services/process/source.rs`，统一"source_path → 文件内容"的解析，避免散落在多处重复拼接：

```rust
// source_path 两种前缀 → 磁盘路径；无法识别返回 None。
pub fn resolve_source_path(source_path: &str, local_path: &str) -> Option<PathBuf>

// 读取工艺定义正文；文件缺失/读取失败映射为 ProcessSourceError。
pub fn read_definition(source_path: &str, local_path: &str) -> Result<String, ProcessSourceError>
```

- `ProcessSourceError` 为新增小枚举（`NotFound` / `Read(io::Error)`）。
- 实现 `From<ProcessSourceError> for AppError` 与 `From<ProcessSourceError> for InstallError`，
  使 handler（返回 `AppError`）与 installer（返回 `InstallError`）都能用 `?` 直接传播错误。

> 为什么集中到新模块而不是在 handler 里各写一遍：路径前缀规则只有两处，集中后改一处即可，
> 也便于单测覆盖 `bundled://` / `user://` / 非法前缀三种情况。

## 5. 测试计划

1. **source 解析单测**：`bundled://` / `user://` 正确解析；非法前缀返回 `None`；缺失文件返回 `NotFound`。
2. **v78 迁移单测**：在 `:memory:` 库建带 `definition` 列的 `process_templates`（`CREATE TABLE` 内联），
   跑 `up()` 后断言 `table_has_column(db,"process_templates","definition")` 为 false。
3. **installer 单测**：依赖项改为传入 `definition` 字符串，验证安装产物不变（原 2 个用例平移）。
4. **既有 `bundled.rs` 导入测试**：这些测试写临时 YAML 并导入，断言能从 DB 读到元数据；
   改造后其"详情接口应返回与文件一致的正文"应补充一条基于文件读取的断言。

## 6. 风险与回滚

- **风险**：任何 `source_path` 与实际文件不一致（如导入时写错 path）会导致读取失败。
  缓解：导入时已按真实文件路径生成 `source_path`，且 `copy` / `install` 均在读取失败时返回明确错误而非静默空内容。
- **回滚**：迁移只删一列、不删数据；如需回滚可手动 `ALTER TABLE ... ADD COLUMN definition TEXT`，
  但历史正文已不可恢复——因此合并前需在 dev 库验证功能完整。

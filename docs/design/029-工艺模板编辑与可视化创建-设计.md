## 1. 设计目标

对应 `docs/requirements/029-工艺模板编辑与可视化创建-需求.md` 的 3 个核心目标：

1. **工艺 YAML 可编辑**：用户工艺可编辑保存，系统工艺只读 + "复制到用户层"
2. **可视化创建工艺**：泳道图式 React Flow 编辑器，横向加 phase，纵向加 link
3. **YAML ↔ 可视化双向联动**：单一 `ProcessDefinition` 对象 + sync flag 防循环

### 2.1 新增 API

#### 2.1.1 `PUT /api/v1/processes/{name}` — 保存编辑后的 YAML

```rust
pub async fn update_process(
    State(state): State<AppState>,
    Path(name): Path<String>,
    Json(req): Json<UpdateProcessRequest>,
) -> Result<impl IntoResponse, AppError>
```

**处理流程**（3 步，每步职责单一，单函数体 < 30 行）：

```text
1. validate_process_name(&name)?                          // 路径注入防御
2. let template = db.get_process_template_by_name(&name)  // 加载现有工艺
       .await?.ok_or(AppError::NotFound)?;
3. if template.is_system {                                // 系统工艺拒绝直接编辑
       return Err(AppError::Conflict(
           "系统工艺不可直接编辑，请先复制到用户层"));
   }
4. serde_yaml::from_str::<ProcessDefinition>(&req.definition)  // 结构校验
       .map_err(|e| AppError::BadRequest(e.to_string()))?;
5. let target_path = compute_user_process_path(&template)?;    // 计算用户目录路径
6. atomic_write(&target_path, &req.definition)?;              // 临时文件 + rename
7. import_user_process_templates(&state).await?;             // 刷新入库
8. Ok(ApiResponse::ok(json!({ "updated_at": now })))
```

**请求/响应类型**：

```rust
#[derive(Deserialize)]
pub struct UpdateProcessRequest {
    pub definition: String,
}

#[derive(Serialize)]
pub struct UpdateProcessResponse {
    pub updated_at: String,
}
```

| HTTP | 场景 |
|------|------|
| 400 | YAML 结构校验失败（serde 错误消息含 line/column） |

### 2.3 共享工具函数

在 `backend/src/handlers/process.rs` 提取 3 个 helper（每个 < 15 行，职责单一）：

```rust
/// 计算用户工艺文件路径：~/.ntd/processes/<rel_path>
/// rel_path 从 source_path 剥 "user://" 前缀，若无则用 <name>.yaml
fn compute_user_process_path(template: &process_templates::Model) -> Result<PathBuf, AppError> {
    let user_dir = user_processes_dir()
        .ok_or_else(|| AppError::Internal("无法获取 home 目录".to_string()))?;
    let rel_path = template.source_path
        .as_ref()
        .and_then(|s| s.strip_prefix("user://"))
        .unwrap_or(&format!("{}.yaml", template.name));
    Ok(user_dir.join(rel_path))
}

/// 原子写盘：临时文件 + rename，避免崩溃导致文件损坏。
fn atomic_write(path: &Path, content: &str) -> Result<(), AppError> {
    if let Some(parent) = path.parent() {
        std::fs::create_dir_all(parent)
            .map_err(|e| AppError::Internal(format!("创建目录失败: {}", e)))?;
    }
    let tmp = path.with_extension("tmp");
    std::fs::write(&tmp, content)
        .map_err(|e| AppError::Internal(format!("写入临时文件失败: {}", e)))?;
    std::fs::rename(&tmp, path)
        .map_err(|e| AppError::Internal(format!("rename 失败: {}", e)))?;
    Ok(())
}

/// name 合法字符校验：^[a-zA-Z0-9_-]+$
fn validate_name_regex(name: &str) -> Result<(), AppError> {
    let valid = name.chars().all(|c| c.is_ascii_alphanumeric() || c == '_' || c == '-');
    if !valid {
        return Err(AppError::BadRequest(
            "工艺名称只能包含字母、数字、下划线、连字符".to_string(),
        ));
    }
    Ok(())
}
```

### 4.3 数据流：YAML ↔ 可视化双向联动

#### 4.3.1 可视化 → YAML

```typescript
// 用户在 React Flow 上增删 phase/link、改属性面板字段、拖连线
// → 修改 ProcessDefinition 对象对应字段
// → 立即 yaml.dump(definition) 刷新 Monaco 内容

function handleVisualChange(newDefinition: ProcessDefinition) {
  if (isSyncing) return;  // 防止 YAML→可视化 触发的回写
  setIsSyncing(true);
  setDefinition(newDefinition);
  setYamlText(yaml.dump(newDefinition));
  setIsDirty(true);
  setTimeout(() => setIsSyncing(false), 0);  // 下一个 tick 清 flag
}
```

#### 4.3.2 YAML → 可视化

```typescript
// 用户在 Monaco 编辑 YAML 文本
// → onChange 触发 debounced (300ms) yaml.load()
// → 成功则更新 ProcessDefinition 对象 → React Flow 节点重渲染
// → 失败则只在 Monaco 标红错误，不破坏当前可视化状态

const handleYamlChange = useMemo(() =>
  debounce((newText: string) => {
    if (isSyncing) return;
    try {
      const parsed = yaml.load(newText) as ProcessDefinition;
      setIsSyncing(true);
      setDefinition(parsed);
      setYamlText(newText);
      setIsDirty(true);
      clearMonacoErrors();
      setTimeout(() => setIsSyncing(false), 0);
    } catch (e) {
      setMonacoError(e);  // 在 Monaco 行号槽标红波浪线 + 浮窗
      // 不更新 definition / 不破坏可视化状态
    }
  }, 300),
  [isSyncing]
);
```

#### 4.3.3 sync flag 时序

```text
可视化操作 → setDefinition → yaml.dump → setYamlText → Monaco onChange 触发
                                                                  ↓
                                          isSyncing=true 拦截 → 不再 parse
                                                                  ↓
                                          setTimeout tick → isSyncing=false
```

关键点：`setIsSyncing(true)` 在 `setYamlText` **之前**设置，确保 Monaco 的 `onChange` 回调执行时 flag 已生效；`setTimeout(..., 0)` 在下一个事件循环清 flag，避免同步执行链中 flag 过早失效。

### 5.2 节点类型

注册两个自定义节点类型：

```typescript
const nodeTypes = {
  phase: PhaseNode,   // 横向泳道容器
  link: LinkNode,     // 环节卡片
};
```

#### 5.2.1 PhaseNode（泳道容器）

**职责**：渲染一个矩形容器，头部显示 `phase.name` + 删除按钮，内部纵向排列 LinkNode 子节点。

**React Flow group 节点语义**：
- PhaseNode 的 `position` + `width` + `height` 定义容器边界
- 内部 LinkNode 的 `parentNode` 指向 PhaseNode id，`position` 相对于父节点
- React Flow 自动处理"拖动父节点移动子节点"

**视觉**：
- 容器背景：`rgba(phaseColor, 0.05)`
- 容器边框：`1px dashed phaseColor`
- 头部：`▸ {phase.name}` + 右上角小叉号删除按钮
- 内部：纵向 flex 布局，每个 LinkNode 之间间距 16px

**交互**：
- 点击头部 → 选中 phase → 右侧属性面板切换到 `PhasePropertyForm`
- 点击删除按钮 → 弹 `Modal.confirm`（级联重置悬空 goto 引用，见 §5.5）

#### 5.2.2 LinkNode（环节卡片）

**职责**：渲染一个环节卡片，显示 `link.name` + `step_template`，右侧两个 handle 供连线。

**视觉**：
- 卡片宽度：240px，高度：自适应内容（~80px）
- 卡片背景：白色，边框：`1px solid #e2e8f0`，圆角：8px
- 内容：`{link.name}` + 小字 `{step_template || '无原型引用'}`
- 右侧两个 source handle：
  - 上方绿色 handle = `on_success` 连线起点
  - 下方橙色 handle = `on_gate_fail` 连线起点
- 左侧一个 target handle：连线终点

**交互**：
- 点击卡片 → 选中 link → 右侧属性面板切换到 `LinkPropertyForm`
- 从绿色 handle 拖出线 → 松开在目标 LinkNode 的 target handle 上 → 触发 `onConnect` → 更新 `on_success: goto:<target_id>`
- 从橙色 handle 拖出线 → 同上 → 更新 `on_gate_fail: goto:<target_id>`

### 5.3 布局算法

#### 5.3.1 横向布局（dagre）

按 `phases` 数组顺序从左到右排列 PhaseNode：

```typescript
function layoutPhases(phases: PhaseDefinition[]): Map<string, { x: number; y: number }> {
  const g = new dagre.graphlib.Graph();
  g.setGraph({ rankdir: 'LR', ranksep: 80 });
  g.setDefaultEdgeLabel(() => ({}));

  // 每个 phase 是一个节点，宽度 = max(内部 link 宽度) + padding，高度 = links.length * (link高度+间距)
  phases.forEach((phase, i) => {
    const linkCount = phase.links?.length ?? 0;
    const width = NODE_WIDTH + 40;     // 280px
    const height = linkCount * (NODE_HEIGHT + 16) + 60;  // 头部 60px
    g.setNode(`phase-${i}`, { width, height });
    if (i > 0) g.setEdge(`phase-${i-1}`, `phase-${i}`);  // 顺序连边
  });

  dagre.layout(g);
  // 返回每个 phase 的左上角坐标
  return new Map(phases.map((_, i) => {
    const node = g.node(`phase-${i}`);
    return [`phase-${i}`, { x: node.x - node.width / 2, y: node.y - node.height / 2 }];
  }));
}
```

#### 5.3.2 纵向布局（phase 内部 flex）

每个 PhaseNode 内部用 CSS flex 纵向排列 LinkNode，间距固定 16px，头部 60px：

```typescript
function layoutLinksInPhase(phase: PhaseDefinition, phaseIndex: number) {

  }));
}
```

#### 5.4.2 onConnect 处理

```typescript
function handleConnect(connection: Connection) {
  // connection.sourceHandle 区分 on_success / on_gate_fail
  // sourceHandle 命名约定：'on_success' | 'on_gate_fail'
  const handleType = connection.sourceHandle;  // 'on_success' | 'on_gate_fail'
  const targetNodeId = connection.target;
  const targetLink = findLinkByNodeId(targetNodeId);
  const targetId = targetLink?.id;

  if (!targetId) return;

  // 更新 ProcessDefinition 对应 link 的 on_success / on_gate_fail
  const newDefinition = updateLinkField(
    definition,
    sourceLinkPhaseIndex,
    sourceLinkIndex,
    handleType,           // 'on_success' | 'on_gate_fail'
    `goto:${targetId}`
  );
  handleVisualChange(newDefinition);
}
```

#### 5.4.3 删除连线

```typescript
function ProcessEdge({ id, sourceX, sourceY, targetX, targetY, data }: EdgeProps) {
  const [hovered, setHovered] = useState(false);
  const midX = (sourceX + targetX) / 2;
  const midY = (sourceY + targetY) / 2;

  return (
    <>
      <BaseEdge
        id={id}
        path={getSmoothStepPath({ sourceX, sourceY, targetX, targetY })}
        style={{ stroke: data.color, strokeDasharray: data.dashed ? '6,3' : undefined }}
        onMouseEnter={() => setHovered(true)}
        onMouseLeave={() => setHovered(false)}

        <g onMouseEnter={() => setHovered(true)} onMouseLeave={() => setHovered(false)}>
          <circle cx={midX} cy={midY} r={10} fill="#fff" stroke="#ef4444" />

```

点击叉号 → 调用 `onDelete(edgeId)` → 把对应 link 的 `on_success` / `on_gate_fail` 重置为默认值（`next` / `break`）。

### 5.5 删除节点级联处理

#### 5.5.1 删除 link 节点

拦截 React Flow `onNodesDelete`，弹 `Modal.confirm`：

```typescript
function handleDeleteLinkNode(linkId: string, linkName: string) {
  // 查找所有引用此 link 的 goto
  const referrers = findGotoReferrers(definition, linkId);
  Modal.confirm({
    title: `删除环节「${linkName}」？`,
    content: referrers.length > 0
      ? `有 ${referrers.length} 处其他环节的跳转引用了此环节，将被重置为 next/break。`
      : '此环节无被引用的跳转。',
    onOk: () => {
      const newDefinition = removeLinkAndResetGoto(definition, linkId);
      handleVisualChange(newDefinition);
    },
  });
}
```

`removeLinkAndResetGoto` 逻辑：
1. 从 `phases[].links[]` 移除该 link
2. 遍历所有 link，把 `on_success: goto:<被删link.id>` 重置为 `next`
3. 把 `on_gate_fail: goto:<被删link.id>` 重置为 `break`

#### 5.5.2 删除 phase 容器

泳道头部删除按钮点击：

```typescript
function handleDeletePhase(phaseId: string, phaseName: string) {
  const phase = definition.phases?.find(p => p.id === phaseId);
  const linkCount = phase?.links?.length ?? 0;
  // 查找所有引用本阶段环节的 goto
  const referrers = findGotoReferrersForPhase(definition, phaseId);

  Modal.confirm({
    title: `删除阶段「${phaseName}」？`,
    content: `将删除本阶段及其下 ${linkCount} 个环节。` +
      (referrers.length > 0
        ? `有 ${referrers.length} 处其他环节的跳转引用了本阶段的环节，将被重置为 next/break。`
        : ''),
    onOk: () => {
      // 遍历 phase 下所有 link，对每一个执行"删除 link 时重置悬空 goto"
      const newDefinition = removePhaseAndResetGoto(definition, phaseId);
      handleVisualChange(newDefinition);
    },
  });
}
```

```typescript
interface ProcessYamlEditorProps {
  value: string;                // YAML 文本
  onChange: (newText: string) => void;
  error: YamlError | null;      // 解析错误，用于标红
  readOnly?: boolean;           // 系统工艺只读
}

export function ProcessYamlEditor({ value, onChange, error, readOnly }: ProcessYamlEditorProps) {
  const editorRef = useRef<monaco.editor.IStandaloneCodeEditor | null>(null);
  const [decorations, setDecorations] = useState<string[]>([]);

  // 错误标记：error 不为 null 时，在对应行号槽标红波浪线
  useEffect(() => {
    if (!editorRef.current || !error) {
      setDecorations([]);
      return;
    }
    const newDecorations = editorRef.current.deltaDecorations(decorations, [
      {
        range: new monaco.Range(error.line, 1, error.line, 1),
        options: {
          isWholeLine: true,
          className: 'yaml-error-line',
          glyphMarginClassName: 'yaml-error-glyph',
          hoverMessage: { value: error.message },
        },
      },
    ]);
    setDecorations(newDecorations);
  }, [error]);

  return (
    <Editor
      height="100%"
      language="yaml"
      theme="vs-dark"
      value={value}
      onChange={(v) => onChange(v ?? '')}
      onMount={(editor) => { editorRef.current = editor; }}
      options={{
        readOnly,
        minimap: { enabled: false },
        fontSize: 13,
        lineNumbers: 'on',
        glyphMargin: true,  // 行号槽，用于标红
        scrollBeyondLastLine: false,
      }}
    />
  );
}
```

## 9. 前端设计：未保存修改的离开拦截

### 9.1 isDirty 状态

用户改了任何字段（`definition` 或 `yamlText` 变更）就置 `isDirty = true`，保存成功后置回 `false`。

### 9.2 路由内跳转拦截

用 React Router v6 的 `useBlocker`（项目需确认 React Router 版本，若 < 6.4 则用 `unstable_usePrompt`）：

```typescript
import { useBlocker } from 'react-router-dom';

function ProcessEditor() {
  const isDirty = useProcessEditorStore(s => s.isDirty);

  const blocker = useBlocker(({ currentLocation, nextLocation }) =>
    isDirty && currentLocation.pathname !== nextLocation.pathname
  );

  useEffect(() => {
    if (blocker.state === 'blocked') {
      Modal.confirm({
        title: '你有未保存的修改',
        content: '确认离开？未保存的修改将丢失。',
        onOk: () => blocker.proceed(),
        onCancel: () => blocker.reset(),
      });
    }
  }, [blocker]);

  // ...
}
```

> **注**：项目现有路由是 `useViewState` 的 hash 路由，非 React Router。若沿用 hash 路由，需在 `useViewState` 的 `pushUrl` / `replaceUrl` 入口加 `isDirty` 检查 + `Modal.confirm` 拦截。设计阶段需确认是否引入 React Router，或在现有 hash 路由基础上扩展拦截能力。

### 9.3 刷新/关页签拦截

```typescript
useEffect(() => {
  const handler = (e: BeforeUnloadEvent) => {
    if (isDirty) {
      e.preventDefault();
      e.returnValue = '';  // 兼容旧浏览器
    }
  };
  window.addEventListener('beforeunload', handler);
  return () => window.removeEventListener('beforeunload', handler);
}, [isDirty]);
```

## 15. 风险与缓解

| 风险 | 缓解措施 |
|------|---------|
| Monaco 包体积大（~2MB） | 按需动态 import，只在打开 YAML 编辑时加载 |
| React Flow v12 学习曲线 | 团队已有 dagre 经验，React Flow 文档完善 |
| YAML ↔ 可视化双向联动循环 | sync flag 机制，一方推送时另一方忽略 onChange |
| 删除 phase 级联重置悬空 goto 引用 | 弹 `Modal.confirm` 明确告知受影响数量，重置策略用"回退到默认值" |

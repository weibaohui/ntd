# 030-任务详情页 Tabs 布局重设计

| 修改人 | 修改时间 | 修改内容 |
|--------|---------|---------|
| CodeBuddy | 2026-07-28 | 初始版本 — 将单栏堆叠的 TaskDetailPanel 改为「顶部条 + Tabs」布局 |

---

## 1. 背景与问题

`TaskDetailPanel.tsx` 当前为**单栏竖排全宽**：概览 Descriptions → 工艺要求 Collapse → 执行历史 → 嵌入 `ProcessExecutionBoard`。实测痛点：

1. 执行看板嵌在窄栏下方，把页面撑得极长，往上翻才能看任务上下文。
2. 工艺要求用「卡片套卡片」，视觉沉重；行内 Tag 换行排版乱。
3. 「再次执行」主操作埋在「执行历史」小标题旁，不突出。
4. 进详情页第一眼看不到「最近一次执行进度」等关键状态。

决策（用户确认）：采用 **标签页 Tabs** 方案。

---

## 2. 设计方案

### 2.1 结构总览

```
┌─ PageCard 标题：任务详情              [← 返回列表]       │
├────────────────────────────────────────────────────────┤
│ TaskDetailPanel                                            │
│ ┌─ 顶部条（sticky）─────────────────────────────────┐   │
│ │ #123 任务标题                      [⚡ 再次执行]     │   │
│ │ 模板 v3 · 复杂度 中 · 状态 运行中                  │   │
│ └────────────────────────────────────────────────────┘   │
│ ┌─ Tabs ───────────────────────────────────────────┐    │
│ │ [概览] [工艺要求] [执行历史]                       │    │
│ │ ─────────────────────────────────────────────────  │    │
│ │ (tab 内容，全宽，独立滚动)                         │    │
│ └────────────────────────────────────────────────────┘   │
└────────────────────────────────────────────────────────┘
```

### 2.2 三个 Tab

- **概览**：任务标题/模板/版本/复杂度/状态 Descriptions + 需求描述 + 最近一次执行进度条（Progress）。
- **工艺要求**：步骤列表，去掉「卡片套卡片」，改为带序号徽标 + 细分隔线的轻量列表项；技能/产物/门禁分组展示，换行更整齐。
- **执行历史**：执行列表；点「查看详情」在 **tab 内容区全宽** 展开 `ProcessExecutionBoard`（不再被窄栏挤压）。

### 2.3 顶部条

- 任务标题（`#id` + 标题）+ 一行元信息（模板·版本·复杂度·状态）。
- 「再次执行」主按钮右对齐、始终可见（跨 Tab 不丢失）。

### 2.4 样式方案

- 新增 `TaskDetailPanel.module.css`：顶部条、Tabs 填满高度并让内容区 `overflow:auto`、步骤列表项样式。
- 主题用 CSS 变量 / antd token，避免硬编码颜色。
- 响应式：窄屏下顶部条换行（标题与按钮上下排列），Tabs 内部均自适应宽度。

## 4. 预期效果

- 进详情页第一眼看到任务状态 + 最近执行进度；主操作随时可点。
- 工艺要求与执行历史分 Tab，互不干扰；看板拿到全宽空间，密集数据看得清。
- 整体从「一长条堆叠」变为「顶部条 + 分组标签」，层次清晰、滚动可控。

---

## 5. 安全反思

- 复用现有 `bundledApi.getTaskDetail` / `createTaskExecution`，不新增 API。
- 任务标题/需求来自后端，React 默认转义，不使用 `dangerouslySetInnerHTML`。
- 输入校验：再次执行 Modal 校验需求非空（沿用既有逻辑）。

# 设计：工艺列表拆分「我的 / 模板」双视图（039）

## 1. 方案概述

区分系统/用户的字段 `is_system` 已贯通 DB → 后端 DTO → 前端类型，无需迁移。方案分两层：

- **后端**：`list_process_templates` 全链路加 `is_system: Option<bool>` 过滤（DB → Handler 查询参数），
  不传参保持全量返回，向后兼容。
- **前端**：工艺列表页顶部加 `Segmented`（我的 / 模板），切换即按视图调带参接口重新拉取；
  视图选择写 localStorage 持久化。

控件选型 `Segmented` 而非 `Tabs`：项目内同列表视图切换已有先例（`frontend/src/components/SkillsPanel.tsx:32`、
`TasksPage.tsx:215`），视觉轻量、不遮挡现有搜索/筛选栏。

## 2. 后端改动

### 2.1 DB 层（`backend/src/db/process_template.rs`）

`list_process_templates`（第 29 行）签名加过滤参数：

```rust
// is_system 为 Some 时按系统/用户过滤；None 返回全量（兼容统计、推荐等旧调用方）。
pub async fn list_process_templates(
    &self,
    is_system: Option<bool>,
) -> Result<Vec<process_templates::Model>, sea_orm::DbErr>
```

实现上 `Some(v)` 时追加 `.filter(process_templates::Column::IsSystem.eq(v))`。
现有 3 个内部调用方（`backend/src/handlers/process.rs:705/726/824`，统计/推荐类逻辑）改传 `None`，
语义不变。

### 2.2 Handler 层（`backend/src/handlers/process.rs`）

`list_process_templates`（第 109 行）加 `Query<ListProcessTemplatesQuery>`：

```rust
// serde(default) 保证不传参时反序列化为 None，旧客户端零影响。
#[derive(serde::Deserialize)]
pub struct ListProcessTemplatesQuery {
    #[serde(default)]
    is_system: Option<bool>,
}
```

透传给 DB 层。`/api/bundled/processes` 与 `/api/v1/bundled/processes` 共用该 handler
（路由注册见 `process.rs:1002/1013`），两个入口同时获得过滤能力。

### 2.3 后端单测（内联 `#[cfg(test)]`）

- DB 层（`:memory:` 库）：`Some(true)` 只返回系统模板、`Some(false)` 只返回用户模板、`None` 返回全部。
- 查询结构体解析：缺省 / `is_system=true` / `is_system=false` 三种 URL 反序列化结果正确。

## 3. 前端改动

### 3.1 API 层（`frontend/src/api/bundled.ts`）

`getProcesses`（第 452 行）加可选参数：

```ts
// isSystem 有值时服务端过滤；不传保持全量（设置页模板管理仍用全量）。
getProcesses(isSystem?: boolean)
```

有值时拼 `?is_system=true|false`。

### 3.2 工艺列表页（`frontend/src/components/ProcessPage.tsx`，`ProcessListView` 内）

1. **视图状态 + 持久化**：`scope: 'mine' | 'template'`，localStorage key `ntd_process_list_scope`。
   初始化读取、非法值回退 `'mine'`；切换时写入。默认 `'mine'`——用户日常高频操作是管理自己的工艺。
2. **按视图拉取**：`load()` 调 `getProcesses(scope === 'template')`；`useEffect` 依赖加 `scope`，
   切换视图重新拉取对应子集。
3. **Segmented 布局**：在搜索栏（第 240-261 行）上方独占一行；不带数量徽标（服务端过滤后拿不到
   对侧数量，YAGNI）。
4. **搜索过滤保持客户端**：现有 `searchText` 过滤（第 284 行）作用于当前视图子集，
   切换视图不清空搜索词。
5. **空态文案按视图区分**：
   - 「我的」空：`暂无自定义工艺，可点击右上角「创建工艺」`
   - 「模板」空：`暂无系统模板，请先在「更多设置 → 模板管理」执行同步`
6. **卡片操作不变**：系统卡片本就不渲染「编辑」按钮（第 311 行 `!p.is_system` 条件），
   拆视图后「我的」视图有 详情/安装/编辑，「模板」视图有 详情/安装，无需新增判断。
7. **函数拆分**：卡片渲染抽成 `renderProcessCard(p: ProcessTemplate)` 小函数，控制嵌套层级与函数长度。

### 3.3 同名覆盖语义（无需处理，注释说明）

用户「复制到用户层」后同名工艺的 `is_system` 翻转为 false，会自然出现在「我的」视图——正是期望行为。

2. **前端**：`npx tsc --noEmit` 零错误。
3. **Playwright**（`make dev` 起 18088 后，更新 `frontend/tests/check_process_page.spec.ts`）：

   - 切「模板」只显示系统工艺（卡片无「编辑」按钮）且 localStorage 写入 `template`
   - 刷新后保持「模板」视图；切回「我的」卡片有「编辑」按钮
   - 两个视图空态文案正确
4. **接口手测**：`curl 'http://localhost:18088/api/bundled/processes?is_system=true'` 只返回系统模板，
   不传参返回全部。

## 5. 风险与回滚

- **风险低**：后端是加可选参数（不传行为不变）；前端是一个页面的展示层改动。
- **回滚**：直接 revert commit 即可，无数据结构变更。

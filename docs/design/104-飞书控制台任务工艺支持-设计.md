# 104 - 飞书控制台任务工艺支持

> 关联需求：`docs/requirements/104-飞书控制台任务工艺支持-需求.md`。
> 用户澄清结论：1a（扩展现有 /help 控制台为 6 Tab）2a（仅环路模式任务可一键再执行，委派仅展示）3c（工艺仅查看）4a（每页 10 条、最多 20 条）。

## 1. 背景

`/help` 控制台（`feishu_card.rs` 的 `build_help_console_card`）现有 4 Tab：状态/事项/环路/工作空间。事项与环路的支持链路已经成熟，可直接作为「任务」「工艺」两个新 Tab 的模板复制扩展。任务（tasks）与工艺（process_templates）在飞书侧目前零暴露。

## 2. 现状链路（复用对象）

1. `/help` 命令 → `feishu_slash_commands.rs::handle_help` → `assemble_help_card_state(ctx, db, bot_id, group, page)` 查 DB 组装 `HelpCardState` → `build_help_console_card(&state)` 渲染 → `reply_card` 发送。
2. Tab 按钮：`help_tabs(current)` 生成 `nav:/help <key>` 按钮，当前 Tab primary 高亮。
3. 页面：`build_todo_page`/`build_loop_page` 每页 10 条 list_item + `pagination_buttons(kind, page, total)`（kind="todos"/"loops"）。
4. 回调：`feishu_card_actions.rs::handle_card_callback` 分流 `nav:/help <group>` / `nav:/todos <page>` / `act:/runtodo <id>` 等；act 执行后 `patch_after_action` 重查状态、顶部插入结果提示并 patch 原卡片。
5. `CardAction` 枚举在 `feishu_listener.rs`，`parse_card_action` 在 `feishu_card_actions.rs`。

## 3. 设计总览

### 3.1 Tab 扩展（feishu_card.rs）

`help_tabs` 从 4 项扩为 6 项（每行 2 个、共 3 行）：

```text
状态 | 事项
环路 | 任务
工艺 | 工作空间
```

Tab key：`status / todo / loop / task / process / workspace`。

### 3.2 HelpCardState 新增字段与条目结构

```rust
pub struct HelpCardState {
    // ……既有字段不动……
    /// 任务列表（任务页，按 workspace）
    pub tasks: Vec<TaskItem>,
    /// 工艺模板列表（工艺页：系统内置 + 当前 workspace 用户模板）
    pub processes: Vec<ProcessItem>,
}

/// 任务列表项（任务页）。
pub struct TaskItem {
    pub id: i64,
    pub title: String,
    /// pending ⏸️ / running ⏳ / success ✅ / failed ❌，未知回退 ⏸️
    pub status_icon: String,
    /// 执行方式标签：「环路」/「委派@<处理人>」/未知模式原值
    pub mode_label: String,
    /// 是否可一键再执行（execution_mode=loop 且有 loop_id）
    pub runnable: bool,
}

/// 工艺模板列表项（工艺页，纯查看无按钮）。
pub struct ProcessItem {
    pub display_name: String,
    /// 复杂度（light/standard/complex）+ 版本 + 系统/用户标识
    pub meta: String,
}
```

### 3.3 页面渲染

- `build_task_page`：可执行任务用 `list_item_btn("**<标题>**", "执行", …, "act:/runtask <id>")`；不可执行任务（委派/无 loop）用 markdown 行渲染（`⏸️ **标题** · 委派@xx`），不给按钮；分页 `pagination_buttons("tasks", …)`。
- `build_process_page`：全部用 markdown 行渲染（`**<display_name>** · <复杂度> · v<版本> · <系统/用户>`），无按钮；分页 `pagination_buttons("processes", …)`。
- `pagination_buttons` 无需改动——kind 直接传 "tasks"/"processes" 即可复用（`nav:/tasks`、`nav:/processes`）。

### 3.4 状态组装（feishu_slash_commands.rs）

`assemble_help_card_state` 增加两段查询（失败降级为空列表并 error 日志，口径对齐 todos）：

- 任务：`db.list_tasks(wid, None)` → `take(20)` → `task_to_item`（含 runnable 判断：`execution_mode=="loop" && loop_id.is_some()`；委派标签 `委派@assignee_name`）。
- 工艺：`db.list_process_templates(None)` → 过滤 `workspace_id.is_none() || workspace_id==wid`（系统内置 + 当前 workspace）→ 按 name 升序（DB 已排序）→ `take(20)` → `process_to_item`（meta 拼复杂度/版本/系统或用户）。

### 3.5 回调路由（feishu_card_actions.rs + feishu_listener.rs）

- `CardAction` 增加 `RunTask(i64)`；`parse_card_action` 增加 `"runtask" => RunTask(arg.parse()?)`。
- `handle_nav_action`：todos/loops/tasks/processes 四个列表 Tab 的分页解析统一收敛到纯函数 `parse_nav_page(action) -> Option<(&'static str, usize)>`（前缀 → Tab key + 页码回退 1），命中后以 (group, page) 重查并 patch；`nav:/help`、`nav:/history` 仍走独立分支。
- `run_card_action` / `action_target_group` 增加 `RunTask` → `act_run_task` / 刷新回 "task"。

### 3.6 act_run_task 实现

```text
1. bot_workspace_id(context)：区分「未设置」与 DB 错误，None → 失败提示「未设置工作空间」，Err → 「查询工作空间失败」。
2. db.get_task(id)：不存在 → 「任务 #id 不存在」；DB 错误 → 「查询任务失败」（不伪装成不存在）。
3. validate_task_runnable(task, workspace_id)：归属 / execution_mode=loop / loop_id 三重校验（纯函数，可单测），失败返回具体原因。
4. 取 loop_runner（debounce.loop_runner()），None → 失败提示「环路执行器未就绪」。
5. spawn_run(loop_id, None, "feishu_card", {"requirement": task.description, "source": "task"}, bot_id, receive_id, receive_id_type)
   → 得到 loop_execution_id（飞书层无 loop_trigger_dispatcher，spawn_run 是等价触发路径，meta 口径与 handlers/tasks.rs 一致）。
   返回 -1（创建 loop_execution 失败）时直接报失败——没有可绑定的执行，不能假成功。
6. db.update_loop_execution_task_id(exec_id, task.id) 绑定；失败只 warn 不阻断（执行已触发，需求 §10）。
7. 返回 ActionOutcome{success:true, "已触发任务「title」"}，由 patch_after_action 刷新回任务页并插入提示。
```

## 5. 规模与安全

- 卡片体积：每页 10 条 list_item/markdown 行 + 3 行 Tab + 分页按钮，与事项/环路页同量级，飞书元素上限内。
- 安全口径完全对齐 act_run_todo/act_run_loop：workspace 归属校验 + 执行前实体存在性校验；新增 execution_mode/loop_id 校验，拒绝委派任务与无环路任务。
- 查询失败降级：todos 已有 error 日志 + 空列表降级模板，任务/工艺照抄该口径，不静默吞错。

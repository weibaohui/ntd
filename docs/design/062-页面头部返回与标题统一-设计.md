## 1. 总体思路

以 `PageCard` 为唯一收口点：新增 `onBack` / `backLabel` props，由 PageCard 把返回按钮统一渲染到 extra 区**最右端**（页面操作按钮之后）。各页面删除手写返回按钮，改为传参。标题按 `模块名 #{id}: {具体名称}` 逐页对齐。

不改动 `titleSuffix` prop 本身（BlackboardPage 仍用它放 MobileDebounceIndicator，非返回按钮，不受影响）。

## 2. PageCard 改造（components/common/PageCard.tsx）

```tsx
interface PageCardProps {
  // ...既有 props 不变
  /** 传入后在页头 extra 区最右端渲染统一返回按钮。 */
  onBack?: () => void;
  /** 返回按钮文案，默认「返回列表」；目标非列表时传「返回」。 */
  backLabel?: string;
}
```

渲染逻辑：
- `onBack` 存在时生成 `<Button size="small" type="text" icon={<ArrowLeftOutlined />}>{backLabel ?? '返回列表'}</Button>`；
- extra 区内容 = `{extra}{backButton}`，即返回按钮永远最右；
- `extra` 与 `onBack` 都为空时不渲染 extra 容器（保持现状行为）。

`.ntd-page-card-extra` 已有 `display:flex; gap:8px; justify-content:flex-end`，追加按钮无需改 CSS。

## 4. 环路名称上提（LoopDetailPage 唯一的数据流改动）

`LoopStudioDetailPanel` 内部持有 `detail.name`，但 `hideTitleRow=true` 时内层标题行整体隐藏，环路名无处展示。
参照 `TaskDetailPanel.onTitleReady` 既有模式：

- `LoopStudioDetailPanel` 新增 `onTitleReady?: (name: string) => void` prop；
- 在现有「detail 变化上报 onActionsReady」的 effect 中同步调用 `onTitleReady(detail.name)`；
- `LoopDetailPage` 用 `useState` 存名字，标题 = `环路 #{id}` + （名字就绪后）`: {name}`。

注意引用稳定性：回调需 `useCallback`/setState 函数式更新，避免 NTD-007 记录过的 effect 死循环。

## 5. 不改动的部分

- 列表页标题（纯模块名）已统一，不动。
- ProcessEditor 仍用自建 Toolbar（有未保存拦截、保存/删除等编辑器特有控件），只对齐样式/位置/文案/标题，不强行套 PageCard。
- `backToList` 导航逻辑（replaceUrl/history.back 策略）不变，只改按钮呈现。

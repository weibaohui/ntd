# 027-资源贡献扩展-设计

| 修改人 | 修改时间 | 修改内容 |
|--------|---------|---------|
| AI | 2026-08-14 | 初始版本：专家贡献（026）扩展到事项模板 / 技能 / 工艺三类资源 |

---

# 1. 设计目标

在 026「专家贡献」已建成的贡献通道（PAT 管理 + ActionButton + AI 提示词驱动提交 PR）之上，把「分享到官方仓库」扩展到 **事项模板 / 技能 / 工艺** 三类资源。复用 026 全部基础设施，只做「资源适配」：通用化分享按钮、按资源类型出提示词、为事项模板补后端 YAML 导出能力。

对应需求：`docs/requirements/027-资源贡献扩展-需求.md`。

# 2. 总体架构

```
用户点「分享」（资源行操作区）
  └─ ShareToRepoButton（通用，由 ContributeButton 抽取）
       ├─（可选）onPrepare()：事项模板先调后端导出 YAML → 拿到本地文件路径
       ├─ GET /api/v1/contribution/auth/status
       │    ├─ 未配置 PAT → 提示并跳「设置 → 第三方授权 → GitCode」（与 026 一致）
       │    └─ 已配置 → 渲染 ActionButton（action_type 按资源区分）
       │         prompt = buildResourceContributePrompt(params)（按资源类型）
       │         AI 读 PAT → fork → 建分支 → 写文件（远端子目录）→ 建 PR
       └─ 展示 PR 链接
```

远端仓库目录结构（已确认，与同步源一致）：

```
ntd-resource/
├── experts/      → contents/experts/{name}/…          （专家，目录）
├── processes/    → contents/processes/{name}.yaml     （工艺，单文件，按 category 子目录）
├── skills/       → contents/skills/{source}/{skill}/…（技能，目录）
└── todos/        → contents/todos/{title}.yaml        （事项模板，单文件）
```

# 3. 前端设计

## 3.1 通用分享按钮 `ShareToRepoButton`（新组件）

从 `experts/ContributeButton.tsx` 抽取通用逻辑，新文件 `frontend/src/components/settings/contribute/ShareToRepoButton.tsx`：

```ts
interface ShareToRepoButtonProps {
  resourceName: string;    // 资源名（PR 标题/分支名用）
  version?: string;        // 版本（可选）
  resourceDir: string;     // 待提交文件/目录路径（~ 相对路径，调用方负责 toHomePath）
  actionType: string;      // expert_contribute | process_contribute | todo_contribute | skill_contribute
  panelTitle: string;      // ActionButton 面板标题
  panelDescription: string;// 面板说明
  buildPrompt: () => string; // 提示词构建函数（按资源类型）
  /** 可选：点击分享后先执行的准备动作（如事项模板导出 YAML），返回新的 resourceDir */
  onPrepare?: () => Promise<string | undefined>;
  size?: 'small' | 'middle';
}
```

交互流程（与现有 ContributeButton 完全一致）：
1. 点击 →（onPrepare）→ 查 PAT 配置态
2. 未配置 → `message.info` + `showView('settings', { tab: 'thirdParty' })` 跳转
3. 已配置 → 切 ActionButton（提示词可编辑、选执行器、看日志、展示 PR 链接）

`experts/ContributeButton.tsx` 改为 `ShareToRepoButton` 的薄封装（专家参数 + 专家提示词），**对外接口不变**，现有 2 个专家调用点零改动。

## 3.2 提示词泛化 `contributePrompts.ts`（新文件）

新文件 `frontend/src/components/settings/contribute/contributePrompts.ts`，抽公共模板（PAT 读取、GitCode API 步骤、安全约束），按资源类型参数化：

```ts
interface ContributePromptParams {
  type: 'expert' | 'process' | 'todo' | 'skill';
  resourceName: string;  // 占位符 {{resource_name}}
  version?: string;
  resourceDir: string;   // {{resource_dir}}（~ 相对）
  remotePath: string;    // 远端目标路径（如 contents/processes/{name}.yaml）
  isDirectory: boolean;  // true=遍历目录（expert/skill）；false=单文件（process/todo）
  titlePrefix: string;   // PR 标题前缀：[专家贡献]/[工艺贡献]/[模板贡献]/[技能贡献]
}
export function buildResourceContributePrompt(p: ContributePromptParams): string;
```

- **expert**（目录）：`remotePath=contents/experts/{name}/`，遍历目录跳过 `.downloaded_at/.clawhub/.git`
- **process**（单文件）：`remotePath=contents/processes/{name}.yaml`（category 有子目录时 `processes/{category}/{name}.yaml`），单文件读取提交
- **todo**（单文件）：`remotePath=contents/todos/{title}.yaml`，单文件读取提交
- **skill**（目录）：`remotePath=contents/skills/{source}/{skill}/`，遍历目录跳过同步元数据

`experts/contributePrompt.ts` 保留 `buildContributePrompt()`（专家版，内部调公共模板），026 的 Playwright 用例与既有引用零改动。

## 3.3 工艺分享（ProcessTemplatesTab）

行操作区（当前「查看 + 系统行复制到用户层」）追加：**用户行（`is_system=false`）渲染分享按钮**。

```tsx
{!record.is_system && (
  <ShareToRepoButton
    resourceName={record.name}
    version={record.version}
    resourceDir={toHomePath(record.source_path)}   // ~/.ntd/processes/{name}.yaml
    actionType="process_contribute"
    panelTitle={`分享工艺 ${record.display_name || record.name}`}
    buildPrompt={() => buildProcessPrompt(record)}
    size="small"
  />
)}
```

远端路径：`processes/{category}/{name}.yaml`（category 非空且有远端匹配）或 `processes/{name}.yaml` 兜底。

## 3.4 事项模板分享（TodoTemplatesTab）

行操作区（当前「编辑/复制/删除」）追加：**用户行（`is_system=false`）渲染分享按钮**，点击时先经 `onPrepare` 导出 YAML：

```tsx
{!record.is_system && (
  <ShareToRepoButton
    resourceName={record.title}
    resourceDir=""  // 由 onPrepare 返回
    actionType="todo_contribute"
    panelTitle={`分享事项模板 ${record.title}`}
    buildPrompt={() => buildTodoPrompt(record.title)}
    onPrepare={() => exportTodoTemplateYaml(record.id)}  // 返回导出文件路径
    size="small"
  />
)}
```

远端路径：`todos/{title}.yaml`（title 做安全化，与后端导出文件名一致）。

## 3.5 技能分享（SkillTemplatesTab）

行操作区（当前无操作列，纯展示）新增「分享」列：**全部行渲染分享按钮（不做来源守卫，用户明确要求）**：

```tsx
<ShareToRepoButton
  resourceName={record.short_name}
  version={record.version}
  resourceDir={toHomePath(`~/.ntd/bundled/skills/${record.name}`)}  // name = {source}/{skill}
  actionType="skill_contribute"
  panelTitle={`分享技能 ${record.short_name}`}
  buildPrompt={() => buildSkillPrompt(record)}
  size="small"
/>
```

远端路径：`skills/{record.name}/`（保持来源集合结构）。

# 4. 后端设计

## 4.1 事项模板导出接口（唯一后端改动）

`backend/src/handlers/todo_template.rs` 新增：

```
GET /api/v1/todo-templates/:id/export
请求：无
响应：{ path: "~/.ntd/contribution-export/todos/{safe_title}.yaml" }
```

逻辑：
1. 按 id 查模板；不存在 → NotFound。
2. `is_system=true` → BadRequest（「系统模板不可导出」）。
3. `safe_title`：去空白/路径分隔符/非法字符（`..` 防越界），空则用 id 兜底。
4. serde_yaml 序列化 `{title, category, prompt, sort_order}`（与远端 `todos/*.yaml` 字段对齐）。
5. 写入 `~/.ntd/contribution-export/todos/{safe_title}.yaml`（目录不存在则创建，同名覆盖）。
6. 返回 `~/` 相对路径（复用 toHomePath 语义，不暴露家目录用户名）。

前端 `utils/database/todos.ts` 新增 `exportTodoTemplateYaml(id): Promise<string>`（返回 path）。

## 4.2 复用（零改动）

- PAT：`contribution/pat.rs` + `handlers/contribution.rs`（与资源类型无关）
- ActionButton 执行链路：`POST /api/v1/actions/execute`

# 5. 安全设计

- PAT 沿用 026（0600、Debug 脱敏、不内联提示词）。
- 导出文件名安全化（防路径逃逸）；导出目录限定 `~/.ntd/contribution-export/todos/`。
- 提示词要求 AI 输出不回显 PAT 明文；PR 由维护者 review 兜底。

# 6. 测试计划

- **后端单测**（todo_template.rs）：导出成功（YAML 字段与远端对齐）、系统模板拒绝、非法标题名安全化、目录自动创建。
- **前端**：`npx tsc --noEmit` 零错误；`npm run build` 成功。
- **Playwright**：
  - 工艺 Tab：系统行无分享 / 用户行有分享（行内断言）。
  - 事项模板 Tab：系统行无分享 / 用户行有分享；点击用户行分享（桩 PAT）→ 导出成功 → Drawer 提示词含 `todos/` 路径与导出文件路径。
  - Skill 模板 Tab：全部行有分享；点击（桩 PAT）→ Drawer 提示词含 `skills/` 路径。
  - 专家 026 用例回归（4 个全过）。

# 7. 关键决策记录

- **ShareToRepoButton 通用化而非 4 个复制组件**：PAT 检查 + ActionButton 渲染逻辑 4 类完全一致，只差异在参数与提示词，抽公共组件消除重复（DRY）。
- **专家薄封装保留对外接口**：现有 2 个专家调用点与 026 spec 零改动，降低回归风险。
- **事项模板用后端导出 YAML**：模板存 DB、AI 执行器只能读文件，必须后端先落盘；导出目录独立于 bundled 与用户目录，避免污染同步源。
- **技能全量可分享**：用户明确要求不区分来源；分享入口覆盖 bundled 技能列表（`~/.ntd/bundled/skills/`），用户自建技能（执行器目录）本期不单独处理。

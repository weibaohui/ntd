## 1. 概述

本文档描述 032 三个功能的实现方案：详情标题动态化、工艺列展示、工艺实例环路升级。这些改动分布在前后端多个文件，属于 029 工艺编辑器生态的收尾增强。

## 2. 功能一：详情标题动态化

### 2.1 现状

`TaskDetailPage` 和 `TodoDetailPage` 的 PageCard `title` 是静态字符串，数据加载后不更新：
- 任务：`title={`任务 #${taskId}`}`
- 事项：`title={`事项 #${todoId}`}`

### 2.2 方案

| 组件 | 方案 | 说明 |
|------|------|------|
| TodoDetailPage | 从 `actionsCtx.todo.title` 读取 | `onActionsReady` 回调已有的 `TodoDetailActionsProps.todo.title` |
| TaskDetailPage | `TaskDetailPanel` 新增 `onTitleReady` 回调 | 数据加载完成后将 `task.title` 上报给 PageCard |

**数据流（TaskDetailPage）：**

```
TaskDetailPanel (内部加载任务数据)
  → onTitleReady(task.title)
  → TaskDetailPage setDetailTitle(...)
  → PageCard title={detailTitle}
```

### 2.3 回退策略

数据未加载或加载失败时标题保持 `#{id}` 格式，不会显示 undefined/null。

## 3. 功能二：工艺列展示

### 3.1 现状

| 视图 | 当前工艺信息 |
|------|------------|
| 事项列表 (TodoListView) | 无，只有 `referencing_loops` 字段但未展示 |
| 任务列表 (TasksTableView) | 列名「模板」 |
| 任务详情概览 Tab (TaskDetailPanel) | Descriptions 条目名「模板」 |

### 3.2 方案

| 视图 | 改动 | 数据来源 |
|------|------|---------|
| TodoListView | 新增「工艺」列（在「调度」之后） | `record.referencing_loops[]` — 各 Loop 的 `.loop_name` |
| TasksTableView | 「模板」→「工艺模板」 | `record.template_name`（不变） |
| TaskDetailPanel | 「模板」→「工艺模板」 | `template.display_name`（不变） |

### 3.3 设计决策

- **事项列表**不直接展示 process_template_name 是因为 `TodoCenterItem` 的后端响应不含该字段。现用 `referencing_loops[].loop_name` 间接展示（Loop 名通常包含模板名）。如需精确展示可在后续迭代往 `LoopRefSummary` 追加 `process_template_name` 字段。
- **任务列表和详情**只是列名/标签名改名，数据结构和 API 不变。

## 4. 功能三：工艺实例环路升级

### 4.1 现状

工艺模板编辑保存后（含自动版本递增），已安装的 Loop 仍使用旧版本。当前没有任何机制让旧 Loop 升级到最新版本——用户只能删除重建。

### 4.2 后端设计

#### 4.2.1 新端点

```
POST /api/v1/processes/{name}/loops/{loop_id}/upgrade
Request Body: 空
Response: { loop_id, loop_name, phase_count, step_count }
```

#### 4.2.2 处理流程

```
1. 获取工艺模板（404 如果不存在）
2. 获取 Loop（404 如果不存在）
3. 校验 Loop.process_template_id == template.id（400 如果不匹配）
4. 获取 loop.workspace_id → 解析 workspace.path
5. 调用升级服务函数
   a. 解析模板最新定义 YAML
   b. 获取旧 loop_steps 及其 todo_id
   c. 使用 SeaORM EntityTrait 删除：
      - loop_steps（WHERE loop_id=xx）
      - loop_phases（WHERE loop_id=xx，ON DELETE CASCADE 自动清理 loop_phase_executions）
   d. 软删除旧步骤关联的 todos（delete_todo 设置 deleted_at）
   e. 更新 Loop：name/description/limits_config/process_template_version
   f. 重新调用 create_phases_and_steps 创建新的阶段和步骤
   g. 解析 goto 目标
6. 返回 InstallProcessResponse
```

#### 4.2.3 安全考量

- **FK 约束**：`loop_steps` 与 `loop_step_executions` 之间无 FK 约束（历史 step_id 引用保留）；`loop_phases` 的 `ON DELETE CASCADE` 自动清理 `loop_phase_executions`。
- **数据保留**：`loop_executions` 记录保留不删；`loop_step_executions` 保留旧 step_id 引用（无 FK，SQLite 不报错）。
- **todo 软删除**：旧步骤关联的 todo 通过 `deleted_at` 标记删除，不物理删除，可恢复。

#### 4.2.4 升级函数签名

```rust
pub async fn upgrade_process_template_loop(
    db: &Database,
    template: &process_templates::Model,
    loop_id: i64,
    workspace_id: i64,
    workspace_path: &str,
) -> Result<InstallResult, InstallError>
```

### 4.3 前端设计

#### 4.3.1 API 客户端

```typescript
bundledApi.upgradeProcessLoop(name: string, loopId: number): Promise<InstallProcessResponse>
```

#### 4.3.2 UI

在 `ProcessPage.tsx` 的工艺详情 Modal → 实例环路 Tab → 每行操作列追加「更新」按钮：

```tsx
<Button
  type="link" size="small"
  loading={upgradingLoopId === rec.id}
  onClick={() => handleUpgradeLoop(detail!.name, rec.id)}
>更新</Button>
```

#### 4.3.3 交互

1. 点击「更新」→ 按钮进入 loading 态（`upgradingLoopId` state 控制）
2. 调 API → 成功：弹出 success + 自动刷新实例环路列表
3. 失败：弹出 error、按钮恢复

## 6. 安全反思

- **后端**：端点有路径参数注入风险——`name` 由 existing code 的路径校验保护（`validate_process_name`），`loop_id` 受 SeaORM 类型约束（i64），不会出现 SQL 注入。
- **权限**：升级操作不校验用户身份（项目整体暂无 RBAC），后续需叠加 worksapce 归属校验。
- **数据安全**：旧 todo 软删除而非物理删除，可通过 `deleted_at IS NOT NULL` 查询找回。
- **前端**：工艺列的数据来自后端响应的 `referencing_loops`，React 默认编码避免 XSS。

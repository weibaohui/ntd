# 033-环节评审模板-设计

| 修改人 | 修改时间 | 修改内容 |
|--------|---------|---------|
| Claude | 2026-07-28 | 初始版本（基于 feat/recipe-editor @ a8a5537b） |

---

## 1. 概述

环路执行环节时的 AI 评审，其评审模板当前来自 `review_templates` 表（环路级 `review_template_id` → 全局「默认评审任务」），与工艺 YAML 完全解耦，无法按环节定制。本设计在工艺 YAML 的每个环节（`LinkDefinition`）新增 `review_prompt` 字段，经 installer 写入 `loop_steps.review_prompt`，执行评审时按 **环节 → 环路 → 默认** 三级回退选取评审模板正文，让每个环节都能拥有专属评审模板。

基于需求：`docs/requirements/033-环节评审模板-需求.md`。

## 2. 现状分析

### 2.1 评审 prompt 的真实来源

环路评审走 `backend/src/services/loop_runner.rs::apply_rating_gate`（两处调用：L805 工艺步骤分支、L938 普通 AI 评审分支），签名：

```rust
async fn apply_rating_gate(
    &self,
    record_id: i64,
    min_rating: i32,
    step_prompt: &str,
    step_acceptance_criteria: Option<&str>,
    review_template_id: Option<i64>,   // ← 来自 loop_.review_template_id
) -> Result<(bool, Option<i32>, Option<String>), String>
```

- 模板选取：`ensure_review_template(review_template_id)`（L1574）—— 环路级 id → 全局默认。
- prompt 合成（L1425）：`template.prompt.replace("{{original_prompt}}", …).replace("{{original_output}}", …).replace("{{acceptance_criteria}}", …)`。
- 触发条件（L1396）：仅当 `step_acceptance_criteria` 非空才评审；否则直接判 FAIL。

### 2.2 与 YAML 解耦的证据

- `LinkDefinition`（`services/process/mod.rs:114-147`）无任何评审模板字段。
- `installer.rs` 安装/升级路径完全不引用 `review_templates` 表。
- 因此评审内容不可在工艺定义中按环节定制。

### 2.3 接入点

| 接入点 | 位置 | 作用 |
|--------|------|------|
| YAML schema | `services/process/mod.rs::LinkDefinition` | 新增 `review_prompt` 字段 |
| DB 列 | `db/entity/loop_steps.rs` + migration v75 | 持久化环节级模板 |
| 写入 | `installer.rs::create_loop_step_for_link`（L258） | install + upgrade 共用此写入点 |
| 读取/选用 | `loop_runner.rs::apply_rating_gate`（L1367） | 三级回退 + 触发条件扩展 |
| 前端 | `types/process.ts` + `LinkPropertyForm.tsx` | 编辑入口 |

## 3. 总体设计

### 3.1 字段与存储

- YAML：`phases[].links[].review_prompt`（string，可选，`#[serde(default)]` 空串 = 未设置）。
- DB：`loop_steps.review_prompt`（`TEXT NULL`，NULL = 未设置）。
- 不落入 `review_templates` 表 —— 内联存储，避免污染全局模板表。

### 3.2 三级回退（评审模板正文选取）

```
环节 step.review_prompt 非空  →  用其作为模板正文（跳过查表）
        ↓ 否则
环路 loop.review_template_id  →  ensure_review_template 查表
        ↓ 否则（id 不存在/未设）
全局「默认评审任务」模板
```

### 3.3 触发条件扩展

当前：`acceptance_criteria` 非空才评审。扩展为：**`acceptance_criteria` 非空 或 `review_prompt` 非空** 即触发。`min_rating` 仍作为评分闸门阈值的外层前置（L799/L936），不在本次改动。

### 3.4 完整替代语义

`review_prompt` 非空时**整体替代**默认模板正文。占位符替换机制不变（4 个占位符）。若用户希望验收标准出现在评审中，需自行在 `review_prompt` 中写 `{{acceptance_criteria}}`；否则验收标准不注入。

## 4. 详细设计

### 4.1 YAML schema（`services/process/mod.rs`）

在 `LinkDefinition` 末尾（`acceptance_criteria` 之后）新增：

```rust
/// 环节级评审模板正文（完整替代默认评审模板）。
/// 非空时作为评审 prompt 模板，仍支持 {{original_output}}/{{acceptance_criteria}} 等占位符替换；
/// 空串 = 未设置，回退到环路级/默认评审模板。
#[serde(default)]
pub review_prompt: String,
```

`#[serde(default)]` 保证旧 YAML 反序列化为空串，向后兼容。

### 4.2 DB 实体与 migration

**实体** `db/entity/loop_steps.rs`：在 `review_type` 字段附近新增：

```rust
/// 环节级评审模板正文（完整模板，含占位符）；NULL = 未设置，回退到环路级/默认。
pub review_prompt: Option<String>,
```

**migration v75**（新建 `db/migration/v75.rs`，注册到 `mod.rs::all_migrations` 尾部）：用幂等 `add_column_if_missing` 为 `loop_steps` 加列：

```rust
pub(super) struct V75AddLoopStepReviewPrompt;

#[async_trait::async_trait]
impl Migration for V75AddLoopStepReviewPrompt {
    fn version(&self) -> i64 { 75 }
    fn name(&self) -> &'static str { "V75AddLoopStepReviewPrompt" }
    async fn up(&self, db: &Database) -> Result<(), sea_orm::DbErr> {

        super::add_column_if_missing(
            db,
            "loop_steps",
            "review_prompt",
            "ALTER TABLE loop_steps ADD COLUMN review_prompt TEXT",

    }
}
```

`mod.rs` 同步：`mod v75;` + `Box::new(v75::V75AddLoopStepReviewPrompt),`。

### 4.3 installer 写入（`installer.rs::create_loop_step_for_link`）

在 `ActiveModel` 构造中（L272-304）新增一行，把 `link.review_prompt` 写入（空串 → `None`）：

```rust
// 环节级评审模板：空串视为未设置（NULL），评审时回退到环路级/默认
review_prompt: ActiveValue::Set(if link.review_prompt.trim().is_empty() {
    None
} else {
    Some(link.review_prompt.clone())
}),
```

**upgrade 自动同步**：`upgrade_process_template_loop`（L509）是「删除旧 steps/phases → 重建」模式（L528-535 删除，随后走 `create_phases_and_steps` → `create_loop_step_for_link`），故新版 `review_prompt` 随重建自动写入，**无需在 upgrade 段单独处理**。

### 4.4 评审执行（`loop_runner.rs::apply_rating_gate`）

**签名**新增 `step_review_prompt: Option<&str>` 参数（插在 `step_acceptance_criteria` 之后）：

```rust
async fn apply_rating_gate(
    &self,
    record_id: i64,
    min_rating: i32,
    step_prompt: &str,
    step_acceptance_criteria: Option<&str>,
    step_review_prompt: Option<&str>,   // ← 新增
    review_template_id: Option<i64>,
) -> Result<(bool, Option<i32>, Option<String>), String>
```

**两处调用**（L805、L938）补充传参 `step.review_prompt.as_deref()`（`step` 已在调用上下文）。

**内部逻辑改造**（建议抽成 ≤30 行的小函数，便于单测）：

```rust
// 触发条件：有验收标准 或 有环节内联评审模板
let criteria_text = step_acceptance_criteria.filter(|s| !s.trim().is_empty());
let inline_prompt = step_review_prompt.filter(|s| !s.trim().is_empty());
if criteria_text.is_none() && inline_prompt.is_none() {
    return Ok((false, None, Some("环节未设置验收标准或评审模板，无法触发自动评审".to_string())));
}

// 模板正文：环节内联优先；否则查表（环路级 → 默认）
// 返回 (prompt 正文, 归属 template_id, 归属 template_name)
let (template_prompt, owning_template_id, owning_template_name) = match inline_prompt {
    Some(rp) => {
        // 内联模板无对应 review_templates 行，用哨兵 id 归属评审实例 todo
        (rp.to_string(), INLINE_REVIEW_TEMPLATE_ID, "环节内联评审")
    }
    None => {
        let t = self.ensure_review_template(review_template_id).await?;
        (t.prompt, t.id, /* name 字段 */)
    }
};

// 占位符替换（机制不变；criteria 为空时 {{acceptance_criteria}} 替换为空串）
let review_prompt = template_prompt
    .replace("{{original_prompt}}", step_prompt)
    .replace("{{max_output_chars}}", &MAX_OUTPUT_CHARS.to_string())
    .replace("{{original_output}}", &truncated)
    .replace("{{acceptance_criteria}}", criteria_text.unwrap_or(""));
```

后续 `reuse_or_create_review_instance(owning_template_id, owning_template_name, &review_prompt, …)` 与执行逻辑不变。

> **实现要点**：`ReviewTemplate` 模型当前可能不带 `name` 字段，需核对 `crate::models::ReviewTemplate`；若缺则 `ensure_review_template` 顺带返回 name，或 inline 分支用固定名、查表分支用「环路评审模板」。哨兵常量 `INLINE_REVIEW_TEMPLATE_ID` 建议定义为模块常量（如 `0`），并确认 `todos.review_template_id` 接受该值（逻辑引用、非 FK）。

## 5. 数据流

```
用户编辑 review_prompt (前端)
  → yamlDump → PUT /api/v1/processes/{name}  (definition YAML 文本)
  → 后端 serde_yaml 解析为 ProcessDefinition (LinkDefinition.review_prompt)
  → 写入 process_templates.definition

安装/升级 (installer)
  → create_loop_step_for_link → loop_steps.review_prompt (TEXT)

环路执行 (loop_runner)
  → apply_rating_gate(step.review_prompt, …)
  → 三级回退选取模板正文
  → 占位符替换 → run_todo_execution → AI 评审 → 评分
```

## 8. 安全反思

- **prompt 注入**：`review_prompt` 由工艺作者定义，信任级别同 `acceptance_criteria`，按现状不过滤。未引入新的越权面（字段经 installer 写库、经 apply_rating_gate 读取，路径封闭）。
- **占位符泄漏**：占位符替换发生在发给 AI 之前，未替换的占位符不会出现在用户可见输出（替换覆盖 4 个已知占位符；用户自定义文本中的 `{xxx}` 不替换，属预期行为）。
- **无 SQL 注入**：使用 SeaORM ActiveModel 与参数化迁移 helper，无字符串拼接 SQL。

## 9. 风险与回退

| 风险 | 应对 |
|------|------|
| `ReviewTemplate` 模型无 `name` 字段，导致 owning_template_name 取值困难 | 编码时核对 `models::ReviewTemplate`；缺则 inline 用固定名、查表分支用 loop 名/固定名 |
| 哨兵 `INLINE_REVIEW_TEMPLATE_ID=0` 与既有评审 todo 冲突 | 编码时确认 `find_review_instance_by_template(0)` 行为；必要时改用 -1 或独立标志列 |
| migration v75 与未来 main 合并冲突 | 本分支当前 = main（a8a5537b），v75 顺序递增无冲突；后续若 main 新增 v75+ 再重编号 |
| 旧工艺无 `review_prompt` | serde default 空串 + DB NULL，行为完全兼容 |
| 回退 | 字段全部可选/可空；删除前端控件、后端回退到原 `apply_rating_gate` 即恢复原行为 |

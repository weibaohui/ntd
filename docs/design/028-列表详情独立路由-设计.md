## 1. 整体方案

### 1.1 现状

```text
/#/items  (ItemsPage)
  ├ viewMode = 'card' → TodoCenterCardView（全宽卡片墙）
  └ viewMode = 'list' → TodoPage
                       └ ListDetailPage（双栏）
                          ├ 左：TodoList（listMode='item'）
                          └ 右：TodoDetail（selectedTodoId 驱动）

/#/loops  (LoopPage)
  └ ListDetailPage（双栏）
     ├ 左：TodoList（listMode='loop'）
     └ 右：LoopStudioDetailPanel（selectedLoopId 驱动）

/#/items?id=xxx&panel=detail     ← 事项详情（在右栏）
/#/items?id=xxx&panel=post&record=yyy    ← 帖子详情
/#/loops?id=xxx&panel=detail     ← 环路详情（在右栏）
```

### 1.2 目标架构（统一命名空间）

```text
/#/todos                  事项列表（卡片/列表形态切换，统一命名空间）
  ├ viewMode = 'card' → TodoCenterCardView（点击卡片 → /#/todos/:id）
  └ viewMode = 'list' → TodoListView（单栏 Ant Design Table）

/#/todos/:id                     ← 事项详情独立页（TodoDetailPage）
/#/todos/:id/posts/:recordId     ← 帖子详情页（TodoPostPage，复用现有组件）

/#/loops                         环路列表（LoopListPage → LoopListView 单栏 Table）
/#/loops/:id                     ← 环路详情独立页（LoopDetailPage）
```

> **统一原则**：`/#/todos` 是事项命名空间的根路径，列表与详情共用 View 类型 `todos`，靠 path 段区分。`items` 旧 View 类型与 `/#/items` 旧 URL 全部废弃，不做兼容重定向。

### 1.3 核心决策

| 决策点 | 方案 | 理由 |
|--------|------|------|
| View 类型命名 | 统一为 `todos`（列表+详情共用，靠 path 段区分）；删除 `items` | 命名空间统一，列表与详情同源；`items` 与 `todos` 双名容易混淆，统一为 `todos` 与后端 `todos` 表一致 |
| 路由参数传递 | path 段（`/todos/:id`）而非 query | RESTful 语义更清晰；与 `/processes?name=` 这类 query 参数的语义不冲突（后者是「打开页面时自动开 Modal」的辅助参数） |
| 列表数据源（事项） | 调用 `db.getTodoCenter(workspaceId)` 而非 `db.getAllTodos` | `getTodoCenter` 已返回 `last_execution_status` / `last_execution_at` / `referencing_loops` 等聚合字段，table 显示需要；`getAllTodos` 仍是详情页的来源（通过 `state.todos` 缓存） |
| 列表数据源（环路） | `dbLoops.listLoops(workspaceId)` | 现状如此，`LoopListItem` 已含 `last_execution_status` / `last_execution_at` / `step_count` |
| 旧 URL 兼容 | **不做兼容重定向** | 用户明确要求统一处理；所有内部跳转、文档、书签同步迁移到新路由；旧外链失效成本由用户承担 |
| table 组件 | Ant Design `Table` | 项目已用，零新增依赖 |
| 详情页容器 | `PageCard`（与卡片墙、设置页一致） | 视觉一致性 |
| 旧组件处理 | 直接删除 `ListDetailPage` / `TodoPage` / `LoopPage` / `EmptyDetailPlaceholder` | 无其他引用方，避免 dead code |

## 2. 路由设计

### 2.1 View 类型统一

```typescript
// frontend/src/hooks/useViewState.ts
export type View =
  | 'todos'          // 事项命名空间（列表 /#/todos + 详情 /#/todos/:id + 帖子 /#/todos/:id/posts/:rid）
  | 'loops'          // 环路命名空间（列表 /#/loops + 详情 /#/loops/:id）
  | 'tasks'
  | 'processes'
  | 'dashboard'
  // ... 其他保持不变
// 删除：'items'（统一到 'todos'）
```

> `todos` 同时承担「列表」和「详情」两种语义：当 URL 为 `/#/todos` 时是列表，`/#/todos/:id` 时是详情。通过 `pathSegments.length` 区分：
> - `['todos']` → 列表
> - `['todos', '123']` → 详情
> - `['todos', '123', 'posts', '456']` → 帖子

`loops` 同理：`['loops']` → 列表，`['loops', '456']` → 详情。

### 2.2 URL 解析扩展

```typescript
// 现有：getHashPath() 返回 '/items' 或 '/todos/123'
// 扩展：getHashPathSegments() 返回 ['items'] 或 ['todos', '123'] 或 ['loops', '456']

function getHashPathSegments(): string[] {
  const path = getHashPath(); // 已存在，返回 '/items' 或 '/todos/123'
  const viewPart = path.startsWith('/') ? path.slice(1) : path;
  return viewPart.split('/').filter(Boolean);
}
```

### 2.3 状态扩展

```typescript
// useViewState 新增状态
const [todoDetailId, setTodoDetailId] = useState<number | null>(getInitialPathId(1));
const [loopDetailId, setLoopDetailId] = useState<number | null>(getInitialPathId(1));
const [postRecordId, setPostRecordId] = useState<number | null>(getInitialPathId(3));

// getInitialPathId(segmentIndex): 从 path 段中提取 id
//   /#/todos/123/posts/456 → segments=['todos','123','posts','456']
//   segmentIndex=1 取 123（todoId），segmentIndex=3 取 456（recordId）
//   /#/loops/456 → segments=['loops','456']，segmentIndex=1 取 456
```

### 2.4 pushUrl / replaceUrl 扩展

```typescript
interface NavOpts {
  id?: number | null;
  recordId?: number | null;  // 帖子记录 id（用于 /todos/:id/posts/:recordId）
  tab?: string | null;
  mode?: BoardMode;
  workspace?: number | null;
  slug?: string | null;
  file?: string | null;
  name?: string | null;
  // 移除 panel（不再需要 list/detail/post 区分，由 View 类型与 path 段决定）
}

function buildHashUrl(view: View, opts?: NavOpts): string {
  // 事项详情：/#/todos/123 或 /#/todos/123/posts/456
  if (view === 'todos' && opts?.id != null) {
    if (opts.recordId != null) {
      return `#/todos/${opts.id}/posts/${opts.recordId}`;
    }
    return `#/todos/${opts.id}`;
  }
  // 事项列表：/#/todos
  if (view === 'todos') {
    return `#/todos`;
  }
  // 环路详情：/#/loops/456
  if (view === 'loops' && opts?.id != null) {
    return `#/loops/${opts.id}`;
  }
  // 环路列表：/#/loops
  if (view === 'loops') {
    return `#/loops`;
  }
  // 其他 view 走原逻辑（query 参数）
  // ...
}
```

### 2.5 popstate 处理

```typescript
const onPopState = () => {
  const segments = getHashPathSegments();
  const view = parseViewFromSegments(segments);
  // 根据 view 与 segments 设置 todoDetailId / loopDetailId / postRecordId
  // - view === 'todos' && segments.length === 1 → 列表，todoDetailId=null
  // - view === 'todos' && segments.length === 2 → 详情，todoDetailId=segments[1]
  // - view === 'todos' && segments.length === 4 → 帖子，todoDetailId=segments[1], postRecordId=segments[3]
  // - view === 'loops' && segments.length === 1 → 列表，loopDetailId=null
  // - view === 'loops' && segments.length === 2 → 详情，loopDetailId=segments[1]
};
```

> **不做旧 URL 重定向**：popstate 中不调用任何 `redirectLegacyUrlIfNeeded`。若用户后退到 `/#/items` 旧 URL（仅在用户手动输入或老书签时出现），`parseViewFromSegments` 找不到 `items` View 类型 → fallback 到默认 view（`dashboard` 或 `todos`）。**实施时确认**：fallback 策略是显示 404 还是跳到 `/#/todos`，建议跳到 `/#/todos`（友好引导）。

## 3. 数据流设计

### 3.1 事项列表数据流

```text
TodoListPage (URL: /#/todos)
  └ TodoListView
     ├ useEffect: 监听 selectedWorkspace / refreshKey
     │  └ db.getTodoCenter(workspaceId) → dispatch SET_TODO_CENTER_BY_WORKSPACE
     ├ 从 useApp().state.todoCenterByWorkspace[ws] 读取列表
     ├ 外部 searchKeyword 过滤
     └ Ant Design Table 渲染
```

### 3.2 事项详情数据流

```text
TodoDetailPage (todoDetailId from URL)
  ├ useEffect: 监听 todoDetailId
  │  └ db.getTodo(workspaceId, todoDetailId) → dispatch UPDATE_TODO（若未在 state.todos 中）
  ├ 从 state.todos.find(t => t.id === todoDetailId) 读取
  └ 复用 TodoDetail 内部组件渲染
```

> 复用策略：把 `TodoDetail` 组件重构为接收 `todoId` prop 的纯组件（不再读 `state.selectedTodoId`），原 `TodoDetail` 内部所有逻辑保留。原 `TodoDetail` 直接读 `selectedTodoId` 的方式迁移到 `TodoDetailPage` 顶层。

### 3.3 环路列表数据流

```text
LoopListPage (URL: /#/loops)
  └ LoopListView
     ├ useEffect: 监听 selectedWorkspace / loopUpdateCount
     │  └ dbLoops.listLoops(workspaceId) → 本组件 state
     ├ 外部 searchKeyword 过滤
     └ Ant Design Table 渲染
```

### 3.4 环路详情数据流

```text
LoopDetailPage (loopDetailId from URL)
  ├ useEffect: 监听 loopDetailId
  │  └ dbLoops.getLoop(workspaceId, loopDetailId) → 本组件 state（LoopDetail）
  └ 复用 LoopStudioDetailPanel 渲染
```

> `LoopStudioDetailPanel` 当前接收 `loopId` prop，已与 URL 解耦，可直接复用。

### 3.5 state 扩展

`useApp` 的 state 新增 `todoCenterByWorkspace` 缓存（若不存在）：

```typescript
interface AppState {
  // ... 现有
  todoCenterByWorkspace: Record<number, TodoCenterItem[]>;
}
```

dispatch 新增 action：

```typescript

```

> 若 `useApp` 已有该字段则直接复用，不重复定义。设计阶段确认。

```tsx
  <TodoDetailPage
    todoId={todoDetailId}
    onBack={() => replaceUrl('todos')}
    onOpenPost={(todoId, recordId) => pushUrl('todos', { id: todoId, recordId })}
  />
)}

{/* 帖子详情页（URL: /#/todos/:id/posts/:recordId，复用现有 TodoPostPage） */}
{activeView === 'todos' && todoDetailId != null && postRecordId != null && (
  <TodoPostPage
    todoId={todoDetailId}
    recordId={postRecordId}
    onBack={() => replaceUrl('todos', { id: todoDetailId })}
  />
)}

{/* 环路列表页（URL: /#/loops） */}
{activeView === 'loops' && loopDetailId == null && (
  <LoopListPage ... />
)}

{/* 环路详情独立页（URL: /#/loops/:id） */}
{activeView === 'loops' && loopDetailId != null && (
  <LoopDetailPage
    loopId={loopDetailId}
    workspaceId={state.selectedWorkspace}
    tags={state.tags}
    onBack={() => replaceUrl('loops')}
    onOpenProcess={handleOpenProcess}
    onSelectTodo={(todoId) => pushUrl('todos', { id: todoId })}
    onLoopChanged={() => setLoopUpdateCount(c => c + 1)}
  />
)}
```

> **删除**：原 `activeView === 'items'` 分支与所有 `?panel=detail|post` 处理逻辑。

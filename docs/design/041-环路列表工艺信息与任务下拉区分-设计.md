# 设计：环路列表展示工艺信息 + 新建任务下拉区分环路（041）

## 1. 方案概述

两处独立的前端体验修复，围绕「同一工艺可被安装成多个同名环路」这一事实：

1. **环路列表页**（`/#/loops`）新增「工艺名称」「版本」两列：让用户一眼看出某环路来自哪个工艺、哪个版本。
   仅当环路由工艺安装（`process_template_id` 非空）时才有值，手工环路显示 `-`。
2. **新建任务 Modal**（`/#/tasks`）的环路下拉，选项文案由 `环路名称` 改为 `#<环路ID> <环路名称>`，
   让多个同名环路可凭 ID 区分。

数据现状（决定了改动面）：

- 后端 `LoopDto`（`backend/src/models/loop_.rs:120`）已含 `process_template_id` /
  `process_template_version`（来自 `loops` 行）/ `process_template_display_name` /
  `process_template_name` / `process_template_guid`。
- `LoopDto::from(loops::Model)` 自动带出 `process_template_id` 与 `process_template_version`；
  名称类字段需经 `LoopDto::with_process_template(Option<process_templates::Model>)`（同文件 :198）注入——
  详情接口 `get_loop`（`handlers/loop_.rs:154`）已是此模式。
- **缺口**：列表接口 `list_loops_v1`（`handlers/loop_.rs:2251`，前端实际调用的 v1 路由）只注入了
  `with_tags`，没注入工艺模板信息，所以列表拿不到工艺名称。

结论：前端列表的「版本」数据其实后端已经返回（只是前端类型 `LoopListItem` 没声明、也没渲染）；
唯一需要补的后端逻辑是「列表接口注入工艺名称」。

## 2. 后端：列表接口注入工艺名称

### 2.1 批量查询方法（`backend/src/db/process_template.rs`）

新增 `get_process_templates_by_ids(ids: &[i64]) -> Vec<process_templates::Model>`，
用 `Entity::find().filter(Column::Id.is_in(ids))` 一次取回，避免逐 loop N+1。
参考已有 `get_process_template_by_id`（同文件 :10）。空入参直接返回空 Vec，不发 SQL。

### 2.2 列表 handler（`backend/src/handlers/loop_.rs::list_loops_v1`）

在现有 `with_tags` 注入的同一 `map` 里追加：

1. 从 `items` 收集所有非空 `process_template_id`，去重；
2. `get_process_templates_by_ids` 批量查，构建 `HashMap<i64, process_templates::Model>`；
3. 对每个 item：`item.with_process_template(map.get(&template_id).cloned())`（无模板的传 `None`，
   字段保持缺省不序列化，与详情页一致）。

`process_template_version` 由 `LoopDto::from` 自动带出，无需额外处理。

v0 `list_loops`（:50）前端不再调用，保持不动（YAGNI）。

### 2.3 测试

- `db/process_template.rs` 内补单测：批量查命中/部分命中/空入参。
- `models/loop_.rs` 的 `loop_dto_tests` 已覆盖 `with_process_template`，无需再加。

## 3. 前端：环路列表新增两列

### 3.1 类型（`frontend/src/types/loop.ts` `LoopListItem` :265）

补三个可选字段，与 `LoopDto` 对齐（当前只有 `process_template_id?`）：
`process_template_display_name?`、`process_template_name?`、`process_template_version?`。

### 3.2 列定义（`frontend/src/components/loop-list/LoopListViewParts.tsx::buildColumns`）

在「名称」列（:151）后插入：

- **工艺名称**：`record.process_template_display_name ?? record.process_template_name ?? '-'`，
  `ellipsis`，`width ≈ 160`。
- **版本**：`record.process_template_version`，无值 `-`，等宽小字（`monospace` +
  `var(--color-text-tertiary)`，与 ID 列风格一致），`width ≈ 90`。

### 3.3 横向滚动（`frontend/src/components/loop-list/LoopListView.tsx:125`）

`scroll={{ x: 1200 }}` 调至约 `1440`（+两列宽度），避免新增列挤压。

### 3.4 测试（`LoopListViewParts.test.tsx`）

补一例：构造含 `process_template_display_name` / `process_template_version` 的行，
经 `buildColumns` 渲染后断言两列文本；另构造无工艺字段的行断言渲染 `-`。
（`buildColumns` 返回列定义，测试以列 `render` 直接求值断言，与现有冒泡测试同文件、同风格。）

## 4. 前端：新建任务下拉区分环路

`TasksPage`（:129）已按 `process_template_id != null` 过滤，均不动。

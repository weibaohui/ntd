# 097 - 运行中心重构：看板视图归位 + memorial 命名清理

## 1. 背景

用户反馈：左侧导航的独立「看板」菜单与「任务」菜单里的看板视图疑似重复，质疑独立菜单是否还有必要。

调查结论（见 `KanbanBoard.tsx` / `TasksKanbanView.tsx`）：

- 两者**维度不同**，并非真重复：
  - 独立「看板」菜单 → **Todo 维度**，4 列（待办/进行中/已完成/失败），**可拖拽改状态**，数据源 `getTodoBriefs`。
  - 任务菜单看板 → **Task 维度**，5 列（含待审批虚拟泳道），**只读**，数据源 `listTasks`。
- 但独立「看板」菜单**名不副实**：`MemorialBoard.tsx` 顶部 Segmented 实际聚合 4 个视图（kanban / running / loop_kanban / memorial），叫「看板」与 Task 看板撞名，造成重复错觉。
- **入口割裂**：todo 维度的状态看板（唯一能拖拽改状态）藏在独立菜单里，而「事项」菜单（`/#/todos`）自身只有 card/list 两态，没有看板。与 tasks 三态设计不对齐。

## 2. 方案（B）

1. **todo 看板归位**：把 todo 状态看板移到「事项」菜单，与 tasks 三态对齐为 `card | list | kanban`，复用现有 `KanbanBoard`（其 props 已支持「不传 searchText 时自带顶栏」的复用形态，见 `KanbanBoard.tsx:19,418`）。
2. **独立菜单瘦身 + 改名**：去掉 kanban 视图，保留 running / loop_kanban / memorial 三视图，改名为「**运行中心**」（key `ops`，组件 `OpsCenter`），默认进入「运行视图」。
3. **命名清理**：同步清除误导性的 `memorial` 标识符（路由 / 组件 / BoardMode / CSS / 文案）。

## 5. 风险

- **旧 URL 失效**：`/#/memorial?mode=kanban` 等外部书签失效。按项目惯例（`useViewState.ts:29` 已声明不做旧 URL 兼容）**不加重定向**，内部链接全部同步。
- **双重顶栏**：事项菜单看板态必须让 `TodoListHeader` 隐藏搜索框，否则与 `KanbanBoard` 自带顶栏重复（块 1 已处理）。
- 纯前端重构，后端无改动。

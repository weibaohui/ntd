## 1. 设计总览

任务页看板的时间过滤已收敛为公共组件 `TimeRangeSegmented`（showAll 形态 = 全部/6h/12h/24h/3d/7d）。
本需求把同款交互复制到事项页与环路页，并按各页数据形态选择正确的过滤实现层：

| 页面形态 | 数据加载方式 | 过滤实现层 | 过滤字段 | 默认值 |
|---------|-------------|-----------|---------|--------|
| 事项页 卡片/列表 | 服务端分页（/todos/center） | **SQL 下推**（新增 hours 参数） | `created_at` | 全部（null） |
| 环路页 列表 | 全量前端（listLoops） | 前端 useMemo 过滤 | `created_at` | 全部（null） |
| 环路页 看板 | 每环路执行历史分页 | 现有链路（hours 透传后端） | `started_at`（现状） | 24h（现状） |

设计原则：**同一组件、同一口径、各形态独立状态**。
- 三页共用 `TimeRangeSegmented`，不新增时间档位常量；
- 时间过滤一律不持久化（与任务页一致）；
- 事项页 card/list 共享一个页级 state；环路页 list/kanban 数据维度不同，各持独立 state。

## 2. 后端设计

### 2.1 数据流

```text
GET /api/v1/workspaces/{ws_id}/todos/center?hours=24
  → TodoCenterQueryV1.hours: Option<u32>
  → TodoCenterPageQuery { hours: Option<u32>, ... }
  → center_page_where: AND t.created_at >= ?（cutoff = utc_timestamp_minus_hours(24)）
  → count_todo_center / get_todo_center_page / count_todo_center_buckets 三处共用同一 where
  → total、bucket_counts、items 口径自动一致
```

### 2.2 关键实现

- **cutoff 生成**：复用 `crate::models::utc_timestamp_minus_hours(h)`（093 引入）。
  存储侧统一 T/Z ISO（应用层毫秒精度 / 触发器秒级兜底），字符串序=时间序，裸列比较可用。
- **参数绑定**：`values.push(cutoff.into())`，禁止列上套 REPLACE/datetime 函数（历史教训：索引恒失效）。
- **0/缺省语义**：`q.hours.filter(|&h| h > 0)` 为 None 时不追加条件，与既有 hours 接口一致。
- **bucket_counts 口径**：`count_todo_center_buckets` 内部用 `bucket=None` 克隆查询——
  克隆时 hours 字段原样携带，因此 Tab 角标与当前列表同口径（与 search/status/action_type 行为一致）。

### 2.3 改动文件

| 文件 | 改动 |
|------|------|
| `backend/src/handlers/todo.rs` | `TodoCenterQueryV1` 加 `hours`；`get_todo_center_v1` 解析并透传 |
| `backend/src/db/todo.rs` | `TodoCenterPageQuery` 加 `hours` 字段；`center_page_where` 追加 created_at 条件；全部既有构造点补 `hours: None`；新增过滤单测 |

## 3. 前端设计

### 3.1 事项页

```text
TodoListPage（新增页级 state hours: number | null = null）
 ├─ TodoListHeader（新增 hours/onHoursChange props）
 │     card/list 形态渲染 <TimeRangeSegmented showAll />（搜索框后、刷新前）
 │     running 形态 / 移动端不渲染（保持精简）
 ├─ list 形态：useTodoListData 新增 hours 参数 → getTodoCenter({ hours }) → 服务端过滤
 └─ card 形态：TodoCenterCardView 新增 hours prop → 内部 reload 时一并下推
```

- `getTodoCenter`（`utils/database/todos.ts`）options 加 `hours?: number`，`> 0` 时写 `params.hours`。
- `TodoCenterCardView.reload` 的依赖数组加入 `hours`：时间窗变化自动重拉当前 Tab（页码由调用方重置？不——
  时间窗变化时沿用当前 page 即可，数据量变小后端会截断有效页码，与 status/actionType 筛选行为一致；
  为避免「旧页码超界」歧义，与筛选 setter 一致地回到第 1 页：在 `hours` 变化 effect 里 `setPage(1)`）。

### 3.2 环路页

```text
LoopListPage
 ├─ state: listHours = null（全部）、kanbanHours = 24（保持历史默认）
 ├─ LoopListHeader 统一渲染 <TimeRangeSegmented showAll />（list/kanban 均显示）
 │      props.hours / onHoursChange 按当前 viewMode 路由到对应 state
 ├─ list 形态：filteredItems 追加 created_at 窗口过滤（hours != null 时生效）
 └─ kanban 形态：LoopKanban hours prop 改 number | null；null 表示不过滤
        useLoopExecutions hours 类型改 number | null（null → 请求不带 hours）
```

- `LoopKanban` 内部 fallback 逻辑从 `externalHours ?? internalHours` 改为
  `externalHours !== undefined ? externalHours : internalHours`：
  **null 是合法值（=全部）**，不能再被 ?? 吞掉回退到内部 24h。
- 环路列表 `created_at` 为 null 的记录视为不在窗口内（与任务页对非法时间的处理一致）。

## 5. 兼容性与安全

- **接口向后兼容**：hours 为新增可选查询参数，旧客户端不带该参数行为不变。
- **无写入语义变化**：过滤只影响 SELECT 条件，不触碰任何写路径。
- **越权无新增面**：hours 过滤叠加在既有 workspace_id 过滤之上，不改变数据可见范围。
- **XSS/SQL 注入**：cutoff 由服务端 Rust 生成、参数绑定，无外部字符串进入 SQL 拼接。

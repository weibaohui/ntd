## 1. 背景与目标

ntd 是一个 AI 驱动的任务引擎，功能点多、页面多、数据流长。用户（尤其是新用户和二次开发者）难以快速理解：

- 某个按钮点了之后，数据从前端到后端是怎么流转的？
- 某个操作涉及哪些表、哪些状态变更？
- 想二次开发某个功能，应该改哪里、注意什么？

**目标**：在前端 LeftRail 底部加一个「帮助」入口，点开后是一个抽屉，按「页面 → 功能点」两级树形组织，每个功能点展示：

1. **数据流图** — 用户操作 → 前端组件 → API → 后端 service → DB
2. **调用关系链路图** — 函数/组件调用栈
3. **数据结构图** — 涉及的 TypeScript 类型 / Rust struct / DB 表
4. **数据变更图** — CRUD 时哪些表/状态变了
5. **开发指导** — 如何二次开发、改哪里、注意什么

所有帮助内容用 **Markdown 文件**承载，前端用 `import.meta.glob` 动态读取后渲染。图用 **Mermaid** 写在 md 的 ```mermaid 代码块里，由 `MermaidDiagram` 组件实时渲染。

**设计原则**：

- **YAGNI**：只做帮助展示，不做搜索/后端化/权限
- **动态统一**：所有内容从注册表 + md 文件派生，不写死
- **AI 可读写**：md 文件 AI 可直接 `read_file`/`write_file`/`edit_file`
- **复用**：md 渲染复用项目已有的 `@ant-design/x-markdown`（`XMarkdown`）

## 2. 技术选型

| 决策点 | 选择 | 理由 |
|---|---|---|
| 图的渲染 | **Mermaid**（`mermaid` 包） | md 里写 ```mermaid 自动出图，AI 写 md 即图。项目已有 React Flow / 手画 SVG，但帮助图需要"AI 写 md 即可生成图"，Mermaid 是唯一能让 md 里写 ```mermaid 自动出图的方案 |
| Markdown 渲染 | 复用现有 `@ant-design/x-markdown` 的 `XMarkdown` | 项目已用，零新依赖 |
| 帮助内容载体 | `frontend/src/help/pages/*.md` + `frontend/src/help/index.ts` 注册表 | md 文件随仓库走，AI 可直接 read_file/edit_file |
| 帮助内容加载 | Vite 的 `import.meta.glob('./pages/*.md', { query: '?raw', import: 'default' })` | 原生支持，构建时打进去，运行时动态读，无需 fetch |
| Mermaid 渲染 | `mermaid` 包 + 轻量 `<MermaidDiagram>` 组件，在 XMarkdown 的自定义渲染器里拦截 ```mermaid 代码块 | 单一职责，图与文档分离 |
| 入口位置 | `LeftRail` 底部主题切换旁加「帮助」按钮 | 用户最易触达，复用现有 rail 布局 |
| 抽屉载体 | Antd `Drawer` right placement | 与现有 `navDrawerOpen` 模式一致 |

## 5. 内容加载机制（`useHelpContent.ts`）

```typescript
// 构建时把所有 md 文件以 raw string 形式打进去
const allDocs = import.meta.glob('./pages/*.md', {
  query: '?raw',
  import: 'default',
}) as Record<string, string>;

/** 根据 md 文件名取出内容，找不到返回空串。 */
export function loadHelpDoc(docFile: string): string {
  const key = `./pages/${docFile}`;
  return allDocs[key] ?? '';
}
```

**为什么用 `import.meta.glob` 而不是 fetch**：

- Vite 原生支持，零运行时 IO
- 构建时把 md 打进 bundle，部署后不依赖 server 返回 md
- md 文件仍在源码树里，AI 可直接编辑

## 6. Mermaid 渲染（`MermaidDiagram.tsx`）

```typescript
import { useEffect, useRef, useState } from 'react';
import mermaid from 'mermaid';
import { useTheme } from '@/hooks/useTheme';

interface MermaidDiagramProps {
  /** mermaid 源码（不含 ```mermaid 围栏）。 */
  chart: string;
}

/** 单个 mermaid 图的渲染组件：初始化一次 mermaid，每次 chart 变更重新 render。 */
export function MermaidDiagram({ chart }: MermaidDiagramProps) {
  const { themeMode } = useTheme();
  const containerRef = useRef<HTMLDivElement>(null);
  const [svg, setSvg] = useState('');

  useEffect(() => {
    mermaid.initialize({
      startOnLoad: false,
      theme: themeMode === 'dark' ? 'dark' : 'default',
      securityLevel: 'strict', // 禁止 mermaid 里的 html/script
    });
  }, [themeMode]);

  useEffect(() => {
    let cancelled = false;
    const id = `mmd-${Math.random().toString(36).slice(2)}`;
    mermaid.render(id, chart).then(({ svg }) => {
      if (!cancelled) setSvg(svg);
    }).catch(() => {
      if (!cancelled) setSvg(''); // 渲染失败显示空，不打断整个文档
    });
    return () => { cancelled = true; };
  }, [chart, themeMode]);

  return (
    <div
      ref={containerRef}
      className="help-mermaid"
      dangerouslySetInnerHTML={{ __html: svg }}
    />
  );
}
```

**安全**：`securityLevel: 'strict'` 禁止 mermaid 源码里嵌入 HTML/script。`dangerouslySetInnerHTML` 仅用于 mermaid 自己产出的 svg，mermaid 在 strict 模式下会 sanitize。

## 7. md 渲染 + mermaid 拦截（`HelpContentRenderer.tsx`）

`@ant-design/x-markdown` 的 `XMarkdown` 接受 `components` prop 自定义渲染。我们拦截 `code` 节点：若 `language === 'mermaid'`，渲染 `<MermaidDiagram>`；否则走默认 `code` 渲染。

```typescript
import XMarkdown from '@ant-design/x-markdown';
import type { Components } from 'react-markdown';
import { MermaidDiagram } from './MermaidDiagram';

interface HelpContentRendererProps {
  /** md 源码。 */
  source: string;
}

/** 把 md 源码渲染成带 mermaid 拦截的视图。 */
export function HelpContentRenderer({ source }: HelpContentRendererProps) {
  const components: Components = {
    code({ className, children }) {
      const match = /language-mermaid/.exec(className ?? '');
      const text = String(children);
      if (match) {
        return <MermaidDiagram chart={text} />;
      }
      return <code className={className}>{children}</code>;
    },
  };
  return <XMarkdown components={components}>{source}</XMarkdown>;
}
```

## 8. 抽屉容器（`HelpDrawer.tsx`）

- 右侧 `Drawer`，width 560，placement right
- 内容分两栏：左侧 `Tree`（页面一级 + 功能点二级），右侧 `HelpContentRenderer`
- 树选中节点 → 取对应 md → 渲染
- 默认选中「当前页面」总览（由 `activeView` 派生 pageId）

```typescript
interface HelpDrawerProps {
  open: boolean;
  onClose: () => void;
  /** 当前所在视图，用于树形默认选中。 */
  activeView: View;
}
```

**树形数据派生**：从 `HELP_PAGES` map 出 `treeData`，每个页面节点 `key = pageId`，每个功能点节点 `key = ${pageId}/${featureId}`。

**默认选中逻辑**：

```typescript
const currentPage = HELP_PAGES.find(p => p.pageId === viewToPageId(activeView));
const defaultSelectedKey = currentPage ? currentPage.pageId : '_overview';
```

## 9. LeftRail 入口

在 `LeftRail` 底部「主题切换」按钮旁追加「帮助」按钮（`QuestionCircleOutlined`）。点击触发上层 `onOpenHelp` 回调，由 `App.tsx` 控制 `helpDrawerOpen` 状态并渲染 `<HelpDrawer>`。

**为什么放 LeftRail 底部**：用户最易触达，且与主题切换并列符合「全局辅助操作」语义。移动端 `navDrawerOpen` 模式下同样可见。

## 10. 功能点 md 统一模板

每个功能点 md 必须包含 5 个二级标题，顺序固定：

```markdown
# <功能中文名>

## 功能位置
<页面名> → <按钮/入口位置>

## 数据流图（前端 → 后端）
​```mermaid
flowchart LR
  U[用户操作] --> C[前端组件]
  C --> A[API 路径]
  A --> S[后端 service]
  S --> DB[(数据库表)]
​```

## 调用关系链路图
​```mermaid
flowchart TD
  ComponentA.handler --> ComponentB.method
  ComponentB.method --> db.xxx
​```

## 数据结构图
​```mermaid
classDiagram
  class TypeName {
    +field: type
  }
​```

## 数据变更图
​```mermaid
stateDiagram-v2
  [*] --> 状态A
  状态A --> 状态B: 操作
  状态B --> [*]
​```

## 开发指导
- **前端入口**：`<文件路径>` 的 `<函数/组件名>`
- **后端入口**：`backend/src/handlers/xxx.rs` / `backend/src/services/xxx.rs`
- **注意**：<避坑点>
- **扩展**：<如何加新字段/新状态>
```

页面级总览 md（如 `todos-list.md`）只包含一段页面介绍 + 一张页面级数据流总图（可选），不强制 4 图。

## 14. 风险与对策

| 风险 | 对策 |
|---|---|
| mermaid 包体积大（~2MB） | 用 `mermaid/dist/mermaid.core.js` + 按需 register diagram，或动态 import 懒加载 |
| mermaid 首次渲染慢 | `MermaidDiagram` 用 `useEffect` 异步 render，不阻塞 md 渲染 |
| md 内容过期（代码改了 help 没改） | M3 填充时在 md 里标注「基于 commit xxx」，后续由 AI 定期 reconcile |
| XMarkdown 的 components API 与 react-markdown 版本不一致 | M1 先验证 XMarkdown 是否支持 `components` prop，不支持则用 `remark-mermaid` plugin 或自定义 code renderer |

## 15. YAGNI 自检

- ✅ Mermaid：必须，4 种图没有它就只能纯 ASCII，AI 写 md 出图效率最高
- ✅ `import.meta.glob`：Vite 原生，零成本动态加载
- ✅ 复用 `XMarkdown`：项目已用，不引新 md 渲染器
- ❌ 不做帮助内容搜索（YAGNI，后续要再加）
- ❌ 不做帮助内容后端化（YAGNI，前端 md 即够，AI 可直接改）
- ❌ 不做帮助内容多语言（YAGNI，全中文即可）

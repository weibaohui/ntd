## 1. 设计目标

在 M1（静态模板 → Loop 实例化）和 M2（运行时产物/门禁/返工/审计）的基础上，M3 面向工艺管理的持续改进闭环：

1. **智能推荐**：任务有了 → 系统推荐合适工艺；
2. **版本进化**：模板改了 → 用户能感知变化、有选择地升级；
3. **可度量**：做完了 → 能看出哪个工艺好用、哪个环节经常失败；
4. **可编辑**：不用手写 YAML → 有可视化编辑器。

---

## 2. 总体架构

M3 不新增后端运行时模块（产物捕获、门禁引擎不再变化），主要改动在：

```
后端：
  handlers/process.rs         → 新增 recommend/validate/versions/stats/diff API
  services/process/           → 新增 recommender.rs（推荐引擎）、metrics.rs（指标采集）
  db/                         → 新增 migration（版本 diff、四流预留表）

前端：
  components/process/
    ProcessRecommendBar.tsx    → 搜索推荐栏
    ProcessVersionHistory.tsx  → 版本历史
    ProcessYamlEditor.tsx      → 可视化编排器
    ProcessDashboard.tsx       → 指标仪表盘
  types/process.ts            → 扩展类型
  api/bundled.ts              → 新增 API 方法
```

## 3. 核心模块设计

### 3.1 工艺推荐引擎（`recommender.rs`）

**推荐策略**：M3 首期使用**关键词匹配 + 规则打分**，不引入 embedding。

```rust
pub struct RecommendRequest {
    pub description: String,
}

pub struct RecommendResult {
    pub template_name: String,
    pub display_name: String,
    pub score: f64,         // 0.0 ~ 1.0
    pub reasons: Vec<String>,
}

pub fn recommend_templates(
    templates: &[ProcessTemplate],
    request: &RecommendRequest,
) -> Vec<RecommendResult>;
```

**打分规则**：

| 维度 | 权重 | 规则 |
|------|------|------|
| 关键词匹配 | 50% | 任务描述中出现「需求/PRD」→ 匹配 4p12s-delivery，「小需求/修bug」→ 匹配 superpowers-task |
| 复杂度匹配 | 20% | 描述中「复杂/大型/重构」→ complex，「简单/小/快速」→ light |
| 历史采纳率 | 20% | 该工艺历史安装次数 / 总安装次数 |
| 完成率 | 10% | 该工艺实例的成功率 |

**关键词表**（内置在代码中，后续可配置化）：

```rust
const KEYWORD_TEMPLATE_MAP: &[(&[&str], &str)] = &[
    (&["需求", "PRD", "用户故事", "设计", "测试", "交付"], "4p12s-delivery"),
    (&["小需求", "修bug", "修复", "快速", "简单"], "superpowers-task"),
    (&["重构", "复杂", "大型", "规约", "治理"], "gienspec-complex"),
    (&["口头", "需求", "整理", "记录"], "oral-requirement"),
];
```

### 3.3 三层指标与仪表盘

**指标定义**：

| 层级 | 指标 | 数据来源 |
|------|------|---------|
| 结果 | 产物数量、门禁通过率、完成/失败比 | `loop_step_artifacts` + `loop_step_execution_gates` + `loop_executions` |
| 过程 | 环节均时长、返工率、AI/人工干预比 | `loop_step_executions.rework_count` + `loop_step_execution_gates.evaluated_by` |
| 使用 | 安装次数、执行次数、完成率 | `process_templates` + `loops.process_template_id` |

**聚合 API**：

```rust
// GET /api/v1/processes/stats
pub struct ProcessStats {
    pub template_usage: Vec<TemplateUsage>,
    pub overall: OverallStats,
}

pub struct TemplateUsage {
    pub template_name: String,
    pub install_count: i64,
    pub execution_count: i64,
    pub completion_rate: f64,
    pub avg_rework: f64,
    pub avg_gate_pass_rate: f64,
}

pub struct OverallStats {
    pub total_installs: i64,
    pub total_executions: i64,
    pub avg_completion_rate: f64,
}
```

实现方式：使用现有 `loop_.rs::get_loop_stats_for_workspace` 模式，新增一条聚合 SQL。

### 3.4 可视化编排器

**编辑器布局**：

```
┌──────────────────────────────────────────────┐
│ [YAML 文本]          │  [可视化预览]          │
│                      │                       │
│ process:             │  ┌─────┐    ┌─────┐  │
│   name: my-template  │  │需求 │ →  │设计 │  │
│ phases:              │  └──┬──┘    └──┬──┘  │
│   - id: req          │     │          │      │
│     name: 需求        │  4p12s-prd  write-   │
│     links:            │  PRD.md     design   │
│       ...             │                      │
│                       │                      │
├───────────────────────┴──────────────────────┤
│ [校验] 第 12 行: missing required field 'name' │
│ [保存] [预览]                                 │
└──────────────────────────────────────────────┘
```

**实现方式**：

- 编辑器使用 `@monaco-editor/react`（YAML 语法高亮 + 实时校验）；
- 右侧预览使用自定义 SVG/Canvas 渲染阶段流图（节点 + 连线 + skill/artifact/gate 标注）；
- 校验调用 `POST /api/v1/processes/{name}/validate`，后端解析 YAML 返回错误列表；
- 保存调用 `PUT /api/v1/processes/{name}`。

### 3.5 四流闭环预留

**四张预留表**（M3 只建表 + stub API，不全量实现闭环）：

```sql
-- 洞察流：每次工艺执行完成后，AI 生成的改进建议
CREATE TABLE IF NOT EXISTS insight_events (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    loop_execution_id INTEGER NOT NULL,
    phase_id INTEGER,
    step_id INTEGER,
    insight_type TEXT,       -- 'bottleneck' | 'improvement' | 'risk'
    content TEXT,
    generated_by TEXT,       -- 'ai'
    created_at TEXT
);

-- 治理流：组织级规则，如「当某环节返工率 > 30% 时告警」
CREATE TABLE IF NOT EXISTS governance_rules (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    rule_type TEXT,          -- 'rework_threshold' | 'duration_threshold' | 'mandatory_gate'
    config TEXT,             -- JSON
    enabled INTEGER DEFAULT 1,
    created_at TEXT,
    updated_at TEXT
);

-- 资产流：skill / 工艺模板的版本进化链
CREATE TABLE IF NOT EXISTS asset_evolution (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    asset_type TEXT,         -- 'skill' | 'process_template' | 'step_template'
    asset_name TEXT NOT NULL,
    from_version TEXT,
    to_version TEXT NOT NULL,
    change_summary TEXT,
    created_at TEXT
);
```

## 9. 风险

| 风险 | 处理 |
|------|------|
| 关键词推荐覆盖不足 | 内置关键词表可扩展，后续可配置化 |
| 指标聚合 SQL 性能 | SQLite 单表查询 + 内存聚合，量级可控 |
| Monaco 编辑器包体积大 | 按需加载（lazy import），不阻塞首屏 |
| 四流预留表未用先占 | 仅建表 + stub API，不参与运行时 |

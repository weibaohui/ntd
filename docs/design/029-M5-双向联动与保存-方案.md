## 2. 技术决策

### 2.1 双向联动数据流（对应需求 §3.4.1）

**单一数据源**：`ProcessEditor` 父组件维护 `ProcessDefinition` 对象作为 source of truth。

#### 2.1.1 可视化 → YAML

1. 用户在 React Flow 上增删 phase/link、改属性面板字段、拖连线
2. 修改 `ProcessDefinition` 对象对应字段（M4 已实现的 `processDefinitionUpdater` 纯函数）
3. 立即 `yaml.dump(processDefinition)` 刷新 Monaco 的内容（用 `editor.setValue`）
4. **设置 `isSyncing = true` flag**，Monaco 的 `onChange` 在 flag 期间忽略，推完后清 flag

#### 2.1.2 YAML → 可视化

1. 用户在 Monaco 编辑 YAML 文本
2. `onChange` 触发 debounced（300ms）`yaml.load()`
3. **成功** → 更新 `ProcessDefinition` 对象 → React Flow 节点重新渲染
   - 设置 `isSyncing = true` flag，React Flow 的 `onNodesChange` 在 flag 期间忽略，推完后清 flag
4. **失败** → 只在 Monaco 上标红错误（M3 已实现），**不破坏当前可视化状态**

### 2.2 isSyncing flag 防循环

**决策**（需求 §3.4.1）：用显式 `isSyncing` boolean flag 防止"可视化→YAML→可视化"循环更新。

**实现**：
```typescript
// ProcessEditor 父组件维护
const [isSyncing, setIsSyncing] = useState(false);

// 可视化 → YAML 路径
const handleDefinitionChange = useCallback((newDefinition: ProcessDefinition) => {
  setDefinition(newDefinition);
  // 设置 flag，Monaco onChange 期间忽略
  setIsSyncing(true);
  // yaml.dump 刷新 Monaco
  const newYaml = yamlDump(newDefinition);
  setYamlText(newYaml);
  // 推完后清 flag（用 setTimeout 0 让 Monaco 先处理 onChange）
  setTimeout(() => setIsSyncing(false), 0);
}, []);

// YAML → 可视化路径
const handleYamlChange = useCallback((newYaml: string) => {
  setYamlText(newYaml);
  if (isSyncing) return; // flag 期间忽略（可视化触发的刷新）
  // debounced 300ms parseYaml
  debouncedParseYaml(newYaml);
}, [isSyncing]);

// debounced 解析成功后
const onParseSuccess = (parsed: ProcessDefinition) => {
  setIsSyncing(true);
  setDefinition(parsed);
  // React Flow onNodesChange 期间忽略
  setTimeout(() => setIsSyncing(false), 0);
};
```

### 2.3 保存按钮（对应设计 §8 + 需求 §3.7）

**决策**：顶部 Toolbar 加"保存"按钮，调用 `PUT /api/v1/processes/{name}`。

**处理流程**：
1. 点击保存 → `setIsSaving(true)` 禁用按钮
2. 调用 `bundledApi.putProcess(processName, yamlText)`（用 Monaco 当前 YAML 文本）
3. 成功 → `message.success("工艺已保存")` + `setIsDirty(false)` + `setIsSaving(false)`
4. 失败 → `message.error("保存失败：" + err.message)` + `setIsSaving(false)`

**不跳路由、不清表单**：保留当前 `ProcessDefinition` 对象和 React Flow 节点位置。

### 2.4 删除按钮（对应设计 §8）

**决策**：顶部 Toolbar 加"删除"按钮，`Modal.confirm` 确认后调用 `DELETE /api/v1/processes/{name}`。

**处理流程**：
1. 点击删除 → 弹 `Modal.confirm("确认删除工艺「<name>」？此操作不可恢复。")`
2. 确认 → `setIsDeleting(true)` 禁用按钮
3. 调用 `bundledApi.deleteProcess(processName)`
4. 成功 → `message.success("工艺已删除")` + 跳路由 `/#/processes`（回列表页）
5. 失败 → `message.error("删除失败：" + err.message)` + `setIsDeleting(false)`

**仅用户工艺可见**：`is_system=true` 时不渲染删除按钮（M1 后端也会拒绝）。

### 2.5 离开拦截（对应需求 §3.6）

**决策**：两层拦截，共享 `isDirty` 状态。

#### 2.5.1 路由内跳转：`useBlocker`

**现状核对**：项目无 `react-router-dom`（用 hash 路由 + 自研 `useViewState`），
故 `useBlocker` 不可用。改用自研 `beforeunload` + hash 路由拦截。

**实现**（`window` 层）：
```typescript
// 路由内跳转拦截：监听 hashchange，isDirty 时弹 Modal.confirm 阻止
useEffect(() => {
  if (!isDirty) return;
  const handler = (e: HashChangeEvent) => {
    // 阻止默认跳转
    Modal.confirm({
      title: '你有未保存的修改',
      content: '确认离开？未保存的修改将丢失。',
      onOk: () => {
        // 用户确认后允许跳转：先置 isDirty=false 避免二次拦截
        setIsDirty(false);
        window.location.hash = e.newURL.split('#')[1] ?? '';
      },
      // 取消时不跳转（hashchange 已触发，需回退）
      onCancel: () => {
        // 回退到旧 hash（用 history.replaceState 避免再触发 hashchange）
        history.replaceState(null, '', e.oldURL);
      },
    });
    // 阻止默认行为（已通过 replaceState 回退处理）
  };
  window.addEventListener('hashchange', handler);
  return () => window.removeEventListener('hashchange', handler);
}, [isDirty]);
```

#### 2.5.2 刷新/关页签：`beforeunload`

**实现**：
```typescript
useEffect(() => {
  const handler = (e: BeforeUnloadEvent) => {
    if (isDirty) {
      e.preventDefault();
      // Chrome 旧版需要 returnValue
      e.returnValue = '';
    }
  };
  window.addEventListener('beforeunload', handler);
  return () => window.removeEventListener('beforeunload', handler);
}, [isDirty]);
```

### 2.6 isDirty 标记

**决策**（需求 §3.6）：用户改了任何字段就置 `isDirty = true`，保存成功后置回 `false`。

**实现**：
- `handleDefinitionChange`（可视化操作）和 `handleYamlChange`（Monaco 编辑）都触发 `setIsDirty(true)`
- 保存成功后 `setIsDirty(false)`
- 加载工艺时 `setIsDirty(false)`（初始态）

### 2.7 删除节点级联的 Modal.confirm（M4 遗留优化）

**决策**：M4 的 `ProcessVisualEditor` 用 `window.confirm` 简化，M5 换成 Ant Design `Modal.confirm`。

**改动**：`ProcessVisualEditor.handleDeletePhase` 从 `window.confirm` 改为 `Modal.confirm`。

### 2.8 系统工艺复制后自动刷新（M3 遗留优化）

**决策**（M3 §6.1）：M3 用 `message.success` 提示用户重新打开，M5 优化为自动刷新。

**实现**：`handleCopyToUser` 成功后：
1. `message.success("已复制到用户层")`
2. 重新调用 `bundledApi.getProcess(processName)` 刷新 `detail` + `definition` + `isSystem`（此时 `is_system` 应为 `false`）
3. `setIsDirty(false)`

## 4. 数据流

### 4.1 M5 数据流（双向联动）

```
ProcessEditor (父，维护 definition + yamlText + isSyncing + isDirty)
  ↓ definition
ProcessVisualEditor (React Flow)
  ├─ buildProcessGraph(definition) → nodes + edges
  ├─ onConnect / onNodesDelete → handleDefinitionChange
  └─ 属性面板修改 → handleDefinitionChange
  ↓ handleDefinitionChange(newDefinition)
  ├─ setDefinition(newDefinition)
  ├─ setIsDirty(true)
  ├─ setIsSyncing(true)
  ├─ yamlDump(newDefinition) → setYamlText(newYaml)
  └ Monaco setValue 刷新
  └ setTimeout(() => setIsSyncing(false), 0)

  ↓ yamlText
ProcessYamlEditor (Monaco)
  └ onChange(newYaml) → handleYamlChange
  ↓ handleYamlChange(newYaml)
  ├─ setYamlText(newYaml)
  ├─ setIsDirty(true)
  ├─ if (isSyncing) return  // flag 期间忽略
  └ debouncedParseYaml(newYaml) → 300ms 后
      ├─ 成功 → setDefinition(parsed) + setIsSyncing(true) + setTimeout 清 flag
      └─ 失败 → Monaco 标红（M3 已实现），不破坏可视化
```

### 4.2 保存数据流

```
ProcessEditorToolbar
  └ 保存按钮点击 → handleSave
  ├─ setIsSaving(true)
  ├─ bundledApi.putProcess(processName, yamlText)
  ├─ 成功 → message.success + setIsDirty(false) + setIsSaving(false)
  └ 失败 → message.error + setIsSaving(false)
```

### 4.3 离开拦截数据流

```
ProcessEditor (isDirty 状态)
  ├─ useBlocker (路由内跳转)
  │   └ isDirty && 路由变化 → blocker.state = 'blocked'
  │   └ Modal.confirm("未保存修改，确认离开？")
  │       ├ onOk → blocker.proceed()
  │       └ onCancel → blocker.reset()
  └ beforeunload (刷新/关页签)
      └ isDirty → e.preventDefault() + e.returnValue = ''
```

## 7. 风险与缓解

| 风险 | 缓解措施 |
|------|---------|
| React Router 版本不支持 `useBlocker`（< 6.4） | 步骤 1 先核对版本，不支持则用 `useNavigate` + `beforeunload` 替代 |
| `yaml.dump` 输出格式与原 YAML 不一致（注释丢失、顺序变化） | M5 接受这一限制（YAML 是结构化数据，注释非核心），M7 评估是否保留注释 |
| 双向联动循环更新（可视化→YAML→可视化） | 显式 `isSyncing` flag，setTimeout 0 清 flag 让 Monaco 先处理 onChange |
| debounced 300ms 期间用户快速操作导致竞态 | 用 `useRef` 存最新 YAML 文本，debounce 回调取 ref 值而非闭包值 |
| `Modal.confirm` 与 `useBlocker` 的交互（删除确认时 blocker 误触发） | `Modal.confirm` 的 onOk 内跳路由前先 `setIsDirty(false)`，避免 blocker 拦截 |

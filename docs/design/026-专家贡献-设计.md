# 1. 设计目标

在 ntd 内为用户提供「把本地专家一键提交为官方仓库 PR」的完整链路：填写 GitCode PAT → ActionButton 唤起 AI → AI 读取 PAT、调 GitCode API 建 PR → 返回 PR 链接。后端只负责 PAT 存储与验证，提交流程固化为可编辑提示词。

对应需求：`docs/requirements/026-专家贡献-需求.md`。

# 2. 总体架构与数据流

```
用户点击「分享到官方仓库」
  └─ 前端 GET /api/v1/contribution/auth/status
       ├─ 未配置 PAT：
       │    提示并跳转「设置 → 第三方授权 → GitCode」
       │    在 PAT 管理表单填写 PAT → 保存
       │    POST /api/v1/contribution/pat  { pat }
       │        后端 GET /api/v5/user 验证 PAT → 持久化 0600（不存 username）
       │    表单支持清空（POST /api/v1/contribution/logout，二次确认）
       └─ 已配置 PAT：
            渲染 ActionButton（action_type=expert_contribute, action_key=专家名）
            用户点开 Drawer → 查看/编辑提交提示词 → 选执行器 → 点「执行」
            POST /api/v1/actions/execute（prompt + params）
            执行器（Claude Code 等）读取 ~/.ntd/contribution_pat.json 拿 PAT
               → 遍历专家目录 → fork → 建分支 → 写文件 → 建 PR
            前端展示 PR 链接
```

外部依赖（GitCode 平台，由 AI 按提示词调用，均已实测验证）：
- 验证用户：`GET https://api.gitcode.com/api/v5/user`
- fork：`POST https://api.gitcode.com/api/v5/repos/{owner}/{repo}/forks`
- 建分支：`POST https://api.gitcode.com/api/v5/repos/{owner}/{repo}/branches`
- 写文件：`POST https://api.gitcode.com/api/v5/repos/{owner}/{repo}/contents/{path}`
- 建 PR：`POST https://api.gitcode.com/api/v5/repos/{owner}/{repo}/pulls`

# 3. 凭据与配置方案（不新增 config.yaml 字段）

| 项 | 来源 | 说明 |
|---|---|---|
| PAT | 用户运行时在前端填写 | 后端验证后存 `~/.ntd/contribution_pat.json`（0600，只存 pat） |
| 贡献目标 `owner` / `repo` | 前端提示词固定 | `weibaohui` / `ntd-resource`，与 bundled 同步源一致 |
| GitCode 平台端点 | 前端提示词固定 | `api.gitcode.com` |

> 说明：PAT 方案下不再需要编译期注入的 `client_id`/`client_secret`，也不再需要 OAuth 授权/回调/刷新链路；提交由 AI 执行器完成，后端不再实现确定性 fork/建分支/写文件/建 PR 调用。

# 4. 后端设计

## 4.1 模块结构

```
backend/src/contribution/
  mod.rs        # 模块声明
  gitcode.rs    # 平台常量 + PAT 验证（verify_pat）
  pat.rs        # PAT 持久化到 ~/.ntd/contribution_pat.json（0600 原子写）

backend/src/handlers/contribution.rs   # Handler + contribution_routes()
```

> 原 `oauth.rs`、`issue.rs` 已删除；原 `gitcode.rs` 中的 fork/建分支/写文件/建 PR 确定性调用已删除。

## 4.2 关键实现点

### 4.2.1 PAT 持久化（`pat.rs`）

`~/.ntd/contribution_pat.json`，结构：
```json
{ "pat": "[redacted]" }
```
- Unix 下用 `OpenOptions::mode(0o600)` 原子创建（消除「先写 0644 再 chmod」的 TOCTOU 窗口）。
- `PatCredential` 自定义 `Debug` 脱敏（`pat` 字段显示 `[redacted]`）。
- 提供 `load` / `save` / `clear`。

### 4.2.2 保存并验证 PAT（Handler）

`POST /api/v1/contribution/pat` 入参 `{ pat }`：
1. 校验非空。
2. 调 `gitcode::verify_pat(&pat)` 验证 PAT 有效。
3. 验证失败返回可读错误（不落盘）；成功则 `pat::save`（只存 pat，不存 login）。

### 4.2.3 登录态与退出

- `GET /api/v1/contribution/auth/status` → `{ configured }`。
- `POST /api/v1/contribution/logout` → 清除本地 PAT。

## 4.3 路由与 Handler

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/contribution/auth/status` | `{ configured }` |
| POST | `/api/v1/contribution/pat` | `{ pat }` → 验证 + 保存 |
| POST | `/api/v1/contribution/logout` | 清除本地 PAT |

> 提交动作复用现有 `POST /api/v1/actions/execute`（ActionButton 链路）。

# 5. 前端设计

## 5.1 API 模块

`frontend/src/utils/database/contribution.ts`：

```ts
getContributionAuthStatus(): Promise<{ configured: boolean }>
saveContributionPat(pat: string): Promise<void>
logoutContribution(): Promise<void>
```

## 5.2 提交提示词（`contributePrompt.ts`）

`buildContributePrompt()` 返回提交 PR 的提示词模板，占位符 `{{expert_name}}` / `{{version}}` / `{{expert_dir}}` 由 ActionButton 的 params 注入。要点：
- 指示 AI 从 `~/.ntd/contribution_pat.json` 读 PAT（不内联 PAT 明文）。
- `expert_dir` 用 `~/` 相对路径（`toHomePath` 把绝对路径转 `~/.ntd/...`），不暴露家目录下的用户名。
- 描述遍历专家目录（跳过 `.downloaded_at` / `.clawhub` / `.git`）与调用 GitCode API 的完整步骤（验证用户 → fork → 建分支 → 写文件 → 建 PR）。
- 要求最终输出 PR 的 `web_url`，且不回显 PAT 明文。

## 5.3 PAT 管理：设置-第三方授权（`ThirdPartyPanel.tsx`）

设置页新增「第三方授权」Tab（`SettingsPage.tsx` 的 `tabItems` 追加，key=`thirdParty`，URL `/#/settings?tab=thirdParty`）。面板内嵌子 Tabs，第一个为 **GitCode**（预留后续平台扩展）：

- 展示当前配置态：`GET /api/v1/contribution/auth/status` → 已配置/未配置。
- PAT 填写：`Input.Password`，必填校验。
- 保存：`POST /api/v1/contribution/pat { pat }`（后端验证 + 0600 持久化）；成功后清空输入并刷新配置态。
- 清空：`POST /api/v1/contribution/logout`，`Popconfirm` 二次确认；未配置时禁用。
- 说明文案：PAT 仅存本机 `~/.ntd/contribution_pat.json`（0600），分享专家时由 AI 执行器读取。

## 5.4 UI 改动（`ContributeButton.tsx`）

1. 点击「分享」→ 查 `auth/status`：
   - `configured=false` → `message` 提示 + `showView('settings', { tab: 'thirdParty' })` 跳转设置引导填写（不再内嵌 PAT Modal）。
   - `configured=true` → 直接切到 ActionButton。
2. ActionButton（`actionType="expert_contribute"`，`actionKey=专家名`，`prompt=buildContributePrompt()`，`params={expert_name, version, expert_dir}`）承载提交：打开 Drawer → 编辑提示词 → 选执行器 → 执行 → 看日志与结果。
3. **移除**分享按钮旁的「更换 PAT」（清除）入口：清空操作统一走设置-第三方授权，避免在分享区误触。

双入口（独立「专家」页 + 「专家模板」Tab）复用同一 `ContributeButton`。

## 5.4 交互流程

1. 点「分享」→ `getContributionAuthStatus()`：
   - 未配置 → PAT Modal → 保存成功后切 ActionButton。
   - 已配置 → 直接切 ActionButton。
2. 点 ActionButton → Drawer 展示提示词 → 用户点「执行」→ AI 提交 → 展示 PR 链接。

> 取舍：PAT 配置成功后需再点一次「分享」（ActionButton 按钮）才打开提交 Drawer，沿用「配置态切换」的 MVP 取舍，避免为 ActionButton 增加受控打开能力。

# 6. 安全设计

- PAT 只存本地 `~/.ntd/contribution_pat.json`（0600），不进源码 / config.yaml / 前端产物 / 日志 / 错误信息。
- `auth/status` 只回传 `configured`；`PatCredential` 的 `Debug` 脱敏。
- PAT **不内联进提示词模板**（避免落库到 `todo.prompt` / 执行记录）；提示词只指示 AI 执行时从本地文件读取，并要求最终输出不回显 PAT。
- 提交动作由 AI 执行器完成，PAT 会进入执行器工具调用与 LLM 上下文（本方案已知风险，见需求文档 §10）。
- PAT 验证失败的错误信息只含 HTTP 状态码，不回显 PAT 相关请求 URL/明文。

- **后端单测**：
  - `pat.rs`：save/load 往返、缺失文件、`Debug` 脱敏。
  - `gitcode.rs`：`truncate_for_log` 截断。
- **编译与静态检查**：`cargo clippy --all-targets -- -D warnings` 零告警；`cd frontend && npx tsc --noEmit` 零错误。

# 8. 关键决策记录

- **提 PR 而非直接 push**：普通用户零 git 学习成本，官方仓库保留人工 review 门槛。
- **PAT 而非 OAuth**：OAuth 需要维护者注册应用并注入 `client_id`/`client_secret`，部署门槛高；PAT 由用户自行生成、运行时填写。
- **ActionButton + 提示词而非后端确定性调用**：把提交流程固化为可编辑提示词，复用 ntd 已有的 AI 执行能力，后端只负责 PAT 存储与验证，逻辑最小化。
- **PAT 不内联进提示词**：PAT 只在执行时由 AI 从本地文件读取，减少 PAT 进入 `todo.prompt` / 执行记录的暴露面。
- **保存时立即验证 PAT**：填完即反馈有效性，验证只确认 PAT 能通过认证、不落盘用户名。

# 3. 执行顺序与提交策略

按可独立 revert 的粒度分 4 个 commit：

1. `chore: 删除前端孤儿组件文件（5 个）` — 文件删除 + 失效注释引用清理
2. `chore: 删除前端未使用导出（37 项）` — tsc 验证
3. `chore: 删除后端零引用 pub 项（60 项）` — 含 import 级联清理，clippy + test 验证
4. `chore: 移除未使用 Cargo 依赖（3 个）` — clippy + test 验证

每步完成后执行对应验证，全部完成后重跑扫描脚本做级联复查。

# 4. 级联处理规则

- 删除函数后其专用 import 变未用 → 同 commit 内清理
- 删除后新出现的零引用项（如只被死代码调用的私有辅助函数）→ 重跑扫描确认后一并删除，在设计文档变更记录中注明
- **保留项（scanner 误报已人工核实）**：前端 18 个导出仅模块内部使用但属于在岗代码的组成部分，不删——12 个 `INSTALL_*_PROMPT`（被同文件注册表引用）、`PHASE_RANKSEP`、`GraphCallbacks`、`CreateQuickButtonParams`/`UpdateQuickButtonParams`、`UpdateWorkspaceSettingsParams`/`UpdateWorkspaceSlashCommandParams`（均为在岗函数的参数类型）
- 注释中提及被删项的 → 修正或删除该注释行（遵循"注释与代码同步"规范）

## 1. 设计目标

在 025 工艺管理 M1~M3 已完成的基础上，新增一个面向用户的统一入口——**任务（Task）**：

- 「任务」是工艺管理的**入口**，不是替代。
- 用户写自然语言描述意图 → 系统推荐/选择工艺模板 → 一键创建 Loop 并注入需求 → 执行。
- 零新增数据库表，复用 `loops` 表字段。

---

## 2. 概念模型

ntd 实体层级（从用户视角，从上到下）：

```
任务 (Task)
  │  用户想做的事。一条任务 = 一个由工艺模板创建的 Loop。
  │  存储：loops 表（process_template_id IS NOT NULL）。
  │
  ├── 工艺模板 (Process Template)
  │     方法库。定义了"怎么做这类事"的标准套路。
  │     存储：process_templates 表。
  │
  ├── 回路 (Loop)
  │     执行实例。按模板生成，用户可编辑后执行。
  │     存储：loops 表。
  │
  ├── 事项 (Todo)
  │     最小执行单元。Loop 的每个环节对应一个 Todo。
  │
  └── 执行记录 (ExecutionRecord)
        每次执行的结果。评分、产物、Token 消耗。
```

**区分规则**：`loops.process_template_id IS NOT NULL` → 这是一个「任务」创建的 Loop；`IS NULL` → 手工创建的 Loop。

```
用户输入需求
    │
    ▼
POST /api/v1/tasks { requirement, workspace_id, template_name? }
    │
    ├─(未指定模板)→ recommender.rs → 选最高分模板
    │
    ├─ installer.rs → 安装模板为 Loop
    │

    │

    │
    └─ enhanced_prompt.replace("{{requirement}}", &loop_.description)
```

## 4. 后端设计

### 4.1 handlers/tasks.rs（新建）

```rust
// POST /api/v1/tasks
pub async fn create_task(
    State(state): State<AppState>,
    Json(req): Json<CreateTaskRequest>,
) -> Result<impl IntoResponse, AppError>;

// GET /api/v1/tasks
pub async fn list_tasks(
    State(state): State<AppState>,
) -> Result<impl IntoResponse, AppError>;

#[derive(Deserialize)]
pub struct CreateTaskRequest {
    pub requirement: String,
    pub workspace_id: i64,
    pub template_name: Option<String>,
}
```

**create_task 逻辑**：

1. 未指定 template_name → 调 `recommender::recommend`，取第一结果；
2. 调 `installer::install_process_template` 创建 Loop；
3. 用 `loops.description` 存需求文本（走已有 `update_loop` 或 SQL update）；
4. 返回结果。

**list_tasks 逻辑**：

```sql
SELECT l.id, l.name, l.description, l.status, l.created_at,
       pt.name AS template_name, pt.complexity
FROM loops l
JOIN process_templates pt ON pt.id = l.process_template_id
WHERE l.process_template_id IS NOT NULL
ORDER BY l.updated_at DESC
LIMIT 50
```

async createTask(requirement: string, workspaceId: number, templateName?: string): Promise<{
  task_id: number; loop_name: string; template_name: string; phase_count: number; step_count: number;

  return unwrap(await api.post('/api/v1/tasks', {

  }));

async listTasks(): Promise<Array<{
  loop_id: number; name: string; description: string;
  template_name: string; complexity: string; status: string; created_at: string;
}>> {
  return unwrap(await api.get('/api/v1/tasks'));
}

## 6. 数据库影响

**零新增表**。`loops` 表已有字段：

| 字段 | 含义 | 任务用途 |
|------|------|---------|
| `id` | 主键 | 任务 ID |
| `name` | 名称 | 模板名（可由用户修改） |
| `description` | 描述 | **需求文本** |
| `process_template_id` | FK → process_templates | 关联的工艺模板 |
| `workspace_id` | FK → project_directories | 所属工作空间 |
| `status` | enabled/paused/archived | 任务状态 |
| `created_at` | 创建时间 | 任务创建时间 |

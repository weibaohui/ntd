# 设计：评审默认值按钮 + 执行注入工作空间背景 + 工艺版本号递增修复（042）

## 1. 方案概述

三个独立问题，均在本分支修复：

1. **评审 prompt「使用默认值」按钮**：系统已有 `DEFAULT_REVIEWER_PROMPT`（`services/auto_review.rs:31`），
   新增只读端点暴露它，前端在两处评审 prompt 输入框（环节级 + 全局模板编辑）加按钮一键填入。
2. **执行注入工作空间背景**：所有 todo 执行入口都收敛到 `prepare_execution_state`（`stages.rs:45`），
   在其专家上下文注入之后、命令构造之前，统一前置 `# 运行背景（工作空间名称/地址）` 到最终 prompt 最外层。
3. **工艺版本号递增修复（回归）**：`bump_semver_minor` 代码没丢（`process.rs:364-372`），但 038 文件模式下
   磁盘=DB 同源，前端 Monaco 保存后不回刷，第二次保存起 `yaml_version != template.version` 跳过 bump 且
   回写旧版本。修复 = 前端回刷 Monaco（后端 PUT 回传 new_yaml）+ 后端防倒退兜底。

## 2. 问题1：评审默认值按钮

### 后端（`handlers/review_template.rs`）
新增 `get_default_review_prompt`，返回 `Json<ApiResponse<String>>` = `crate::services::auto_review::DEFAULT_REVIEWER_PROMPT`。
`v1_routes()` 加 `GET /api/v1/review-templates/default-prompt`（`action.rs:248` 已 merge）。
常量即真源，不依赖 DB 种子行；不改常量文本（避免破坏 `auto_review.rs:181` 快照断言）。

### 前端
- `utils/database/reviewTemplates.ts` 加 `getDefaultReviewPrompt(): Promise<string>`。
- 抽 `components/common/DefaultReviewPromptButton.tsx`（`size="small"`+`loading`，`onApply(text)` 回调，
  catch → `message.error`），两处复用。
- `process/propertyForms/LinkPropertyForm.tsx:444`「可用参数」chip 条同行末尾接入（`handleFieldChange('review_prompt', t)`）。
- `settings/ReviewTemplatesPanel.tsx:261` TextArea 下接入（`form.setFieldValue('prompt', t)`）。

## 3. 问题2：执行注入工作空间背景（最外层）

用户选定注入到最终 prompt **最外层**（盖在专家角色定义之前）。

- `executor_service/pre_spawn.rs` 新增 `inject_workspace_background(db, workspace_id: Option<i64>, message) -> String`：
  - `workspace_id=None` 或查询失败 → 返回原 message（静默回退，与 `inject_workspace_prompt:550` 同模式）。
  - `get_project_directory_by_id`（`db/project_directory.rs:139`）取 name/path，name 缺省回退 path。
  - 格式：`# 运行背景\n工作空间：{name}\n地址：{path}\n---\n{message}`。
- `executor_service/stages.rs::prepare_execution_state`（:70-74）Step 5 后插 Step 5.5：
  `ws_id = request.workspace_id.or_else(|| todo.workspace_id)`（loop 路径 request.workspace_id=None 时回退），
  结果作为 Step 6 `select_executor_and_build_command` 的 message 入参。
- 不动 `loop_runner.rs:836/1770`（那是需求 022 的 workspace 共识 system_prompt，不同内容）。
- 单测三态：有 ws 含 name、name 缺省回退 path、ws_id=None/查失败回退原 message。

## 4. 问题3：工艺版本号递增修复

根因：前端 `handleSave`（`ProcessEditor.tsx:213-227`）保存后不回刷 Monaco，`putProcess` 返回 `void`。
陈旧 version 第二次保存起触发 `yaml_version != template.version` 跳过 bump 并回写旧版本。

### 后端（`handlers/process.rs::update_process`，:362-392）
- bump 逻辑保持（`yaml_version == template.version` 才递增，尊重用户手动改版本）。
- **防倒退兜底**：写盘前确保 `definition.process.version` 不低于 `template.version`，用 `semver::Version`
  比较（项目已依赖 semver），parse 失败按字符串比较。防前端陈旧提交倒退磁盘版本。
- **响应回传 `definition`**：把序列化出的 `new_yaml` 放进 `ApiResponse::ok({ updated_at, definition })`。

### 前端
- `api/bundled.ts::putProcess`（:509）返回 `Promise<{ definition: string }>`。
- `ProcessEditor.tsx::handleSave`（:216-219）：成功后 `setYamlText(res.definition)` 回刷 Monaco，再 `setIsDirty(false)`。
- 后端单测：bump 正常路径 + 防倒退兜底。

## 5. 不在范围

- 不删 `loop_runner` workspace 共识预注入。
- 不做版本链 `previous_version_id` 写入 / 版本历史 UI。

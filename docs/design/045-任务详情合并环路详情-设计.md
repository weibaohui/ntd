## 1. 总体思路

任务（Task）与环路（Loop）是 1:1 关系（`task.loop_id → loop.id`），本设计将环路详情面板嵌入任务详情页，在单页面内完成查看执行环路结构、验收标准、执行历史与环路管理操作。

### 设计目标

1. **减少跳转**：环路详情与任务详情合并为单页，无需跨页面导航
2. **保留原有能力**：不删除环路详情已有的展示能力（DAG 流程图、执行历史面板），只改变挂载位置
3. **降级友好**：环路加载失败或不存在时，任务详情正常展示

## 3. 数据加载

两级并行拉取，不阻塞用户：

```
渲染流程:
  初始空白 → useEffect[taskId] → getTaskDetail (loading)
     → 渲染概览（task/template）+ 环路 loading spinner
     → if loop_id: useEffect[detail] → getLoop
         → 渲染环路信息 / DAG / 执行历史
     → if no loop_id: 渲染空态回退视图
```

### 竞态保护

两个 useEffect 各自使用 `alive` flag（闭包捕获），确保：

- 快速切换任务时晚返回的请求不会覆盖新数据
- 环路加载失败不覆盖任务详情（静默 catch + 保留当前 detail）

## 4. Tab 设计

### 概览 Tab（OverviewTab）

- **环路存在时**：三个 DetailSection 区块
  1. 基本信息：工作空间（含目录路径 / Git Worktree / 自动清理标志）+ 待审批红色角标
  2. 全局限制：最大执行步数 / 最大 Token 数 / 超限异常处理启用状态
  3. （无需求描述和执行进度——已在 045 中移除，让概览聚焦运行态元信息）
- **环路不存在时**：回退展示工艺模板基本信息（Ant Design Descriptions 组件）

### 执行环路 Tab（DAGTab）

- 空态检查：`!loopDetail?.steps?.length` → Empty 组件
- 环路描述文本（可选，来自工艺定义）
- `LoopStepsPanel`：SVG DAG 流程图（复用 `LoopFlowGraph`）
- 步骤验收标准列表：按 `order_index` 排序的环节卡片
  - 每个卡片含序号圆标、环节名称、技能 Tag(紫)、产物 Tag(蓝)、门禁 Tag

### 执行历史 Tab（ExecHistoryTab）

- 空态检查：`!loopId` → Empty 组件（提示"暂无关联环路"）
- 完整复用 `LoopExecutionsPanel`：分页 + TokenSummaryBar + StepExecList + BlackboardDrawer
- 与环路详情页使用同一组件，保持行为一致

## 5. 关键决策

### 5.1 为何移除执行看板 Tab（第四 Tab）

任务执行看板（`ProcessExecutionBoard`）取最新一条执行记录展示完整执行过程。该组件更适用于环路详情页的下钻场景而非任务详情页的概览场景。用户查看任务详情时如果关心某次执行的完整过程，通过执行历史 Tab 进入即可。移除后 Tab 数从 4 降为 3，UI 更简洁。

### 5.2 为何移除来源工艺面包屑

来源工艺（`TraceBreadcrumb`）在任务详情页的信息增益有限——任务详情页顶部已经展示了工艺模板名称（`{template?.display_name}`），点击环路详情页的「来源工艺」面包屑跳转到工艺列表属于深链路导航，在任务上下文中的需求频次低。

### 5.3 为何移除概览中的执行进度

概览页的执行进度条（`Progress`）只显示最近一次执行的分步完成比例，信息量有限。完整执行历史在「执行历史」Tab 中可查看，概览应聚焦任务和环路的静态元信息。移除后概览 Tab 加载速度快（不需要 `executions` 数据参与渲染）。

## 8. 安全反思

- 环路删除操作来自详情页内 Popconfirm，与环路列表页删除使用同一后端接口（`delete_loop_v1`），权限校验逻辑不变
- 新增 `onOpenTodo` 回调经由 `App.tsx` `handleSelectTodo` 处理，与事项列表跳转使用同一路径
- 无新增 API 端点，不扩大攻击面

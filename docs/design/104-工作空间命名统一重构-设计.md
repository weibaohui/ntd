# 104-工作空间命名统一重构-设计

> 目标：消除「项目目录 (project_directory)」旧命名与「工作空间 (workspace)」现行命名并存的状况，
> 让组件、路由、API、数据库表在命名上完全统一为 workspace。

|--------|---------|---------|
| AI 协作开发者 | 2026-08-15 | 初始版本：命名统一重构设计 |

## 1. 背景与问题

工作空间功能从「工作目录/项目目录」演化而来，系统内大部分概念已改称「工作空间」（工作空间）。
但**工作空间注册实体**的命名仍停留在旧时代「项目目录」：

| 层级 | 旧命名（现状） | 新命名（目标） |
|------|--------------|--------------|
| 数据库表 | `project_directories` | `workspaces` |
| SeaORM 实体 | `entity/project_directories.rs` → `ProjectDirectories` | `entity/workspaces.rs` → `Workspaces` |
| DB 模块 | `db/project_directory.rs` → `ProjectDirectory` 结构体 | `db/workspace.rs` → `Workspace` |
| Handler | `handlers/project_directory.rs` | `handlers/workspace.rs` |
| 后端 API 路由 | `/api/v1/project-directories`（CRUD） | `/api/v1/workspaces`（CRUD） |
| CLI HTTP 路径 | `/project-directories` | `/workspaces` |
| 前端组件 | `ProjectDirectoriesPanel` | `WorkspacesPanel` |
| 前端视图/路由 | `projectDirectories`、`/#/projectDirectories` | `workspaces`、`/#/workspaces` |
| 前端 API 函数 | `getProjectDirectories` 等 | `getWorkspaces` 等 |
| 前端类型 | `ProjectDirectory` | `Workspace` |
| 飞书绑定列 | `feishu_project_bindings.project_dir_id` | `workspace_id` |

附带清理的旧名残留：

- 备份文件名 `aietodo-backup-*.yaml` → `ntd-backup-*.yaml`（项目早期名 aietodo 残留）
- launchd 标签 `com.nothing-todo.ntd` → `com.ntd.ntd`（工作目录名 nothing-todo 残留）

## 2. 设计决策（已与用户确认）

1. **全套统一为 workspace**：前端组件/视图/API 函数/类型、后端模块/函数/路由、数据库表全部对齐。
2. **API 直接改，不留旧路径**：`/api/v1/project-directories` 直接改为 `/api/v1/workspaces`，
   不保留重定向（项目无历史用户、无兼容包袱，与 020 工作空间重构先例一致）。
3. **表名改为 `workspaces`**：新增 V94 迁移执行表改名；历史迁移（v1..v93）保持原样不可变。
4. **前端路由改 `/#/workspaces`，不做旧路由兼容**（与 028 路由重构先例一致）。
5. **连带清理** aietodo 备份文件名与 launchd 标签。

## 3. 数据库迁移方案（V94）

新建 `backend/src/db/migration/v94.rs`，内容：

```sql
-- 1) 先删除依赖旧表名的触发器（SQLite RENAME 会改写触发器体内引用，显式重建更可控）
DROP TRIGGER IF EXISTS set_project_directories_created_at_utc;
-- 2) 删除旧名索引，重建为新名（SQLite 无 RENAME INDEX）
DROP INDEX IF EXISTS idx_project_directories_path;
-- 3) 核心：表改名；SQLite ≥3.25 自动把其它表 REFERENCES project_directories(id) 改写为 workspaces(id)
ALTER TABLE project_directories RENAME TO workspaces;
-- 4) 以新名重建索引与触发器（保持既有行为：path 索引 + created_at UTC 触发器）
CREATE INDEX IF NOT EXISTS idx_workspaces_path ON workspaces(path);
CREATE TRIGGER IF NOT EXISTS set_workspaces_created_at_utc AFTER INSERT ON workspaces
  BEGIN UPDATE workspaces SET created_at = strftime('%Y-%m-%dT%H:%M:%SZ', 'now', 'utc') WHERE rowid = new.rowid; END;
-- 5) 飞书绑定表列改名（API 可见字段一并统一）
ALTER TABLE feishu_project_bindings RENAME COLUMN project_dir_id TO workspace_id;
```

要点：

- 历史迁移（v1.rs、v2_v5.rs、v41_v46.rs、v47_v53.rs、v56/v57/v61/v69.rs 等）**不修改**——
  它们先于 V94 执行，当时表名确实是 project_directories，属于不可变历史快照。
- `consolidated_schema.rs`（全新库 bootstrap 用）必须同步：`workspaces` 表 + 外键引用 +
  `idx_workspaces_path` 索引。通过运行 `cargo test --test dbg_gen_schema -- --ignored`
  重新生成，并用漂移测试 `test_consolidated_schema_matches_incremental` 校验 bootstrap 与
  增量迁移结果一致。
- SeaORM 实体 `table_name` 改为 `"workspaces"`，模块名 `workspaces`，
  prelude 别名 `ProjectDirectories` → `Workspaces`。
- `feishu_project_bindings` 表名保留（表名中的 project 是产品语义「项目=工作空间」，
  不含目录含义；列名 `project_dir_id` 含 dir 必须改）。实体字段同步改名。

## 4. 后端改动清单（Rust）

- 文件改名（git mv）：
  - `db/entity/project_directories.rs` → `db/entity/workspaces.rs`
  - `db/project_directory.rs` → `db/workspace.rs`
  - `handlers/project_directory.rs` → `handlers/workspace.rs`
- 标识符替换（全局，含注释）：
  - `project_directories` → `workspaces`（表名/实体模块/复数）
  - `project_directory` → `workspace`（模块名/函数名/单数）
  - `ProjectDirectory` → `Workspace`（结构体）
  - `ProjectDirectories` → `Workspaces`（实体别名）
  - `project_dir_id` → `workspace_id`（飞书绑定列/字段/Column 枚举）
  - `/project-directories` → `/workspaces`（API 与 CLI 路径）
- 函数改名映射（`db/workspace.rs` + 全部调用方）：
  `get_project_directories`→`get_workspaces`、`create_project_directory`→`create_workspace`、
  `update_project_directory`→`update_workspace`、`delete_project_directory`→`delete_workspace`、
  `get_project_directory_by_path`→`get_workspace_by_path`、
  `get_project_directory_by_id`→`get_workspace_by_id`、
  `get_or_create_project_directory`→`get_or_create_workspace`、
  `list_project_directories`→`list_workspaces` 等。
- 请求结构体：`CreateProjectDirectoryRequest`→`CreateWorkspaceRequest`、
  `UpdateProjectDirectoryRequest`→`UpdateWorkspaceRequest`。
- 路由注册：`/api/v1/project-directories` → `/api/v1/workspaces`（与已有
  `/api/v1/workspaces/{ws}/...` 嵌套路由不冲突：新注册的 `{id}` 叶子路由与
  `{ws}` 前缀嵌套段数不同，`v1_workspace_routes` 也无根路径路由）。
- 中文注释「项目目录」→「工作空间」；纯文件系统语义的「目录」保留（如 worktree 目录）。
- session scanner（pi/kimi/atomcode）中仅指文件系统路径的局部变量 `project_dir` 保留，
  指向工作空间实体的引用改名。
- CLI：`resolve_workspace_id_by_path` 等 HTTP 路径 `/project-directories` → `/workspaces`。

## 7. 风险与验证

- **SQLite 表改名**：RENAME 后 FK 引用改写依赖 SQLite ≥3.25（bundled 版本满足）；
  漂移测试验证 bootstrap 与增量一致。V94 前用真实旧库快照验证升级路径。
- **API 破坏性变更**：已与用户确认直接改不留旧路径；前端与 CLI 同步更新。
- **验证**：`cargo clippy --all-targets -- -D warnings` 零告警；`cargo test` 全绿；
  `npx tsc --noEmit` 零错误；Playwright 关键路径冒烟；`dbg_gen_schema` 重新生成合并 schema。

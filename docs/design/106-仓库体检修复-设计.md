# 106 仓库体检修复 — 设计文档

> 来源：2026-08-15 全仓库体检（5 路并行审计 + clippy/test/tsc 静态检查）。
> 范围：Critical 3 项 + High 全部 + Medium 全部，单一 PR 合入。
> 不在范围：Low 级 15 项（另立 issue 跟进）；完整的 API 鉴权体系（见 §1.1 取舍说明）。

---

## 1. 安全域（Phase A）

### 1.1 C1：监听地址硬编码 0.0.0.0，忽略 cfg.host

- **现状**：`main.rs:693` `TcpListener::bind(format!("0.0.0.0:{}", port))`，`config.rs` 有 `host` 字段但不生效。
- **方案**：
  1. 绑定改为 `format!("{}:{}", cfg.host, port)`；
  2. `config.rs` 的 `host` 默认值从 `0.0.0.0` 改为 `127.0.0.1`（已有配置文件里的显式 `0.0.0.0` 不受影响，行为不变）；
  3. 启动日志：当绑定非回环地址时打印一条 warn，提示未鉴权暴露面。
- **取舍**：完整的 token 鉴权中间件是独立特性（涉及前端登录态、飞书/webhook 白名单、升级兼容），不在本 PR。本 PR 把默认暴露面收回 localhost，并在文档中声明风险。

### 1.2 C2：session 删除/读取路径穿越

- **现状**：`handlers/session.rs:427` delete、`scanners/claude_code.rs:344`、`hermes.rs:91`、`kimi.rs:103` 详情读取，均直接 `join(format!("{}.jsonl", session_id))`，`..%2F` 可逃逸。
- **方案**：新增 `validate_session_id`（只允许 `[A-Za-z0-9_-]`，拒绝含 `/`、`\`、`..`、空串），三个入口统一调用，非法 id 返回 400。session id 由 Claude Code 等工具生成为 UUID，白名单字符集不会误伤。

### 1.3 bundled skill content 路径穿越（Medium）

- **现状**：`handlers/bundled.rs:1541` `get_bundled_skill_content` 未复用同文件 `resolve_skill_path_for_read`。
- **方案**：content 接口改走 `resolve_skill_path_for_read` 同款校验（拒绝绝对路径/ParentDir + canonicalize 后 containment 检查）。

### 1.4 artifact 接口（Medium + High panic）

- **现状**：`handlers/tasks.rs:439-476`：路由不在 workspace 命名空间下、无归属校验；`read_workspace_file` 128KB 截断 `&s[..128*1024]` 按字节切片，多字节字符边界处 panic。
- **方案**：
  1. artifact 查询后校验其关联 execution/todo 的 workspace 与请求上下文一致；
  2. locator 做 containment：canonicalize 后必须 `starts_with(workspace_path)`；
  3. 截断改用 `chars().take(128*1024).collect()`（或 `floor_char_boundary`），杜绝字节边界 panic。同型修复：`feishu_push.rs:251` 改 `chars().take(60)`。

### 1.5 凭证明文泄露（High ×3）

- `handlers/config.rs` GET /config：给 `cloud_sync.sync_token` 加 `#[serde(skip_serializing)]`（写路径走专门接口，不受影响）。
- `handlers/profiles.rs:122` provider 详情：`api_key` 返回脱敏值（保留前 4 位 + `***`，空则空），前端编辑场景改用"留空表示不修改"语义——需检查前端提交逻辑兼容。
- `handlers/sync.rs` save_config：`server_url` 校验——必须 https（允许 localhost http 便于开发）、复用 `is_private_host` 风格校验拒绝字面私网 IP，并拒绝含 `..` 的异常值；push 时不再允许通过 config 接口静默换 host 后立即外发 token（加 warn 日志）。

### 1.6 跨 workspace 校验缺口（High）

- `handlers/todo.rs:438` `batch_delete_todos`：补上 `verify_todos_belong_to_ws`，与同文件其他 batch 接口对齐。
- `handlers/tasks.rs`：
  - `create_task` 环路模式：校验 `loop_id` 归属当前 ws（调 `verify_loop_belongs_to_ws`），`lp.workspace_id.unwrap_or(1)` 改为优先取路径 ws；
  - `get_task_detail`/`delete_task`/`batch_delete_tasks`/`create_task_execution`：补 task→workspace 归属校验。
- `handlers/workspace.rs:89` `delete_workspace`：删除前计数校验，仍有 todo 时返回 409；不存在返回 404。

## 2. 飞书链路（Phase B）

### 2.1 C3：重连计数器永不复位 + 无 supervisor

- `feishu/channel.rs listen()`：连接成功后（`handle` 正常返回 Ok 且曾建立连接）`attempt` 复位为 0；额度只惩罚"连续失败"。
- `feishu_listener.rs:144-150`：spawn 的任务返回 Err 后增加 supervisor 循环——带退避重新调用 `listen()`，并推一条系统告警日志/事件。

### 2.2 心跳 pong 不刷新 ping_time

- `feishu/sdk/ws_client.rs`：`handle_message` 解析到 pbbp2 pong 控制帧时同样刷新 `ping_time`；协议级 Ping 路径保持不变。

### 2.3 HTTP 无超时 + 每次新建 Client

- `feishu_api_client.rs`：模块级 `OnceLock<reqwest::Client>` 共享实例，`timeout` 取 `Config::req_timeout`（把该字段真正接线，默认 15s）；`token_manager.rs` 同理。

### 2.4 事件无 dedup

- `ws_client.rs` 事件入口：按 `event_id`（message_id 兜底）做 LRU 去重（容量 1000），重复事件直接回 200 不再下发。

### 2.5 try_send 静默丢弃

- `channel.rs:193,291`：256 容量 try_send 失败时改为把该事件标记为未处理 + error 日志带 message_id；消费端慢的问题由 2.3 超时兜底缓解。不改为阻塞 send（避免反压拖死 ws 读循环）。

## 3. loop_runner 流转（Phase C）

- `resolve_next` 拆分为按成败语义取值：调用方传 `gates_passed: bool`，`goto` 臂按 `if passed { success_goto } else { fail_goto }` 选取，与 `process/transition_resolver.rs:60-64` 对齐。
- 裸环节名策略（installer 写入的 `"write-prd"` 等）：`resolve_next` 的 `_` 臂改为按"goto 目标名"解析——在 step 列表中按名称查找目标，找不到才 warn + next。消除与 transition_resolver 的语义分裂。
- 回归测试：失败分支 goto 到返工环节、裸名策略跳转、resume 审批拒绝路径，各加一条单测。

## 4. 后端并发/资源（Phase D）

1. **message_debounce abort 自杀竞态**：entry 加 generation 计数；timer 触发后 `remove` 时比对 generation，不匹配说明已被新 push 替换，直接归还消息不执行。 
2. **p2p drain 窗口**：把"检查 running 标记 + 入队"与"清 running 标记"收进同一把锁的临界区（或 drain 结束后再做一次队列非空复查，非空则续跑一轮）。
3. **executor_session**：行缓冲加上限（如 10k 行/路，超限丢弃并记 warn）；`child.wait()` 包 `tokio::time::timeout`；kill 改进程组（与 spawn_lifecycle 主链路一致，用 command_group）。
4. **blackboard_debouncer 调大阈值**：timer task 不捕获固定值，到期前读当前配置重算剩余 sleep；cancel_timer 同时 abort 旧任务（配 generation 防误删新状态）。
5. **log_flusher 回滚乱序**：失败回滚改 `snapshot.extend(logs.drain(..)); logs = snapshot`（旧条目回到头部），保持时间序。
6. **log_capture UTF-8**：`lines()` 改用 `read_line` + `String::from_utf8_lossy` 容错，单行错误不终止循环。
7. **worktree 并发 init + 元数据残留**：同 repo 路径加 `DashMap<PathBuf, Arc<tokio::sync::Mutex>>` 锁；cleanup 失败时追加 `git worktree prune` + 删除 `wt-*` 分支兜底。
8. **git_sync / auto_update 超时**：`Command::output()` 包 `tokio::time::timeout`（git 120s、npm 60s）；`StrictHostKeyChecking=no` 改 `accept-new` 并加配置项可覆盖。

2. `useLeaveGuard`：改为导航前拦截——hash 路由下在点击/跳转入口先查 dirty（或 popstate 时先 `history.go(1)` 恢复再弹窗），消除 URL/视图脱节。

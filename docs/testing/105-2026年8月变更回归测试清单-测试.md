## 5.2 测试发现并修复的缺陷（executor_session stderr 丢失）

- **现象**：`cargo test` 全量 1 失败——`services::executor_session::tests::test_spawn_and_stream_双流分流捕获不串流` 稳定失败（`raw_stderr` 为空）。
- **根因**：`stream_lines_until_exit` 的 select! 主循环中，**stdout EOF 分支直接 wait 子进程并返回**。当 stdout/stderr 双流同时产出（如 `echo out; echo err 1>&2`）时，select! 可能先命中 stdout EOF，此时 stderr 管道缓冲（`err\n`）尚未被读取即被丢弃——执行器诊断信息静默丢失。
- **修复**（PR 分支 `fix/executor-session-stderr-drain`）：
  - stdout EOF 后不再立即返回：置 `stdout_done` 并继续轮询 stderr 至 EOF，**两路齐备才收尾**（stderr 已 EOF 则立即收尾）；
  - 收尾逻辑（wait + kill 回退 + 日志 + 打包）抽取为 `finish_session`，两处 EOF 收敛点共用，消除重复；
  - 副作用改进：原实现在「stdout 关闭但进程存活」场景会永久阻塞于 `child.wait()`，修复后超时分支可正常 kill 回收；
  - 新增反向时序用例 `test_spawn_and_stream_stderr先结束_stdout后收尾` 覆盖 stderr 先 EOF 的收敛点。
- **评审追加修复**（同分支）：
  - stderr **读失败**分支补齐收敛检查——此前该分支只置 `stderr_done` 不判断 `stdout_done`，stdout 已 EOF 时两分支同禁用：不限时（u64::MAX 计时）实质挂死，drain_mode 下则触发 select! 全分支禁用 panic；
  - take/join/收尾样板抽取为 `converge_finish`，三个收敛点（stdout EOF / stderr EOF / stderr 读失败）共用，从结构上防止新增分支漏写收敛；
  - 新增用例 `test_stream_lines_until_exit_stderr读失败_stdout已eof_正常收尾`（注入假流 FailingReader + 5s timeout 兜底，回归即失败而非卡死）。

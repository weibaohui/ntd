## 3. 测试用例清单

测试文件：`frontend/tests/nav-board-nodes.spec.ts`

### TC-01：关系图渲染 12 个节点，含黑板/看板

**步骤**：
1. 访问 `/#/onboarding`
2. 滚到「概念关系图」section

**预期**：
- `data-testid="onboarding-graph-node-blackboard"` 可见
- `data-testid="onboarding-graph-node-kanban"` 可见
- 全图 `<circle>` 节点总数 = 12（原 10 + 新 2）

---

### TC-02：点击黑板 → Drawer 说明 + 跳转黑板页

**步骤**：
1. 点击 `onboarding-graph-node-blackboard`
2. 检查 Drawer 内容与按钮
3. 点击 `onboarding-graph-drawer-goto-blackboard` 按钮

**预期**：
- Drawer 打开，文案同时包含「事项」「执行记录」「环节」三个关键词（覆盖需求 §5.3 三层语义）
- 按钮文案为「去黑板页」
- 点击后 URL hash 匹配 `#/blackboard`，且 Drawer 关闭（遮罩消失）

---

### TC-03：点击看板 → Drawer 说明 + 跳转看板页（kanban 模式）

**步骤**：
1. 点击 `onboarding-graph-node-kanban`
2. 点击 `onboarding-graph-drawer-goto-kanban` 按钮

**预期**：
- Drawer 文案包含「进度」关键词（需求 §5.4）
- 按钮文案为「去看板页」
- 点击后 URL 匹配 `#/memorial?mode=kanban`（query 顺序由 buildHashUrl 决定，mode 为唯一参数）

---

### TC-04：hover 黑板 → 事项/执行记录/环路同步高亮

**步骤**：
1. hover `onboarding-graph-node-blackboard`
2. 读取 `onboarding-graph-node-todo` / `-execution` / `-loop` 的 circle fill

**预期**：
- 三者 fill 均为 `#1677ff`（激活态）
- 无关节点（如 `-executor`）fill 不为此激活色

---

### TC-05：hover 看板 → 执行记录高亮

**步骤**：
1. hover `onboarding-graph-node-kanban`

**预期**：
- `onboarding-graph-node-execution` 的 circle fill 为 `#1677ff`

---

### TC-06：回归 — 既有 fallback 节点行为不变

**步骤**：
1. 点击 `onboarding-graph-node-trigger`（触发器，无 drawerDesc/navTarget）

**预期**：
- Drawer 展示通用文案「这是关系图的支线节点，用于辅助说明主概念关系」
- Drawer 内不存在任何 `onboarding-graph-drawer-goto-*` 按钮

## 7. 风险与降级

| 风险 | 降级 |
|------|------|
| Vite dev 下后端 API 不可达导致页面部分骨架屏 | 关系图纯静态，断言只针对图与 Drawer，不受影响 |
| hover 后 fill 断言依赖 0.2s CSS transition | fill 是 SVG attribute（React 受控），非 CSS 动画，hover 后立即可读，无需 wait |
| URL query 参数顺序差异 | kanban 仅 mode 一个参数，直接全串匹配 `#/memorial?mode=kanban`；若未来加参数改正则 |
